2-1. 函式開頭的 push %rbp 和 mov %rsp,%rbp 各在做什麼？

第 1 次（2026-10-19）

作答（🔒 已批改）
🔒 已批改，不能再修改
批改

大致對。兩條指令的動作都描述對了，但只講了「做什麼」，沒講「為什麼」：

  • push %rbp 存的是呼叫者的 %rbp，為的是返回前要還原給它。
  • mov %rsp,%rbp 是把現在的頂端定成自己這個函式的基準點：之後 %rsp 還會動（push、sub），%rbp 不動，區域變數就能用 -0x8(%rbp) 這種固定偏移存取。
參考答案

【第四節】

核心關鍵（答到這幾點就算對）：

  1. push %rbp：把呼叫者的 %rbp 存到堆疊上，返回前要還原。
  2. mov %rsp,%rbp：把現在的頂端定成自己堆疊框的基準點，之後區域變數用 %rbp 加固定的負偏移存取。

詳細說明：實測：add3 的 push %rbp 之後，d400 裡是 main 的 %rbp（d420）；mov 之後 %rbp ＝ d400。每個框的 %rbp 那格都存著上一層的 %rbp，串成一條鏈，bt 就是沿著它往回找。

第 1 次（2026-10-19）

作答（🔒 已批改）
🔒 已批改，不能再修改
批改

不完整。「add3 沒有 call 所以不需要」方向對，但沒說出兩個關鍵：

  • 為什麼 %rsp 下面能放變數：照第二節的規則，比 %rsp 低的地方還不屬於堆疊，隨時會被下一次 push／call 蓋掉。能放是因為 ABI 的紅區：%rsp 下方 128 byte 保證不會被別人（例如訊號處理函式）蓋掉；add3 是葉函式，自己也不會再 push／call，所以安全。
  • 為什麼 main 不行：call 會把返回位址推到 %rsp - 8，正好蓋掉 %rsp 下面那一區，所以 main 要先 sub 把變數的空間收進堆疊裡。

你寫的 16 byte 對齊是對的觀察，但它解釋的是「為什麼挪 0x10 而不是 8」（r 只要 8 byte），不是「為什麼要 sub」。

參考答案

【第四節〈上圖 add3 的變數在 %rsp 的「下面」：紅區〉】

核心關鍵（答到這幾點就算對）：

  1. 紅區：ABI 保證 %rsp 下方 128 byte 不會被別人蓋掉；add3 是葉函式，自己也不會 push／call，所以直接用、省一條 sub。
  2. main 要 call：call 推返回位址會寫在 %rsp 下面、蓋掉那一區，所以必須 sub 把變數空間放進堆疊（%rsp 上面）。

詳細說明：sub 的大小是 0x10 不是 8，才是 16 byte 對齊的緣故（第六節〈上面的 sub $0x8,%rsp：16 byte 對齊〉：進 main 時 d428，push 後 d420，sub $0x10 後 d410 是 16 的倍數）。kernel 不能用紅區（中斷會直接推資料到目前的堆疊上），所以編譯時加 -mno-red-zone。

4. callee-saved 與對齊

下面兩個函式用 -O2 編譯（g 只有宣告）。

/* saved.c */                          /* noret.c */
long g(long x);                         long g(long x);

long f(long x)                          long f(long x)
{                                       {
    long y = g(x);                          long y = g(x);
    return x + y;                           return y * 2;
