一句話結論：組合語言就是機器碼的文字版，一行一個指令。讀它只要抓三件事： (1) 資料在哪——16 個通用暫存器（%rax、%rdi…，同一個暫存器有 64／32／16／8 位元四個名字）或記憶體（D(B,I,S) ＝ 位址 D + B + I×S，正好就是 a[i] 的 a + i×sizeof）； (2) 做什麼——mov 搬資料（可能碰記憶體），lea 只算位址不碰記憶體（所以被拿來做加法和乘法），add／sub／xor／and 算術； (3) 怎麼決定走哪條路——cmp／test 只設旗標（ZF、SF、CF、OF），後面的 jle、jb、setl 才去讀旗標。 有號還是無號，不是 cmp 決定的，是後面那個指令挑哪幾個旗標決定的：l／g（less／greater）是有號，b／a（below／above）是無號——C 的型別到了組合語言，就只剩這個字母。

一、組合語言在哪裡：一行文字＝一個機器指令

第 1 課看過：gcc -S 停在「編譯」之後，產生 .s 檔，as 再把它組譯成 .o。 .s 裡的每一行指令，在 .o 裡都對應一串固定的 byte（機器碼）。用 objdump -d 可以兩邊對照著看。

實驗用的程式就是 gcc最佳化等級 的 sum_to（第 1 課作業資料夾裡的 sumto.c），左邊標的是行號，第六節會用到：

/* sumto.c */
#include <stdio.h>                          /* 第 1 行 */
                                            /* 第 2 行 */
int sum_to(int n)                           /* 第 3 行 */
{                                           /* 第 4 行 */
    int total = 0;                          /* 第 5 行 */
    for (int i = 1; i <= n; i++)            /* 第 6 行 */
        total += i;                         /* 第 7 行 */
    return total;                           /* 第 8 行 */
}

int answer(void)
{
    return sum_to(100);
}

int main(void)
{
    printf("answer:%d\n", answer());
    return 0;
}

（上面的 /* 第 N 行 */ 是為了標行號才加的；實際檔案裡沒有這些註解，行號一樣。）

gcc -O0 -c sumto.c -o s0.o
objdump -d s0.o

0000000000000000 <sum_to>:
   0:	f3 0f 1e fa          	endbr64
   4:	55                   	push   %rbp
   5:	48 89 e5             	mov    %rsp,%rbp

  12:	c7 45 fc 01 00 00 00 	movl   $0x1,-0x4(%rbp)

  1e:	01 45 f8             	add    %eax,-0x8(%rbp)

三欄怎麼讀：

欄 例子 是什麼
第 1 欄 1b: 這個指令的位址（十六進位）。在 .o 裡就是「從 .text 區段開頭算起第幾個 byte」，不是從函式開頭算——sum_to 剛好是 .text 裡的第一個函式，才會從 0 開始。.text 是什麼、連結後這個數字怎麼變，見下面的〈第 1 欄的位址從哪裡算：.text 區段〉
第 2 欄 8b 45 fc 機器碼：CPU 真正讀的 byte。指令長度不固定，1～15 byte 都有（x86 的特色）
第 3 欄 mov -0x4(%rbp),%eax 同一個指令的文字版（反組譯的結果），就是組合語言

機器碼本身也看得出第 2 課的東西：

  • c7 45 f8 00 00 00 00（movl $0x0,-0x8(%rbp)）後面四個 byte 是常數 0；c7 45 fc 01 00 00 00 是常數 1——小端序，低位的 01 在前面。
  • 7e ee 是 jle 1b。ee 不是目標位址，是相對距離，用有號的二補數解讀：0xee 當 signed char 是 −18。跳躍距離是從「下一個指令的位置」算起：下一個指令在 0x2d，0x2d − 18 = 0x1b，正好是跳過去的地方。同理 eb 0a（jmp 25）：下一個指令在 0x1b，0x1b + 10 = 0x25。

讀組合語言時不需要背機器碼，objdump 會幫你翻成文字。這裡只是要看到：組合語言跟機器碼是一對一的，不是另一種「比較高階的語言」。

第 1 欄的位址從哪裡算：.text 區段

2026-10-05 課後提問：「第 1 欄說的 .text 是什麼？」這一段也更正了原本表格的錯誤：原本寫「從函式開頭算」，實際上是從 .text 區段開頭算。

.text 是 ELF 檔裡放「機器碼」的那個區段（section）。 ELF是什麼第四節講過， ELF 檔的內容被切成很多有名字的區段：程式碼放 .text、字串常數放 .rodata（第 3 課第四節）、有初值的全域變數放 .data……。名字叫「text」是歷史慣例（早期 Unix 就把程式碼段叫 text），跟文字無關。

它跟 .s 檔裡的 .text 指示詞是同一個東西：gcc 在 sum_to: 前面寫 .text，就是叫 as「接下來的指令，機器碼放進 .text 區段」； main 前面的字串則先切到 .section .rodata，寫完再切回 .text（見第六節）。

證據一：.o 裡三個函式都在同一個 .text 裡，位址接著排下去。 用的是本節開頭的 sumto.c 與 s0.o：

objdump -d s0.o | grep "section\|>:"

Disassembly of section .text:          ← objdump 告訴你：下面反組譯的是 .text 區段
0000000000000000 <sum_to>:
0000000000000032 <answer>:             ← answer 從 0x32 開始，不是 0
0000000000000046 <main>:

所以第 1 欄是「.text 開頭往後第幾個 byte」。sum_to 佔 0x00～0x31（最後的 ret 在 0x31），answer 緊接在 0x32。 nm s0.o 印的符號位址也是同一套數字：0000000000000000 T sum_to、0000000000000032 T answer、0000000000000046 T main（T 就是「在 text 區段的符號」）。

證據二：區段表裡的 .text。

readelf -S -W s0.o

  [Nr] Name              Type            Address          Off    Size   ES Flg Lk Inf Al
  [ 1] .text             PROGBITS        0000000000000000 000040 000070 00  AX  0   0  1
  [ 2] .rela.text        RELA            0000000000000000 000270 000060 18   I 11   1  8
  ...
  [ 5] .rodata           PROGBITS        0000000000000000 0000b0 00000b 00   A  0   0  1
欄 .text 的值 意思
Address 0 還沒連結，還不知道會被放到哪裡，所以 .o 裡每個區段都從 0 算
Off 0x40 在 .o 檔案裡從第 64 個 byte 開始（前 64 byte 是 ELF 檔頭）
Size 0x70 112 byte ＝ sum_to（0x32）＋ answer（0x14）＋ main（0x2a），三個函式的機器碼全部
Flg AX A（alloc）：執行時要載入記憶體；X（execute）：可以執行。對照 .rodata 只有 A，不能執行也不能寫

.rela.text 是 .text 的重定位項目——第 1 課第四節那些「洞」（call printf 後面的 00 00 00 00）的清單。

readelf 說從 0x40 開始、objdump 說從 0 開始，誰對？

2026-10-05 課後提問：「readelf -S 看 .text 從 0x40 開始、大小 0x70；objdump -d 卻是從 0x00 開始、最後一行是 0x6f。兩個命令對程式碼在哪裡的判斷怎麼不一樣？」

兩個都對，因為它們講的是兩套不同的座標，加上一個區間的讀法：

1. 0x40 是「在檔案裡的位置」，0 是「位址」。 readelf -S 一行裡同時有兩欄：

欄 .text 的值 座標系 誰用它
Off（offset） 0x40 檔案位置：從 .o 檔第 0 個 byte 數起 讀檔的程式（readelf、ld）要知道去檔案哪裡拿
Address 0 位址：程式載入記憶體後在哪裡（.o 還沒決定，所以是 0） 指令、跳躍、call、objdump -d 的第 1 欄

objdump -d 第 1 欄印的是 Address 那一套，所以從 0 開始；你看到的 0x40 是 Off 那一欄。 objdump -h 也把兩者並列，叫 VMA（Virtual Memory Address，虛擬記憶體位址）和 File off：

objdump -h s0.o

Idx Name          Size      VMA               LMA               File off  Algn
  0 .text         00000070  0000000000000000  0000000000000000  00000040  2**0

同一個東西，三個工具三種叫法（2026-10-05 第四個追問：「位址是指 Address、VirtAddr、PhysAddr 嗎？檔案位置是 Off、Offset 嗎？」）：

本筆記的說法 readelf -S（區段標頭） readelf -l（程式標頭） objdump -h 意思
位址 Address VirtAddr VMA 虛擬位址：程式在自己的位址空間裡看到的位址，指令、指標、gdb 用的都是它
檔案位置 Off Offset File off 從檔案第 0 個 byte 數起，第幾個 byte
（不用） — PhysAddr LMA 實體位址（physical address）：一般 Linux 程式用不到，見下面
  • 區段標頭和程式標頭是兩張表（ELF是什麼第四節的兩種視角），各自有位址和檔案位置兩欄，只是欄名不同；同一塊內容在兩張表裡的數字是一致的（例如 .init_array 的 Address 0x3db8／Off 0x2db8，就是它所在 LOAD 的 VirtAddr 0x3db8／Offset 0x2db8）。
  • 「位址」一律指虛擬位址，不是實體位址。 程式碼和 gdb 看到的位址都是虛擬的，實際落在 RAM 的哪裡由核心的分頁表決定，程式自己看不到也不需要知道。
  • PhysAddr 為什麼存在、又為什麼可以忽略：ELF 也用在沒有虛擬記憶體的環境（微控制器、開機程式），那裡的程式要被放到某個固定的實體位址，這一欄才有意義。 Linux 核心載入一般程式時只看 VirtAddr、不看這一欄，所以連結器直接填成跟 VirtAddr 一樣（本機每一行都一樣）。 objdump -h 的 LMA（Load Memory Address，載入位址）是同一個概念的 binutils 叫法。
  • 同理，readelf -l 還有 FileSiz／MemSiz 兩個大小：檔案裡佔多少、載入記憶體後佔多少。第 4 個 LOAD 是 0x258／0x260，差的 8 byte 就是 .bss（readelf -S 的 Type 是 NOBITS：檔案裡不存內容，載入時直接補 0）。

要 objdump 把兩套一起印出來，加 -F（--file-offsets）：

objdump -d -F s0.o | grep "<sum_to>\|<answer>\|<main>"

0000000000000000 <sum_to> (File Offset: 0x40):
0000000000000032 <answer> (File Offset: 0x72):
0000000000000046 <main> (File Offset: 0x86):

每個函式都是「檔案位置 ＝ 位址 ＋ 0x40」。直接去檔案的 0x40 看那幾個 byte，就是 sum_to 的第一個指令：

xxd -s 0x40 -l 16 s0.o      # 從檔案第 0x40 個 byte 開始，印 16 個
xxd -s 0xa8 -l 8 s0.o       # 從 0xa8 開始印 8 個，看 .text 的結尾

00000040: f30f 1efa 5548 89e5 897d ecc7 45f8 0000  ....UH...}..E...
000000a8: 00b8 0000 0000 5dc3                      ......].

f3 0f 1e fa 是 endbr64、55 是 push %rbp、48 89 e5 是 mov %rsp,%rbp，跟 objdump -d 位址 0～5 的機器碼一樣；結尾的 5d c3（pop %rbp、ret）在檔案的 0xae、0xaf，就是 objdump 位址 0x6e、0x6f 那兩行。

2. 大小 0x70、最後一行 0x6f：區間是半開的。 0x70 是 byte 數（112 個），從位址 0 開始的 112 個 byte 佔 0x00～0x6f，寫成 [0x00, 0x70)——跟第 3 課第七節〈[96, 101) 怎麼讀〉的 ASan 區間同一種讀法，右端是「第一個不屬於它的 byte」。最後一個指令 ret（c3）只有 1 byte，剛好在 0x6f，所以 .text 用完 0x70 個 byte 一個不差。在檔案裡就是 [0x40, 0xb0)；readelf -S 裡下一個區段 .data 的 Off 正好是 0xb0，緊接在後。

連結後的執行檔：sumto0 的 .text 是 Address 0x1060、Off 0x1060，兩欄剛好一樣，但這只是巧合，不是規則。

.init_array 到 .bss 被打包成第 4 個 LOAD，權限 RW；它前面那個 LOAD（.rodata 那一塊）權限只有 R。 記憶體權限是以分頁（4096 ＝ 0x1000 byte）為單位設定的，一頁只能有一種權限。現在用位址算算看「如果不加 0x1000 會怎樣」：

唯讀段（R） 可寫段（RW）
檔案位置 0x2000 起，0x144 byte → 結束在 0x2144 0x2db8 起

實際位址 0x2000（那一頁是 R） 0x3db8（換到 0x3000～0x3fff 這一頁，可以設成 RW）

所以連結器把可寫段的位址往後推一頁。檔案位置卻不用動：檔案只是存放內容，不需要權限，緊接著放就好，不必在檔案裡空出 4096 byte。

為什麼剛好推 0x1000、而不是推到 0x3000 整數？因為載入時是「整頁整頁」從檔案對映進記憶體（Align 0x1000），規則是位址和檔案位置除以 0x1000 的餘數要一樣（都是 0xdb8），這樣檔案的某一頁才能原封不動地對到記憶體的某一頁。（至於為什麼從 0xdb8 這個不整齊的地方開始：0x3db8 + 0x248 = 0x4000，連結器刻意讓 .init_array～.got 這一塊剛好結束在分頁邊界，.data 從 0x4000 整頁開始。 .init_array～.got 在動態載入器填完之後會被改成唯讀，叫 RELRO（RELocation Read-Only），就是 readelf -l 裡 GNU_RELRO 那一行；第 5 課之後碰到 .got 再詳講。）

兩種寫法：AT&T 與 Intel

同一個指令有兩種文字寫法。gcc、objdump、gdb 在 Linux 上預設都用 AT&T 語法，Linux kernel 原始碼裡的組合語言也是 AT&T，所以本課全部用 AT&T。 Intel 的手冊和 Windows 世界用的是 Intel 語法，兩邊都會遇到，要認得。用 -masm=intel 讓 gcc 改產生 Intel 語法：

gcc -S -O0 -masm=intel -fno-asynchronous-unwind-tables sumto.c -o sumto0_intel.s
AT&T（gcc 預設） Intel（-masm=intel）
運算元順序 mov 來源, 目的 mov 目的, 來源（反過來）
暫存器 加 %：%eax 不加：eax
常數 加 $：$1 不加：1
大小 寫在指令後綴：movl 寫在記憶體運算元前：DWORD PTR
記憶體 -4(%rbp)、(%rdi,%rsi,4) -4[rbp]、[rdi+rsi*4]
本機實例 movl $1, -4(%rbp) mov DWORD PTR -4[rbp], 1
本機實例 cmpl -20(%rbp), %eax cmp eax, DWORD PTR -20[rbp]

最容易出錯的是順序：看到 cmp、sub 時，AT&T 的「目的」在右邊。

二、暫存器：CPU 裡的 16 個變數

暫存器（register）是 CPU 內部的儲存格，存取不用經過記憶體，所以最快。x86-64 有 16 個通用暫存器（general-purpose register），每個 64 位元（8 byte）。同一個暫存器的低位部分有自己的名字：

64 位元 低 32 位元 低 16 位元 低 8 位元 慣例用途（System V ABI，第 5 課詳講）
%rax %eax %ax %al 回傳值
%rbx %ebx %bx %bl 被呼叫者要保存（callee-saved）
%rcx %ecx %cx %cl 第 4 個參數
%rdx %edx %dx %dl 第 3 個參數
%rsi %esi %si %sil 第 2 個參數
%rdi %edi %di %dil 第 1 個參數
%rbp %ebp %bp %bpl 基準指標（base pointer）：-O0 用它當「這個函式的區域變數從哪裡算起」
%rsp %esp %sp %spl 堆疊指標（stack pointer）：永遠指著堆疊頂端，不能拿來亂用
%r8 %r8d %r8w %r8b 第 5 個參數
%r9 %r9d %r9w %r9b 第 6 個參數
%r10、%r11 %r10d… %r10w… %r10b… 暫用（呼叫者要保存，caller-saved）
%r12～%r15 %r12d… %r12w… %r12b… 被呼叫者要保存

%rax、%rbx、%rcx、%rdx 另外還有 %ah、%bh、%ch、%dh（第 8～15 位元），是 16 位元時代留下來的，gcc 很少用。

本課只要記住四個：第 1 個參數在 %rdi、第 2 個在 %rsi、回傳值放 %rax、%rsp 是堆疊頂端。為什麼是這些暫存器、呼叫時堆疊怎麼變，是第 5 課的內容。

除了 16 個通用暫存器，本課還會碰到兩個特殊的：

  • %rip（instruction pointer，指令指標）：存著「下一個要執行的指令在哪裡」。不能直接 mov 進去，只有跳躍、call、ret 會改它。可以拿它當基準算位址（.LC0(%rip)，見第六節）。
  • rflags（旗標暫存器）：一堆 1 位元的旗標，由運算指令順便設定，條件跳躍去讀。見第五節。

（還有浮點／SIMD 用的 %xmm0～%xmm15 等暫存器，依課程規劃不在範圍內。）

寫低位的名字時，高位會怎樣？

這條規則很重要，而且不對稱：

寫入的大小 高位會怎樣
寫 32 位元名字（%eax） 高 32 位元自動清成 0
寫 16 位元（%ax）或 8 位元（%al） 高位不動，保留原本的值

所以 movl %edi, %eax 不只是寫 %eax，整個 %rax 都被設定好了（高 32 位元是 0）。用下面這個實驗看它的後果（檔案：ops.c）：

/* ops.c：只用 -S 看組合語言，不需要 main */
long widen_s(int x)       { return x; }
long widen_u(unsigned x)  { return x; }
int  get(int *a, long i)  { return a[i]; }
int *addr(int *a, long i) { return &a[i]; }
long times3(long x)       { return x * 3; }
int  lt_s(int a, int b)           { return a < b; }
int  lt_u(unsigned a, unsigned b) { return a < b; }

gcc -S -O2 -fno-asynchronous-unwind-tables ops.c -o ops.s

（以下只列每個函式的本體，省略以 . 開頭的指示詞，它們是什麼見第六節。endbr64 是什麼也在第六節。）

widen_s:
	endbr64
	movslq	%edi, %rax
	ret
widen_u:
	endbr64
	movl	%edi, %eax
	ret

（unsigned 單獨寫就是 unsigned int，見第 2 課第一節〈unsigned 單獨寫就是 unsigned int：整數型別的所有寫法〉。）

兩個函式都是「把 32 位元的參數變成 64 位元的 long 回傳」，就是第 2 課第六節〈變寬（擴展，extension）〉那一段講的擴展：

  • widen_u（unsigned → long）要零擴展：高位補 0。剛好「寫 %eax 就把高 32 位元清 0」，所以一個普通的 movl 就做完了。
  • widen_s（int → long）要符號擴展：高位補符號位元。普通的 mov 做不到，要用專門的 movslq。

擴展用的指令有一套命名規則：movs 或 movz，接「來源大小」，再接「目的大小」。大小用一個字母表示：b＝1、w＝2、l＝4、q＝8 byte（完整說明在第三節的大小後綴表；這裡的 long 是 4 byte，不是 C 的 long，原因見第三節〈為什麼 l 叫 long 卻是 4 byte〉）：

指令 讀法 意思
movsbw、movsbl、movsbq move sign-extended byte to word／long／quad 1 byte 符號擴展成 2／4／8 byte
movswl、movswq … word to long／quad 2 byte 符號擴展成 4／8 byte
movslq … long to quad 4 byte 符號擴展成 8 byte（Intel 語法叫 movsxd）
movzbw、movzbl、movzbq move zero-extended byte to … 1 byte 零擴展
movzwl、movzwq move zero-extended word to … 2 byte 零擴展

沒有 movzlq：因為「寫 32 位元自動清高位」，movl 就是 4 → 8 byte 的零擴展了。

C 的型別到這裡，只剩下「選哪個指令」：int 和 unsigned 在暫存器裡都是同樣的 32 個位元，差別只在要變寬時用 movs 還是 movz。

三、指令的文法：助憶符、大小後綴、運算元

AT&T 語法的一行指令：

    addl    %eax, -8(%rbp)
    │  │    │     └─ 目的運算元（destination）：結果寫到這裡
    │  │    └─────── 來源運算元（source）
    │  └──────────── 大小後綴（suffix）：l ＝ 4 byte
    └─────────────── 助憶符（mnemonic）：指令的名字

骨架是 <助憶符>[大小後綴] [來源], [目的]。逐個位置：

1. 助憶符：指令的名字（mov、add、cmp…）。x86-64 有上千個，本課教的見第八節。

2. 大小後綴：這個指令處理幾個 byte。

後綴 名稱 byte 數 C 型別（本機）
b byte 1 char
w word 2 short
l long（double word） 4 int、unsigned
q quad word 8 long、指標

（「word」是 2 byte，是 16 位元時代的命名留下來的。注意 AT&T 的 l 是 4 byte，跟 C 的 long（8 byte）不一樣。）

  • 運算元裡有暫存器時，大小其實看暫存器名字就知道（%eax 一定是 4 byte），後綴可以省略。objdump 就常省略：上面的 mov -0x4(%rbp),%eax。
  • 運算元裡沒有暫存器時（例如 movl $0x0,-0x8(%rbp)：常數搬到記憶體），後綴就一定要有——否則不知道要寫 1、2、4 還是 8 個 byte。所以 objdump 在這種地方會印出 movl、addl。
  • 省略的規則：有暫存器可以推斷大小時才該省略。兩邊都推不出大小時，本機 as 2.42 不會報錯，而是發出警告 Warning: no instruction mnemonic suffix given and no register operands; using default for `mov'，自己挑一個預設大小（實測 mov $0, -8(%rbp) 被組譯成 movl，4 byte）——這很危險，你想寫 8 byte 時它只寫了 4 byte。自己寫組合語言時永遠加後綴。

3. 運算元（operand）：有三種，用前綴區分。

種類 寫法 例子 意思
立即數（immediate） $ 開頭 $1、$0x64、$5050 常數本身
暫存器 % 開頭 %eax、%rdi 暫存器裡的值
記憶體 D(B,I,S) 或它的省略形式 -4(%rbp)、(%rdi,%rsi,4) 算出一個位址，用的是那個位址裡的值

記憶體運算元的完整形式是 D(B,I,S)，位址 ＝ D ＋ B ＋ I × S：

位置 名稱 可以是什麼 省略時
D 位移（displacement） 常數（可以是負數）或符號名稱（.LC0） 0
B 基底（base） 一個 64 位元暫存器 0
I 索引（index） 一個 64 位元暫存器（不能是 %rsp） 0
S 倍數（scale） 只能是 1、2、4、8 1

常見的省略形式：

寫法 位址 典型用途 本課實例
(B) B *p addq (%rdi), %rax（作業第 4 題）
D(B) B ＋ D 區域變數、結構成員 -4(%rbp)：%rbp 往下 4 byte，就是 i
(B,I,S) B ＋ I × S a[i] (%rdi,%rsi,4)
D(B,I,S) B ＋ I × S ＋ D a[i + 常數] 1(%rdx,%rax,2)（第七節，拿來算數）
D(,I,S) I × S ＋ D 沒有基底，只要倍數 0(,%rdi,8)（作業第 1 題會看到）
D(%rip) 下一個指令的位址 ＋ D 取全域資料的位址（PIE 用） .LC0(%rip)

2026-10-06 課後提問：「(%rdi) 的 %rdi 不是暫存器嗎？為什麼變成記憶體位址了？」

上表 (B) 那一列寫「位址 ＝ B」，例子是 (%rdi)。乍看會奇怪：%rdi 明明是暫存器，怎麼變成記憶體？關鍵是：暫存器裡裝的永遠只是一個 64 位元的數字。同一個暫存器，寫法不同，指令拿這個數字做的事就不同：

寫法 指令拿到的是 對應 C
%rdi 暫存器裡的數字本身 x（用變數的值）
(%rdi) 把暫存器裡的數字當成位址，到記憶體的那個位址去讀（或寫）那裡的值 *p（用指標指向的值）

所以 (%rdi) 裡的 %rdi 仍然是暫存器；括號的意思是「它裝的數字是一個位址，請去記憶體的那裡」。這就是運算元種類表說的「用的是那個位址裡的值」。上表其他寫法也一樣，只是位址不再只是 B，而是 D ＋ B ＋ I × S 算出來的數字，算完同樣去那個位址拿值。

int main(void)
{

    int  nums[6] = {10, 11, 12, 13, 14, 15};
    printf("%ld %d %d %ld %ld\n", second(arr), get(nums, 1), get3(nums, 1), get_tbl(2), get_g());

為什麼 l 叫 long 卻是 4 byte：組合語言的大小名稱和 C 的型別是兩套

2026-10-06 課後提問：「第二節的 movsbl 說 long 是 4 byte，跟 C 的 long 是 8 byte 不一樣，這正常嗎？」

正常。組合語言的 l（long）和 C 的 long 只是剛好同名，是兩套各自定下來、後來沒有一起改的名字。

  • 組合語言這套（byte／word／long／quad）是按 x86 的歷史定的：x86 最早的 CPU（8086）是 16 位元的，所以「一個 word」＝ 2 byte。後來 CPU 變成 32 位元，32 位元的資料就叫「兩個 word」——Intel 的手冊叫 double word（dword），AT&T 語法叫 long，字尾寫 l；再變成 64 位元時叫 quad word（四個 word），字尾寫 q。為了讓舊的組合語言程式還能用，名字一旦定了就不改，所以到了 64 位元的今天，word 仍然是 2 byte、long 仍然是 4 byte。
  • C 的 long 是按平台的慣例定的：C 標準只規定 long 至少 32 位元，確切大小由平台決定。本機 x86-64 Linux 採用 LP64（第 2 課第一節），long 是 8 byte； 64 位元 Windows 的 long 是 4 byte。所以連 C 的 long 自己，換平台都不一定一樣大。

因此讀組合語言時，看到字尾的 l 就想「4 byte」，不要想成 C 的 long。本機 C 型別對到字尾的關係是： char → b、short → w、int／unsigned → l、C 的 long、指標 → q。

實驗一：C 的 long 編出來是 q，不是 l。 suffix.c（檔案：suffix.c）完整原始碼（只用 -S，不需要 main）：

int   add1_int(int x)            { return x + 1; }
int   widen_char(signed char c)  { return c; }
long  widen_char_l(signed char c){ return c; }

$ gcc -S -O2 -fno-asynchronous-unwind-tables suffix.c -o suffix.s
（只列函式本體）

	endbr64
	leaq	1(%rdi), %rax        ← C 的 long：字尾 q（8 byte），64 位元暫存器 %rax
	ret

	endbr64

行 是什麼 意思

讀懂實驗一的範例：為什麼寫 1(%rdi)、為什麼用 %dil

2026-10-06 課後提問：「為什麼 rdi 要寫成 1(%rdi)？為什麼要用 dil，我們不是在用 64 位元的系統嗎？」

leaq 1(%rdi), %rax 是「%rax = %rdi + 1」，不是讀記憶體。 1(%rdi) 是記憶體運算元的寫法 D(B,I,S) 只寫了 D 和 B （D ＝ 1、B ＝ %rdi，省略 I、S，見上面的 D(B,I,S) 表），算出來的數字是 1 + %rdi。但指令是 lea，只算數字、不去那個位址讀東西（第四節〈lea 被拿來做算術〉）。 %rdi 是第 1 個參數 x，%rax 是回傳值，所以這一行就是 return x + 1;。

為什麼不用 add：add 只能把結果寫回其中一個運算元。addq $1, %rdi 的結果在 %rdi，還得再 movq %rdi, %rax 搬到回傳值的位置，要兩個指令；lea 可以讀 %rdi、把結果寫到另一個暫存器 %rax，一個指令做完。

「64 位元系統」指的是暫存器和位址是 64 位元，不是每個資料都變成 64 位元。 C 的 signed char 仍然是 1 byte、int 仍然是 4 byte。參數 c 是 signed char，放在第 1 個參數暫存器 %rdi 裡，但只有最低的 1 byte 是 c，這 1 byte 的名字就是 %dil（第二節的暫存器表）。 movsbl %dil, %eax 的意思是「讀 %rdi 最低的 1 byte，符號擴展成 4 byte，放進 %eax」。

為什麼不能直接讀整個 %rdi：另外 7 個 byte 不是 c，裡面是什麼不保證。 呼叫的人只負責把 c 放進最低的 1 byte，高位是多少沒有約定（這是 System V ABI 的規定，第 5 課講呼叫慣例時再細看；這裡只實測 gcc 的行為）。下面用 gdb 實際看。dil.c（檔案：dil.c）完整原始碼：

#include <stdio.h>

__attribute__((noinline)) int widen_char(signed char c) { return c; }

int main(void)
{
    printf("%d\n", widen_char(-1));
    return 0;

（__attribute__((noinline)) 是 gcc 的擴充語法，意思是「不要把這個函式內嵌」。不加的話，-O2 會把 widen_char(-1) 直接算成 -1 （gcc最佳化等級第二節〈「內嵌」是什麼〉），就看不到呼叫了。）

main 寫的是 %edi（4 byte），所以 %rdi 的高 4 byte 被清成 0（第二節〈寫低位的名字時，高位會怎樣？〉），整個 %rdi 是 0x00000000ffffffff。如果 widen_char 把整個 %rdi 當成數字，得到的是 4294967295，不是 −1。（main 裡其他幾行是準備 printf 的參數，printf 在 -O2 下被換成檢查版的 __printf_chk，跟本題無關。）

接著在 gdb 裡故意把 %rdi 的高 7 byte 改成亂七八糟的值，只留最低 1 byte 是 0xff，看 movsbl 的結果會不會變：

上面 break *widen_char+4 的 *：為什麼要加？

2026-10-06 課後提問：「break *deref+4 為什麼前面要加 *？」

break 後面的「位置」有兩種主要寫法（gdb完整命令參考第三節〈位置（LOCATION）〉的表）：

寫法 例子 gdb 怎麼理解
行號規格（linespec） break deref、break 4 後面是函式名或行號，gdb 用除錯資訊找出那一行「該停的地方」
位址 break *deref、break *deref+4、break *0x11f4 * 開頭：後面是一個算出位址的式子，就停在那個位址的那條機器指令

這裡的 * 是 break 的語法記號，意思是「後面是位址」，不是 C 的取值 *。* 後面的 deref+4 會當成式子計算： deref 代表函式的開頭位址，+4 是往後 4 byte。本機 paren.c（上面〈上表第一列 (B)〉那段的程式）實測：

（0x11f4 是 objdump -d 印出的 deref 裡 mov (%rdi),%rax 那一行的位址。程式還沒執行時，gdb 顯示的是檔案裡的位址，所以 3 和 4 看起來一樣；程式跑起來以後就不一樣了，見下方。）

上面中斷點 4 的 break *0x11f4：為什麼 run 之後失敗？

組合語言裡只有 %edi、%dil，為什麼 gdb 印得出 $rdi？

2026-10-06 課後提問：「組合語言完全沒有用到 rdi，為什麼 gdb 打印 rdi 出得來？文中也要我看 rdi。」

因為 %edi、%di、%dil 不是另外的暫存器，它們都是 %rdi 這一個暫存器的一部分的名字（第二節的表，同一列就是同一個暫存器）。 CPU 裡實際只有 16 個 64 位元的通用暫存器，%rdi 是其中一個；寫 %edi 就是寫它的低 4 byte，讀 %dil 就是讀它的最低 1 byte：

             %rdi（64 位元，8 byte）
┌────┬────┬────┬────┬────┬────┬────┬────┐
│ 11 │ 22 │ 33 │ 44 │ 55 │ 66 │ 77 │ 88 │   ← 高位在左（這是數值的寫法，不是記憶體裡的順序）
└────┴────┴────┴────┴────┴────┴────┴────┘
                    └──── %edi（低 4 byte）┘
                              └ %di（低 2 byte）┘
                                   └ %dil（最低 1 byte）┘

所以 main 的 mov $0xffffffff,%edi 寫的就是 %rdi（低 4 byte 寫 ff ff ff ff、高 4 byte 清成 0），widen_char 的 movsbl %dil,%eax 讀的也是 %rdi（最低 1 byte）。組合語言沒寫出 %rdi 這個名字，只代表那個指令只碰它的一部分，暫存器本身一直都在。

gdb 可以印任何一個暫存器，不管程式有沒有用到。 暫存器是 CPU 裡固定存在的儲存格，程式停下來時，gdb 請核心把這個行程整組暫存器的值讀出來給它（讀的方法是第 ② 站之後的內容），所以 $rdi、$rsi、$rcx 都印得出來；程式沒用到的暫存器裡，是之前留下來的值。

同一個暫存器、不同名字的實驗。接著上面的 dil.c 與 dil，停在 widen_char 裡，先把 %rdi 設成一個每個 byte 都不同的值，再用各種名字去看、去改：

%dil 是 0xff，為什麼 %eax 變成 0xffffffff：符號擴展補的是第 7 位元

2026-10-06 課後提問：「%dil 已經是 0xff，從 %eax 出來為什麼是 0xffffffff？高 3 個 byte 怎麼自動用 1 填？」

這就是 movsbl 的「s」：符號擴展（sign extension）。 movsbl %dil, %eax ＝ move sign-extended byte to long：把 1 byte 放進 %eax 的最低 1 byte，新多出來的高 3 byte，每一個 bit 都複製來源的最高位元（第 7 位元，也就是符號位）。 0xff 是 1111 1111，第 7 位元是 1，所以高 3 byte 全補 1，得到 0xffffffff。C 層級的同一件事在 第 2 課第六節〈變寬（擴展，extension）〉（extend.c 的 a1）。

為什麼要補 1：為了讓值不變。 參數是 signed char，0xff 用二補數讀是 −1（最高位的權重是 −2⁷）： −128 + 127 = −1。要把它變成 int 而且仍然是 −1，int 的二補數裡 −1 就是 0xffffffff（−2³¹ + (2³¹ − 1) = −1）。一般來說，在二補數最前面多補一個「跟原本最高位相同」的 bit，值不會變：

  • 最高位是 0（正數或 0）：前面補 0，多出來的位元權重乘上 0，值當然不變。
  • 最高位是 1（負數）：原本最高位的權重是 −2ⁿ，補一個 1 在更前面之後，新的最高位權重是 −2ⁿ⁺¹、原本那一位變成 +2ⁿ，合起來 −2ⁿ⁺¹ + 2ⁿ = −2ⁿ，跟原來一樣。補幾個都是同樣的道理。

對照零擴展（zero extension）的 movzbl（move zero-extended byte to long）：不管第 7 位元是什麼，高位一律補 0。參數是 unsigned char 時 gcc 就用它，因為無號的 0x80 代表 128，補 0 才能保持 128。

四、mov 與 lea：搬資料 vs 算位址

mov：把來源複製到目的

mov S, D：D ＝ S。來源和目的可以是暫存器或記憶體（不能兩個都是記憶體），來源也可以是立即數。 有記憶體運算元時，mov 真的會去讀或寫那個位址。

lea：只算位址，不碰記憶體

lea（load effective address）的來源寫法跟記憶體運算元一樣，但它只把算出來的位址放進目的暫存器，不去讀那個位址。對照 ops.c 的兩個函式（第 3 課：a[i] 就是 *(a + i)，&a[i] 就是 a + i）：

get:                                  # int  get(int *a, long i)  { return a[i]; }
	endbr64
	movl	(%rdi,%rsi,4), %eax       # %eax = 記憶體[a + i×4] 裡的 4 byte → 真的讀記憶體
	ret
addr:                                 # int *addr(int *a, long i) { return &a[i]; }
	endbr64
	leaq	(%rdi,%rsi,4), %rax       # %rax = a + i×4 這個數字本身 → 不讀記憶體
	ret
  • 第 1 個參數 a 在 %rdi，第 2 個參數 i 在 %rsi，倍數 4 是 sizeof(int)。
  • get 回傳 int（4 byte），用 movl 和 %eax；addr 回傳指標（8 byte），用 leaq 和 %rax。
  • 兩行的括號一模一樣，差別是 mov 會去那個位址取值（*），lea 只要位址本身（&）。所以 lea 碰到不合法的位址也不會 segfault，因為它根本沒去存取。

lea 被拿來做算術

lea 本質上是「一個指令算出 D + B + I×S」，跟位址無關的計算也能借用它：

times3:                               # long times3(long x) { return x * 3; }
	endbr64
	leaq	(%rdi,%rdi,2), %rax       # %rax = x + x×2 = 3x
	ret

x 不是位址，但 (%rdi,%rdi,2) 算出來就是 x + 2x。gcc 很愛這樣用：一個指令就做完「乘一個小常數再加東西」，而且不會改旗標（add 會），也可以把結果放到另一個暫存器（add 只能寫回其中一個運算元）。第七節 -O2 的迴圈本體就是一個 lea。

判斷原則：看到 lea，不要假設它跟位址有關；問自己「它算出什麼數字」就好。

本課的算術與邏輯指令

指令 效果（AT&T：op S, D） 改不改旗標 本課在哪出現
add S, D D ＝ D ＋ S 改 addl %eax, -8(%rbp)（total += i）
sub S, D D ＝ D − S 改 作業第 1 題（x * 7）
imul S, D D ＝ D × S（有號乘法） 改 本課沒出現，gcc 能用 lea／add 時就不用它
and S, D D ＝ D & S（逐位元且） 改 andl $1, %edi（第七節：n 是不是奇數）
xor S, D D ＝ D ^ S（逐位元互斥或） 改 xorl %eax, %eax（清成 0）
mov、movs*、movz*、lea 見上面 不改

xorl %eax, %eax 是「把 %eax 設成 0」的慣用寫法：任何數跟自己 xor 都是 0。它的機器碼只有 2 byte（31 c0），比 movl $0, %eax（5 byte）短，而且寫的是 32 位元名字，連 %rax 的高位也一起清掉。-O2 幾乎都這樣寫；-O0 則照字面寫 movl $0, ...。

五、旗標與條件跳躍：cmp 只負責比，跳不跳由下一個指令決定

C 的 if、for、while 在組合語言裡都變成兩步：

  1. cmp 或 test：做一次運算，只設旗標，不存結果。
  2. 條件跳躍 j<條件>（或 set<條件>）：讀旗標，決定跳不跳（或把 0／1 寫進一個 byte）。

四個旗標

rflags 裡跟比較有關的四個旗標，都是「上一個會改旗標的指令」順手設定的：

旗標 名稱 什麼時候是 1 對誰有意義
ZF Zero Flag 結果是 0 兩者都適用（相等）
SF Sign Flag 結果的最高位元是 1（當成有號數是負的） 有號
CF Carry Flag 當成無號數運算時，進位或借位了（cmp 時就是「D 比 S 小（無號）」） 無號
OF Overflow Flag 當成有號數運算時溢位了（結果超出範圍，第 2 課第八節的那種溢位） 有號

（rflags 還有 PF、AF 等其他旗標，gdb 的 info registers eflags 會把設成 1 的都列出來，例如 IF 是「允許中斷」，在使用者程式裡永遠是 1，跟比較無關。）

上表的四個旗標在講什麼：用 10 組數字實際跑一次

2026-10-07 課後提問：「第5節旗標這邊完全看不懂在幹嘛？」（指上面〈四個旗標〉那張表）

上表「什麼時候是 1」那一欄很難懂，因為它同時在講同一次運算的兩種解讀。先抓住一件事：

CPU 做一次加法或減法，只得到一串位元；四個旗標是從四個角度替「這一次運算」各記一筆。

旗標 它在回答的問題 看的是什麼
ZF 「留下來的位元是不是全為 0？」 結果的位元
SF 「留下來的最高位元是不是 1？」 結果的位元（只是把最高位元抄一份）
CF 「把兩個數當無號數算，正確答案裝得進這個大小嗎？」裝不下（加法超過最大值、減法變成負的）就是 1 運算過程
OF 「把兩個數當有號數算，正確答案裝得進這個大小嗎？」裝不下就是 1 運算過程

CPU 不知道你的資料是有號還是無號，所以 CF 和 OF 兩個都算、兩個都設；上表最右欄「對誰有意義」的意思是：你的資料如果是無號數，就只有 CF 的答案對你有用，OF 是在回答一個跟你無關的問題，反之亦然。

為了心算方便，下面的實驗全部用 8 位元（1 byte）：無號能裝 0～255，有號能裝 −128～127（第 2 課第五節）。32、64 位元的道理完全一樣，只是範圍變大。

實驗程式：flags.s（檔案：flags.s）做一次 cmpb 或 addb，把做完後的旗標整包回傳；flagsmain.c（檔案：flagsmain.c）餵 10 組數字、把四個旗標拆出來印。完整原始碼：

# flags.s：做一次 8 位元的 cmp 或 add，把做完後的旗標整包回傳
# 參數：%dil = D（第 1 個參數的最低 1 byte），%sil = S（第 2 個參數的最低 1 byte）
	.text
	.globl	flags_cmp
flags_cmp:                       # unsigned long flags_cmp(unsigned char d, unsigned char s)
	cmpb	%sil, %dil           # 算 D − S（8 位元），結果丟掉，只設旗標
	pushfq                       # 把整個 rflags 複製一份放到堆疊上
	popq	%rax                 # 再從堆疊取到 %rax ＝ 回傳值
	ret

	.globl	flags_add
flags_add:                       # unsigned long flags_add(unsigned char d, unsigned char s)
	addb	%sil, %dil           # 算 D + S（8 位元），結果寫回 %dil，同時設旗標
	pushfq
	popq	%rax
	ret

	.section	.note.GNU-stack,"",@progbits

逐行說明：

  • .text、.globl：指示詞（第六節〈先看完整的 .s 檔：哪些是指令、哪些不是〉），「下面是程式碼」、「這個名字給別的檔案用」。
  • cmpb %sil, %dil：b 字尾是 1 byte；%dil、%sil 是 %rdi、%rsi 最低的 1 byte（第二節）。參數是 unsigned char，只佔那 1 byte（第三節〈讀懂實驗一的範例：為什麼寫 1(%rdi)、為什麼用 %dil〉）。
  • addb %sil, %dil：同上，但做加法；結果寫回 %dil，函式不用它，我們只要旗標。
  • pushfq ＋ popq %rax（新指令，本課沒教）：旗標不能用 mov 讀——本機寫 mov %rflags, %rax 會得到 Error: bad register name '%rflags'。pushfq 把整個 rflags 推到堆疊（stack）上，popq %rax 再把它取進 %rax，兩行合起來就是「把 rflags 複製到 %rax」。堆疊是什麼，第 5 課以後講；這裡只要知道這兩行的效果。%rax 是回傳值（第二節的暫存器表），所以 C 拿到的回傳值就是整包旗標。
  • pushfq、popq 都不改旗標（第五節〈哪些指令會改旗標〉：只有算術與邏輯指令會改），所以存下來的就是 cmpb／addb 剛設好的旗標。
  • .section .note.GNU-stack,...：告訴連結器「堆疊不需要能執行」。手寫 .s 沒加這行，本機連結時會出現 warning: ... missing .note.GNU-stack section implies executable stack；gcc 自己產生的 .s 都會自動帶這行。

#include <stdio.h>

unsigned long flags_cmp(unsigned char d, unsigned char s);   /* 在 flags.s */
unsigned long flags_add(unsigned char d, unsigned char s);

/* rflags 裡四個旗標的位置：CF 第 0 位元、ZF 第 6、SF 第 7、OF 第 11 */
static void show(const char *op, unsigned char d, unsigned char s)
{
    unsigned long f;
    unsigned char r;

    if (op[0] == 'c') { f = flags_cmp(d, s); r = (unsigned char)(d - s); }
    else              { f = flags_add(d, s); r = (unsigned char)(d + s); }

    printf("%s D=0x%02x S=0x%02x -> 0x%02x | 無號 %3u %c %3u -> %3u | 有號 %4d %c %4d -> %4d | ZF=%lu SF=%lu CF=%lu OF=%lu\n",
           op, d, s, r,
           d, op[0] == 'c' ? '-' : '+', s, r,
           (signed char)d, op[0] == 'c' ? '-' : '+', (signed char)s, (signed char)r,
           (f >> 6) & 1, (f >> 7) & 1, (f >> 0) & 1, (f >> 11) & 1);
}

int main(void)
{

    show("cmp", 5, 3);        /* 一般的大減小 */
    show("cmp", 3, 5);        /* 小減大 */
    show("cmp", 0xff, 1);     /* 第五節實驗那組：-1 和 1 */
    show("cmp", 1, 0xff);     /* 反過來 */
    show("cmp", 0x80, 1);     /* -128 - 1 */
    show("add", 0x7f, 1);     /* 127 + 1 */
    show("add", 0xff, 1);     /* 255 + 1，也就是 -1 + 1 */
    show("add", 200, 100);    /* 200 + 100 */
    show("add", 0x80, 0x80);  /* -128 + -128 */

}

上面⑦：位元變成 0x80 很正常，為什麼還要特別注意？

2026-10-07 課後提問：「這看起來很正常？有什麼問題嗎？為什麼說它是陷阱？」

對，位元本身完全正常：8 位元的 127 + 1 就是會變成 0x80——addb 只是把位元相加、留下最低 8 位元（C 裡的有號溢位是未定義行為，見第 2 課第八節；但機器指令本身就是這樣算），SF 也沒算錯，它忠實地抄了第 7 位元。要注意的不是 SF，而是讀 SF 的人：SF 叫「正負號旗標」，很容易被當成「這次運算的答案是負的」。但 127 + 1 的答案是 +128，是正的；SF = 1 只說得出「留下來的位元當有號讀是負的」。兩件事只在沒溢位時一致。

這會在哪裡出錯？cmp 就是靠減法比大小：想知道 D < S，最直覺的做法是看「D − S 是不是負的」，也就是只看 SF。這個直覺在溢位時就會答錯——下面〈回頭看條件碼表〉的⑥就是實例：−128 < 1 明明成立，但 −128 − 1 溢位，SF 卻是 0。所以 CPU 另外用 OF 記下「這次有沒有溢位」，條件碼 l 才能用 SF ≠ OF 把 SF 校正回來。⑦ 先讓你看到 SF 會「說錯」，⑥ 讓你看到說錯的後果。

CF（當成無號數，裝不下）——只看「無號」那一欄：

  • ③ 3 − 5：無號數沒有負數，小減大要向更高位借位（borrow），CF = 1。所以 cmp 之後 CF = 1 就代表 D < S（無號），上表寫的「cmp 時就是 D 比 S 小」就是這個意思。
  • ⑤ 1 − 255：一樣小減大，CF = 1。注意有號那一欄是 1 − (−1) = 2，完全正常——CF 不管有號的解讀。
  • ④ 255 − 1 = 254：大減小，不用借位，CF = 0。有號那欄是 −1 − 1 = −2（負的），CF 還是 0。
  • ⑧ 255 + 1、⑨ 200 + 100、⑩ 128 + 128：正確答案 256、300、256 都超過 255，最高位元往外進位（carry），CF = 1。
  • ⑦ 127 + 1 = 128，沒超過 255，CF = 0。

上面③：3 − 5 在 CPU 裡實際上是怎麼算的？

2026-10-07 課後提問：「3 − 5 實際上到底是怎麼運作的？」

跟小學的直式減法一模一樣，只是每一位只有 0 和 1、借位借到的是 2 而不是 10。先用十進位暖身：算 03 − 05，個位 3 減 5 不夠，向十位借 1（＝個位的 10），13 − 5 = 8；十位變成 0 − 0 − 1，又不夠，再往左借……如果紙上只有兩位數，最後一次要向「百位」借，但紙上沒有百位——照樣先借、記一筆欠帳，紙上留下 98，外加一個「我向紙外借了 1」的記號。98 就是 3 − 5 + 100，那個記號提醒你「這個答案多加了 100，真正的答案是 98 − 100 = −2」。

上面這段十進位暖身：十位也是 0，98 是從哪裡冒出來的？

2026-10-07 課後提問：「看不懂，向 10 借位，但 10 位數也是 0，就像外面借，然後就突然出現了 98？不懂」

先用倒數來想，不用借位。 想像一個只有兩格的機械計數器（像舊式的里程表），現在顯示 03。3 − 5 就是往回撥 5 下：

03 → 02 → 01 → 00 → 99 → 98

撥到 00 再往回一下，兩格裝不下 −1，計數器就翻過去變成 99，再一下是 98。98 不是突然出現的，是「翻過 0」之後接著倒數的結果。翻過去的那一下，等於向紙外的百位借了 100：98 = 3 − 5 + 100。

8 位元一模一樣，只是翻過 0 之後回到的是 255。countdown.c（檔案：countdown.c）用 8 位元的 unsigned char 從 3 減 1 減 5 次：

/* countdown.c：8 位元的計數器從 3 往回倒數 5 下，看它怎麼「翻過 0」 */
#include <stdio.h>

int main(void)
{
    unsigned char x = 3;            /* 8 位元，只能裝 0～255 */

    printf("開始：%3u (0x%02x)\n", x, x);
    for (int i = 1; i <= 5; i++) {
        x = x - 1;                  /* 每次減 1，總共減 5，就是 3 − 5 */
        printf("減第 %d 下：%3u (0x%02x)\n", i, x, x);
    }
    return 0;
}

borrow.c（檔案：borrow.c）用 C 照直式減法一位一位地算，最後再呼叫上面 flags.s 的 flags_cmp 讓 CPU 真的做一次 cmpb，兩邊對照。完整原始碼：

/* borrow.c：用直式減法一個位元一個位元地算 8 位元的 D − S，跟 CPU 的 cmpb 對照 */
#include <stdio.h>

unsigned long flags_cmp(unsigned char d, unsigned char s);   /* 在 flags.s */

static void print_bits(unsigned char x)
{
    for (int i = 7; i >= 0; i--)
        putchar(((x >> i) & 1) ? '1' : '0');
}

static void sub_by_hand(unsigned char d, unsigned char s)
{
    unsigned char r = 0;
    int borrow = 0;                       /* 從右邊那一位借走的 1 */

    printf("D = %3u = ", d); print_bits(d); putchar('\n');
    printf("S = %3u = ", s); print_bits(s); putchar('\n');
    printf("位元  D  S  借入  這一位的算式        借出\n");
    for (int i = 0; i < 8; i++) {         /* 從最右邊（第 0 位元）往左做 */
        int db = (d >> i) & 1, sb = (s >> i) & 1;
        int v = db - sb - borrow;         /* 這一位要算的：D 位 − S 位 − 被借走的 */
        int out = 0;
        if (v < 0) { v += 2; out = 1; }   /* 不夠減：向左邊那一位借 1（＝這一位的 2） */
        printf("  %d   %d  %d   %d    %d - %d - %d %s= %d    %d\n",
               i, db, sb, borrow, db, sb, borrow,
               out ? "+ 2 " : "    ", v, out);
        r |= (unsigned char)(v << i);
        borrow = out;
    }
    printf("手算結果 = "); print_bits(r);
    printf(" = 0x%02x，最高位元還要往外借：%d\n", r, borrow);

    unsigned sum = d + (unsigned char)~s + 1;   /* 加法器的做法：D + (S 反轉) + 1 */
    printf("加法器：%u + %u + 1 = %u，%s 255 → 往外進位 %d\n",
           d, (unsigned char)~s, sum, sum > 255 ? "超過" : "沒超過", sum > 255);

    unsigned long f = flags_cmp(d, s);
    printf("CPU cmpb：結果 0x%02x，CF = %lu\n\n", (unsigned char)(d - s), f & 1);
}

int main(void)
{
    sub_by_hand(3, 5);
    sub_by_hand(5, 3);
    return 0;
}

程式裡沒教過的寫法：(d >> i) & 1 是「取出第 i 位元」（上面 flagsmain.c 用過）；~s 是 C 的「每個位元反過來」運算子，就是第 2 課第五節「取負數：每個 bit 反過來，再加 1」的那個「反過來」；r |= v << i 是把算好的這一位放回第 i 位元。

對照 5 − 3：只有第 1 位借了一次，第 2 位就把它還清了（1 − 0 − 1 = 0），最高位不用往外借，CF = 0。

為什麼「CF = 1」剛好等於「D < S（無號）」：兩個都在 0～255 之間時，D ≥ S 的差落在 0～255，8 格裝得下，最高位不必往外借；D < S 的差是負的，無號數裝不下負數，一定會借到最高位之外。所以「最高位有沒有往外借」跟「D 是不是比 S 小」是同一件事。

電路上其實是用加法做的：CPU 裡沒有另外一套減法電路，它算 D − S 的方法是 D + (S 每個位元反過來) + 1——「反過來再加 1」就是 −S（第 2 課第五節），所以等於 D + (−S)。輸出的「加法器」那一行就是這樣算的：

  • 3 − 5：3 + 250 + 1 = 254，沒超過 255，沒有往外進位。
  • 5 − 3：5 + 252 + 1 = 258，超過 255，有往外進位（留下 258 − 256 = 2）。

注意進位跟借位剛好相反：減法時「加法器沒有進位」就代表「減法要借位」。x86 在 sub／cmp 時會把加法器的進位反過來再存進 CF，所以 CF 在減法裡的意思統一是「借位了」：3 − 5 的 CF = 1、5 − 3 的 CF = 0，跟直式減法的結論一致。（有些 CPU，例如 ARM，減法時直接存加法器的進位，CF 的意思就反過來；讀別的架構的組合語言時要注意。）

OF（當成有號數，裝不下）——只看「有號」那一欄：

  • ⑥ −128 − 1：正確答案 −129，比 −128 還小，裝不下 → OF = 1。留下的 0x7f 讀成 +127，正負號反了。
  • ⑦ 127 + 1：正確答案 +128，比 127 大 → OF = 1（留下的讀成 −128）。
  • ⑩ −128 + −128：正確答案 −256 → OF = 1。這一列 CF 也是 1：兩種解讀都裝不下。
  • ⑧ −1 + 1 = 0、⑨ −56 + 100 = 44：有號看完全正常，OF = 0；但無號看都進位了，CF = 1。

把兩個「裝不下」放在一起比：⑦ 只有 OF、⑧⑨ 只有 CF、⑩ 兩個都有、①～④ 的減法裡 ③⑤ 只有 CF、⑥ 只有 OF。同一串位元，兩個旗標經常給相反的答案——所以 CF 只對無號數有意義、OF 只對有號數有意義，用錯了就是在聽一個跟你的資料無關的答案。

回頭看條件碼表：為什麼有號的「小於」是 SF ≠ OF，而不是只看 SF？ cmp 之後想知道 D < S，直覺是「D − S 是負的」，也就是 SF = 1。看三列 D < S（有號）的：

  • ③ 3 < 5：SF = 1、OF = 0，直覺對。
  • ④ −1 < 1：SF = 1、OF = 0，直覺對。
  • ⑥ −128 < 1：SF = 0、OF = 1。−128 − 1 溢位了，SF 被翻成「正的」。只看 SF 會答錯，但 OF = 1 告訴你「SF 是反的」，所以要把 SF 再翻回來——SF ≠ OF 就是「沒溢位時看 SF；溢位時看 SF 的相反」。

無號的「小於」（b）就簡單：CF = 1。③ 3 < 5、⑤ 1 < 255 都是 CF = 1，其他列都是 0。本節下面〈實驗：同一個 cmp、同一組旗標，setl 說是、setb 說否〉是 32 位元版的④：SF = 1、OF = 0、CF = 0，所以 setl 說是、setb 說否。

cmp 與 test

上表「典型用途」欄的 i、n 是誰？

2026-10-07 課後提問：「這裡面提到的 i、n 是什麼？」

上表的兩個例子都是從後面第六節、第七節要逐行讀的 sum_to 抄來的，在這裡還沒介紹就先用了。sum_to 是第 1 課就寫過的函式（檔案：sumto.c），n 是它的參數、i 是迴圈變數：

int sum_to(int n)
{
    int total = 0;
    for (int i = 1; i <= n; i++)
        total += i;
    return total;
}

cmpl -20(%rbp), %eax 為什麼是在比 i 和 n（-O0 版，第六節）：-O0 把每個變數放在記憶體的固定位置——n 在 -20(%rbp)、i 在 -4(%rbp)（%rbp 往下 20、4 byte；%rbp 本身是什麼第 5 課講，這裡只要知道「那是某個變數的位置」）。迴圈條件 i <= n 編出來是這三行：

	movl	-4(%rbp), %eax	# 把 i 讀進 %eax
	cmpl	-20(%rbp), %eax	# 算 %eax − n，也就是 i − n，只設旗標
	jle	.L3	# i <= n 就跳回迴圈本體 .L3

所以 cmpl 的 S 是 n（記憶體裡）、D 是 %eax（i 的複本），照上面的 AT&T 順序，算的是 i − n。

testl %edi, %edi 為什麼是在看 n（-O2 版，第七節）：-O2 不把 n 存到記憶體，它一直待在第 1 個參數的暫存器 %edi（第二節）。sum_to 一進來第一件事是：

	testl	%edi, %edi	# 算 n & n，只設旗標
	jle	.L4	# n <= 0 就直接跳去回傳 0（迴圈一次都不用跑）

& 是逐位元的 AND：兩邊都是 1 才得 1。一個數 AND 自己，每一位都不變，所以 n & n 就是 n。test 不存結果、只設旗標，等於「拿 n 本身來設 ZF 和 SF」：n 是 0 → ZF = 1；n 是負的（最高位元是 1）→ SF = 1；兩個都是 0 就是正的。CF、OF 被 test 清成 0。

上面 gdb 命令裡的 $pc 是什麼？

2026-10-07 課後提問：「請問在 gdb $pc 是什麼意思？」

$pc 是 program counter（程式計數器） 的縮寫，就是「CPU 下一個要執行的指令在哪個位址」。在 x86-64 上，存這個位址的暫存器叫 %rip（第二節暫存器表下面「%rip（instruction pointer，指令指標）」那一點），所以 gdb 的 $pc 就是 $rip，兩個名字指同一個暫存器。

  • $：在 gdb 的表達式裡，$ 開頭的名字代表暫存器或 gdb 自己的變數（gdb完整命令參考第三節〈表達式、值歷史、便利變數〉）。暫存器在組合語言裡寫 %rip，在 gdb 裡寫 $rip。
  • 為什麼有 $pc 這個別名：每種 CPU 的「指令位址暫存器」名字不同（x86-64 叫 rip、32 位元 x86 叫 eip、ARM 叫 pc）。gdb 提供四個每種架構都通用的標準名字，寫 gdb 命令時不用管是哪種 CPU：
gdb 標準名字 意思 在 x86-64 上 本課用到嗎
$pc program counter：下一個要執行的指令的位址 就是 $rip 用到
$sp stack pointer：堆疊頂端 就是 $rsp 第 5 課
$fp frame pointer：目前這一層函式的框架（frame）位址 gdb 自己算出來的，第 5 課講堆疊時再看 第 5 課
$ps processor status：狀態旗標 就是 eflags（印出來跟 info registers eflags 一樣） 用到（等於看旗標）

（這是 gdb 手冊〈Registers〉一節列的全部 4 個標準名字。）

逐步算：

  1. -1 的位元是 0xffffffff（第 2 課第五節），兩個函式拿到的 %edi 位元完全一樣；gdb 只是依照除錯資訊的型別，一個印成 a=-1、一個印成 a=4294967295。
  2. cmpl %esi, %edi 算 0xffffffff − 0x00000001 = 0xfffffffe：
    • 結果不是 0 → ZF = 0
    • 最高位元是 1 → SF = 1
    • 無號看：4294967295 − 1，不用借位 → CF = 0
    • 有號看：−1 − 1 = −2，沒溢位 → OF = 0
  3. gdb 印的 [ SF IF ] 就是「只有 SF（和無關的 IF）是 1」，兩個函式的旗標一模一樣。
  4. setl 看 SF ≠ OF：1 ≠ 0 → 成立 → 回傳 1（有號：−1 < 1）。 setb 看 CF = 1：CF 是 0 → 不成立 → 回傳 0（無號：4294967295 < 1 不成立）。

cmp 不知道也不在乎你的資料是有號還是無號，它把兩種解讀需要的旗標一次都設好；是 gcc 依照 C 的型別，挑了 l 或 b 去讀。 這就是第 2 課第七節「-1 < 0u 為假」在機器上的樣子：int 遇上 unsigned 被轉成無號，gcc 就改用 b。

哪些指令會改旗標

算術和邏輯指令（add、sub、and、xor、cmp、test…）會改旗標；mov 系列、lea、跳躍不會。 所以 gcc 可以把 cmp／and 和真正讀旗標的 j<cc> 中間夾幾個 mov，旗標不會被破壞——第七節 -O2 就這樣排。反過來，cmp 和 j<cc> 之間只要夾了一個 add，旗標就變成 add 的結果了。

從這張表看出 -O0 的三個特徵：

  1. 每個變數都住在記憶體裡的固定位置：n 在 -20(%rbp)、total 在 -8(%rbp)、i 在 -4(%rbp)。每次用都從記憶體讀，改完就寫回去，即使下一行馬上又要用（.L3 的 addl $1, -4(%rbp) 寫回 i，下一行 .L2 又把它讀出來）。
  2. 每一行 C 都對得到一小段組合語言，順序也一樣。
  3. 迴圈的形狀：for 被翻成「先 jmp 到底部檢查，條件成立再跳回頂端」。這樣每圈只需要一個條件跳躍。用 C 寫出來就是：
    i = 1;
    goto test;
loop:
    total += i;
    i++;
test:
    if (i <= n) goto loop;

-O0 這樣寫是為了除錯：變數一直在記憶體裡，gdb 隨時 print total 都讀得到正確的值，停在任何一行也都對應得到原始碼（gcc最佳化等級第三節）。代價是每圈有 5 個指令要碰記憶體（其中兩個 addl 還是先讀再寫）。

if 怎麼翻：條件跳躍檢查的是 C 條件的「反面」

2026-10-08 批改作業時補教：作業 3-3 問「C 寫 a > b，pick_s 的條件跳躍為什麼檢查小於或等於」，這是本課原本沒教的新觀念。

上面的 for 迴圈，底部的 jle .L3 檢查的條件跟 C 一樣（i <= n）。換成 if，條件卻會反過來。用一個最小的例子看：

指令 做什麼 對應的 C
movl %edi, -4(%rbp) 參數 x 存進記憶體 參數 x
cmpl $0, -4(%rbp) 算 x − 0，設旗標 x < 0 的比較
jns .L2 SF = 0（結果不是負的）就跳到 .L2 條件不成立（x >= 0）就跳過 if 的本體
movl $0, %eax 回傳值設成 0 return 0;（if 的本體）
jmp .L3 無條件跳到結尾 本體做完，跳過後面的 return x;
.L2: movl -4(%rbp), %eax 回傳值設成 x return x;
.L3: popq %rbp ret 回到呼叫者 函式結束

為什麼是反面？ 條件跳躍只有兩條路：條件成立就跳，不成立就往下一行執行。-O0 照原始碼的順序排，if 的本體緊接在條件跳躍的下面：

  • 條件成立 → 要執行本體 → 本體就在下面，所以不跳，直接往下走；
  • 條件不成立 → 要跳過本體 → 這時才需要跳。

跳躍是拿來「跳過本體」的，所以它檢查的是「什麼時候該跳過」，也就是 C 條件的反面。用 C 的 goto 寫出來：

    if (!(x < 0)) goto L2;   // jns .L2：x 不是負的，就跳過本體
    return 0;                // 本體：條件成立時不跳，往下就執行到這裡
L2:
    return x;

!(x < 0) 就是 x >= 0。照條件碼表，有號的 >= 是 ge（SF = OF），這裡 gcc 印的卻是單一旗標的 ns（SF = 0）：跟 0 比時 x − 0 不可能溢位，OF 一定是 0，所以「SF = OF」跟「SF = 0」是同一件事。

跟迴圈對照：往前跳是為了「跳過」，用反面條件；往回跳是為了「再跑一次」，用原本的條件。 sum_to 迴圈底部的 jle .L3 是往回跳（條件成立就回去再跑一圈），所以跟 C 的 i <= n 同向；if 的跳躍是往前跳過本體，所以是反向。

這不是唯一的排法：gcc 也可以把「條件成立」的程式放到後面、用原本的條件跳過去，只是 -O0 固定照原始碼順序排；-O2 則常把短的 if 改寫成不需要跳躍的指令（例如上面條件碼表下方提到的 set<cc>、cmov<cc>），所以作業第 3 題要用 -O0 才看得到跳躍。

先找出「誰是誰」

-O2 沒有 -20(%rbp) 這種記憶體位置了，變數全部住在暫存器裡。第一步是從用法推出每個暫存器代表什麼：

逐行

指令 做什麼 對應的意思
testl %edi, %edi n & n（就是 n），設旗標 看 n 是正、零還是負

上表的 andl 和 testl：看起來一樣，差在哪？

算的東西確實一樣：兩個都做逐位元 AND，也用同樣的規則設旗標（結果是 0 → ZF = 1、最高位元是 1 → SF = 1、CF 和 OF 清成 0）。差別只有一個：

指令 算什麼 結果寫到哪 旗標
and S, D D & S 寫回 D（D 被改掉） 照結果設
test S, D D & S 丟掉（D 不變） 照結果設，跟 and 一模一樣

這跟 sub 和 cmp 的關係完全一樣：cmp 就是「不寫回結果的 sub」，test 就是「不寫回結果的 and」（第五節〈cmp 與 test〉）。

  • 中間的 andl $1, %edi 時，n + 1 已經存進 %ecx，之後的指令只用 %eax、%edx、%ecx，%edi 再也沒被讀過。原本的 n 被改成 n & 1 也無所謂，gcc 就直接用 and。這裡換成 testl $1, %edi 也一樣正確，只是 gcc 選了 and。

判斷法：看到 and 就問「被改掉的 D 之後還有沒有用到？」——有用到的話，它要的是 AND 的結果；沒用到的話，它要的只是旗標，效果跟 test 一樣。

陣列迴圈的 i 為什麼不見了：歸納變數最佳化

2026-10-08 批改作業時補教：作業 4-4 後半「gcc 為什麼要把 i 改寫掉」是本課原本沒教的新觀念。

sum_to 的 -O2 還留著 i（%eax），因為 i 本身就是要加進 total 的數。如果 i 只拿來算位址（a[i]）和判斷結束（i < n），gcc 會把它整個換掉。用一個走訪 int 陣列的迴圈看：

ivopts.c（檔案：ivopts.c）完整原始碼：

long sum_int(int *a, long n)
{
    long t = 0;
    for (long i = 0; i < n; i++)
        t += a[i];
    return t;
}

分別用預設的 -O2，和 -O2 加上關掉這個最佳化的 -fno-ivopts 編譯：

gcc -S -O2 -fno-asynchronous-unwind-tables ivopts.c -o ivopts.s
gcc -S -O2 -fno-ivopts -fno-asynchronous-unwind-tables ivopts.c -o noivopts.s

本機 gcc 13.3 的輸出（.p2align 指示詞已刪掉；movslq 是第二節擴展指令表裡的「4 byte 有號 → 8 byte」，因為元素是 int、t 是 long）：

	endbr64                          	endbr64
	testq	%rsi, %rsi               	testq	%rsi, %rsi
	jle	.L4                          	jle	.L4

兩邊的暫存器各代表什麼：

預設 -O2 -O2 -fno-ivopts
指向元素的東西 %rdi：一個一直往前走的指標 p，每圈 +4（一個 int） %rdi：固定是 a；%rax：i，每圈 +1
讀元素 movslq (%rdi), %rdx：*p movslq (%rdi,%rax,4), %rcx：a[i]，每圈算一次 a + i×4
終點 %rcx ＝ a + n×4，也就是 &a[n]（迴圈前用 leaq 算一次） %rsi：n
判斷結束 p != &a[n]（cmpq ＋ jne） n > i（cmpq %rax, %rsi 算 n − i，jg）
t %rax %rdx，最後要多一個 movq %rdx, %rax 搬到回傳值

預設版等於把 C 改寫成這樣：

    int *p = a, *end = a + n;
    do {
        t += *p;
        p++;
    } while (p != end);

為什麼要這樣改寫？ 迴圈裡每圈固定加一個量的變數叫歸納變數（induction variable），i（每圈 +1）和 a + i×4（每圈 +4）都是。原本的寫法同時維護 i，又每圈用 i 重算一次位址；gcc 發現 i 除了算位址和判斷結束之外沒有別的用途，就只留下「每圈 +4 的位址」這一個，把結束條件也改成拿位址去比終點。這類「把每圈重算的乘法換成每圈加一個固定量」的改寫叫強度削減（strength reduction）。gcc 做這件事的最佳化就是 -fivopts（gcc --help=optimizers 的說明是 Optimize induction variables on trees.），預設開著：gcc -Q -O2 --help=optimizers 會列出 -fivopts [enabled]。（-O0 也列成 [enabled]，但 -O0 根本不執行這一類最佳化，所以開關本身沒有作用。）

上面的對照看得出它換到什麼：

  1. 少一個變數：i 和 a 合成一個指標，迴圈裡用到的暫存器少一個；n 在算出終點之後就不再需要。
  2. 記憶體運算元變簡單：(%rdi,%rax,4) 變成 (%rdi)，不用每圈算 B + I×S。gcc 的成本模型（cost model）認為簡單的定址比較便宜。

要老實說的是：這個例子裡每圈的指令數一樣（都是 5 個），差別不在指令數。本課沒有量測兩版的速度，在現代 CPU 上這種小迴圈差異通常很小——重點是讀懂 -O2 為什麼常常「找不到 i」：看到一個每圈加固定量、拿來跟某個終點位址比的暫存器，它就是被換掉的 i。

  1. movl (%rdi,%rsi,4), %eax 和 leaq (%rdi,%rsi,4), %rax 括號裡寫的一模一樣，兩個指令做的事差在哪？各對應 C 的什麼寫法？為什麼 gcc 會拿 lea 來算 x * 3 這種跟位址無關的東西？

    參考答案

    （核心關鍵＋詳細說明）

    1-1【第四節〈lea：只算位址，不碰記憶體〉】核心關鍵：

    1. movl 先算出位址 a + i×4，再去記憶體讀那個位址的 4 byte，放進 %eax。
    2. leaq 只把算出來的位址數字本身放進 %rax，不讀記憶體。

    詳細說明：括號寫法一樣，代表兩個指令算出同一個數字 D ＋ B ＋ I × S；差別只在要不要拿這個數字去存取記憶體。因為 lea 根本不存取，位址不合法也不會 segfault。

    1-2【第四節〈lea：只算位址，不碰記憶體〉】核心關鍵：

    1. movl (%rdi,%rsi,4), %eax ↔ a[i]（就是 *(a + i)，a 是 int *）。
    2. leaq (%rdi,%rsi,4), %rax ↔ &a[i]（就是 a + i，結果是指標）。

    詳細說明：第 3 課：a[i] ＝ *(a + i)、&a[i] ＝ a + i；括號裡的 a + i×4 是 a + i 換算成 byte 的算法。mov 比 lea 多做的就是那個 *。

    純算數的寫法也會編出同一行（本機 gcc -O2 -S 實測），所以單看一行 lea 分不出是指標還是算數：

    long  f(long a, long b) { return a + 4*b; }   /* → leaq (%rdi,%rsi,4), %rax */
int  *h(int *a, long i) { return &a[i]; }     /* → leaq (%rdi,%rsi,4), %rax */

    跟 movl 並排時，參數 a 被拿去讀記憶體，表示它是指標，這時 lea 讀成 &a[i] 才是對的對照。

    1-3【第四節〈lea 被拿來做算術〉】核心關鍵：

    1. lea 只算 D ＋ B ＋ I × S 這個數字、不碰記憶體，所以算的東西不必是位址。
    2. x * 3 ＝ x + x×2，正好寫成 leaq (%rdi,%rdi,2), %rax，一個指令做完。

    詳細說明：另外兩個好處：lea 不改旗標（add 會），而且結果可以放到另一個暫存器（add 只能寫回其中一個運算元）。能一次做到的倍數是 x × S 或 x ＋ x × S：1、2、3、4、5、8、9 倍（作業第 1 題）。

  2. long widen_u(unsigned x) { return x; } 只要一個 movl %edi, %eax，long widen_s(int x) { return x; } 卻要 movslq %edi, %rax。為什麼 movl 就足以完成前者？如果改寫 16 位元的 %ax，同樣的理由還成立嗎？

    參考答案

    （核心關鍵＋詳細說明）

    2-1【第二節〈寫低位的名字時，高位會怎樣？〉】核心關鍵：

    1. unsigned → long 是零擴展：高 32 位元補 0。
    2. 寫 32 位元的名字（%eax）時，CPU 會自動把 %rax 的高 32 位元清成 0，所以一個 movl %edi, %eax 就完成了零擴展。

    詳細說明：這也是擴展指令裡沒有 movzlq 的原因：4 → 8 byte 的零擴展，movl 就做完了。widen_s 要補符號位元，CPU 不會自動補，才需要 movslq。

    2-2【第二節〈寫低位的名字時，高位會怎樣？〉】核心關鍵：

    1. 不成立。
    2. 寫 16 位元（%ax）或 8 位元（%al）的名字時，高位保留原本的值、不會自動清 0；只有寫 32 位元名字才會清。所以要零擴展得用 movzwl／movzbl 這類指令。

    詳細說明：這條規則不對稱：

    寫入的大小 高位會怎樣
    32 位元（%eax） 高 32 位元清成 0
    16 位元（%ax）、8 位元（%al） 不動，保留舊值

  3. lt_s 和 lt_u 的 cmpl %esi, %edi 一模一樣，gdb 也看到兩者的旗標完全相同（[ SF IF ]），為什麼一個回傳 1、一個回傳 0？C 的「有號還是無號」在組合語言裡到底是在哪裡決定的？

    參考答案

    （核心關鍵＋詳細說明）

    3-1【第五節〈實驗：同一個 cmp、同一組旗標，setl 說是、setb 說否〉】核心關鍵：

    1. 旗標相同，差在讀旗標的條件碼：lt_s 用 setl（看 SF ≠ OF），lt_u 用 setb（看 CF）。
    2. 這次 SF = 1、OF = 0 → setl 成立，回傳 1；CF = 0 → setb 不成立，回傳 0。

    詳細說明：實驗的 a 是 −1（位元 0xffffffff）、b 是 1。有號看是 −1 < 1；無號看是 4294967295 < 1，不成立。cmpl 算出的位元與旗標只有一份，兩種讀法是 gcc 挑條件碼時決定的。

    3-2【第五節〈實驗：同一個 cmp、同一組旗標，setl 說是、setb 說否〉、第三節〈%dil 是 0xff，為什麼 %eax 變成 0xffffffff〉】核心關鍵：

    1. 在編譯時由 gcc 依照 C 的型別選指令決定；CPU、暫存器、旗標裡都沒有「有號／無號」。
    2. 這題的情境：比較之後挑哪個條件碼（有號 l／g，無號 b／a）。（2026-10-12 使用者爭論後修正：變寬原列為核心，移到詳細說明）

    詳細說明：另一個看得出有號無號的地方是變寬時挑 movs 還是 movz。cmp 把兩種解讀需要的旗標（OF 給有號、CF 給無號）一次都設好，add、sub 的位元也不分有號無號。所以從組合語言反推型別時，只能看這兩種地方。

  4. -O2 的 sum_to 裡，andl $1, %edi 和 je .L3 中間夾了一個 movl $1, %eax。je 判斷的是哪個指令的結果？為什麼 gcc 可以這樣排？如果中間夾的是 addl $1, %eax，會怎樣？

    參考答案

    （核心關鍵＋詳細說明）

    4-1【第七節〈逐行〉】核心關鍵：

    1. andl $1, %edi：它是 je 之前最後一個會改旗標的指令。

    詳細說明：je 看 ZF：n & 1 是 0（偶數）就跳到 .L3。

    4-2【第五節〈哪些指令會改旗標〉】核心關鍵：

    1. mov 不改旗標，夾在 andl 和 je 中間不會蓋掉 andl 設的旗標。

    詳細說明：mov 系列、lea、跳躍都不改旗標；算術和邏輯指令（add、sub、and、xor、cmp、test）會改。gcc 利用這點把不相干的指令塞進比較和跳躍之間。

    4-3【第五節〈哪些指令會改旗標〉】核心關鍵：

    1. addl 會改旗標，je 判斷的就變成 addl（%eax + 1 是不是 0）的結果，不再是 n 是不是奇數。

    詳細說明：程式邏輯就錯了，所以 gcc 不會把會改旗標的指令排在 andl 和 je 中間。

  5. 情境題：你在 kernel 的反組譯裡看到 movq 24(%rdi,%rsi,8), %rax，%rdi 是函式的第 1 個參數、%rsi 是第 2 個。推測它對應的 C 可能長怎樣：第 1 個參數最可能是指向什麼大小的元素的指標？存取的是第幾個元素（用 i 表示）？如果同一個位置看到的是 leaq 而不是 movq，C 又會是什麼？

    參考答案

    （核心關鍵＋詳細說明）

    參考答案

    （核心關鍵＋詳細說明）

    9-1【第三節〈%dil 是 0xff，為什麼 %eax 變成 0xffffffff：符號擴展補的是第 7 位元〉】核心關鍵：

    詳細說明：0xff 的第 7 位元是 1 → 高 3 byte 全補 1；0x7f 的第 7 位元是 0 → 全補 0。

    1. 二補數的最高位權重是負的：8 位元 0xff ＝ −2⁷ ＋ (2⁷ − 1) ＝ −1；32 位元 0xffffffff ＝ −2³¹ ＋ (2³¹ − 1) ＝ −1。
    2. 所以高位全補 1，值還是 −1；補 0 的話 0x000000ff ＝ 255，值就變了。

    詳細說明：（2026-10-13 複習批改時修正核心關鍵：題目問的是 −1，用權重算出全 1 的 int 是 −1 就答到了；一般化的推導移到這裡）一般化：前面多補一個 1，新的最高位權重是 −2⁸，原本那一位從 −2⁷ 變成 +2⁷，合起來 −2⁸ ＋ 2⁷ ＝ −2⁷，跟原來一樣，值不變；補幾個都同理。對照零擴展 movzbl：一律補 0，用在 unsigned char（0x80 才能保持 128）。
