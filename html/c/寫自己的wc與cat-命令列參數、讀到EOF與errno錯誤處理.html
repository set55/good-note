課程：Linux 與系統程式系統化學習｜第 ① 站第 8 課
建立日期：2026-10-31

零、開課複習：第 7 課卡住的觀念

第 7 課的作業與自我測驗批改後，記成「第 8 課開頭先複習」的觀念如下。這些題目 11-01 的複習（review/2026-11-01-函式庫-組語）都會考，這裡只講解、不另外出題。

  1. mov D(%rip),%rax 是「讀」那格，不是拿那格的位址：%rip 加 D 算出 GOT 那格的位址，mov 把那格裡面裝的值（變數的位址）讀進 %rax；要拿格子本身的位址才用 lea。出處：第 7 課第九節第 1 章。
  2. 變數不能延遲綁定：函式第一次呼叫會先經過 PLT 跳板，跳板有機會叫 ld.so 去查；讀變數就是一條 mov，中間沒有任何可以插手的地方，所以變數的 GOT 那格一定要在載入時就填好。出處：第九節第 4 章。
  3. 複製重定位（R_X86_64_COPY）：只在主程式自己用到 .so 的變數時才發生；ld 在執行檔的 .bss 留一格（大小照連結時那份 .so），ld.so 載入時把初值複製進來，之後 .so 自己也改讀主程式那份。.so 換版後大小不合，ld.so 會警告 has different size。出處：第九節第 3 章。
  4. 填 GOT 的是執行時的 ld.so，不是連結時的 ld：ld 只在檔案裡寫下「這格要填誰」的重定位紀錄。
  5. .got.plt 裡的位址 ＝ 這個行程的載入基底 ＋ 檔案內位置：兩個行程的基底因 ASLR 不同，所以數字不同；檔案裡看到的值只是初值。出處：第九節第 8 章。
  6. 寫入時複製讓 .text 不能被改：如果 ld.so 把位址直接寫進 .text，被寫到的那一頁就會被複製成這個行程自己的一份，不再共用——所以才要把「會變的東西」集中到 GOT。
  7. --as-needed：讀到 .so 那一刻，此刻的未定義符號清單裡沒人需要它就丟掉；-l 一定要寫在用到它的檔案後面。出處：第九節第 15 章。
  8. 錯誤出在哪個階段，從第一個會失敗的階段看：找不到 .h 是前處理（fatal error: xxx.h），沒給 -l 是連結（undefined reference），找不到 .so 是執行（error while loading shared libraries）。出處：第九節第 11 章。

前七課一直在用 wc、cat、nm、readelf 這些工具，但都把它們當黑盒子。這一課要自己寫兩支：mywc（數行、字、byte）與 mycat（把檔案依序印出來）。寫之前先看一支命令列工具只透過哪幾個地方跟外界溝通——寫對這四個介面，你的工具就能像 wc 一樣被 shell、管線、腳本使用：

二、命令列參數：argc 與 argv

main 的兩個參數

int main(int argc, char *argv[])
位置 型別 是什麼
argc int argument count，參數的個數，包含程式名稱本身，所以至少是 1
argv char *argv[]（等於 char **argv） argument vector，一個陣列，每一格是一個指向字串的指標；argv[0] 是程式名稱，argv[1]～argv[argc-1] 是使用者給的參數，argv[argc] 固定是 NULL

char *argv[] 寫在參數列裡時就是 char **argv（陣列當參數會退化成指標，第 3 課第三節〈函式參數寫成 int a[]，其實就是 int *a〉），兩種寫法完全一樣。名字 argc／argv 只是慣例，叫別的也可以，但大家都這樣寫。

實驗：把 argv 一格一格印出來

args.c（檔案：args.c）完整原始碼：

#include <stdio.h>

int main(int argc, char *argv[])
{
    printf("argc = %d\n", argc);
    for (int i = 0; i < argc; i++)
        printf("argv[%d] = \"%s\"\n", i, argv[i]);
    printf("argv[%d] = %p\n", argc, (void *)argv[argc]);   /* 最後一格固定是 NULL */
    return 0;
}

編譯與執行（資料夾裡先放兩個空檔 a.txt、b.txt）：

$ gcc -Wall args.c -o args
$ touch a.txt b.txt
$ ./args
argc = 1
argv[0] = "./args"
argv[1] = (nil)
$ ./args hello "two words" '*.txt' *.txt -
argc = 7
argv[0] = "./args"
argv[1] = "hello"
argv[2] = "two words"
argv[3] = "*.txt"
argv[4] = "a.txt"
argv[5] = "b.txt"
argv[6] = "-"
argv[7] = (nil)
$ ./args ""
argc = 2
argv[0] = "./args"
argv[1] = ""
argv[2] = (nil)

逐行看：

  • 不帶參數時 argc 是 1：argv[0] 是 "./args"，就是你在 shell 打的那個字串（用完整路徑執行，argv[0] 就是完整路徑）。argv[1] 已經是 NULL（印成 (nil)）。
  • "two words" 是一格：shell 用空白切參數，引號裡的空白不切。程式拿到的字串裡沒有引號——引號是給 shell 看的，shell 用完就拿掉了。
  • '*.txt' 和 *.txt 不一樣：單引號裡的 *.txt 原樣傳進來；沒加引號的 *.txt 被 shell 換成符合的檔名 a.txt、b.txt，程式拿到的是兩格，根本看不到 *。
  • - 只是一個普通字串：wc -、cat - 的「- 代表標準輸入」是程式自己看到 argv[i] 是 "-" 才決定的慣例，shell 不管。作業要自己處理。
  • "" 也算一格：空字串的參數，argc 照樣加 1。

誰把 *.txt 換成檔名：shell，在 execve 之前

用 strace 只看 execve（第 1 課用過的「啟動一支程式」的系統呼叫，見第 1 課第六節〈執行：從 execve 到 write〉與第十節〈實驗三：編譯時跑了哪些程式、執行時又跑了哪些〉）：

$ strace -e trace=execve ./args '*.txt' *.txt
execve("./args", ["./args", "*.txt", "a.txt", "b.txt"], 0x7fff540f5dc8 /* 91 vars */) = 0

execve 的第二個參數就是已經展開好的字串陣列——shell 先展開萬用字元（glob）、處理引號、切好每一格，再把這個陣列交給 kernel，kernel 放到新程式的堆疊上，C 的啟動程式碼再把它交給 main 當 argv。所以程式沒有辦法知道使用者原本打的是 *.txt 還是 a.txt b.txt。

沒有任何檔案符合時，bash 和 zsh 的處理不一樣（在一個空資料夾裡跑）：

$ bash -c '../args *.txt; echo "exit=$?"'
argc = 2
argv[0] = "../args"
argv[1] = "*.txt"
argv[2] = (nil)
exit=0
$ zsh -c '../args *.txt; echo "exit=$?"'
zsh:1: no matches found: *.txt
exit=1
  • bash：沒有符合的就把 *.txt 原樣傳進去，程式會收到一個叫 *.txt 的參數（wc *.txt 因此會說 wc: '*.txt': No such file or directory）。
  • zsh（本機的登入 shell 是 /usr/bin/zsh）：預設直接報錯 no matches found，程式根本沒有被執行，exit=1 是 zsh 自己給的。

圖：./args hello "two words" 時 argv 在記憶體裡的樣子（位址是通用名字，不是實測值）：

argv ──▶ ┌──────────┐
         │ argv[0] ─┼──▶ "./args\0"
         ├──────────┤
         │ argv[1] ─┼──▶ "hello\0"
         ├──────────┤
         │ argv[2] ─┼──▶ "two words\0"
         ├──────────┤
         │ argv[3]  │  = NULL   ← argv[argc]，迴圈也可以用「走到 NULL 為止」來停
         └──────────┘
  每一格是 8 byte 的指標（char *），字串本身在別的地方，各自以 '\0' 結尾

圖要看的重點：argv 是「指標的陣列」，不是一大串字；每個參數是獨立的 C 字串，所以 argv[2][0] 是 't'、argv[2][3] 是 ' '。

三、讀到 EOF：getc 為什麼回傳 int

一次讀一個 byte：getchar、getc

函式 宣告（<stdio.h>） 做什麼
getchar int getchar(void); 從標準輸入（stdin）讀一個 byte
getc int getc(FILE *stream); 從指定的 FILE（例如 fopen 打開的檔案）讀一個 byte；getc(stdin) 等於 getchar()
fgetc int fgetc(FILE *stream); 跟 getc 一樣；差別是 getc 允許被實作成巨集（macro），fgetc 一定是真的函式
putchar int putchar(int c); 把一個 byte 寫到 stdout
putc／fputc int putc(int c, FILE *stream); 把一個 byte 寫到指定的 FILE（例如 stdout、stderr）；兩者的差別同 getc／fgetc

回傳值：讀到東西時回傳那個 byte 的值，範圍 0～255（當成 unsigned char 再轉成 int）；沒有東西可讀了（讀完、或出錯）回傳 EOF。 EOF（End Of File）是 <stdio.h> 定義的巨集，glibc 是 −1。

所以 getchar 有 257 種可能的回傳值：256 種 byte ＋ 1 個 EOF。char 只有 256 種值，裝不下——這就是它回傳 int 的原因。

實驗：數 stdin 有幾個 byte

getbytes.c（檔案：getbytes.c）完整原始碼：

#include <stdio.h>

int main(void)
{
    int c;                 /* 一定要用 int：要裝得下 0～255 再加上 EOF */
    long n = 0;

    while ((c = getchar()) != EOF)
        n++;
    printf("讀到 %ld 個 byte，EOF = %d\n", n, EOF);
    return 0;
}

while ((c = getchar()) != EOF) 拆開讀：先呼叫 getchar()，把回傳值存進 c，整個 (c = getchar()) 的值就是剛存進去的值，再拿它跟 EOF 比。外層括號不能省：c = getchar() != EOF 會因為 != 優先順序比 = 高，變成把「比較的結果（0 或 1）」存進 c。

準備一個 5 byte 的檔案，中間有一個 0xff（printf 的 \xff 寫出一個值是 255 的 byte）：

$ gcc -Wall getbytes.c -o getbytes
$ printf 'AB\xffCD' > ff.bin
$ od -An -tx1 ff.bin
 41 42 ff 43 44
$ ./getbytes < ff.bin
讀到 5 個 byte，EOF = -1
$ printf 'hello\n' | ./getbytes
讀到 6 個 byte，EOF = -1
$ ./getbytes < /dev/null
讀到 0 個 byte，EOF = -1
  • < ff.bin：shell 把檔案接到程式的 stdin（fd 0），程式完全不知道檔名，只是從 stdin 讀。
  • printf 'hello\n' |：管線把前一個程式的輸出接到 stdin，\n 也是 1 byte，所以是 6。
  • /dev/null：讀它立刻就是檔案結尾，第一次 getchar() 就回傳 EOF。
  • 從鍵盤輸入時，在一行開頭按 Ctrl-D，終端機會讓這次 read 回傳 0 個 byte，getchar 因此回傳 EOF（這裡需要互動的終端機，未實測；終端機的行為在 PTY是什麼 有講）。

錯誤示範：用 char 接 getchar()

charbug.c（檔案：charbug.c）只差一個型別：

#include <stdio.h>

int main(void)
{
    char c;                /* 錯誤示範：用 char 裝 getchar() 的回傳值 */
    long n = 0;

    while ((c = getchar()) != EOF)
        n++;
    printf("讀到 %ld 個 byte\n", n);
    return 0;
}

分別用預設（x86-64 上 char 是有號的）和 -funsigned-char（讓 char 變成無號，ARM 上的 Linux 預設就是這樣）編：

$ gcc -Wall charbug.c -o charbug
$ gcc -Wall -funsigned-char charbug.c -o charbug_u
$ ./charbug < ff.bin
讀到 2 個 byte
$ timeout 2 ./charbug_u < ff.bin; echo "exit=$?"
exit=124

（兩個都沒有警告：-Wall 抓不到這個錯。timeout 2 是 2 秒後砍掉程式，被砍時 timeout 回傳 124。）

版本 讀到 0xff 時 讀到檔案結尾時 結果
int c（getbytes） c ＝ 255，≠ −1，繼續 c ＝ −1，＝ EOF，停 正確：5 個
有號 char c（charbug） 255 存進有號 char 變成 −1；比較時 c 升成 int 還是 −1，＝ EOF，提早停 （到不了） 錯：只數到 A、B 兩個
無號 char c（charbug_u） 255 存進無號 char 還是 255，繼續 EOF（−1）存進無號 char 變成 255；比較時是 255 ≠ −1，永遠不等於 EOF 錯：無窮迴圈，getchar 一直回傳 EOF、一直被當成 255

為什麼 255 存進有號 char 會變 −1：char 只有 8 位元，255 的位元是 11111111，當有號數讀就是 −1（二補數，第 2 課第五節；存進比較小的型別只留低位元，第 2 課第六節）。EOF 的 −1 存進 8 位元也是 11111111——一旦存進 char，「byte 255」和「EOF」就變成同一個位元樣式，再也分不出來。用 int 接，兩者是 0x000000ff 和 0xffffffff，不會混。

這個錯在純文字（ASCII）檔案上不會出現，因為 ASCII 的值都 ≤ 127；但中文的 UTF-8 會出現 0x80～0xff 的 byte（字元是什麼〈char 有號，讀到中文會變負數〉），二進位檔更是什麼值都有。

四、開檔與錯誤：fopen、errno、perror、strerror

fopen：打開檔案，拿到一個 FILE *

FILE *fopen(const char *pathname, const char *mode);
int fclose(FILE *stream);
位置 是什麼
pathname 檔案路徑字串，例如 argv[1]
mode 開啟模式字串，本課只用 "r"（讀）；全部的模式見第八節〈fopen 的模式〉
回傳值 成功：一個 FILE *，之後傳給 getc、fclose；失敗：NULL，並且設定 errno

FILE 是 stdio 用來記住「這個檔案讀到哪、緩衝區在哪」的結構；stdin、stdout、stderr 也是 FILE *，程式開始時就已經打開好了，不用 fopen。用完的檔案要 fclose：它會把還沒寫出去的緩衝區寫出去、釋放 FILE，並關掉底下的檔案描述符（fd）。

錯誤回報的慣例：回傳值說「失敗了」，errno 說「為什麼」

C 函式庫與系統呼叫幾乎都用同一套慣例（man 3 errno）：

  1. 函式用回傳值表示失敗：fopen 回傳 NULL、getc 回傳 EOF、系統呼叫回傳 −1。每個函式的失敗回傳值不同，要看它的 man page 的 RETURN VALUE 一節。
  2. 失敗時把原因寫進 errno：errno 是 <errno.h> 宣告的一個整數（glibc 裡每個執行緒各一份），值是 ENOENT（2）、EACCES（13）這種錯誤碼。
  3. 成功時不保證動 errno：所以 errno 只有在「回傳值說失敗了」之後馬上讀才有意義。

把錯誤碼翻成文字的兩個函式：

函式 宣告 做什麼
strerror char *strerror(int errnum);（<string.h>） 回傳錯誤碼對應的說明字串，例如 strerror(2) → "No such file or directory"；不印，要自己印
perror void perror(const char *s);（<stdio.h>） 把 s、": "、strerror(errno)、換行印到 stderr；s 是 NULL 或空字串時只印說明字串

實驗：四種開檔結果

openfail.c（檔案：openfail.c）完整原始碼：

#include <errno.h>
#include <stdio.h>
#include <string.h>

int main(int argc, char *argv[])
{
    if (argc != 2) {
        fprintf(stderr, "用法：%s 檔名\n", argv[0]);
        return 2;
    }

    FILE *fp = fopen(argv[1], "r");
    if (fp == NULL) {
        int saved = errno;                       /* 先存起來：之後呼叫的函式可能改掉 errno */
        printf("fopen 失敗：errno = %d\n", saved);
        printf("strerror(errno) = \"%s\"\n", strerror(saved));
        errno = saved;
        perror(argv[1]);                         /* 印到 stderr：「<參數>: <strerror 的字串>」 */
        return 1;
    }

    int c = getc(fp);
    if (c == EOF && ferror(fp))                  /* EOF 有兩種原因：讀完了，或出錯了 */
        perror("getc");
    else
        printf("第一個 byte 讀到了：%d\n", c);
    fclose(fp);
    return 0;
}

逐個看：

  • nofile.txt：errno ＝ 2，名字是 ENOENT（Error NO ENTry，沒有這個目錄項目）。perror(argv[1]) 印出「nofile.txt: No such file or directory」——把檔名放在前面，使用者才知道是哪個檔案出錯；wc、cat 的錯誤訊息也是這個格式，只是前面再加程式名稱（wc: nofile.txt: …）。
  • locked.txt：errno ＝ 13，EACCES（ACCESS denied）。檔案存在，但沒有讀取權限。
  • adir：fopen 成功了——打開目錄來讀，kernel 允許；是第一次真的讀（getc 底下的 read 系統呼叫）才失敗，errno ＝ 21，EISDIR（Is a directory）。所以錯誤不一定發生在開檔，讀的時候也要檢查。這支程式在這裡印了訊息卻回傳 0，是範例偷懶，作業不能這樣。
  • ok.txt：第一個 byte 是 'h' ＝ 104。
  • ''（空字串）：空的路徑一樣是 ENOENT；perror 的參數是空字串，所以只印說明，前面沒有「: 」。
  • 沒給參數：程式自己檢查 argc，用法錯誤印到 stderr、回傳 2（命令列工具常用 2 表示「用法錯誤」，跟「執行失敗」的 1 分開）。

errno 的值是 kernel 給的。用 strace 看 nofile.txt 那次的系統呼叫（openat 是 fopen 底下真正開檔的系統呼叫，下一節再看）：

kernel 讓 openat 回傳 −1 並帶回 ENOENT；glibc 把 ENOENT 存進 errno、讓 fopen 回傳 NULL；perror 讀 errno，用 write(2, …) 寫到 fd 2，也就是 stderr。（countch 是第六節的範例，開檔失敗的處理跟 openfail 一樣。）

實驗：成功的呼叫不會把 errno 清成 0

stale.c（檔案：stale.c，跟 openfail 放在同一個資料夾，用到同一個 ok.txt）完整原始碼：

#include <errno.h>
#include <stdio.h>
#include <string.h>

int main(void)
{
    FILE *bad = fopen("nofile.txt", "r");      /* 失敗：設 errno */
    printf("失敗之後：bad = %p, errno = %d\n", (void *)bad, errno);

    FILE *good = fopen("ok.txt", "r");         /* 成功：不會把 errno 清成 0 */
    printf("成功之後：good = %p, errno = %d (%s)\n", (void *)good, errno, strerror(errno));

    errno = 0;                                 /* 要拿 errno 判斷，得自己先清 */
    FILE *good2 = fopen("ok.txt", "r");
    printf("先清 0 再成功：errno = %d\n", errno);

    fclose(good);
    fclose(good2);
    return 0;
}

$ gcc -Wall stale.c -o stale && ./stale
失敗之後：bad = (nil), errno = 2
成功之後：good = 0x612d78eab2a0, errno = 2 (No such file or directory)
先清 0 再成功：errno = 0

第二行是重點：good 明明開成功了，errno 卻還是 2——那是上一次失敗留下來的。如果寫成「fopen 之後看 errno 是不是 0 來判斷成功」，這裡就會誤判成失敗。所以：

  • 先看回傳值（NULL、EOF、−1）判斷有沒有失敗，失敗了才去讀 errno；
  • 讀 errno 要緊接在失敗的呼叫後面。中間呼叫的任何函式（包括 printf）都可能在內部失敗又成功、改掉 errno。openfail.c 先把 errno 存進 saved、印完再放回去給 perror 用，就是這個原因；只呼叫一次 perror 的話，直接緊接著呼叫就好。
  • 少數函式只能靠 errno 判斷（回傳值沒有專門表示失敗的值），這時才要先 errno = 0 再呼叫——第三行示範的就是這個寫法。本課的函式都不需要。

EOF 有兩種意思：讀完了，或出錯了

getc 回傳 EOF 時有兩種可能：真的讀到檔案結尾，或者讀的時候出錯（例如上面的目錄 EISDIR、磁碟讀取錯誤 EIO）。迴圈 while ((c = getc(fp)) != EOF) 兩種情況都會停，停下來之後要問 FILE 自己：

函式 宣告 回傳
ferror int ferror(FILE *stream); 這個 FILE 發生過讀寫錯誤 → 非 0
feof int feof(FILE *stream); 這個 FILE 讀到過檔案結尾 → 非 0
clearerr void clearerr(FILE *stream); 把上面兩個記號都清掉

所以讀檔迴圈的標準寫法是：迴圈照常用 != EOF 停，停下來之後用 ferror 檢查，是錯誤就回報、算失敗。openfail.c 的 if (c == EOF && ferror(fp)) 就是這樣分辨出「目錄讀不了」和「空檔案」。

五、stdout 與 stderr，以及結束狀態

結果寫 stdout，錯誤寫 stderr

perror 固定寫到 stderr；自己印錯誤訊息時用 fprintf(stderr, ...)（fprintf 跟 printf 一樣，只是第一個參數指定寫到哪個 FILE）。分開的理由是使用者重新導向時，兩者會被分到不同地方：

$ ./openfail nofile.txt > out.txt 2> err.txt
$ cat out.txt
fopen 失敗：errno = 2
strerror(errno) = "No such file or directory"
$ cat err.txt
nofile.txt: No such file or directory
$ ./openfail nofile.txt 2>/dev/null; echo "exit=$?"
fopen 失敗：errno = 2
strerror(errno) = "No such file or directory"
exit=1
  • > out.txt 只導 fd 1（stdout），2> err.txt 導 fd 2（stderr）。語法逐字拆解見 輸出重新導向與dev-null。
  • 想像 mywc *.txt > report.txt：如果錯誤訊息也寫 stdout，report.txt 裡就會混進「nofile.txt: No such file or directory」，下一個讀 report.txt 的程式會把它當成資料；使用者自己反而在終端機上看不到出錯。錯誤寫 stderr，報告乾淨、錯誤照樣顯示在終端機上。

輸出順序為什麼會變：stdout 有緩衝、stderr 沒有

同一個 ./openfail nofile.txt，輸出接到管線時順序不一樣：

$ ./openfail nofile.txt 2>&1 | cat
nofile.txt: No such file or directory
fopen 失敗：errno = 2
strerror(errno) = "No such file or directory"

stderr 那行跑到最前面了。原因是第 7 課課後討論學過的緩衝（第 7 課第九節第 14 章）：stdout 接到管線時是全緩衝，兩行 printf 先存在緩衝區，return 時才寫出去；stderr 不緩衝，perror 馬上寫。接到終端機時 stdout 是行緩衝，每遇到 \n 就寫，所以看到的是程式裡的順序。這不影響正確性（各自的內容都對），只是提醒：不要靠兩個資料流的相對順序，作業比對輸出時要分開比。

結束狀態：return 的值

main 回傳的數字就是結束狀態，shell 用 $? 看得到（分號與結束狀態〈程式自己決定〉）。命令列工具的慣例：

結束狀態 意思 例子
0 全部成功 wc one.txt
1 執行時有失敗（但可能已經處理了一部分） wc one.txt nofile.txt：印了 one.txt 的結果，結束狀態仍是 1
2 用法錯誤（參數不對），通常什麼都沒做 openfail 沒給檔名；ls --bogus、grep --bogus x 都回傳 2

「用法錯誤回 2」只是慣例，不是每個工具都遵守：本機 wc --bogus、cat --bogus 印出 unrecognized option 後回傳的是 1（GNU coreutils 的 wc、cat 不分「用法錯誤」和「執行失敗」）。所以判斷別人的工具時要看它的 man page 的 EXIT STATUS 一節；自己寫的工具則照自己的規格（作業的規格寫在題目裡）。

<stdlib.h> 另外定義了 EXIT_SUCCESS（0）和 EXIT_FAILURE（1），寫 return EXIT_FAILURE; 跟 return 1; 在 Linux 上一樣。在 main 以外的函式裡要直接結束程式，用 exit(1)——它跟 main 裡的 return 1 一樣會先把緩衝區寫出去。

為什麼 wc、cat 遇到一個壞檔案不馬上停：使用者打 wc *.txt，其中一個檔案沒有權限，他要的還是其他檔案的結果。所以這些工具的做法是：每個檔案各自處理，壞的印錯誤到 stderr、記下「有失敗過」，繼續下一個；全部做完，有失敗過就回傳 1。腳本用 if wc ... ; then 判斷時，才知道結果不完整。第七節的實測會看到 wc 和 cat 都是這樣。

六、接起來：countch 與用 strace 看它做了哪些系統呼叫

把前三節組合成一支完整的小工具：數一個檔案裡某個字元出現幾次。它只處理一個檔案、一個字元，作業的 mywc、mycat 要處理多個檔案、標準輸入、總計，比它多很多。

countch.c（檔案：countch.c）完整原始碼：

#include <stdio.h>

/* 用法：./countch 檔名 字元 —— 數這個檔案裡有幾個該字元 */
int main(int argc, char *argv[])
{
    if (argc != 3 || argv[2][0] == '\0' || argv[2][1] != '\0') {
        fprintf(stderr, "用法：%s 檔名 單一字元\n", argv[0]);
        return 2;
    }

    FILE *fp = fopen(argv[1], "r");
    if (fp == NULL) {
        perror(argv[1]);
        return 1;
    }

    int target = (unsigned char)argv[2][0];
    long hits = 0;
    int c;
    while ((c = getc(fp)) != EOF)
        if (c == target)
            hits++;

    if (ferror(fp)) {                 /* 迴圈停下來，是讀完了還是出錯？ */
        perror(argv[1]);
        fclose(fp);
        return 1;
    }
    fclose(fp);

    printf("%ld %s\n", hits, argv[1]);
    return 0;
}

幾個細節：

  • argv[2][0] == '\0' || argv[2][1] != '\0'：第二個參數要剛好一個字元——第 0 個不是結尾（不是空字串）、第 1 個是結尾。
  • (unsigned char)argv[2][0]：getc 回傳的是 0～255，argv 的 char 卻是有號的；要比較就先把它轉成同一個範圍，不然搜中文的 byte（≥ 0x80）會變成負數，永遠比不到。
  • 讀完先檢查 ferror，再 fclose；錯誤路徑也要 fclose。

七、wc 與 cat 的精確行為：作業的規格

作業要寫出跟 GNU wc、cat 行為一致的簡化版。這一節用實測把「一致」講清楚。

這一節的定位：作業的規格書，不用背。 第二～六節教的是第一節那四個介面的機制；這一節把它們套到兩支真的工具上，記下 wc、cat 在每個介面上具體怎麼做——哪些情況算一行、什麼算一個字、錯誤印什麼格式、壞檔案要不要繼續、結束狀態是幾。這些細節靠直覺猜不到（例如最後沒有 \n 的那行不算一行），作業 README 每題的「規格」都連到這裡，作業 2-1、3-1 要你逐行比對的標準也是這裡。讀法：先看過一遍，知道有哪些邊界情況；寫 mywc、mycat 時再回來逐條對照。節末 wc、cat 的全部選項是查詢用的，作業只用到其中幾個。

這一節的做法本身也是寫「相容工具」的標準流程：用 printf 造出邊界情況的測試檔、用 od 確認檔案裡的 byte、拿參考實作（GNU wc）實際跑、把結果記成規格——規格是量出來的，不是憑印象寫的。第 ① 站第 9 課用 Rust 重寫 wc 時，照的也是這一份。

$ printf '  lots   of\t\tspace  \n\n\nend\n' > spaces.txt     # 多餘的空白、tab、空行
$ : > empty.txt                                             # 0 byte 的空檔案

wc 數的三個數字

one.txt：一般的一行

$ wc one.txt
 1  2 12 one.txt
  • 1 行（1 個 \n）、2 個字（hello、world）、12 byte（11 個字元加 \n）。

nonl.txt：最後沒有換行

$ wc nonl.txt
 0  4 17 nonl.txt
  • 0 行：行數數的是 \n，這個檔案一個都沒有；4 個字；17 byte。

spaces.txt：多餘的空白與空行

$ wc spaces.txt
 4  4 27 spaces.txt
  • 4 行：4 個 \n，兩個空行也算；4 個字（lots、of、space、end），多餘的空白不影響；27 byte。

empty.txt：空檔案

$ wc empty.txt
0 0 0 empty.txt
  • 三欄都是 0。欄寬變成 1，因為 GNU wc 照「總 byte 數有幾位數」決定欄寬（見下面〈多個檔案、標準輸入、錯誤〉的 ⑥）。

整理成定義——三欄依序是行數、字數、byte 數，最後是檔名：

欄 wc --help 的定義 精確地說 例子
行數（-l） print the newline counts 數 \n 這個 byte 出現幾次，不是「有幾行字」 nonl.txt 有一行字但沒有 \n → 0；spaces.txt 有 4 個 \n（中間兩個空行也算）→ 4
字數（-w） a word is a non-zero-length sequence of printable characters delimited by white space 被空白隔開的一段、裡面至少有一個可印字元，算一個字；空白連續好幾個也只是分隔。不可印又不是空白的 byte（控制字元、0x7f 以上）不算字、也不切字，細節見下面〈第三種 byte〉 spaces.txt：lots、of、space、end → 4；開頭、中間、結尾多餘的空白不影響
byte 數（-c） print the byte counts 檔案總共幾個 byte，\n 也算 one.txt：hello world 11 個＋\n ＝ 12

「空白」是哪些 byte：C 的 <ctype.h> 有 isspace(int c)，在預設的 C 語系下，它對下面 6 個值回傳非 0。spaces.c（檔案：spaces.c）完整原始碼：

#include <ctype.h>
#include <stdio.h>

int main(void)
{
    for (int c = 0; c <= 255; c++)          /* isspace 只能吃 0～255 或 EOF */
        if (isspace(c))
            printf("%3d  0x%02x\n", c, c);
    return 0;
}

$ gcc -Wall spaces.c -o spaces && ./spaces
  9  0x09
 10  0x0a
 11  0x0b
 12  0x0c
 13  0x0d
 32  0x20

依序是 \t（tab）、\n（換行）、\v（垂直 tab）、\f（換頁）、\r（歸位）、空格。isspace 的參數只能是 0～255 或 EOF，傳負數是未定義行為——所以傳 getc 的回傳值（int，0～255）沒問題，傳有號的 char 就可能出事，理由同第三節。

wc 跟 isspace 的判斷一致，\v、\f、\r 也會切字：

$ printf 'a\vb\fc\rd\n' | wc -w     # 用 \v、\f、\r 把 a、b、c、d 隔開
4
  • 4 個字：\v、\f、\r 都算空白，都會切字。

第三種 byte：不是空白、也不可印

wc --help 說的是「可印字元（printable characters）組成的一段」。C 語系下每個 byte 可以分成三類，<ctype.h> 的 isprint(int c) 判斷可不可印（參數規定跟 isspace 一樣：0～255 或 EOF）。classes.c（檔案：classes.c）把 0～255 分類、印出每一類的範圍：

#include <ctype.h>
#include <stdio.h>

/* 把 0～255 分成三類：空白、可印（不含空白）、其他；印出每一類的範圍 */
int main(void)
{
    const char *name[] = { "空白（isspace）", "可印、不是空白（isprint 且非 isspace）", "其他（兩者都不是）" };
    int prev = -1, start = 0;

    for (int c = 0; c <= 256; c++) {
        int kind = -1;
        if (c <= 255)
            kind = isspace(c) ? 0 : isprint(c) ? 1 : 2;
        if (kind != prev) {
            if (prev != -1)
                printf("0x%02x～0x%02x  %s\n", start, c - 1, name[prev]);
            prev = kind;
            start = c;
        }
    }
    return 0;
}

$ gcc -Wall -Wextra classes.c -o classes && ./classes
0x00～0x08  其他（兩者都不是）
0x09～0x0d  空白（isspace）
0x0e～0x1f  其他（兩者都不是）
0x20～0x20  空白（isspace）
0x21～0x7e  可印、不是空白（isprint 且非 isspace）
0x7f～0xff  其他（兩者都不是）

注意空格 0x20 同時是 isspace 和 isprint（空格印得出來，只是看不見），所以分類時要先判斷 isspace。

「其他」那一類（控制字元 0x00～0x08、0x0e～0x1f，以及 0x7f～0xff，包含 UTF-8 中文的每一個 byte）在 wc 裡的行為，用 LC_ALL=C 實測（printf 的 \x01 寫出值是 1 的 byte）：

輸入 LC_ALL=C wc -w 讀法
\x01\n 0 只有「其他」byte，沒有可印字元 → 不算字
\xff\n 0 同上
\x01a\n 1 a 開始一個字
a\x01b\n 1 \x01 不切字：a、\x01、b 是同一個字
a\x01 b\n 2 切字的是空格，不是 \x01
\xff a\n 1 \xff 不算字，a 算一個
a\xffb\n 1 同 a\x01b
\x01\x02 a\n 1 前兩個 byte 不算字

所以 wc 判斷字數，可以想成每個 byte 依類別做一件事：空白 → 「現在不在字裡」；可印 → 如果現在不在字裡，字數加 1、變成「在字裡」；其他 → 什麼都不改。所以內容全是 0x80 以上 byte 的時候，C 語系下一個字都數不到。下面的輸入前 6 個 byte 是「中文」兩個字的 UTF-8，接一個空格，再接 \xff\xfe（不是合法的 UTF-8）：

C 語系：0 個字

$ printf '\xe4\xb8\xad\xe6\x96\x87 \xff\xfe\n' | LC_ALL=C wc -w
0
  • 8 個非空白的 byte 都 ≥ 0x80，全是「其他」類，沒有一個可印字元 → 不算字。

UTF-8 語系（本機預設）：1 個字

$ printf '\xe4\xb8\xad\xe6\x96\x87 \xff\xfe\n' | wc -w
1
  • wc 先把 3 個 byte 合成一個字元再判斷：「中」「文」是可印字元 → 1 個字；\xff\xfe 合不成合法字元，不算。

同一份輸入、只換語系，字數就不同——這就是下一段的語系問題。

語系（locale）的例外：wc 會照目前的語系判斷，本機是 LANG=en_US.UTF-8。UTF-8 的「不換行空格」（U+00A0，byte 是 c2 a0）在 UTF-8 語系下算空白，在 C 語系下不算：

UTF-8 語系：2 個字

$ printf 'a\xc2\xa0b\n' | wc -w
2
  • c2 a0 合成 U+00A0（不換行空格），算空白 → 切成 a、b 兩個字。

C 語系：1 個字

$ printf 'a\xc2\xa0b\n' | LC_ALL=C wc -w
1
  • c2、a0 各自是「其他」類的 byte，不切字 → a…b 是同一個字。

C 程式沒呼叫 setlocale 時固定是 C 語系，所以作業的 mywc 會跟 LC_ALL=C wc 一致。同樣的理由，wc -m（字元數）在 UTF-8 下把一個中文字算 1 個、C 語系下等於 byte 數；作業不用做 -m。

多個檔案、標準輸入、錯誤

① 兩個以上的檔案：最後多一行 total

$ wc one.txt nonl.txt spaces.txt; echo "exit=$?"     # 三個檔案都正常
 1  2 12 one.txt
 0  4 17 nonl.txt
 4  4 27 spaces.txt
 5 10 56 total
exit=0
  • 每個檔案一行：行數、字數、byte 數、檔名。
  • 最後一行 total 是三欄各自加總（1＋0＋4＝5、2＋4＋4＝10、12＋17＋27＝56）。只有一個檔案時不印 total。

② 中間有壞檔案：印錯誤、繼續、最後回傳 1

$ wc one.txt nofile.txt nonl.txt; echo "exit=$?"     # nofile.txt 不存在
 1  2 12 one.txt
wc: nofile.txt: No such file or directory
 0  4 17 nonl.txt
 1  6 29 total
exit=1
  • 第 2 行是錯誤訊息，印到 stderr，格式「wc: <檔名>: <strerror>」（第四節 perror 的格式）。
  • wc 沒有停，繼續處理 nonl.txt。
  • total 不含壞檔案（1＋0＝1、2＋4＝6、12＋17＝29）；有檔案失敗，結束狀態是 1。

③ 沒有參數：讀 stdin，不印檔名

$ printf 'a b\nc\n' | wc     # 資料從管線進來
      2       3       6
  • 沒有檔名欄：資料不是從檔案來的。
  • 欄寬是 7，見 ⑥。

④ 參數是 -：也讀 stdin，檔名印成 -

$ printf 'a b\nc\n' | wc - one.txt     # - 和一般檔案混用
      2       3       6 -
      1       2      12 one.txt
      3       5      18 total
  • - 那一行是 stdin 的結果，檔名欄印成 -。
  • 兩個參數 → 有 total。

⑤ 參數是目錄：讀的時候 EISDIR

$ wc /tmp; echo "exit=$?"     # /tmp 是目錄
wc: /tmp: Is a directory
      0       0       0 /tmp
exit=1
  • fopen 開得起來，讀的時候才失敗（EISDIR），錯誤印到 stderr、結束狀態 1。
  • GNU wc 還是印了一行 0——這是它的細節，作業不要求印那行 0。

⑥ 欄寬為什麼有時是 2、有時是 7：比較 ① 與 ③。GNU wc 讀檔案時先用 fstat 拿檔案大小，用「總 byte 數有幾位數」決定欄寬——① 的總數 56 是兩位數，所以寬 2；讀 stdin（③、④）或參數不是一般檔案（⑤ 的目錄）時，拿不到可用的大小，固定寬 7。作業一律用寬 7（printf("%7ld %7ld %7ld %s\n", ...)），比對時只比數字。

cat：依序把每個檔案的 byte 原樣寫到 stdout

① 依序原樣輸出

$ cat one.txt nonl.txt one.txt     # 中間的 nonl.txt 結尾沒有換行
hello world
no newline at endhello world
  • cat 不加、不改任何 byte。
  • nonl.txt 沒有 \n，所以下一個檔案的 hello world 直接接在同一行。

② 中間有壞檔案：印錯誤、繼續、最後回傳 1

$ cat one.txt nofile.txt one.txt; echo "exit=$?"     # nofile.txt 不存在
hello world
cat: nofile.txt: No such file or directory
hello world
exit=1
  • 錯誤處理跟 wc 同一套：錯誤印到 stderr（格式「cat: <檔名>: <strerror>」）、繼續印下一個檔案、結束狀態 1。

③ - 讀 stdin，可以放在中間

$ printf 'from stdin\n' | cat one.txt - one.txt     # - 夾在兩個檔案中間
hello world
from stdin
hello world
  • 照參數順序：先 one.txt、再 stdin、再 one.txt（cat --help 的 Examples 就是這個）。沒有參數時也讀 stdin。

④ 參數是目錄

$ cat /tmp; echo "exit=$?"     # /tmp 是目錄
cat: /tmp: Is a directory
exit=1
  • 印錯誤、結束狀態 1；跟 wc 不同，cat 沒有多印任何東西。

緩衝區大小：cat 底下一次 read 131072 byte（strace -o tr.txt cat one.txt nonl.txt 可以看到 read(3, "hello world\n", 131072) = 12），比 stdio 的 4096 大——GNU cat 不用 stdio，自己管緩衝區。作業用 getc／putc 就好，結果一樣。

另外 GNU cat 會擋一件事：

$ cp one.txt self.txt; cat self.txt >> self.txt; echo "exit=$?"     # 把檔案附加到自己後面
cat: self.txt: input file is output file
exit=1

輸入和輸出是同一個檔案、又是附加（>>）時，cat 讀到的永遠是自己剛寫進去的東西，會一直讀不到結尾；GNU cat 先比對兩邊是不是同一個檔案，是就拒絕。作業不要求做這個檢查，也不要用自己的 mycat 試 >> 同一個檔案（會一直寫到磁碟滿）。

全部有多少個系統呼叫

這份輸出出現 19 個不同的系統呼叫：上面第一張表 7 個、第二張表 12 個，全部都講了。x86-64 一共定義 373 個系統呼叫號碼（grep -c __NR_ /usr/include/x86_64-linux-gnu/asm/unistd_64.h），不在這裡逐一列：大部分要到用得到的那一站才有意義。查法：

  • man 2 syscalls：全部系統呼叫的清單（含從哪個核心版本開始有）；
  • man 2 <名稱>：單一個的原型、參數、回傳值、錯誤碼（例如 man 2 openat）；
  • strace -e trace=<名稱,…>：只看某幾個，例如正文的 strace -e trace=read。

正文出處：第三節〈實驗：數 stdin 有幾個 byte〉的 od -An -tx1 ff.bin、第七節開頭的 od -c spaces.txt；作業 1-1、1-3 的 ./mycat ff.bin | od -c、4-4 的 printf 'é' | od -An -tx1 也用到。正文只寫了一句「把每個 byte 印出來」。

本章的輸出都是本機 GNU coreutils 9.4 的 od 實測。

od 在做什麼

od（octal dump，八進位傾印）把檔案裡的每一個 byte 用看得見的方式印出來。cat 把 byte 原樣交給終端機，\n、\t、空白、0xff 都被終端機「解釋掉」了，看不出檔案裡到底是什麼；od 一個 byte 一格列出來，所以拿來檢查 printf 建的測試檔、mycat 的輸出有沒有一 byte 不差。

文法骨架：

od [選項…] [檔案…]        沒給檔案、或檔案寫 - → 讀標準輸入（所以能接在 | 後面）

用法一：od -c——印成字元，看空白和換行

-c 的意思是：能印的字元直接印，不能印的用跳脫寫法（\n、\t）或八進位數字表示。

$ printf '  lots   of\t\tspace  \n\n\nend\n' > spaces.txt
$ od -c spaces.txt
0000000           l   o   t   s               o   f  \t  \t   s   p   a
0000020   c   e          \n  \n  \n   e   n   d  \n
0000033
  • 最左欄是位移（offset）：這一行第一個 byte 是檔案的第幾個（從 0 數），預設用八進位。0000020 是八進位 20 ＝ 十進位 16，所以第二行從第 16 個 byte 開始；每行 16 byte。
  • 每個 byte 佔 4 格：空白 byte 就是一片空白（開頭那 8 格是兩個空白），\t 是 tab、\n 是換行。一眼就看得出 spaces.txt 有連續 3 個 \n——wc -l 數成 3 行就是它們。
  • 最後一行只有位移：0000033（八進位 33 ＝ 27）表示檔案在這裡結束，共 27 byte，跟 wc -c 一致。

不能印的 byte 怎麼顯示：

$ printf 'AB\xffCD' > ff.bin
$ od -c ff.bin
0000000   A   B 377   C   D
0000005

377 是八進位的 255，也就是 0xff。作業 1-1、1-3 用 ./mycat ff.bin | od -c 檢查輸出，看的就是這 5 格：od 讀管線傳來的 stdout，少了 377 那格（用 char 接 getc 時）就一眼看出來。

用法二：od -An -tx1——印成十六進位，一個 byte 一組

$ od -An -tx1 ff.bin
 41 42 ff 43 44
$ od -tx1 ff.bin
0000000 41 42 ff 43 44
0000005
  • -t x1（可以黏成 -tx1）：x ＝ 十六進位，1 ＝ 每組 1 byte。'A' 是 41、0xff 就是 ff——對上第 2 課講的「char 就是 1 byte 的整數」。
  • -An：-A 選位移欄用什麼進位，n ＝ none，不印位移欄。只想看 byte 值的時候用它，輸出比較乾淨（比較上面兩個指令的輸出）。

作業 4-4 的 printf 'é' | od -An -tx1 印出 c3 a9：é 在 UTF-8 是 2 個 byte（字元筆記第四節〈中文字：一個 byte 裝不下，UTF-8 用 3 個 byte〉）。

陷阱：不加選項的預設格式

$ od ff.bin
0000000 041101 041777 000104
0000005

預設是 -t o2：每 2 byte 拼成一個數字、用八進位印，而且照本機的小端序拼。041101（八進位）＝ 0x4241：'A'（0x41）是低位、'B'（0x42）是高位，跟第 2 課第三節〈位元組順序（endianness）〉講的一樣；041777 ＝ 0x43ff（0xff 在低位）、000104 ＝ 0x0044（最後落單的 D，高位補 0）。所以要看「一個一個 byte」，一定要加 -c 或 -tx1，否則順序跟檔案裡的不一樣。

全部選項（od --help 實測，GNU coreutils 9.4）

-t TYPE 的 7 種類型：a（具名字元，例如 nl、sp，忽略最高位元）、c（字元或跳脫寫法）、d（有號十進位）、u（無號十進位）、o（八進位）、x（十六進位）、f（浮點數）。後面接每組幾 byte：數字（x1、d4），或 C／S／I／L（char／short／int／long 的大小），浮點數用 F／D／L（float／double／long double）。任何類型後面加 z，每行右邊多印一欄可讀文字：

$ od -Ax -tx1z spaces.txt
000000 20 20 6c 6f 74 73 20 20 20 6f 66 09 09 73 70 61  >  lots   of..spa<
000010 63 65 20 20 0a 0a 0a 65 6e 64 0a                 >ce  ...end.<
00001b

（-Ax 讓位移改用十六進位：0x1b ＝ 27 byte。）

舊式的單字母選項是 -t 的簡寫，全部 10 個：-a ＝ -t a、-b ＝ -t o1、-c ＝ -t c、-d ＝ -t u2、-f ＝ -t fF、-i ＝ -t dI、-l ＝ -t dL、-o ＝ -t o2、-s ＝ -t d2、-x ＝ -t x2。-j、-N、-w 的數字預設十進位，0x 開頭是十六進位，可加 b（×512）、K（×1024）、KB（×1000）、M 等字尾。完整說明：info '(coreutils) od invocation'。

od -c 的版面：欄寬、八進位、什麼時候換行

每個 byte 佔一樣寬的欄，寬度以這種格式最長的寫法為準。 -c 下一個 byte 可能印成 1 個字元（A）、2 個（\n）或 3 個（377），所以每格給 3 個字元寬、再加 1 個空白隔開＝ 4 格，短的靠右、左邊補空白。對齊之後每行固定 16 格，數第幾格就知道是第幾個 byte：

$ printf 'A\n\377' > w.bin
$ od -c w.bin
0000000   A  \n 377
0000003

換格式，欄寬跟著換；給兩種格式時取寬的那個，讓上下兩列對齊同一個 byte：

$ od -An -tx1 w.bin          十六進位最多 2 位 → 每格 3
 41 0a ff
$ od -An -to1 w.bin          八進位最多 3 位 → 每格 4
 101 012 377
$ od -An -td1 w.bin          有號十進位最長是 -128 → 每格 5
   65   10   -1
$ od -An -tx1 -c w.bin       兩種一起：撐到 4 格，41 在 A 正上方
  41  0a  ff
   A  \n 377

377 是八進位的 255。 八進位每一位的權重是 8 的次方：377 ＝ 3×64 ＋ 7×8 ＋ 7 ＝ 255 ＝ 0xff ＝ 二進位 11111111。三位八進位最大就是 377，剛好是一個 byte 的最大值，所以 -c 用 3 位就寫得出任何 byte。用八進位是 od（octal dump）從早期 Unix 留下的習慣，也跟 C 的八進位跳脫 '\377' 同一種寫法（字元筆記第三節〈跳脫序列（escape sequence）：全部列出〉）。

od 只照 byte 數換行，預設每 16 byte 一行，跟檔案內容無關——檔案裡的 \n 只會印成 \n 兩個字，不會讓 od 換行。上面的 spaces.txt（共 27 byte）就是第一行 16 個、第二行剩下 11 個，space 被切成兩半（s p a ／ c e）。用 -w 改每行幾個 byte：

$ od -w8 -c spaces.txt
0000000           l   o   t   s        
0000010       o   f  \t  \t   s   p   a
0000020   c   e          \n  \n  \n   e
0000030   n   d  \n
0000033

（位移每行加 8，八進位寫成 10。）

例外：跟上一行一模一樣的行縮成 *。 位移會直接跳過去，省略了多少要靠位移推算；加 -v 才全部印。檢查 mycat 的輸出時，一大片相同的內容（例如全是 0x00）會被縮掉，不是不見了：

$ printf 'aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaxyz' > rep.txt     （48 個 a 加 xyz，共 51 byte）
$ od -c rep.txt
0000000   a   a   a   a   a   a   a   a   a   a   a   a   a   a   a   a
*
0000060   x   y   z
0000063
$ od -v -c rep.txt
0000000   a   a   a   a   a   a   a   a   a   a   a   a   a   a   a   a
0000020   a   a   a   a   a   a   a   a   a   a   a   a   a   a   a   a
0000040   a   a   a   a   a   a   a   a   a   a   a   a   a   a   a   a
0000060   x   y   z
0000063

（* 之後的位移 0000060 ＝ 48：第 16～47 個 byte 跟第一行一樣，被省略了。）

printf 怎麼造出指定的 byte：\x 最多 2 位、0x421 要幾個 byte

shell 的 printf 裡，\x 後面最多只吃 2 個十六進位數字。 所以 '\x421' 是 \x42（'B'）接一個普通字元 1，共 2 個 byte：

$ printf '\x421' | od -Ax -tx1
000000 42 31
000002
$ printf '\x421' | od -c
0000000   B   1
0000002

-Ax 讓位移欄用十六進位：第一行 000000 是從第 0 個 byte 開始，42 是第 0 個（'B'）、31 是第 1 個（字元 '1'）；第二行 000002 只有位移，表示共 2 byte。規則可以問工具：/usr/bin/printf --help 與 bash 的 help printf 都寫 \xHH byte with hexadecimal value HH (1 to 2 digits)。

C 的字串不一樣：\x 會把後面「所有」十六進位數字都吃掉。 hexesc.c（檔案：hexesc.c）：

/* hexesc.c：C 字串裡的 \x 會把後面「所有」十六進位數字都當成同一個跳脫 */
#include <stdio.h>

int main(void)
{
    const char s[] = "\x421";          /* 想要 0x42 '1'，C 卻讀成 \x421 一整個 */
    const char t[] = "\x42" "1";       /* 拆成兩個字串字面值，編譯器再接起來 */

    printf("sizeof s = %zu, s[0] = 0x%02x\n", sizeof s, (unsigned char)s[0]);
    printf("sizeof t = %zu, t = \"%s\"\n", sizeof t, t);
    return 0;
}

$ gcc -Wall hexesc.c -o hexesc
hexesc.c: In function ‘main’:
hexesc.c:6:29: warning: hex escape sequence out of range
    6 |     const char s[] = "\x421";          /* 想要 0x42 '1'，C 卻讀成 \x421 一整個 */
      |                             ^
$ ./hexesc
sizeof s = 2, s[0] = 0x21
sizeof t = 3, t = "B1"

C 把 \x421 當成一個值 0x421 的字元，一個 char 裝不下（警告 out of range），只留下低 8 位 0x21；s 只有 1 個字元加結尾的 \0，所以 sizeof s 是 2。要在 \x42 後面接字元 1，就把字串拆開寫（"\x42" "1"，相鄰的字串字面值編譯時會接成一個）。

0x421 不是一個 byte 裝得下的值（1057 ＞ 255）。「印出 0x421」依你要的東西有三種意思：

你要的 寫法 得到的 byte
整數 0x421 在記憶體／檔案裡的樣子（2 byte，小端序） printf '\x21\x04' 21 04
文字「0x421」 printf '%#x' 0x421 30 78 34 32 31（5 個字元）
Unicode 編號 U+0421 的字元（西里爾字母 С） bash -c "printf '\u0421'" d0 a1（UTF-8） 
$ printf '\x21\x04' | od -An -tx1          一個一個 byte：檔案裡的順序
 21 04
$ printf '\x21\x04' | od -An -tx2          2 byte 拼成一個數（照本機小端序）
 0421
$ printf '\x04\x21' | od -An -tx2          反過來寫，本機拼成 2104
 2104
$ printf '\x04\x21' | od -An -tx2 --endian=big    指定照大端序拼
 0421
$ printf '%#x %d\n' 0x421 0x421            印文字：%x 十六進位、# 加 0x、%d 十進位
0x421 1057
$ bash -c "printf '\u0421\n'"
С
$ bash -c "printf '\u0421'" | od -An -tx1
 d0 a1
  • 第一列就是第 2 課第三節〈位元組順序（endianness）〉：x86-64 低位 byte 放前面，C 的 short x = 0x421; 在記憶體裡就是 21 04（int 是 21 04 00 00）。od -tx2 照本機順序把 2 byte 拼回 0421。
  • 第二列是文字，跟第一列的兩個 byte 完全不同：'0'、'x'、'4'、'2'、'1' 各一個 byte。
  • 第三列：\x 給的是一個 byte 的值，\u 給的是一個字元的編號；編號超過 0x7f 的字元在 UTF-8 要好幾個 byte（字元筆記第四節〈中文字：一個 byte 裝不下，UTF-8 用 3 個 byte〉）。\u 是 bash 與 GNU printf 的寫法，所以明確用 bash -c 跑。

一句話：本課只要兩個——看字元、空白、換行用 od -c；看 byte 的值用 od -An -tx1；不加選項的預設格式是 2 byte 一組的八進位，別拿它看 byte。

3. 系統呼叫是 kernel 的介面：C 的包裝函式、syscall 指令、其他語言也一樣

2026-11-04 課後提問：「另外我在這些例子看到的系統呼叫,實際上是不是代表C有很多系統呼叫的函式?例如OPENat?如果是,其他語言也有系統呼叫的功能嗎?」

正文出處：第六節〈用 strace 看 fopen、getc、printf 底下是哪些系統呼叫〉；系統呼叫的參數與 strace 的讀法見第 1 章。

範圍：系統呼叫「本身的機制」（syscall 指令怎麼切進 kernel、kernel 那一側做什麼）還沒排課，這一章只講回答提問需要的部分。

結論先講：系統呼叫不是 C 的函式，是 kernel 提供的介面——用號碼區分（x86-64 共 373 個，write 是 1、openat 是 257），任何語言最後都靠 CPU 的 syscall 指令進 kernel。C 只是剛好有一組名字幾乎一樣的「包裝函式」（wrapper）。

glibc 的 write() 裡面：放號碼、syscall、檢查錯誤

C 的三層：stdio → 包裝函式 → syscall 指令

rawio.c（檔案：rawio.c）不用 stdio，直接呼叫包裝函式，最後一行用通用的 syscall() 直接給號碼：

/* rawio.c：不用 stdio，直接呼叫 glibc 的系統呼叫包裝函式 */
#include <fcntl.h>       /* open、O_RDONLY */
#include <unistd.h>      /* read、write、close、syscall */
#include <sys/syscall.h> /* SYS_write */

int main(void)
{
    char buf[16];
    int fd = open("in.txt", O_RDONLY);          /* 包裝函式叫 open */
    ssize_t n = read(fd, buf, sizeof buf);
    close(fd);
    write(1, buf, n);                           /* 包裝函式 write */
    syscall(SYS_write, 1, "raw\n", 4);          /* 不靠專用包裝，直接給號碼 */
    return 0;
}

  • C 寫的是 open()，kernel 收到的是 openat：glibc 的 open() 用 openat(AT_FDCWD, …) 實作，名字不一定對得上。
  • syscall(SYS_write, …) 跟 write() 產生一模一樣的系統呼叫。
層 例子 是不是系統呼叫
stdio（有緩衝） fopen、getc、printf 不是，是 C 函式庫；需要時才呼叫下一層（正文第六節：16 次 getc 只有 2 次 read）
系統呼叫包裝函式 open、read、write、close 大致一個函式對一個系統呼叫，名字可能不同（open → openat）；文件在 man 2
syscall 指令 syscall(SYS_write, …)、上面的 syscall 那行 真正進 kernel 的一步

其他語言：最後都是同一組系統呼叫

同一件事（讀 in.txt、印到 stdout）用 Python、Go、Rust 各寫一次（檔案：io.py、io.go、io.rs）：

# io.py：Python 的 os 模組，讀 in.txt 印到 stdout
import os
fd = os.open("in.txt", os.O_RDONLY)
data = os.read(fd, 16)
os.close(fd)
os.write(1, data)

// io.go：Go 讀 in.txt 印到 stdout
package main

import "os"

func main() {
	data, _ := os.ReadFile("in.txt")
	os.Stdout.Write(data)
}

// io.rs：Rust 讀 in.txt 印到 stdout
use std::fs;
use std::io::Write;

fn main() {
    let data = fs::read("in.txt").unwrap();
    std::io::stdout().write_all(&data).unwrap();
}

語言 怎麼進 kernel 看得出來的地方
C glibc 的包裝函式 rawio.c 的 strace
Python 直譯器是 C 寫的，os.open 呼叫 glibc 的 open 跟 C 一樣是 openat；Python 自動加上 O_CLOEXEC
Go 不用 libc：ldd 說 not a dynamic executable，Go 的 runtime 自己放號碼、執行 syscall 指令 系統呼叫跟 C 的一樣
Rust 標準函式庫呼叫 glibc 的包裝函式（ldd 看得到 libc.so.6） 系統呼叫跟 C 的一樣

read 一次要幾 byte（16、512、3）是各語言的函式庫自己決定的（Go、Rust 讀到 0 才停，所以多一次 read），但系統呼叫的種類、參數的意義完全相同。所以學系統呼叫學的是 kernel 的介面，換到哪個語言都通用，strace 也照樣看得懂；man 2 用 C 寫，只是因為 kernel 的介面是用 C 的型別與呼叫慣例定義的。

一句話：openat 是 kernel 的系統呼叫（號碼 257），C 的 open()、Python 的 os.open、Go 的 os.ReadFile、Rust 的 fs::read 都只是通往它的不同入口。
