零、開課複習：第 5 課卡住的觀念

第 5 課的作業與測驗批改後，記成「第 6 課開頭先複習」的觀念如下。今天的 10 題複習額度已經用完，這裡只講解、不另外出題；這些題目明天（10-20）會從複習排程考到。

  1. %rsp 本身 vs 它指的那格：%rsp 裡放的是一個位址（例如 0x7fffffffd408）；返回位址是放在那個位址的 8 byte 記憶體裡。要看返回位址，是 x/gx $rsp，不是 info registers rsp。出處：第 5 課第二節、第三節〈停在函式入口時，怎麼知道是誰呼叫的〉。
  2. 紅區：%rsp 下方 128 byte 保證不會被別人（例如訊號處理函式）蓋掉；葉函式自己也不 push／call，所以能直接把變數放在那裡，省一條 sub。會 call 的函式，call 會把返回位址寫進 %rsp − 8，所以 gcc 一律 sub 把變數放到 %rsp 上面。出處：第 5 課第四節〈上圖 add3 的變數在 %rsp 的「下面」：紅區〉與後面三個追問補充。
  3. callee-saved 的 push %rbx：要撐過 call 的值不能留在 %rdi 這種 caller-saved 暫存器（被呼叫的函式可以隨便改），要搬到 %rbx 這種 callee-saved 暫存器；但 %rbx 也是自己的呼叫者的，借用前要先 push 存起來、結束前 pop 還回去。出處：第 5 課第六節〈實驗：要跨過 call 保存的值放哪裡〉。
  4. 停在第一條指令時 gdb 印錯參數：-O0 的除錯資訊只記「參數在堆疊的哪一格」，序言還沒把 %rdi 存進去，所以讀到舊值；真正的參數在 %rdi、%rsi、%rdx。出處：第 5 課第三節〈gdb 為什麼去堆疊讀參數，而不是讀暫存器〉。
  5. 參數的正偏移從 0x10(%rbp) 開始：%rbp 那格是舊 %rbp，8(%rbp) 是返回位址，第 7 個參數才在 0x10(%rbp)。出處：第 5 課第五節〈實驗：8 個參數，第 7、8 個去哪了〉。
  6. 16 byte 對齊的算法：規則是「執行 call 的那一刻 %rsp 是 16 的倍數」。進函式時 call 已經推了 8 byte，所以 %rsp 除以 16 餘 8；之後每個 push、sub 都要算進去，湊回餘 0 才能 call。出處：第 5 課第六節〈上面的 sub $0x8,%rsp：16 byte 對齊〉。
  7. 畫堆疊圖時，區域變數與對齊用的空格也要佔格：相鄰兩個 %rbp 相減再除以 8，就是中間應該有幾格。

本課回到 C 語言本身，組合語言只在第二節用來看一個 bug 的成因，讀到的指令都是第 4、5 課教過的。

一、本課在做什麼：編譯器一次只看一個 .c

到目前為止的程式都是一個 .c 檔。真正的專案（包括 Linux kernel，好幾萬個 .c）都是很多檔案。本課回答：

  • main.c 呼叫 mathx.c 裡的函式，編譯 main.c 的時候編譯器怎麼知道那個函式長什麼樣子（第二、三節）；
  • 兩個 .o 是怎麼接起來的，接不起來時錯誤訊息在說什麼（第四節）；
  • 怎麼讓一個名字只在自己的檔案裡有效，怎麼讓一個變數被很多檔案共用（第五、六節）；
  • 改了一個檔案，怎麼只重編需要重編的部分（第七節）。

關鍵事實只有一個：gcc 編譯時一次只處理一個 .c（加上它 #include 進來的內容），這個範圍叫編譯單元（translation unit，C 標準的用語，也譯「轉譯單元」）。 gcc -c main.c 時，gcc 完全不會去讀 mathx.c。檔案之間的連繫，要等到連結（第 1 課第五節）才發生，而連結器手上只有每個 .o 的符號表——一串名字。

kernel 也是一樣：每個 .c 各自編成 .o，大部分函式都寫成 static（只給自己的檔案用），要給別的模組用的才特別匯出；kernel 的建置系統（Kbuild）也是建立在 make 上的（本課只提一句，K0 才會實際碰到）。

二、宣告與定義：沒有宣告，編譯器只能猜

先分清兩個詞：

是什麼 例子 整個程式可以有幾個
定義（definition） 真正產生東西：函式的本體（機器碼）、變數的儲存空間 long square(long x) { return x * x; } 一個
宣告（declaration） 只告訴編譯器「有這個名字，它的型別是這樣」，不產生東西 long square(long x);（結尾是分號、沒有 {}） 幾個都可以（型別要一致）

函式的宣告也叫原型（prototype）。定義同時也是一個宣告（看到定義，編譯器當然也知道型別了）。

實驗：忘了宣告，square(100000) 印出 1410065408

examples/implicit/：mathx.c（檔案：mathx.c）

long square(long x)
{
    return x * x;
}

main.c（檔案：main.c），沒有 square 的宣告：

#include <stdio.h>

int main(void)
{
    long r = square(100000);
    printf("%ld\n", r);
    return 0;
}

$ gcc -c main.c
main.c: In function ‘main’:
main.c:5:14: warning: implicit declaration of function ‘square’ [-Wimplicit-function-declaration]
    5 |     long r = square(100000);
      |              ^~~~~~
$ gcc -c mathx.c
$ gcc -o calc main.o mathx.o && ./calc
1410065408

100000 × 100000 ＝ 10000000000（一百億），印出來卻是 1410065408。沒有任何錯誤，只有一個警告。

原因：編譯 main.c 時，gcc 沒看過 square，只好照舊式 C 的規則猜它回傳 int（隱式宣告，implicit declaration；第 1 課第九節〈第 2 題〉看過同一件事）。看 main.o 的組合語言就知道它怎麼用這個猜測：

$ objdump -dr --no-show-raw-insn main.o
0000000000000000 <main>:
   0:	endbr64
   4:	push   %rbp
   5:	mov    %rsp,%rbp
   8:	sub    $0x10,%rsp
   c:	mov    $0x186a0,%edi
  11:	mov    $0x0,%eax
  16:	call   1b <main+0x1b>
			17: R_X86_64_PLT32	square-0x4
  1b:	cltq
  1d:	mov    %rax,-0x8(%rbp)
  ...
指令 在做什麼
mov $0x186a0,%edi 第 1 個參數 ＝ 100000（0x186a0）。猜成 int 參數，所以只寫 %edi（寫 32 位元會清高位，第 4 課）
mov $0x0,%eax 沒有原型的函式，gcc 照可變參數函式的規矩把 %al 設成 0（第 5 課第七節）
call 1b ＋ R_X86_64_PLT32 square 呼叫 square；位址還沒填，是重定位項目（第 1 課第四節的「洞」，-r 第 5 課教過）
cltq 把 %eax 符號擴展成 %rax，等於第 4 課的 movslq %eax,%rax（cltq 是 AT&T 對這個特定組合的專用寫法：convert long to quad）
mov %rax,-0x8(%rbp) 存進 r

square 本身是照 long 寫的，imul 算出完整的 10000000000 放在 %rax（0x2540be400）。可是 main 以為回傳值是 int，cltq 只拿 %eax 的低 32 位元，再擴展回 64 位元：

10000000000 = 0x2_540be400
低 32 位元   =   0x540be400 = 1410065408（最高位元是 0，擴展後還是正數）

被呼叫的那邊是對的，呼叫的那邊用錯的型別解讀結果。編譯 main.c 時看不到 mathx.c，連結時連結器只比對名字 square（第 1 課），沒有任何一個階段知道兩邊型別不一樣。

（本機 gcc 13 預設 C17，隱式宣告只是警告；據 gcc 14 的變更說明，新版預設會變成錯誤，本機未實測。這也是為什麼編譯時一定要開 -Wall 而且不能忽略警告。）

三、標頭檔：把宣告寫一次，讓兩邊都檢查

修法是讓 main.c 看到正確的宣告。宣告直接寫在 main.c 裡也行，但有 10 個檔案要用 square 就要寫 10 次，改型別時要改 10 個地方。所以把宣告放進一個標頭檔（header file），要用的檔案 #include 它。

examples/header/：mathx.h（檔案：mathx.h）

#ifndef MATHX_H
#define MATHX_H

long square(long x);

#endif

（#ifndef／#define／#endif 這三行是 include guard，本節後面解釋。）

mathx.c（檔案：mathx.c）——定義的那個檔案自己也 #include 自己的標頭檔：

#include "mathx.h"

long square(long x)
{
    return x * x;
}

main.c（檔案：main.c）：

#include <stdio.h>
#include "mathx.h"

int main(void)
{
    long r = square(100000);
    printf("%ld\n", r);
    return 0;
}

$ gcc -Wall -c main.c mathx.c
$ gcc -o calc main.o mathx.o && ./calc
10000000000

gcc -c 後面可以接好幾個 .c，它會各自編成同名的 .o（還是一次一個編譯單元，只是一個指令做完）。

#include 只是貼上

第 1 課第二節教過：前處理器把 #include 那一行換成檔案的內容。用 gcc -E 看 main.c 前處理後的最後幾行：

$ gcc -E main.c | tail -11

# 4 "mathx.h"
long square(long x);
# 3 "main.c" 2

int main(void)
{
    long r = square(100000);
    printf("%ld\n", r);
    return 0;
}

（全部 827 行，前面幾百行都是 stdio.h 貼進來的。# 4 "mathx.h" 這種行是前處理器留給編譯器的位置標記，讓錯誤訊息能指回原本的檔名與行號。）

所以真正讓編譯器知道型別的，是貼進來的那一行 long square(long x);。標頭檔沒有任何魔法，它就是被很多 .c 共用的一段文字。

定義的那個 .c 為什麼也要 #include 自己的標頭檔

這樣編譯器在編 mathx.c 時，會同時看到宣告和定義，兩者不一致就報錯。故意把定義改成 int：bad.c（檔案：bad.c）

#include "mathx.h"

int square(int x)
{
    return x * x;
}

$ gcc -c bad.c
bad.c:3:5: error: conflicting types for ‘square’; have ‘int(int)’
    3 | int square(int x)
      |     ^~~~~~
In file included from bad.c:1:
mathx.h:4:6: note: previous declaration of ‘square’ with type ‘long int(long int)’
    4 | long square(long x);
      |      ^~~~~~

這就是標頭檔的價值：使用的那邊（main.c）和定義的那邊（mathx.c）看的是同一份宣告，任何一邊跟它不一致，編譯時就會被抓到。如果 mathx.c 沒有 #include "mathx.h"，改了定義卻忘了改標頭檔，main.c 會照舊的宣告呼叫——又回到第二節「連結成功、結果錯誤」的情況。

標頭檔放什麼：宣告（函式原型、extern 變數，第六節）、型別定義（struct、typedef）、巨集（#define）。 不放什麼：函式的定義、變數的定義——標頭檔會被貼進很多個 .c，定義跟著被貼了幾次，連結時就有幾份（第四、六節會看到這個錯誤）。

"..." 與 <...>：去哪裡找標頭檔

寫法 先找哪裡 再找哪裡 用在
#include "mathx.h" 寫這行 #include 的那個檔案所在的資料夾 -iquote 指定的資料夾，然後跟 <...> 一樣 自己專案的標頭檔
#include <stdio.h> -I 指定的資料夾（照命令列的順序） 系統資料夾（下面這份清單） 系統與函式庫的標頭檔

系統資料夾可以問 gcc（-v 印出詳細過程，-E 只做前處理，-x c - 表示從標準輸入讀 C 程式，echo 給它一個空的程式）：

$ echo | gcc -v -E -x c - 2>&1 | sed -n '/#include "..." search/,/End of search/p'
#include "..." search starts here:
#include <...> search starts here:
 /usr/lib/gcc/x86_64-linux-gnu/13/include
 /usr/local/include
 /usr/include/x86_64-linux-gnu
 /usr/include
End of search list.

#include "..." 那一段是空的，因為沒給 -iquote；「目前檔案所在的資料夾」是固定先找的，不列在這裡。

把 mathx.h 用角括號引入會找不到：inc.c（檔案：inc.c）

#include <mathx.h>

$ gcc -c inc.c
inc.c:1:10: fatal error: mathx.h: No such file or directory
    1 | #include <mathx.h>
      |          ^~~~~~~~~
compilation terminated.
$ gcc -I. -c inc.c && echo ok
ok

-I. 把目前資料夾（.）加進 <...> 的搜尋清單，就找得到了。大專案常把所有標頭檔放在 include/ 資料夾，編譯時加 -Iinclude（kernel 也是這樣）。

include guard：同一個標頭檔被貼兩次

函式的宣告重複幾次都沒關係，但 struct 的定義在同一個編譯單元裡只能出現一次。標頭檔又會引入別的標頭檔，很容易「繞了兩條路貼進來兩次」。

examples/guard/without/：point.h（檔案：point.h），沒有 guard：

struct point {
    long x;
    long y;
};

draw.h（檔案：draw.h）與 move.h（檔案：move.h）都需要 struct point：

#include "point.h"
void draw(struct point p);

#include "point.h"
struct point move_right(struct point p, long dx);

guard_main.c（檔案：guard_main.c）兩個都要用：

#include "draw.h"
#include "move.h"

int main(void)
{
    struct point p = { 1, 2 };
    (void)p;
    return 0;
}

（(void)p; 只是「用一下 p」，避免 -Wall 警告變數沒用到。）

$ gcc -c guard_main.c
In file included from move.h:1,
                 from guard_main.c:2:
point.h:1:8: error: redefinition of ‘struct point’
    1 | struct point {
      |        ^~~~~
In file included from draw.h:1,
                 from guard_main.c:1:
point.h:1:8: note: originally defined here
    1 | struct point {
      |        ^~~~~

錯誤訊息把兩條路都印出來了：guard_main.c 第 1 行 → draw.h → point.h，以及 guard_main.c 第 2 行 → move.h → point.h。gcc -E guard_main.c 也看得到 struct point { ... } 被貼了兩次。

examples/guard/with/point.h（檔案：point.h）加上 guard，其他三個檔案不變：

#ifndef POINT_H
#define POINT_H

struct point {
    long x;
    long y;
};

#endif

$ gcc -c guard_main.c && echo OK
OK
$ gcc -E guard_main.c | grep -c "struct point {"
1

三行的意思（都是前處理器的指令，第 1 課第二節）：

行 意思
#ifndef POINT_H 如果 POINT_H 這個巨集還沒定義（if not defined），保留到 #endif 為止的內容；已經定義了就整段丟掉

五、static：兩種完全不同的意思

static 這個關鍵字寫在不同位置，意思完全不一樣：

寫在哪裡 例子 意思
檔案層級（函式外面）的函式或變數前面 static int helper(void) { ... } 這個名字只在這個 .c 裡有效，符號變成 LOCAL，別的檔案看不到、也不會跟別的檔案的同名符號衝突
函式裡面的區域變數前面 static int n = 0; 這個變數不放在堆疊上，整個程式執行期間只有一份，值會留到下一次呼叫

檔案層級的 static：讓名字變成 LOCAL

examples/static/：a.c（檔案：a.c）與 b.c（檔案：b.c）各有一個叫 helper 的函式：

{
    return 1;
}

int a_value(void)
{
    return helper();
}

static int helper(void)
{
    return 2;
}

int b_value(void)
{
    return helper();
}

ab_main.c（檔案：ab_main.c）：

#include <stdio.h>

int a_value(void);
int b_value(void);

int main(void)
{
    printf("a_value() = %d, b_value() = %d\n", a_value(), b_value());
    return 0;
}

反過來，別的檔案想呼叫 static 的 helper 也不行：callhelper.c（檔案：callhelper.c）

什麼時候用：只給自己檔案用的函式與全域變數一律加 static。好處是名字不會跟別的檔案撞、別人不會依賴你的內部細節、讀程式的人一看就知道「這個只在本檔案用」。kernel 的程式碼裡絕大部分函式都是 static。

函式裡的 static：不放堆疊，值留到下一次

examples/staticlocal/nextid.c（檔案：nextid.c）：

#include <stdio.h>

int next_id(void)
{
    static int n = 0;   /* 只初始化一次，值留到下一次呼叫 */
    n = n + 1;
    return n;
}

int plain_id(void)
{
    int n = 0;          /* 每次呼叫都重新放在堆疊上、重新設成 0 */
    n = n + 1;
    return n;
}

int main(void)
{
    for (int i = 0; i < 3; i++)
        printf("next_id() = %d, plain_id() = %d\n", next_id(), plain_id());
    return 0;
}

next_id() = 2, plain_id() = 1
next_id() = 3, plain_id() = 1

  • next_id 的 n 用 0x0(%rip) 存取：D(%rip) 是「相對於目前指令位址」的寫法（第 4 課第三節〈上表其他五列：每一種用一個實際的 C 函式對照〉），指向固定的一塊記憶體，不在堆疊上。0x0 是還沒填的洞（連結時才填）。而且函式裡沒有任何把它設成 0 的指令——初值 0 是程式載入時就準備好的，之後每次呼叫只是讀、加 1、寫回。

  • plain_id 的 n 不在符號表裡：堆疊上的變數只是 -0x4(%rbp) 這種偏移，沒有名字可以給連結器。
  • .bss：放「初值是 0」的全域變數與 static 變數。這些變數全部是 0，檔案裡不必存內容，只記「需要幾 byte」（readelf -S 看它的型別是 NOBITS），程式載入時才配一塊全是 0 的記憶體。初值不是 0 的（例如 static int n = 5;）放 .data，內容要存在檔案裡。（第 1 課〈ELF〉的圖裡看過這兩個區段名，.data／.bss 都在可寫的 LOAD 段。）

所以函式裡的 static 改的是儲存期間（storage duration）：普通區域變數是「自動」（automatic），呼叫時才在堆疊上出現、回傳就消失；static 區域變數是「靜態」（static），整個程式執行期間都在。它的名字仍然只在那個函式裡看得到。

六、extern：全域變數的宣告與定義

函式的宣告和定義很好分（有沒有 {}）。全域變數就不好分了：long hits; 看起來像宣告，其實是定義。要明確寫「只是宣告」，要加 extern。

寫法（寫在函式外面） 是什麼
extern long hits; 宣告：有一個 long 叫 hits，定義在別的地方。不配置空間
long hits = 0; 定義：配置 8 byte，初值 0
long hits; 暫定定義（tentative definition）：同一個檔案裡沒有別的定義時，就當成 long hits = 0;。所以實際上還是定義

正確做法：標頭檔寫 extern 宣告，恰好一個 .c 寫定義。

examples/extern/：hits.h（檔案：hits.h）

#ifndef HITS_H
#define HITS_H

extern long hits;       /* 宣告：hits 這個變數存在，定義在別的檔案 */
void hit(void);

#endif

hits.c（檔案：hits.c）

#include "hits.h"

long hits = 0;          /* 定義：真正配置 8 byte 的地方，整個程式只能有一個 */

void hit(void)
{
    hits = hits + 1;
}

hits_main.c（檔案：hits_main.c）

#include <stdio.h>
#include "hits.h"

int main(void)
{
    hit();
    hit();
    hit();
    printf("hits = %ld\n", hits);
    return 0;
}

$ gcc -Wall -c hits.c hits_main.c && gcc -o hits hits_main.o hits.o && ./hits
hits = 3
$ readelf -s hits_main.o hits.o | grep -E "File| hits?$"
File: hits_main.o
     5: 0000000000000000     0 NOTYPE  GLOBAL DEFAULT  UND hit
     6: 0000000000000000     0 NOTYPE  GLOBAL DEFAULT  UND hits
File: hits.o
     3: 0000000000000000     8 OBJECT  GLOBAL DEFAULT    4 hits
     4: 0000000000000000    29 FUNC    GLOBAL DEFAULT    1 hit

hits_main.o 只有 UND hits（需要），hits.o 有 8 byte 的 OBJECT hits（提供，在第 4 區段 .bss，因為初值是 0）。跟函式完全同一套規則。

忘了 extern：每個 .c 都有一份定義

examples/extern/bad/：hits.h（檔案：hits.h）把 extern 拿掉：

#ifndef HITS_H
#define HITS_H

long hits;
void hit(void);

#endif

hits.c（檔案：hits.c）也不寫自己的定義，只靠標頭檔：

#include "hits.h"

/* 這一版沒有自己寫 long hits = 0;，只靠標頭檔裡的 long hits; */

void hit(void)
{
    hits = hits + 1;
}

hits_main.c（檔案：hits_main.c）跟上面的一樣。

$ gcc -c hits.c hits_main.c
$ readelf -s hits.o hits_main.o | grep -E "File| hits$"

     3: 0000000000000000     8 OBJECT  GLOBAL DEFAULT    4 hits
File: hits_main.o
     4: 0000000000000000     8 OBJECT  GLOBAL DEFAULT    4 hits
$ gcc -o hits hits_main.o hits.o

collect2: error: ld returned 1 exit status

標頭檔被貼進兩個 .c，每個 .c 各有一個暫定定義，各自變成一份 8 byte 的 hits——兩個 GLOBAL 定義，multiple definition。注意 include guard 救不了這個：guard 只防止同一個 .c 裡貼兩次，兩個不同的 .c 本來就各貼一次。

-fcommon：舊程式為什麼這樣寫也能動

舊版 gcc 對「沒有初值的全域變數」有另一種處理：把它標成 common 符號（Ndx 是 COM，nm 印 C），連結器遇到好幾個同名的 common 符號時，會合併成一份，不報錯。這個行為現在要用 -fcommon 才會打開：

$ gcc -fcommon -c hits.c hits_main.c
$ readelf -s hits.o hits_main.o | grep -E "File| hits$"
File: hits.o
     3: 0000000000000008     8 OBJECT  GLOBAL DEFAULT  COM hits
File: hits_main.o
     4: 0000000000000008     8 OBJECT  GLOBAL DEFAULT  COM hits
$ gcc -o hits hits_main.o hits.o && ./hits
hits = 3
$ gcc -Q --help=common | grep -- "-fcommon"
  -fcommon                    		[disabled]

（gcc -Q --help=common 列出「各語言共通的選項」與目前的設定值，-Q 是「印出設定值」；COM 符號的 Value 欄存的是對齊要求，不是偏移。）本機 gcc 13 預設是關閉的（-fno-common）；據 gcc 10 的變更說明，預設是從 gcc 10 開始改成關閉的（本機沒有更舊的 gcc，未實測）。所以很多舊專案升級 gcc 後突然出現一堆 multiple definition，就是這個原因。正確的修法是補上 extern，不是加 -fcommon。

整理：全域變數放哪裡

放在 寫
標頭檔 extern long hits;（宣告，多少個 .c 引入都沒關係）
恰好一個 .c long hits = 0;（定義，這個 .c 也引入同一個標頭檔，讓編譯器檢查型別一致）
只有自己檔案用 static long hits = 0;（第五節，LOCAL，不寫進標頭檔）

七、make：只重編改過的檔案

檔案一多，每次都 gcc -c 全部重編很慢（kernel 全部重編要幾十分鐘）。分開編譯的好處是：改了 mathx.c，只要重編 mathx.o 再重新連結，main.o 不必動。make 就是自動做這個判斷的工具。

文法：規則

Makefile 由規則（rule）組成：

目標 … : 先決條件 …
<TAB>命令
<TAB>命令
位置 是什麼
目標（target） 這條規則要產生的東西，通常是檔名（calc、main.o）；冒號左邊可以有好幾個
: 分隔目標與先決條件（固定符號）
先決條件（prerequisites） 產生目標需要用到的檔案，空格分開；可以是空的
命令（recipe） 怎麼從先決條件產生目標，交給 shell 執行的指令。每一行都必須用 TAB 開頭（不能用空格），可以有好幾行

make 怎麼決定要不要執行命令：目標不存在，或任何一個先決條件的修改時間比目標新，就執行命令；否則跳過。先決條件本身如果也是別的規則的目標，先遞迴處理它。

實驗：第一個 Makefile

examples/make/：mathx.h（檔案：mathx.h），比第三節多一個巨集：

#define MATHX_H

#define DEFAULT_N 7     /* main 要算平方的數字 */

#endif

mathx.c（檔案：mathx.c）與第三節相同：

#include "mathx.h"

long square(long x)
{
    return x * x;
}

main.c（檔案：main.c）：

#include <stdio.h>
#include "mathx.h"

int main(void)
{
    printf("square(%d) = %ld\n", DEFAULT_N, square(DEFAULT_N));
    return 0;
}

先寫一個每個檔案都寫死的版本（這個版本只在本節示範，沒有另外存檔；命令前面是 TAB）：

	gcc -o calc main.o mathx.o

實用的 Makefile：變數、樣式規則、自動產生相依

Makefile（檔案：Makefile），命令前面是 TAB：

CFLAGS = -Wall -g -O0 -MMD -MP
OBJS   = main.o mathx.o

calc: $(OBJS)
	$(CC) -o $@ $^

%.o: %.c
	$(CC) $(CFLAGS) -c $< -o $@

-include $(OBJS:.o=.d)

clean:
	rm -f calc $(OBJS) $(OBJS:.o=.d)

.PHONY: clean

（先把 mathx.h 改回 7，rm -f *.o calc 清掉舊的產物。）

這次改了標頭檔，兩個 .o 都重編了。逐行解釋：

1. 變數：CC = gcc 定義變數，$(CC) 取用（也可以寫 ${CC}）。CC、CFLAGS 是慣用的名字（C 編譯器、C 編譯選項），make 的內建規則也用這兩個名字。變數的賦值有 5 種寫法（GNU make 手冊 6.2、6.5～6.6 節）：

寫法 意思
X = 值 遞迴展開：存的是「文字」，每次 $(X) 被用到時才展開裡面的變數（所以可以引用後面才定義的變數）
X := 值（或 ::=） 立即展開：定義的那一刻就把裡面的變數展開，之後不再變
X ?= 值 只有 X 還沒定義時才設（常用來給預設值，讓命令列或環境變數可以蓋過）
X += 值 在原本的值後面加一個空格再接上
X != 指令 執行 shell 指令，把輸出存進來

命令列也可以蓋掉變數：make CFLAGS=-O2 會讓 Makefile 裡的 CFLAGS = ... 失效（命令列優先）。

2. 自動變數：在命令裡代表「這條規則的某個部分」，make 執行每條規則時自動設好。全部 8 個（GNU make 手冊 10.5.3 節）：

自動變數 代表 本例
$@ 目標 calc、main.o
$< 第一個先決條件 main.c
$^ 全部先決條件（去掉重複） main.o mathx.o
$+ 全部先決條件（保留重複，照原順序） —
$? 比目標新的那些先決條件 —
$* 樣式規則裡 % 對到的部分（「主幹」，stem） main（做 main.o 時）
$| 「只看存在、不看時間」的先決條件（order-only，寫在 | 後面） —
$% 目標是函式庫成員 lib.a(x.o) 時的成員名 —（第 7 課的靜態函式庫才會碰到）

每個都可以加 D／F 取資料夾或檔名部分，例如 $(@D)、$(<F)。

3. 樣式規則（pattern rule）：%.o: %.c 的 % 對到任何字串，意思是「任何 X.o 都可以從 X.c 這樣產生」。有了它，每多一個 .c 只要加進 OBJS，不必再寫一條規則。其實 make 本身就內建了這條規則（make -p 印出內部資料庫，-f /dev/null 表示不讀任何 makefile，只看內建的）：

$ make -p -f /dev/null 2>/dev/null | grep -A3 '^%.o: %.c'
%.o: %.c
#  recipe to execute (built-in):
	$(COMPILE.c) $(OUTPUT_OPTION) $<
...
$ make -p -f /dev/null 2>/dev/null | grep -E "^COMPILE.c|^OUTPUT_OPTION|^CC ="
COMPILE.c = $(CC) $(CFLAGS) $(CPPFLAGS) $(TARGET_ARCH) -c
OUTPUT_OPTION = -o $@
CC = cc

內建的 CC 是 cc（在 Ubuntu 上 cc 是指向 gcc 的連結）。自己寫一次是為了讓規則看得見，也避免依賴內建規則（make -r 可以關掉所有內建規則）。

4. $(OBJS:.o=.d)：替換參照（substitution reference），把 OBJS 裡每個字結尾的 .o 換成 .d，得到 main.d mathx.d。

5. -MMD -MP：讓 gcc 寫出相依檔。這兩個是 gcc 的選項，跟 make 無關：

選項 做什麼
-MMD 編譯的同時，另外寫一個 .d 檔，內容是 make 的規則格式：「這個 .o 依賴哪些檔案」。只列使用者的標頭檔，不列系統標頭檔（stdio.h 那些）
-MD 跟 -MMD 一樣，但連系統標頭檔也列（本機實測 main.c 的 .d 有 24 行，全是 /usr/include/...）
-MP 替每個標頭檔多寫一條沒有先決條件、沒有命令的規則（上面 main.d 的第 2 行 mathx.h:）。萬一之後把 mathx.h 刪掉或改名，make 不會因為「main.o 依賴的 mathx.h 不存在、又沒有規則能產生它」而停下來

main.d 的第 1 行 main.o: main.c mathx.h 就是我們在 Makefile.nodeps 漏掉的那條相依。gcc 在前處理時本來就知道 #include 了哪些檔案，由它寫出來最準。（gcc 的 -M 系列還有 -M、-MM、-MF、-MT、-MQ、-MG 等，完整說明在 man gcc 的 Preprocessor Options。）

6. -include $(OBJS:.o=.d)：把 main.d、mathx.d 的內容讀進來，當成 Makefile 的一部分。include 前面的 - 表示「檔案不存在也不要報錯」——第一次 make 時 .d 還沒產生（那時 .o 也不存在，反正都要編）。同一個目標可以出現在好幾條規則裡：%.o: %.c 給了命令，main.d 的 main.o: main.c mathx.h 補上更多先決條件，make 會把它們合起來。

7. clean 與 .PHONY：clean 不是檔案，是「清掉產物」這個動作的名字，所以沒有先決條件。.PHONY: clean 宣告它是假目標（phony target）：不管有沒有叫 clean 的檔案，make clean 都要執行命令。不宣告會怎樣：Makefile.nophony（檔案：Makefile.nophony，就是上面的 Makefile 拿掉 .PHONY: clean 那一行）

$ touch clean
$ make -f Makefile.nophony clean
make: 'clean' is up to date.
$ make clean
rm -f calc main.o mathx.o main.d mathx.d

剛好有一個叫 clean 的檔案，它沒有先決條件、檔案又存在，make 判斷「已經是最新的」，什麼都不做。有 .PHONY 的版本照樣執行。

位置 是什麼 省略時
選項 下表 —
目標 要做哪些目標，可以好幾個，照順序做 做 Makefile 裡第一條規則的目標（叫「預設目標」，default goal）
