gcc：gcc最佳化等級-O0到O3差在哪

gcc 3. 在 -O2 下，answer() 連呼叫 sum_to 這件事都不見了，直接回傳 5050。編譯器做了哪兩件事才能做到？

盒子 1｜過去的作答：s1-01 quiz.md 第 3 題

編譯器發現sum_to的參數是常數, 在編譯階段直接把sum_to的答案算出來

批改：不完整（盒子 1 → 1）。你只講出第 2 步「編譯時把答案算出來」（常數摺疊），漏了第 1 步內嵌。而且「sum_to 的參數是常數」這件事，要先內嵌才成立：只看 sum_to(int n) 本身，n 是呼叫的人才知道的值，編譯器沒辦法事先算。上次也只答出一步。

參考答案【gcc最佳化等級第二節〈「內嵌」是什麼〉】：(1) 內嵌（inline）：把 sum_to 的本體整段複製進 answer，取代呼叫，n 換成 100；(2) 常數摺疊（constant folding）：內嵌後迴圈的次數和所有數字在編譯時都已知，直接算出 5050。兩步缺一不可，所以第 4 課看到的 answer: 只剩 movl $5050, %eax 和 ret。

gcc 4. 「最佳化等級越高，程式越小」對嗎？用本篇的數字說明。

盒子 1｜過去的作答：s1-01 quiz.md 第 4 題

不一定,最佳化等級只是代表最佳化的方式
例如從O0到O2 程式變大

批改：大致對（盒子 1 → 1）。判斷對（不對），例子的方向也對（-O0 → -O2 變大）。但題目要求「用本篇的數字」，你沒有給數字；理由也只寫「最佳化的方式」，沒講出「用空間換時間」。

參考答案【gcc最佳化等級第二節〈大小〉】：不對。本機 .text 大小：-Oz 30、-Os 35、-O0 70、-O2 90、-O3 234 byte。-O2、-O3 以速度為目標，會把迴圈展開、改寫（第 4 課看到 -O2 的 sum_to 為了一圈加兩個數，指令從 16 個變成 21 個），是用空間換時間。真的要小，要用 -Os／-Oz。

陣列 2. 陣列傳進函式之後

陣列 2-1. int a[10]; 在 main 裡 sizeof a 是 40，傳進 void f(int a[]) 之後 sizeof a 變成 8。為什麼？

盒子 1｜過去的作答：s1-03 quiz.md 2-1

main裏a宣告爲陣列時,原本a會退化稱int指標,指向數組的第一個元素,但是sizeof a是例外,它是顯示整個數組的大小
在f裏,a就死一個int指標的參數,所以f裏sizeof a 就是一個指標的大小

批改：對。陣列名稱遇到 sizeof 不會退化，所以是整個陣列 40 byte；函式參數寫成 int a[] 其實就是 int *a，sizeof 量的是指標，8 byte。（錯字：「退化稱」→「成」、「就死」→「就是」。）

陣列 2-2. 這件事對「怎麼設計接收陣列的函式」有什麼影響？

過去的作答：s1-03 quiz.md 2-2

f只有拿到a陣列第一個元素的位址指標,無法知道這個陣列的大小,所以參數要多出入a陣列的長度

批改：對。函式只拿到第 0 個元素的位址，長度要用另一個參數傳進去（例如 void f(int *a, size_t n)）。

陣列 2-3. a 和 &a 印出來的位址一樣，它們差在哪裡？

過去的作答：s1-03 quiz.md 2-3

a + 1 , 指標位移4byte, a是退化稱int的指標
&a + 1, 指標是位移40byte, &a是 int *[10]的指標類型

批改：不完整。a + 1 走 4 byte、&a + 1 走 40 byte，這兩點對，「差在型別」的方向也對。但型別寫錯了，而這正是上次卡住的地方： int *[10] 是「10 個 int * 組成的陣列」，不是指標；指向整個陣列的指標要加括號，寫成 int (*)[10]。括號讓 * 先跟名字結合，宣告變數時是 int (*p)[10] = &a;。整題取最差的小題，陣列 2 記為不完整（盒子 1 → 1）。

參考答案【第 3 課第三節〈a 和 &a：位址一樣，型別不一樣〉】：位址相同，型別不同。a 退化成 int *，指向第 0 個元素，+ 1 走 sizeof(int) = 4 byte；&a 的型別是 int (*)[10]（指向「10 個 int 的陣列」的指標），+ 1 走 sizeof(int[10]) = 40 byte。

陣列 3. char s1[] 與 char *s2

陣列 3-1. char s1[] = "hi"; 和 char *s2 = "hi"; 的 "hi" 分別在記憶體的哪裡？

盒子 1｜過去的作答：s1-03 quiz.md 3-1

char s1 是在stack裏
char* s2 是在.rodata 常數區

批改：對。精確一點的說法：s1 是堆疊上一個 3 byte 的陣列，裡面是 "hi" 的副本（h、i、\0）；s2 本身是堆疊上的 8 byte 指標，"hi" 本體在 .rodata。

陣列 3-2. 為什麼改 s1[0] 沒事，改 s2[0] 卻 segfault？

過去的作答：s1-03 quiz.md 3-2

因爲常數區的分頁是唯讀權限,並沒有寫入的權限

批改：對。.rodata 被載入到權限 r--p 的分頁，寫入就觸發 segfault；s1 的副本在堆疊，堆疊是 rw-p，可以寫。

陣列 3-3. 你會怎麼在 gdb 裡確認 3-2 的答案？

過去的作答：s1-03 quiz.md 3-3

x s2 找出記憶體位址
info proc mappings 找出s2是落於哪個位置

批改：大致對。info proc mappings 是對的工具，但少了最關鍵的一步：看那一段的權限欄。光知道「落在哪一段」不能證明唯讀，要看到 r--p。另外 x s2 會去讀 s2 指向的內容，要看位址用 print s2 比較直接。整題 3-1、3-2 對、3-3 大致對，陣列 3 記為大致對（盒子 1 → 1）。

參考答案【第 3 課第四節】：在 gdb 裡 run，讓它當在 s2[0] = 'H';，print s2 得到位址；info proc mappings 找到包含這個位址的那一段，權限是 r--p（沒有 w）。對照 print &s1，落在 [stack]，權限 rw-p。

GNU：GNU是什麼-Linux核心與GNU工具的分工

GNU 6. 情境題：同事說「我在這台機器上打 uname -o 看到 GNU/Linux，所以它一定用 glibc」。這個推論錯在哪？uname 的哪些欄位可以信、哪一欄不行，為什麼？你會改看什麼來判斷？

盒子 1｜過去的作答：s1-01 quiz.md GNU 第 6 題

uname -o 並不是向核心詢問得到的,而是 uname自己直接打印出來的
-s, -n -r, -v -m可以信
-p -i -o不能, 其中-p -i是posix標準沒有的,所以在各大系統 不一定支持
用strace -e trace=uname uname -o
-p -i 
uname --help
明確寫着這兩個是non portable不可以移植

批改：不完整（盒子 1 → 1）。前兩問對：-o 是 uname 程式自己印的字串，不是向核心問來的；-s -n -r -v -m 來自 uname() 系統呼叫，可以信，-p -i -o 不行。用 strace -e trace=uname 確認，是好的驗證方法。但第三問「改看什麼來判斷用不用 glibc」沒有答：你寫的 strace、uname --help 都是在驗證 uname，不是在判斷 libc。上次也卡在這一問。

參考答案【GNU是什麼第四節〈uname -o 印出 GNU/Linux，不代表它是 GNU〉】：

  • 錯在把 -o 當證據：它是程式寫死的字串，BusyBox 也印 GNU/Linux，實測 OpenWrt（musl）一樣印。
  • 可以信 -s -n -r -v -m（核心透過 uname() 回傳的 struct utsname）；不能信 -o（寫死），-p、-i 也是程式自己判斷、標明 non-portable。
  • 判斷 libc 要看動態載入器：readelf -l /bin/ls | grep interpreter（glibc 是 /lib64/ld-linux-x86-64.so.2，musl 是 /lib/ld-musl-x86_64.so.1），或 ls /lib/ld-musl-*、直接執行載入器看它的自我介紹。

C資料：C的資料在記憶體裡長怎樣-位元組、指標、位元組順序與有號無號

C資料 8. signed char c = -1; unsigned int u = c; 之後 u 是多少？擴展時新補的高位是 0 還是 1，由哪個型別決定？如果把 c 改宣告成 unsigned char c = 0xff;，u 又是多少？

盒子 2｜過去的作答：s1-02 quiz.md 第 8 題

u = 2^32 -1
補的是1, 由原本的類型決定
還是0xff

批改：對（盒子 2 → 3）。u = 2³² − 1 = 4294967295；補 1，由原本的型別（signed char）決定；改成 unsigned char 補 0，u = 0xff = 255。第 4 課的連結：這就是組合語言裡 movsbl（符號擴展）和 movzbl（零擴展）的差別。

C資料 10. long a = -1; unsigned int b = 1; 與 int c = -1; unsigned long d = 1;，a < b 和 c < d 各是真還是假？兩邊各被轉成什麼型別，依據的是哪一條規則？為什麼 gcc 只對其中一個發出 -Wsign-compare 警告？

盒子 2｜過去的作答：s1-02 quiz.md 第 10 題

a < b 爲真
c < d 爲假

long 有號的最大值大於無號,用有號的規則
unsigned long 有號的最大值小於無號, 用無號

c,d發出警告,因爲c是有號轉無號,c無法確定是否會有溢位,這是個UB

批改：不完整（盒子 2 → 1）。兩個真假對。規則說得不清楚（「有號的最大值小於無號」看不出比的是什麼）。警告的理由錯了：有號轉成無號不是 UB，C 標準規定得很清楚（位元不變，換成無號的讀法，第 2 課第六節）；UB 是有號溢位（第八節），跟這題無關。gcc 警告是因為「−1 被轉成無號，值變了，比較結果可能出乎意料」。

參考答案【第 2 課第四節〈怎麼確定一個常數的型別？比較時以誰為準？〉】：

  • a < b：long 對 unsigned int。無號那邊的等級（rank）比較低，而 long 裝得下所有 unsigned int 的值 → 兩邊轉成 long，−1 < 1 為真。
  • c < d：int 對 unsigned long。無號那邊的等級 ≥ 有號那邊 → 兩邊轉成 unsigned long，−1 變成 18446744073709551615，所以為假。
  • 只有 c < d 警告：只有它把有號的值轉成無號，負數的值會改變；a < b 轉成 long，值不變，不會出事。

字元：字元是什麼-char就是1byte的整數與ASCII和UTF-8

字元 1. char c = 'A'; 和 char c = 65; 存進記憶體的東西一樣嗎？為什麼 printf 用 %c 印出 A、用 %d 印出 65？

盒子 2｜過去的作答：s1-02 quiz.md 字元第 1 題

一樣
%c 說明要用ASCii讀65
%d 用整數

批改：對（盒子 2 → 3）。記憶體裡都是同一個 byte 0x41（65）。%c 把這個數字當成編碼，印出對應的字元 A；%d 把它當整數印成 65。記憶體沒有型別，看你怎麼讀。

字元 2. 使用者輸入的字元是 '7'，你想得到數值 7。直接把它當數字用會得到多少？該怎麼轉，這個方法為什麼成立？

盒子 2｜過去的作答：s1-02 quiz.md 字元第 2 題

55

直接-48, 48代表 '0'

批改：大致對（盒子 2 → 2）。55 對，減 48（'0'）對。但「為什麼成立」沒講出來：關鍵是 '0'～'9' 在編碼表裡是連號的（48～57）。另外建議寫成 c - '0'，不要寫死 48，意思比較清楚。

參考答案【字元是什麼第一節】：'7' 的值是 55（它的 ASCII 編號），不是 7。轉換用 c - '0'：數字字元在編碼表裡是連號的（'0' = 48 … '9' = 57），所以任何數字字元減掉 '0'，就是它跟 '0' 差幾號，也就是它代表的數值。C 標準也保證 '0'～'9' 是連續的。
