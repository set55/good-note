  1. 程式碼在 libc.so.6（printf 在本課被換成 puts）。

gcc：gcc最佳化等級-O0到O3差在哪

gcc 3. 在 -O2 下，answer() 連呼叫 sum_to 這件事都不見了，直接回傳 5050。編譯器做了哪兩件事才能做到？

題目用到的程式：sumto.c（檔案：sumto.c），用 gcc -O0 -S sumto.c 與 gcc -O2 -S sumto.c 產生組合語言（-S：只編譯到組合語言 .s 就停）。

#include <stdio.h>

int sum_to(int n)
{
    int total = 0;
    for (int i = 1; i <= n; i++)
        total += i;
    return total;
}

int answer(void)
{
    return sum_to(100);
}

int main(void)
{
	printf("answer:%d\n", answer());
	return 0;
}

-O0 與 -O2 的 answer（本機 gcc 13.3 實際輸出，刪掉組譯指示）：

# -O0
answer:
	endbr64
	pushq	%rbp
	movq	%rsp, %rbp
	movl	$100, %edi         # 第一個參數 = 100
	call	sum_to             # 呼叫 sum_to
	popq	%rbp
	ret                        # 回傳值就是 sum_to 留在 %eax 的結果

# -O2
answer:
	endbr64
	movl	$5050, %eax        # 回傳值直接設成 5050
	ret

參考答案

【第二節〈「內嵌」是什麼〉】

核心關鍵：

  1. 內嵌（inline）：把 sum_to 的函式本體整段複製進 answer()，取代「呼叫」，參數 n 換成常數 100。
  2. 常數摺疊（constant folding）：內嵌後所有數字在編譯時都已知，編譯器在編譯時就把迴圈算完，得到 5050。

詳細說明：兩步缺一不可。單看 sum_to(int n)，n 要到執行時才知道，沒辦法事先算；是內嵌把 100 帶進來，才算得出來。給別人呼叫的那份 sum_to 仍然保留迴圈。
