objdump 1. objdump -p /usr/bin/curl 只列出 3 個 NEEDED，ldd 卻列出 33 行。多出來的是哪幾類東西？為什麼 objdump 看不到？

作答（🔒 已批改）
🔒 已批改，不能再修改
批改

對（盒子 1 → 2，11-03 再考）。三類都有：linux-vdso.so.1、載入器（ld.so）、間接依賴；第二問這次答到了：objdump -p 只展示主程式自己的 dynamic section，不是主程式直接需要的庫就不在裡面。小修（不扣分，跟 10-30 同一處）：「多出來的有……所有直接與間接的依賴庫」——直接依賴（那 3 個）兩邊都看得到，多出來的只有間接依賴。

參考答案

【第二節】

核心關鍵：

  1. 多出來的三類：間接依賴（最大宗，例如 libssl.so.3 是 libcurl.so.4 要的，不是 curl 自己要的）、linux-vdso.so.1（核心提供的虛擬函式庫）、動態載入器本身。
  2. objdump -p 只讀連結時寫進 curl 的需求單（NEEDED），裡面只有直接依賴；ldd 是請載入器實際跑一次，一路照每個函式庫的 NEEDED 找下去，才拿到完整清單。

詳細說明：NEEDED 放在 dynamic section，不在檔頭。另外兩類也不會出現在 curl 的需求單裡：vdso 是核心在執行時直接放進行程的，沒有對應的檔案；載入器的路徑寫在 INTERP，不在 NEEDED。

組語二 2. 堆疊框

盒子 2｜過去的作答：s1-05 quiz.md 第 2 題、10-23 複習、10-24 複習、10-25 複習、10-28 複習

完整原始碼（檔案：frame.c）與編譯指令：

#include <stdio.h>

long add3(long a, long b, long c)
{
    long s = a + b;
    return s + c;
}

int main(void)
{
    long r = add3(1, 2, 3);
    printf("%ld\n", r);
    return 0;
}

gcc -O0 -g -fno-asynchronous-unwind-tables frame.c -o frame
objdump -d --no-show-raw-insn frame

add3:                                 main:
  push   %rbp                           push   %rbp
  mov    %rsp,%rbp                      mov    %rsp,%rbp
  mov    %rdi,-0x18(%rbp)               sub    $0x10,%rsp
  ...（沒有 sub、沒有 call）              ...（有 call add3、call printf）
  pop    %rbp                           leave
  ret                                   ret

組語二 2-1. 函式開頭的 push %rbp 和 mov %rsp,%rbp 各在做什麼？

作答（🔒 已批改）
🔒 已批改，不能再修改
批改

對。push %rbp 存呼叫者的 %rbp、mov %rsp,%rbp 把現在的頂端定成這個函式的基準點，兩點都有，每條指令的動作（%rsp 減 8、把值寫進去；複製 %rsp 到 %rbp）也寫對了。小修（不扣分）：「原值」可以寫明是呼叫者的 %rbp；AT&T 語法兩個運算元之間要逗號：mov %rsp,%rbp。

參考答案

【第四節】

核心關鍵：

  1. push %rbp：把呼叫者的 %rbp 存到堆疊上，返回前要還原。
  2. mov %rsp,%rbp：把現在的頂端定成自己堆疊框的基準點，之後區域變數用 %rbp 加固定的負偏移存取（例如 -0x18(%rbp)）。

詳細說明：每個框的 %rbp 那格都存著上一層的 %rbp，串成一條鏈，bt 就是沿著它往回找。

自我練習（不批改）

組語二 2-2. main 結尾的 leave 等於哪兩條指令？

作答（🔒 已批改）
🔒 已批改，不能再修改
批改

對。mov %rbp,%rsp 把 sub 開的空間丟掉、pop %rbp 還原，之後 %rsp 指著返回位址給 ret 用，都對。小修（不扣分）：「%rsp 移到堆疊頂端」不精確——是移回基準點（%rbp 指的那格，存著舊 %rbp），移完它就是新的頂端。

參考答案

【第四節〈leave：一條指令做兩件事〉】

核心關鍵：

  1. mov %rbp,%rsp：把 %rsp 拉回基準點，sub 開的空間一次丟掉。
  2. pop %rbp：還原呼叫者的 %rbp。

詳細說明：pop 之後 %rsp 剛好指著 call 推進來的返回位址，下一條 ret 就從那格取。

組語二 2-3. add3 把區域變數放在 %rsp 下面、沒有 sub %rsp，main 卻要 sub $0x10,%rsp，為什麼？

作答（🔒 已批改）
🔒 已批改，不能再修改
批改

對（組語二 2 整題對，盒子 2 → 3，11-07 再考）。紅區（ABI 保證 %rsp 下方 128 byte 別人不會蓋）＋葉函式（自己沒有 push／call）兩半都有了——10-24、10-28 都缺紅區，這次補齊；main 那一半也對：call 推返回位址會寫在 %rsp 下面、蓋掉那一區，所以先 sub。小修（不扣分）：紅區保證的「別人」指訊號處理函式這類非同步進來的程式碼，不包含函式自己的 call，這正是 main 雖然也有紅區、還是要 sub 的原因。

參考答案

【第四節〈上圖 add3 的變數在 %rsp 的「下面」：紅區〉】

核心關鍵：

  1. 紅區：ABI 保證 %rsp 下方 128 byte 不會被別人蓋掉；add3 是葉函式，自己也不會 push／call，所以直接用、省一條 sub。
  2. main 要 call：call 推返回位址會寫在 %rsp 下面、蓋掉那一區，所以 gcc 對會 call 的函式一律 sub，把變數空間放進堆疊（%rsp 上面）。

詳細說明：sub 的大小是 0x10 不是 8，是 16 byte 對齊的緣故。kernel 不能用紅區（中斷會直接推資料到目前的堆疊上），所以編譯時加 -mno-red-zone。

自我練習（不批改）
