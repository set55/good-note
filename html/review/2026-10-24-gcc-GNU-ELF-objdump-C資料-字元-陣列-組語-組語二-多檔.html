對。抓到：O 是 Optimize、0 是不最佳化；不加 -O 就是 -O0。

參考答案

【第一節】

核心關鍵：

  1. O 是大寫字母 O，代表 Optimize（最佳化）；0 是等級 0，即不最佳化。
  2. 不加任何 -O 時 gcc 就用 -O0，所以它是預設值。

詳細說明：man gcc 在 -O0 底下寫著 This is the default。注意 -O0 是字母 O 加數字 0，不是兩個零。

gcc 2. 為什麼 -O0 的組合語言每一圈都在讀寫記憶體（-4(%rbp)），而 -O2 不會？這個差別對 gdb 有什麼影響？

盒子 1｜過去的作答：s1-01 quiz.md gcc 第 2 題、10-09 複習、10-16 複習、10-23 複習

題目用到的程式：sumto.c（檔案：sumto.c），用 gcc -O0 -S sumto.c 與 gcc -O2 -S sumto.c 產生組合語言（-S：只編譯到組合語言 .s 就停）。

#include <stdio.h>

int sum_to(int n)
{
    int total = 0;
    for (int i = 1; i <= n; i++)
        total += i;
    return total;
}

int answer(void)
{
    return sum_to(100);
}

int main(void)
{
	printf("answer:%d\n", answer());
	return 0;
}

-O0 的 sum_to（本機 gcc 13.3 實際輸出，刪掉 .cfi、.type 這類組譯指示，右邊是逐行說明）：

sum_to:
	endbr64                    # 間接跳躍的保護標記（CET），跟這題無關
	pushq	%rbp               # 存起呼叫者的 %rbp
	movq	%rsp, %rbp         # %rbp = 這個函式的堆疊框底
	movl	%edi, -20(%rbp)    # 參數 n（放在 %edi 傳進來）寫到記憶體 -20(%rbp)
	movl	$0, -8(%rbp)       # total = 0，寫到記憶體 -8(%rbp)
	movl	$1, -4(%rbp)       # i = 1，寫到記憶體 -4(%rbp)
	jmp	.L2                # 先跳去檢查條件
.L3:                               # 迴圈本體
	movl	-4(%rbp), %eax     # 從記憶體讀 i 到 %eax
	addl	%eax, -8(%rbp)     # 記憶體裡的 total += %eax
	addl	$1, -4(%rbp)       # 記憶體裡的 i += 1
.L2:                               # 迴圈條件
	movl	-4(%rbp), %eax     # 從記憶體讀 i
	cmpl	-20(%rbp), %eax    # 比較 i 與記憶體裡的 n（算 i − n、設旗標）
	jle	.L3                # i <= n（有號）就回去跑本體
	movl	-8(%rbp), %eax     # 從記憶體讀 total 當回傳值
	popq	%rbp               # 還原 %rbp
	ret

對。抓到：-O0 不最佳化、變數放在堆疊的固定位置、每一圈都讀寫記憶體；-O2 把變數留在暫存器；gdb 上 -O0 每一行對得到指令、變數印得出來，-O2 行號亂跳、<optimized out> 是常態（10-09、10-16、10-23 缺的「每次都讀寫」這次有了）。小修（不扣分）：-O2 這裡是一圈加兩個數（展開兩倍），「一次進行多個計算」說得對，但重點是「暫存器」，不是展開。

參考答案

【第二節、第三節】

核心關鍵：

核心關鍵：

  1. 一個符號 ＝ 名字＋它在哪裡（區段、偏移、大小）；有定義的代表「這個檔案提供」，UND 代表「這個檔案需要」。
  2. 連結器用它做符號解析：把每個 UND 跟別的 .o／函式庫的 GLOBAL 定義配對（只比名字）。
  3. 再做重定位：算出每個符號的最終位址，填進機器碼裡標著那個符號名字的洞。
