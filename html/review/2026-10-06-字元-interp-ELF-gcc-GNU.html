大致對（盒子 2 → 2）。「不會成立」對，改法也能用。缺兩點：(1) 沒講出為什麼 > 127 永遠是假：本機 char 是有號的，範圍 −128～127，任何 char 都不可能大於 127，所以你改法裡的 c > 127 || 那半是死的（-Wextra 會警告 comparison is always false），真正在做事的只有 c < 0；(2) c < 0 依賴「char 有號」，換到 ARM（char 通常無號）就變成永遠假。正解是改讀法，不是補條件。

參考答案

【字元第四節〈跟第 2 課的連結〉、〈判斷「是不是非 ASCII 的 byte」〉】：不會成立。本機 char 有號（−128～127），UTF-8 的非 ASCII byte 是 0x80～0xff，用 char 讀變成負數（例如 0xe5 → −27），c > 127 永遠為假。改成 unsigned char c（或比較時寫 (unsigned char)c > 127），byte 就照 0～255 讀，> 127 的意思才正確。不要改成 unsigned int：會先符號擴展成 0xffffffe5，判斷碰巧對、值卻是錯的。

批改

不完整（盒子 2 → 1）。LGPL 那半對（商業軟體連結 glibc 不必開放自己的原始碼）。GPL 那半講錯了條件與內容：

  • GPL 不要求你「對外發布」。修改了 GPL 軟體自己用、不給別人，沒有任何義務。義務是在散布（distribute）的時候才發生：你把修改版（或連結了它的程式）給別人時，必須用同樣的授權、並提供原始碼。
  • 你寫的「必須對外發布」把「散布時要附原始碼」說成了「有義務發布」，方向反了；也沒寫出 copyleft 最核心的「同樣的授權」——自由不能在傳遞途中被拿走。
參考答案

【GNU 第五節】：copyleft：可以自由使用、修改、散布，但散布修改後的版本時，必須用同樣的授權（GPL）、並提供原始碼。glibc 用 LGPL（較寬鬆）：允許非自由的程式連結它而不必開放自己的原始碼（只有改了 glibc 本身、再散布時，才要公開對 glibc 的修改）。所以任何商業軟體都能動態連結 libc.so.6；如果 glibc 是 GPL，連結它的程式在散布時就得整個用 GPL 開放。
