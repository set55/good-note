組語 7. 參數只佔暫存器的一部分

int widen_char(signed char c) { return c; } 編出 movsbl %dil, %eax。

盒子 1｜過去的作答：s1-04 quiz.md 第 7 題

用到的程式（檔案：dil.c）：

#include <stdio.h>

__attribute__((noinline)) int widen_char(signed char c) { return c; }   /* noinline：不准內嵌，才看得到真的呼叫 */

int main(void)
{
    printf("%d\n", widen_char(-1));
    return 0;
}

gcc -O2 -g dil.c -o dil
objdump -d --no-show-raw-insn dil

widen_char 編出來的組合語言（objdump 節錄）：

widen_char:
	endbr64                # 給 CPU 的控制流程保護標記，跟計算無關（佔 4 byte，所以下一條是 widen_char+4）
	movsbl	%dil, %eax     # 讀 %dil（1 byte），有號擴展成 4 byte 放進 %eax
	ret                    # 回傳 %eax

筆記的 gdb 實驗：停在 movsbl 之前，把 %rdi 整個改掉，再執行一條指令看結果。

gdb -batch -ex 'break *widen_char+4' -ex run -ex 'p/x $rdi' \
    -ex 'set $rdi = 0x11223344556677ff' -ex 'p/x $rdi' -ex 'p/x $dil' \
    -ex stepi -ex 'p $eax' -ex 'p/x $rax' -ex continue ./dil

（break *widen_char+4：停在 widen_char 開頭往後 4 byte 那條指令；set $rdi = …：改暫存器；stepi：只執行一條機器指令。）

組語 7-1. 在 64 位元的機器上，為什麼它只讀 %dil，而不讀整個 %rdi？

🔒 已批改，不能再修改
批改

大致對。抓到「c 是 1 byte 的 signed char，所以讀 %dil」。缺第 2 點：為什麼不能讀整個 %rdi——高 7 byte 不屬於 c，呼叫的人沒有約定要放什麼，內容不保證（跟 10-08 缺同一點）。

參考答案

【第三節〈讀懂實驗一的範例：為什麼寫 1(%rdi)、為什麼用 %dil〉】

核心關鍵：

  1. 參數是 1 byte 的 signed char，只放在 %rdi 最低的 1 byte（%dil）。
  2. 高 7 byte 呼叫的人沒有約定，內容不保證；讀整個 %rdi 會把垃圾一起讀進來。

詳細說明：「64 位元系統」指暫存器和位址是 64 位元，不是每個資料都變成 8 byte。實例：main 寫 %edi 傳 −1，%rdi 是 0x00000000ffffffff，整個讀會得到 4294967295。

假設 widen_char 改成讀 4 byte 的 movl %edi, %eax，在上面的 gdb 實驗裡把 %rdi 改成 0x11223344556677ff。

組語 7-4. 跟 C 期望的 −1 差在哪？

題目：（承 7-2）改成 movl %edi, %eax 之後得到的值，跟 C 期望的 −1 差在哪？

🔒 已批改，不能再修改
批改

大致對。兩個值都寫對了：movl 得到 0x556677ff，C 期望的 −1 是 movsbl 把 0xff 符號擴展成 0xffffffff。缺的是把差別講出來：多讀的高 3 byte 0x556677 是垃圾，不是 c 的一部分，讀進來就變成一個正的大數（1432778751），不是 −1。「movl 的話高位補 0」是在講 %rax 的高 32 位元被清掉，跟這題比的 %eax 無關。 組語 7 記為大致對（盒子 1 → 1）。

詳細說明：所以參數有多大，指令就讀多大的名字：signed char 讀 %dil、short 讀 %di、int 讀 %edi、long 和指標讀 %rdi。

組語 8-3. 跟 CPU 執行 movl $0xaabbccdd, %edi 有什麼不同？

題目：（承 8-2）gdb 的 set $edi = 0xaabbccdd 跟 CPU 執行 movl $0xaabbccdd, %edi 有什麼不同？

🔒 已批改，不能再修改
批改

不完整。第 1 點對：CPU 執行 movl 會把高 32 位元清成 0。但 gdb 那半說成「直接把設定的值寫進 rdi」，配上 8-2 的「會」，等於認為 gdb 也清高位——兩邊其實相反：清高位是 CPU 執行指令的規則，gdb 的 set 不是指令，不套用，只改低 4 byte（跟 10-08 錯在同一處：把 gdb set 與 CPU movl 說反）。 組語 8 記為錯（盒子 1 → 1）。

組語 9-2. 為什麼這樣補，signed char 的 −1 變成 int 之後才會還是 −1（用二補數的權重解釋）？

🔒 已批改，不能再修改
批改

對。抓到二補數最高位權重是負的（−2³¹），並用權重算出 32 個 1 ＝ −2³¹ ＋ (2³¹ − 1) ＝ −1，所以補 1 才保持 −1（10-08 缺的權重這次補上了）。可以再補一句一般化的理由（見詳細說明）：前面每多補一個 1，值都不變。 組語 9 記為對（盒子 1 → 2）。

參考答案

【第三節〈%dil 是 0xff，為什麼 %eax 變成 0xffffffff：符號擴展補的是第 7 位元〉】

核心關鍵：

  1. 二補數的最高位權重是負的：8 位元 0xff ＝ −2⁷ ＋ (2⁷ − 1) ＝ −1；32 位元 0xffffffff ＝ −2³¹ ＋ (2³¹ − 1) ＝ −1。
  2. 所以高位全補 1，值還是 −1；補 0 的話 0x000000ff ＝ 255，值就變了。

詳細說明：一般化：前面多補一個 1，新的最高位權重是 −2⁸，原本那一位從 −2⁷ 變成 +2⁷，合起來 −2⁸ ＋ 2⁷ ＝ −2⁷，跟原來一樣，值不變；補幾個都同理。對照零擴展 movzbl：一律補 0，用在 unsigned char（0x80 才能保持 128）。

組語 10. 暫存器 vs 記憶體運算元

mov %rdi,%rax 和 mov (%rdi),%rax 只差一對括號。

盒子 1｜過去的作答：s1-04 quiz.md 第 10 題

用到的程式（檔案：paren.c）：

#include <stdio.h>

__attribute__((noinline)) long copy_val(long x)  { return x; }    /* 回傳 x 本身 */
__attribute__((noinline)) long deref(long *p)    { return *p; }   /* 回傳 p 指向的值 */

int main(void)
{
    long v = 1234;
    printf("%ld %ld\n", copy_val(v), deref(&v));

  2. 減法時進位跟借位相反：x86 把加法器的進位反過來存進 CF，所以「沒進位」→ CF ＝ 1（借位了）。

詳細說明：「反過來再加 1」就是 −S（二補數取負），所以 D ＋ (S 反轉) ＋ 1 ＝ D − S。9 ＝ 00001001，反轉是 11110110 ＝ 246。對照 5 − 3：5 ＋ 252 ＋ 1 ＝ 258，有進位 → CF ＝ 0（不用借）。ARM 等架構減法時直接存加法器的進位，CF 的意思剛好相反，讀別的架構時要注意。

大致對（盒子 2 → 2）。「不會成立」與理由都對：本機 char 有號，最大 127，c > 127 永遠為假。改法不對（跟 10-06 卡在同一處）：c <= -1 && c >= -128 等於 c < 0（c >= -128 對有號 char 永遠為真，又是一個死條件），它依賴「char 有號」，換到 ARM（char 通常無號）就永遠為假。正解是改讀法：用 unsigned char，byte 照 0～255 讀，> 127 才在任何平台上都成立。

參考答案

【第四節〈跟第 2 課的連結：char 有號，讀到中文會變負數〉、〈判斷「是不是非 ASCII 的 byte」：用哪個型別、為什麼是 127〉】（2026-10-13 改寫成核心關鍵格式）

核心關鍵：

  1. 不會成立：本機 char 有號（−128～127），UTF-8 的非 ASCII byte 是 0x80～0xff，用 char 讀變成負數，c > 127 永遠為假。
  2. 改成 unsigned char c（或比較時寫 (unsigned char)c > 127），byte 照 0～255 讀，> 127 的意思才正確。

詳細說明：例如 0xe5 用 char 讀是 −27。-Wextra 的 -Wtype-limits 會警告「永遠為假」。不要改成 unsigned int：會先符號擴展成 0xffffffe5，判斷碰巧對、值卻是錯的；也不要寫 c < 0，它依賴 char 有號，換到 ARM 就失效。
