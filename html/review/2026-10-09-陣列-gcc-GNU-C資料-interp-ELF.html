陣列 5. 情境題：當掉的那一行

陣列 5-1. 同事的程式偶爾 segfault，gdb 的 bt 顯示當在 parse() 裡 x = buf[k]; 這一行，k 的值是 523871，而 buf 只有 256 個元素。你接下來要怎麼查出真正的錯誤在哪裡？

盒子 1｜過去的作答：s1-03 quiz.md 5-1

使用frame 一層一層看 k是在什麼時候變得超過256, 需要了解k超過256的原因

批改：對。抓到重點：當掉的這一行不是 k 變錯的地方，要用 frame 一層一層往上找 k 是在哪裡變成 523871 的。

參考答案【第 3 課第六節〈當掉的那一行 ≠ 犯錯的那一行〉】

核心關鍵：

  1. 當掉的那一行只是錯的 k 第一次碰到不能碰的分頁的地方，不是 k 變錯的地方。
  2. 用 bt 看呼叫路徑，frame N 切到每一層、print 看 k 和決定 k 的參數與變數，往回推 523871 是在哪一層、哪一步算出來的。

詳細說明：順便檢查 parse 有沒有拿到 buf 的長度、有沒有檢查 k 的範圍。k 可能在更早之前就已經越界過好幾次，只是那幾次落在還能存取的記憶體裡，沒有當掉。

陣列 5-2. 為什麼不能直接修改這一行就算解決？

過去的作答：s1-03 quiz.md 5-2

因爲之修改這一行只是防止 x=buf[k] segfault,但是k變成523871的根因沒有解決,也就是也有可能其他地方也會出問題

批改：對。抓到重點：只改這一行，k 算錯的根因還在，別的地方一樣會出事。

參考答案【第 3 課第六節〈當掉的那一行 ≠ 犯錯的那一行〉】

核心關鍵：

  1. 在這一行加檢查（或把 k 夾在範圍內）只是把症狀藏起來，算錯 k 的程式還在。
  2. 錯的 k 可能已經寫壞其他資料，之後會在別的地方以更難查的方式出現。

陣列 5-3. 如果想在「第一次越界的當下」就抓到它，要怎麼做？

過去的作答：s1-03 quiz.md 5-3

編譯的時候用-fsanitize=address

批改：對。抓到重點：用 AddressSanitizer（ASan）重新編譯。

參考答案【第 3 課第七節】

核心關鍵：

  1. 用 gcc -g -fsanitize=address 重新編譯再重現，ASan 會在第一次越界讀寫的當下停下來報告。

詳細說明：報告會寫出是讀還是寫、幾個 byte、哪一行、越過了哪個變數。限制：要重新編譯、沒有執行到的程式路徑抓不到、程式會變慢，所以用在開發與測試，不放進正式版本。

陣列 2. 陣列傳進函式之後

陣列 2-1. int a[10]; 在 main 裡 sizeof a 是 40，傳進 void f(int a[]) 之後 sizeof a 變成 8。為什麼？

盒子 1｜過去的作答：s1-03 quiz.md 2-1、10-05 複習

在main , sizeof a 指的是指向 a的整個數組 所以是40byte

在f a之指向a陣列頭的指標,指標大小就是8byte

批改：對。抓到重點：main 裡量的是整個陣列，f 裡的 a 其實是指標。

參考答案【第 3 課第三節〈函式參數寫成 int a[]，其實就是 int *a〉】

核心關鍵：

  1. 在 main 裡，sizeof a 是「陣列名稱不退化成指標」的例外，量的是整個陣列：10 × 4 = 40 byte。
  2. 參數寫成 int a[] 其實就是 int *a，呼叫 f(a) 時傳過去的只是 a[0] 的位址，所以 f 裡的 sizeof a 是指標的大小 8。

詳細說明：gcc 對這種寫法有 -Wsizeof-array-argument 警告。

陣列 2-2. 這件事對「怎麼設計接收陣列的函式」有什麼影響？

過去的作答：s1-03 quiz.md 2-2、10-05 複習

a只代表陣列頭的指標,不知道陣列長度,所以需要給長度參數

批改：對。

參考答案【第 3 課第三節〈函式參數寫成 int a[]，其實就是 int *a〉】

核心關鍵：

  1. 函式拿到的只是位址，不知道陣列有多長，所以長度要另外當參數傳進去（例如 long sum(int *p, int n)）。

詳細說明：呼叫端用 sizeof a / sizeof a[0] 算長度（這時 a 還是陣列）。標準函式庫的 memcpy、read 也是這樣設計的。字串是例外：靠結尾的 \0 判斷在哪裡結束。

陣列 2-3. a 和 &a 印出來的位址一樣，它們差在哪裡？

過去的作答：s1-03 quiz.md 2-3、10-05 複習

a 是陣列退化成指標,a就是一個指向整列頭的指標, a+1 就是位移到第二個元素(4byte)

&a 是代表整個陣列的代表位址, 如果&a + 1, 你的位移是位移整個陣列的大小(40byte)

批改：大致對。步長都對：a + 1 走 4 byte、&a + 1 走 40 byte。但這題問「差在哪裡」，答案是型別，而你這次沒有寫出 &a 的型別。上兩次卡住的正是這裡（10-05 寫成 int *[10]），這次沒寫，看不出是不是已經改正。正確寫法是 int (*)[10]：括號讓 * 先跟名字結合，意思是「指標，指向 10 個 int 組成的陣列」； int *[10] 沒有括號，意思是「10 個 int * 組成的陣列」。

參考答案【第 3 課第三節〈a 和 &a：位址一樣，型別不一樣〉】

核心關鍵：

  1. 位址相同、型別不同。
  2. a 退化成 int *，+ 1 走 4 byte；&a 的型別是 int (*)[10]（指向整個陣列的指標），+ 1 走 40 byte。

詳細說明：宣告這種指標的變數要寫成 int (*p)[10] = &a;。

陣列 3. char s1[] 與 char *s2

陣列 3-1. char s1[] = "hi"; 和 char *s2 = "hi"; 的 "hi" 分別在記憶體的哪裡？

盒子 1｜過去的作答：s1-03 quiz.md 3-1、10-05 複習

s1是區域變數, 存在的是stack裏面, 也就是data裏(記憶體權限分區是rw_p)

而s2 指的 hi是常數,是在rodata裏,也就是r__p權限的分區

批改：大致對。s1 在堆疊、s2 指的 "hi" 在 .rodata（r--p），這兩點對。兩個問題：

  • 「stack 也就是 data 裡」錯：堆疊和 .data 是兩個不同的地方。.data 是執行檔裡的一個區段，放有初始值的全域變數與 static 變數；堆疊是程式執行時才有的那一段（info proc mappings 裡的 [stack]），放區域變數。兩者權限剛好都是 rw-p，所以容易混在一起。
  • 漏了 s1 的關鍵：s1 裡的 "hi" 是複製過來的副本，是 s1 自己的一份；s2 本身只是一個 8 byte 的指標。

參考答案【第 3 課第四節】

核心關鍵：

  1. char s1[] = "hi";：在堆疊上開一個 3 byte 的陣列，把 h、i、\0 複製進去。
  2. char *s2 = "hi";："hi" 本體是字串常數，放在 .rodata；s2 只是指向它的 8 byte 指標（s2 自己在堆疊上）。

陣列 3-2. 為什麼改 s1[0] 沒事，改 s2[0] 卻 segfault？

過去的作答：s1-03 quiz.md 3-2、10-05 複習

因爲s2指向的位址,是不能做寫入的,那邊是rodata,權限r_p

批改：對。抓到重點：.rodata 載入後的分頁是 r--p，不准寫。（s1 那一邊可以寫，你在 3-1 已經寫了它在 rw-p。）

參考答案【第 3 課第四節、第五節開頭的表格】

核心關鍵：

  1. s1 的副本在堆疊上，那一頁是 rw-p，可以寫。
  2. s2 指向 .rodata，分頁權限是 r--p：有對映但不允許寫，CPU 拒絕，核心送出 SIGSEGV。

詳細說明：C 標準只說「修改字串常數是未定義行為」；在本機會 segfault，是因為 gcc 把字串常數放進唯讀分頁。

陣列 3-3. 你會怎麼在 gdb 裡確認 3-2 的答案？

過去的作答：s1-03 quiz.md 3-3、10-05 複習

先用 x s2找出他的位址
在用info proc mappings 找出這個位址的權限
就可以知道s2是否在不正確的位址上,導致寫入segfault

參考答案【第 3 課第四節】

核心關鍵：

  1. 讓程式當在 s2[0] = 'H';，用 print s2 拿到 s2 指向的位址。
  2. 用 info proc mappings 找出那個位址落在哪一段，看那一段的權限是 r--p。

詳細說明：拿來對照的話，print &s1 會落在 [stack]，權限是 rw-p。

gcc：gcc最佳化等級-O0到O3差在哪

gcc 2. 為什麼 -O0 的組合語言每一圈都在讀寫記憶體（-4(%rbp)），而 -O2 不會？這個差別對 gdb 有什麼影響？

盒子 1｜過去的作答：s1-01 quiz.md gcc 第 2 題（2026-09-22 之後暫停到第 4 課教完組合語言，這是放回後第一次考）

題目用到的程式：sumto.c（檔案：sumto.c），用 gcc -O0 -S sumto.c 與 gcc -O2 -S sumto.c 產生組合語言（-S：只編譯到組合語言 .s 就停）。

#include <stdio.h>

int sum_to(int n)
{
    int total = 0;
    for (int i = 1; i <= n; i++)
        total += i;
    return total;
}

int answer(void)
{
    return sum_to(100);
}

int main(void)
{
	printf("answer:%d\n", answer());
	return 0;
}

-O0 的 sum_to（本機 gcc 13.3 實際輸出，刪掉 .cfi、.type 這類組譯指示，右邊是逐行說明）：

sum_to:
	endbr64                    # 間接跳躍的保護標記（CET），跟這題無關
	pushq	%rbp               # 存起呼叫者的 %rbp
	movq	%rsp, %rbp         # %rbp = 這個函式的堆疊框底
	movl	%edi, -20(%rbp)    # 參數 n（放在 %edi 傳進來）寫到記憶體 -20(%rbp)
	movl	$0, -8(%rbp)       # total = 0，寫到記憶體 -8(%rbp)
	movl	$1, -4(%rbp)       # i = 1，寫到記憶體 -4(%rbp)
	jmp	.L2                # 先跳去檢查條件
.L3:                               # 迴圈本體
	movl	-4(%rbp), %eax     # 從記憶體讀 i 到 %eax
	addl	%eax, -8(%rbp)     # 記憶體裡的 total += %eax
	addl	$1, -4(%rbp)       # 記憶體裡的 i += 1
.L2:                               # 迴圈條件
	movl	-4(%rbp), %eax     # 從記憶體讀 i
	cmpl	-20(%rbp), %eax    # 比較 i 與記憶體裡的 n（算 i − n、設旗標）
	jle	.L3                # i <= n（有號）就回去跑本體
	movl	-8(%rbp), %eax     # 從記憶體讀 total 當回傳值
	popq	%rbp               # 還原 %rbp
	ret

-O2 的 sum_to（同上，實際輸出）：

sum_to:
	endbr64
	testl	%edi, %edi         # n & n，只為了設旗標
	jle	.L4                # n <= 0 就跳去回傳 0
	leal	1(%rdi), %ecx      # %ecx = n + 1（迴圈的終點）
	xorl	%edx, %edx         # %edx = 0（total）
	andl	$1, %edi           # %edi = n & 1（n 是奇數還是偶數）
	movl	$1, %eax           # %eax = 1（i）
	je	.L3                # n 是偶數就直接進迴圈
	movl	$2, %eax           # n 是奇數：先處理掉 i = 1，i 從 2 開始
	movl	$1, %edx           #           total = 1
	cmpl	%ecx, %eax         #           i 已經到 n + 1 了嗎（n = 1 時）
	je	.L1
.L3:                               # 迴圈本體：一圈加兩個數
	leal	1(%rdx,%rax,2), %edx  # total = total + 2×i + 1（＝ total + i + (i+1)）
	addl	$2, %eax           # i += 2
	cmpl	%ecx, %eax         # i 到 n + 1 了嗎
	jne	.L3
.L1:
	movl	%edx, %eax         # 回傳 total
	ret
.L4:
	xorl	%edx, %edx
	movl	%edx, %eax         # 回傳 0
	ret

-O2 計數的判斷交由andl $1,%edi來做
兩者實現不同

一個計數用記憶體記, O2用的是指令 搭配寄存器

O2無法打印i,有可能產生optimization out, 如果值是存在寄存器

批改：大致對（這是第一次正式作答：09-22 那次是因為組合語言還沒教，不算分）。抓到：-O0 把 i 放在記憶體 -4(%rbp)，-O2 放在暫存器；-O2 下 gdb 可能印不出 i（<optimized out>）。兩個問題：

  • 沒講「為什麼」：-O0 是不做最佳化、照字面翻譯。每個變數都分到一個固定的堆疊位置，每一條語句都「從記憶體讀出來 → 算 → 寫回記憶體」，下一條語句也不假設暫存器裡還留著上一次的值。所以每一圈都在讀寫 -4(%rbp)。-O2 會做暫存器配置，整個迴圈都把 i、total 留在暫存器裡。
  • 「-O2 計數的判斷交由 andl $1,%edi 來做」錯：andl $1, %edi 算的是 n & 1，用來判斷 n 是奇數還是偶數（奇數就先把 i = 1 加掉，迴圈才能一圈加兩個數），而且只在進迴圈前做一次。計數器 i 在 %eax（每圈 addl $2, %eax），終點 n + 1 在 %ecx，每圈用 cmpl %ecx, %eax 判斷要不要繼續。見第 4 課第七節〈先找出「誰是誰」〉。

參考答案【gcc 最佳化第二節、第三節；組合語言見第 4 課第六節、第七節】

核心關鍵：

  1. -O0 不最佳化、照字面翻譯：每個變數都有固定的記憶體位置（i 是 -4(%rbp)、total 是 -8(%rbp)），每條語句都從記憶體讀、再寫回記憶體。
  2. -O2 把變數留在暫存器（i 在 %eax、total 在 %edx），迴圈裡完全不碰記憶體。
  3. 對 gdb 的影響：-O0 原始碼的每一行都對得到一段指令，變數隨時印得出來；-O2 行號會跳、指令被重排，變數可能顯示 <optimized out>。

詳細說明：筆記第三節的實測中，-O2 版停下來時跳過了第 3 行；只走兩行，total 就已經是 3；被內嵌進 main 的那一份，變數全是 <optimized out>；中斷點顯示 (2 locations)（獨立的 sum_to 一份、內嵌進 main 一份）。所以學習、單步除錯用 -O0 -g，日常開發用 -Og -g。

long 比unsigned int還高, 所以將unsigned int 轉成 long b 直接高位補0,故 a<b true

int 轉unsigned long 高位以符號位補位, -1 符號位爲1 補1, 所以 c < d false

核心關鍵：

  1. a < b 為真：long 裝得下所有 unsigned int 的值 → 兩邊轉成 long，值不變，−1 < 1。

詳細說明：有號轉無號不是 UB，C 標準規定得很清楚：位元不變，換成無號的讀法（第 2 課第六節）。UB 是有號溢位。

ELF 5. 情境題：你把 Ubuntu（x86-64）上編好的程式複製到路由器（ARM），file 顯示它是 ELF，執行卻失敗。這跟 interpreter 那篇 第五節「interpreter 不存在」是不是同一種問題？從檔頭的哪一欄可以看出來？

如果是動態編譯的程式

批改：錯（盒子 3 → 1；09-29 那次答對過）。不是同一種問題。

  • 架構不符時，kernel 在 execve 讀檔頭（ELF header）時，就發現 Machine 欄位跟 CPU 不符，根本還沒走到「找 interpreter」那一步，回報 ENOEXEC（Exec format error）。interpreter 不存在則是 ENOENT（not found）。兩種錯誤的訊息不同。

  1. 不是同一種問題：ELF 格式在哪台機器都讀得懂，但裡面的機器碼是給特定 CPU 的。
  2. 看檔頭的 Machine 欄位（readelf -h），它寫著 Advanced Micro Devices X86-64。kernel 在 execve 發現跟 CPU 不符，回 ENOEXEC（Exec format error）；interpreter 不存在則是 ENOENT（not found）。
