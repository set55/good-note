對（盒子 2 → 3）。三個核心關鍵都有：連結時 ld 把版本寫進執行檔（10-23、10-26 都缺這點，這次主動寫出來了）、執行時載入器在這台機器找不到那個版本就報錯、-static 不會發生。小修（不扣分）：(1)「本機沒有這個版本的庫」說得不精確，libc.so.6 是找得到的，缺的是它沒提供執行檔要的版本符號（例如 GLIBC_2.34），跟 10-26 的小修同一處；(2) 連結時 ld 對 libc 的符號不是「重定位」，而是記下「這個符號要從 libc.so.6 的哪個版本拿」，真正的填位址是執行時載入器做的；(3) -static 打包進去的是用到的 libc.a 裡的那些 .o，不是「整個程式碼」。

參考答案

【第九節〈自我測驗第 5 題延伸：「找不到版本符號」是怎麼回事〉】

核心關鍵：

  1. 連結時：ld 把需要的符號版本（例如 GLIBC_2.34）寫進執行檔。
  2. 執行時：動態載入器檢查目標機器的 libc.so.6 有沒有提供這個版本，沒有就報 version `GLIBC_2.34' not found。
  3. -static 不會發生：libc 的程式碼已經整份複製進執行檔，不再找外部的 libc.so.6。

詳細說明：readelf -V hello 看得到版本需求；真正的門檻是 2.34（__libc_start_main），不是 puts 的 2.2.5。-static 的代價是檔案大，而且 libc 的安全修補要重新編譯才會帶進去。

作答（🔒 已批改）

批改

對（盒子 2 → 3）。抓到：修改後要散布才有義務（「若要發佈」也隱含了只自己用沒有義務）、散布時要用同樣的 GPL 並公開原始碼（10-26 缺的「同樣授權」這次寫了）；連結 LGPL 的 glibc 散布時不必公開，GPL 的庫就要。

參考答案

【第五節】

核心關鍵：

  1. copyleft：可以自由使用、修改、散布，但散布修改後（或以它為基礎）的版本時，必須用同樣的授權（GPL）並提供原始碼。
  2. 只是使用、或改了自己用、不給別人，沒有義務。
  3. glibc 用 LGPL：允許非自由的程式連結它而不必開放自己的原始碼，所以商業軟體都能連結 libc.so.6；如果 glibc 是 GPL，連結它的程式在散布時就得整個用 GPL 開放。

詳細說明：copyleft 的目的是讓「自由不能在傳遞途中被拿走」。例子：公司內部改了 GPL 的工具自己用，不必公開；把改過的版本賣給客戶，就要給客戶原始碼，並讓客戶同樣能以 GPL 再散布。

參考答案

【第三節】

核心關鍵：

  1. ldd 讓動態載入器實際處理這支程式：載入器照常找、載入全部依賴（含間接依賴），在進 main 前停下來印清單。
  2. 風險：ldd 要讓載入器真的去處理這個檔案。有些版本的 ldd（上游 glibc 2.27 以前）直接執行程式，這時載入器由檔案的 INTERP 決定，攻擊者可以寫成自己的程式，跑 ldd 就執行了它；你不一定知道眼前的 ldd 是哪一種。
  3. objdump -p 只讀檔案裡的 NEEDED，不啟動任何東西。

詳細說明：grep -n LD_TRACE /usr/bin/ldd 可以看到腳本裡的 LD_TRACE_LOADED_OBJECTS=1；本機的 ldd 等於執行 LD_TRACE_LOADED_OBJECTS=1 /lib64/ld-linux-x86-64.so.2 ./程式，所以 INTERP 指向不存在的檔案時 ldd 照樣列得出來（第三節的 hello_badinterp 實驗）。對來路不明的檔案要看依賴，用 objdump -p 或 readelf -d。

【第四節、第二節】

核心關鍵：

作答（🔒 已批改）

對（陣列 2 整題 盒子 2 → 3）。兩個核心關鍵都有：a 是指向 int 的指標、&a 是指向整個陣列的 int (*)[10]；a + 1 走 4 byte、&a + 1 走 40 byte。而且這次把 &a 正確說成「不退化的特例」，10-23、10-26 兩次的混淆改過來了。小修（不扣分）：a + 1 = a[1] 寫錯一個符號——a + 1 是位址，等於 &a[1]；*(a + 1) 才是 a[1]（10-26 你寫的 *(a + 1) = a[1] 是對的）。

參考答案

【第三節〈a 和 &a：位址一樣，型別不一樣〉】

核心關鍵：

  1. 位址相同，但指的東西不同：a 退化成指向第一個元素（int）的指標，&a 是指向整個陣列的指標。
  2. 所以 a + 1 走 4 byte（一個 int），&a + 1 走 40 byte（一整個陣列）。

詳細說明：用型別的話說，a 是 int *，&a 是 int (*)[10]。記法：退化 ＝ 變成指向第一個元素的指標；sizeof、& 是兩個不退化的例外。

組語 6-1. movsbl 的 l 叫 long，為什麼是 4 byte，而本機 C 的 long 是 8 byte？

作答（🔒 已批改）
🔒 已批改，不能再修改
批改

對。抓到：組合語言的 l 是歷史命名、為了相容沿用；C 的 long 由平台決定，本機 LP64 是 8 byte。要改的筆誤：C 標準要求 long 至少 32 位元（bit）＝ 4 byte，不是「32 byte」——寫成 byte 的話，8 byte 的 long 反而不合標準了。

參考答案

【第三節〈為什麼 l 叫 long 卻是 4 byte〉】

核心關鍵：

  1. 組合語言的 b／w／l／q 是 x86 的歷史命名：8086 是 16 位元，word ＝ 2 byte；32 位元叫 long（兩個 word）＝ 4 byte；為了相容，名字一直沒改。
  2. C 的 long 大小由平台決定（標準只要求至少 32 位元），本機 x86-64 Linux 是 LP64，long ＝ 8 byte。兩者只是剛好同名。

組語 12. 檔案裡的位址 vs 執行時的位址

用 objdump -d paren 查到 deref+4 在 0x11f4，break *0x11f4 之後 run 卻得到 Cannot access memory at address 0x11f4，break *deref+4 就沒問題。

盒子 2｜過去的作答：s1-04 quiz.md 第 12 題、10-13 複習、10-22 複習、10-23 複習、10-26 複習

用到的程式（檔案：paren.c）：

#include <stdio.h>

__attribute__((noinline)) long copy_val(long x)  { return x; }    /* 回傳 x 本身 */
__attribute__((noinline)) long deref(long *p)    { return *p; }   /* 回傳 p 指向的值 */

int main(void)
{
    long v = 1234;
    printf("%ld %ld\n", copy_val(v), deref(&v));
    return 0;
}

-O2 編出的 deref：

deref:
	endbr64                 # 控制流程保護標記（佔 4 byte，所以下一條是 deref+4）
	mov	(%rdi),%rax         # 把 %rdi 當位址，讀 8 byte 放進 %rax
	ret                     # 回傳 %rax

實驗步驟：

gcc -O2 -g paren.c -o paren
objdump -d --no-show-raw-insn paren        # deref 的 mov (%rdi),%rax 那一行印成 11f4
gdb -batch -ex 'break *0x11f4' -ex 'break *deref+4' -ex 'info breakpoints' -ex run -ex 'info breakpoints' ./paren

組語 12-1. 為什麼？

題目：break *0x11f4 之後 run 得到 Cannot access memory at address 0x11f4，break *deref+4 卻沒問題，為什麼？

作答（🔒 已批改）
🔒 已批改，不能再修改
批改

對。兩個核心關鍵都有：執行時位址 ＝ 基底 ＋ 0x11f4，所以寫死的 0x11f4 失敗；*deref+4 有符號，gdb 會用 deref 當時的位址去算（10-13、10-22、10-26 缺的這點這次寫了）。小修兩處（不扣分）：(1) 搬家的原因是 PIE，不是 ASLR——gdb 預設關掉 ASLR，基底固定是 0x555555554000，照樣失敗；ASLR 只是讓每次的基底不同。(2) 不是「interpreter 把符號重定位」：gdb 自己讀執行檔的符號表（deref 在檔案裡是 0x11f0），程式載入後知道基底，就把符號位址加上基底；載入器（ld.so）重定位的是程式裡的 .got 這些洞，不是 gdb 用的符號。

參考答案

【第三節〈上面中斷點 4 的 break *0x11f4：為什麼 run 之後失敗？〉】

核心關鍵：

  1. objdump -d 印的是檔案裡的位址；PIE 執行時整支被搬到基底（gdb 裡是 0x555555554000），執行時位址 ＝ 基底 ＋ 檔案位址，0x11f4 在執行時沒有對映。
  2. *deref+4 裡有符號名稱，程式載入後 gdb 用新的位址重算成 0x5555555551f4；寫死的 0x11f4 只是數字，不會重算。
