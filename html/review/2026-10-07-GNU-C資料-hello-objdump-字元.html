不完整（盒子 2 → 1）。「出問題時找得到責任歸屬」方向對，但有三處錯或缺：(1) 名字是 DCO（Developer Certificate of Origin，開發者原創聲明），不是 DOR；(2) 它負責的不是「程式出 bug 找誰」，而是著作權與授權：聲明「這段是我寫的，或我有權用 GPL-2.0 貢獻它」，kernel 才能合法地整包以 GPL-2.0 散布；(3)「GPL 規定發布時必須署名」不對——Signed-off-by: 是 kernel 社群的規定，GPL 條文本身沒有這個要求。

參考答案

【第五節】Signed-off-by: 是 DCO：加上這一行，就是聲明這段程式碼是你自己寫的，或你有權以這個專案的授權（kernel 是 GPL-2.0）貢獻它。Linux 核心以 GPL-2.0 散布，每段合併進去的程式碼都必須能合法地以 GPL-2.0 散布；DCO 讓每個 patch 都有人為此負責，出了著作權爭議時查得到是誰聲明的。它是 kernel 社群的規定，不是 GPL 條文本身的要求。

C資料 4. int y = x + 1; return y > x; 在 x = INT_MAX 時，-O0 回傳 0、-O2 回傳 1。為什麼會這樣？這算不算 gcc 的 bug？kernel 用哪個選項避免這種情況，代價是什麼？

🔒 已批改，不能再修改
批改

不完整（盒子 2 → 1）。-O0 對、「不算 bug」對。兩處問題：(1) -O2 的推理說反了：不是「gcc 不能確定會不會溢位」，而是正因為有號溢位是 UB，C 標準允許 gcc 假設它一定不會發生；在這個假設下 x + 1 > x 永遠成立，直接回傳 1。(2) 選項沒說出名字：kernel 用 -fno-strict-overflow（等於 -fwrapv -fwrapv-pointer），讓溢位照二補數回繞、變成有定義的行為。代價「少了一些最佳化、可能稍慢」你答到了。

參考答案

【第八節】有號溢位是未定義行為（UB），C 標準允許編譯器假設它不會發生。-O0 照字面算，INT_MAX + 1 回繞成 INT_MIN，y > x 為假 → 0；-O2 推論「x + 1 一定大於 x」，直接回傳 1。不是 gcc 的 bug：標準對發生 UB 的程式沒有任何要求，兩種結果都合法。kernel 用 -fno-strict-overflow（等於 -fwrapv -fwrapv-pointer），讓溢位照二補數回繞、變成有定義的行為；代價是編譯器少了依賴「不會溢位」這個假設的最佳化，程式可能稍慢。

參考答案

【第一節】本機實際接力的是 cc1（前處理＋編譯，C → 組合語言）→ as（組合語言 → 機器碼的 .o，還有洞、不能執行）→ collect2 呼叫 ld（連結成執行檔）。gcc 自己不做任何轉換，只負責依序呼叫它們、在中間傳遞暫存檔，所以叫總指揮（driver）；gcc -v 看得到它實際執行的每個命令。
