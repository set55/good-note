怎麼把檔案內容複製到剪貼簿？

日期：2026-09-21
情境：想把檔案內容直接送進剪貼簿，方便貼到別的地方，不想用滑鼠選取整個終端機畫面
適用範圍：實測 Ubuntu 24.04、X11 工作階段（XDG_SESSION_TYPE=x11）、 xclip 0.13、xsel 1.2.1、tmux 3.4；Wayland 與 SSH 情境另列
相關：PTY是什麼-終端機模擬器與虛擬終端、 輸出重新導向與dev-null

一句話結論：X11 上用 xclip -selection clipboard -in <檔案>（或 xsel -b -i < 檔案）。但先搞懂一件事——X11 有三個獨立的「剪貼簿」，預設操作的不是 Ctrl+V 那個，這是九成的人第一次用會失敗的原因。

一、先看你的工作階段是 X11 還是 Wayland

工具選錯就完全不會動，所以第一步是確認：

$ echo $XDG_SESSION_TYPE
x11                        # ← 本機是這個

# 或者更可靠（環境變數可能沒設）
$ loginctl show-session $(loginctl | awk '/'$USER'/{print $1; exit}') -p Type
Type=x11
工作階段 工具
X11 xclip 或 xsel
Wayland wl-copy / wl-paste（套件 wl-clipboard）
SSH／無圖形介面 OSC 52 跳脫序列，見第六節

本機兩個 X11 工具都有裝；wl-copy 沒有（因為用不到）。

二、X11 的三個選區（selection）

這是最關鍵的概念。X11 沒有「一個剪貼簿」，而是三個互不相干的選區：

選區 什麼時候寫入 怎麼貼出來
PRIMARY 用滑鼠選取文字時自動寫入（不用按任何鍵） 滑鼠中鍵
CLIPBOARD 按 Ctrl+C／選單「複製」時寫入 Ctrl+V
SECONDARY 幾乎沒人用 —

xclip 與 xsel 的預設選區都是 PRIMARY，所以：

xclip file.txt              # 寫進 PRIMARY → 按 Ctrl+V 貼不出來！
xclip -selection clipboard file.txt   # 寫進 CLIPBOARD → Ctrl+V 可以貼

這就是「明明執行了卻貼不出來」的標準原因。 要 Ctrl+V 貼得到，就一定要指定 clipboard。

三、xclip：完整選項

xclip [選項] [檔案]...
選項 作用
-i、-in 從標準輸入或檔案讀進選區（預設行為）
-o、-out 把選區印到標準輸出（通常接管線或導向檔案）
-selection <選區> primary（預設）／secondary／clipboard／buffer-cut
-l、-loops <n> 結束前要服務幾次貼上請求（見下方「為什麼會停留在背景」）
-d、-display <顯示器> 連到哪個 X display（例如 localhost:0）
-target <atom> 指定目標 atom（貼圖片等非純文字時用，例如 image/png）
-rmlastnl 去掉結尾的換行字元 ← 複製單行值時很有用
-noutf8 不當成 UTF-8，用舊式 unicode
-silent 只報錯誤，在背景執行（預設）
-quiet 在前景執行並顯示動作
-verbose 詳細說明
-h、-help / -version 說明／版本

常用寫法

xclip -selection clipboard -in file.txt      # 檔案 → 剪貼簿
xclip -selection clipboard < file.txt        # 等價（用重新導向）
cat file.txt | xclip -selection clipboard    # 等價（多一個行程，沒必要）

xclip -selection clipboard -out > out.txt    # 剪貼簿 → 檔案
xclip -selection clipboard -out              # 剪貼簿 → 螢幕

# 複製單一值時去掉尾端換行（貼進表單不會多一行）
printf '%s' "$(cat id.txt)" | xclip -selection clipboard
xclip -selection clipboard -rmlastnl -in id.txt      # 或用這個選項

# 複製圖片
xclip -selection clipboard -target image/png -in shot.png

建議設成 alias（-sel c 是 -selection clipboard 的合法縮寫）：

alias cbcopy='xclip -selection clipboard'
alias cbpaste='xclip -selection clipboard -out'

為什麼 xclip 執行完還留在背景？

X11 的選區內容不是存在系統某處，而是「由擁有它的那個行程保管」—— 別人要貼上時，X server 會去跟擁有者要。所以 xclip 寫完之後必須繼續活著，否則剪貼簿內容就消失了。這就是它預設 -silent（背景執行）的原因。

-loops <n> 就是「服務 n 次貼上請求之後就可以死了」。預設 0＝永遠留著。

副作用：關掉終端機或該 xclip 行程被殺，剪貼簿就空了。 GNOME 等桌面環境通常有 clipboard manager 會接手保存，但不是所有環境都有。

四、xsel：完整選項

xsel [選項]

輸入

選項 作用
-i、--input 讀標準輸入進選區
-a、--append 附加到選區而不是取代
-f、--follow 持續附加（輸入增長時跟著加，像 tail -f）
-z、--zeroflush 收到 \0 時覆寫選區

輸出

選項 作用
-o、--output 把選區寫到標準輸出

動作

選項 作用
-c、--clear 清空選區
-d、--delete 要求清空，並請擁有者刪除內容

選區

選項 作用
-p、--primary PRIMARY（預設）
-s、--secondary SECONDARY
-b、--clipboard CLIPBOARD ← Ctrl+V 要的那個
-k、--keep 不改內容，但讓 PRIMARY／SECONDARY 在來源程式結束後仍保留
-x、--exchange 交換 PRIMARY 與 SECONDARY

X 與其他

選項 作用
--display <顯示器> 指定 X server 連線
-m、--name <wm> 行程識別名稱
-t、--selectionTimeout <毫秒> 取得選區的逾時（0＝不逾時，預設）
--trim 去掉輸入／輸出結尾的換行
-l、--logfile <檔> detach 後的錯誤記錄檔
-n、--nodetach 不要 fork 到背景（預設會 fork）

常用寫法

xsel -b -i < file.txt        # 檔案 → 剪貼簿
xsel -b -o > out.txt         # 剪貼簿 → 檔案
xsel -b -o                   # 剪貼簿 → 螢幕
xsel -b -c                   # 清空剪貼簿

xclip 與 xsel 怎麼選

xclip xsel
直接吃檔名 ✅ xclip file.txt ❌ 只能用重新導向
附加模式 ❌ ✅ -a／-f
非文字 target（圖片） ✅ -target ❌
去尾端換行 -rmlastnl --trim
選區預設 PRIMARY PRIMARY

兩個都能用就挑順手的；要貼圖片或指定 MIME 型別只能用 xclip，要「持續附加」只能用 xsel。

五、Wayland：wl-copy / wl-paste

本機沒裝（X11 用不到），但換到 Wayland 就得改用它：

sudo apt install wl-clipboard

wl-copy < file.txt                 # 檔案 → 剪貼簿
wl-copy --primary < file.txt       # 寫進 PRIMARY
wl-paste > out.txt                 # 剪貼簿 → 檔案
wl-paste -n                        # 不補尾端換行
wl-copy --clear                    # 清空
wl-copy --type image/png < a.png   # 指定型別

Wayland 的預設剛好相反：wl-copy 預設寫 CLIPBOARD，要 PRIMARY 才要加 --primary。 比 X11 直覺。

六、SSH 或純終端機：OSC 52

前面那些都需要圖形介面。你 SSH 進 OpenWrt 時，路由器上根本沒有 X server， xclip 也不會裝。這時可以用 OSC 52——一個讓終端機模擬器代為寫入剪貼簿的跳脫序列。

原理：程式印出一段特殊字元，你本機的終端機（alacritty 等）認得它，就把內容放進你本機的剪貼簿。因為是走終端機輸出，所以穿得過 SSH。

# 把檔案內容送進本機剪貼簿（在遠端主機上執行）
printf '\033]52;c;%s\a' "$(base64 -w0 < file.txt)"

寫成函式方便用：

osc52() { printf '\033]52;c;%s\a' "$(base64 -w0 "${1:-/dev/stdin}")"; }
osc52 file.txt
cat file.txt | osc52

三個限制：

  1. 終端機必須支援且允許。alacritty 預設支援；有些終端機要開設定（安全考量—— 遠端主機能寫你的剪貼簿本來就有風險）。
  2. 有長度上限，各終端機不同（常見數十 KB），大檔案會被截斷。
  3. 在 tmux 裡要另外開：tmux 預設會攔掉。需要 set -g set-clipboard on（tmux 2.6+），並確認外層終端機也支援。

我沒辦法在這裡替你驗證 OSC 52——我執行指令時 stdout 是管線，跳脫序列到不了你的終端機。 你自己在互動式終端機裡跑一次上面那行，然後按 Ctrl+V 看看就知道你的終端機支不支援。

七、tmux 自己的緩衝區

tmux 有獨立於系統剪貼簿的緩衝區，常被搞混：

tmux load-buffer file.txt            # 檔案 → tmux 緩衝區
tmux save-buffer out.txt             # tmux 緩衝區 → 檔案
tmux show-buffer                     # 印出內容
tmux list-buffers                    # 列出所有緩衝區
tmux set-buffer "文字"                # 直接設定內容

# 讓 tmux 緩衝區與系統剪貼簿互通
tmux show-buffer | xclip -selection clipboard
tmux load-buffer <(xclip -selection clipboard -o)

在 tmux 裡按 Prefix + ] 貼的是 tmux 緩衝區，不是系統剪貼簿—— 這兩者預設不同步，除非你設定 set -g set-clipboard on 並讓終端機支援 OSC 52。

八、速查

# X11（本機）
xclip -selection clipboard -in  file.txt     # 檔案 → 剪貼簿
xclip -selection clipboard -out              # 剪貼簿 → 螢幕
xsel  -b -i < file.txt                       # 同上（xsel 版）
xsel  -b -o

# Wayland
wl-copy < file.txt ; wl-paste

# SSH／遠端（靠終端機）
printf '\033]52;c;%s\a' "$(base64 -w0 < file.txt)"

# tmux 緩衝區（≠ 系統剪貼簿）
tmux load-buffer file.txt ; tmux show-buffer

# 建議的 alias
alias cbcopy='xclip -selection clipboard'
alias cbpaste='xclip -selection clipboard -out'

自我測驗

  1. 你執行了 xclip file.txt，接著在瀏覽器按 Ctrl+V 卻什麼都沒貼出來。為什麼？要怎麼改？
  2. X11 的選區內容「存在哪裡」？為什麼 xclip 執行完之後還會留在背景不結束？這個設計會造成什麼副作用？
  3. 你 SSH 到一台沒有圖形介面的機器，想把上面某個檔案的內容複製到你本機的剪貼簿。 xclip 不能用，還有什麼辦法？它為什麼穿得過 SSH？
  4. 在 tmux 裡按 Prefix + ] 貼出來的內容，和你按 Ctrl+V 貼出來的，是同一份東西嗎？為什麼？
  5. 情境題：你要把一個 API token 複製到網頁表單，但貼上後發現多了一個換行導致驗證失敗。用 xclip 和 xsel 各有一個選項可以解決，分別是什麼？還有什麼不靠選項的寫法？
