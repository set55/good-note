查詢 Linux 的轉發表（forwarding table）

Linux 沒有獨立叫「forwarding table」的指令，實務上查的就是核心的路由表（routing table）——核心會根據這張表決定封包怎麼轉發。

ip route / ip rule 的完整動詞、參數與全域選項見 ip-rule與ip-route完整指南，本篇只列查詢路由表會用到的。

常用指令

# IPv4 路由/轉發表（最常用）
ip route show

# 查特定目的 IP 實際會走哪條路由（最推薦拿來驗證）
ip route get <目的IP>

# IPv6
ip -6 route show

# 傳統舊指令（等同 ip route，較舊系統/腳本常見）
route -n
netstat -rn

# 核心是否開啟 IP forwarding（轉發功能本身開關）
cat /proc/sys/net/ipv4/ip_forward
sysctl net.ipv4.ip_forward

# ARP（Address Resolution Protocol，位址解析協定）/ 鄰居表（L2，OSI 模型第二層／資料鏈結層 對應，MAC（Media Access Control，網卡實體位址）↔ IP）
ip neigh show

# 有多張路由表時（policy-based routing）
ip route show table all
ip rule show

輸出範例與欄位說明

default via 192.168.1.1 dev eth0 proto dhcp metric 100
192.168.1.0/24 dev eth0 proto kernel scope link src 192.168.1.50 metric 100
10.0.0.0/8 via 192.168.1.254 dev eth0 metric 200
169.254.0.0/16 dev eth0 scope link metric 1000
欄位 意義
default 或 192.168.1.0/24 目的網段。default = 0.0.0.0/0，其他路由都不符合時的最後選擇
via 192.168.1.1 下一跳（next hop）IP，封包先送到這台設備
dev eth0 從哪個網卡送出
proto dhcp / proto kernel / proto static 這條路由的來源（DHCP，Dynamic Host Configuration Protocol，動態主機設定協定，自動配、核心自動產生、手動設定）
scope link 同網段可直接到達，不需要 gateway
src 192.168.1.50 從這條路由送封包時使用的來源 IP
metric 100 優先度，數字越小優先權越高

src 欄位詳解：來源 IP 是怎麼決定的

src 只影響這台主機自己發起的封包，代表核心會在 IP header 的 source address 欄位填上這個值——前提是應用程式（socket）沒有自己指定要用哪個來源 IP。

  • 只管本機發起的封包，不管轉發的封包：如果這台機器只是路由器/閘道，幫別人轉發封包，封包的來源 IP 是原始發送者的，不會被改成這個 src（除非有設定 NAT/SNAT，Network Address Translation／Source NAT，網路位址轉換／來源位址轉換）。只有本機自己發起連線（例如在這台機器上 curl、ping）時，才會用這個 src 當來源 IP。
  • 是「該路由的預設來源 IP」，可以被 app 覆蓋：如果程式用 bind() 明確指定了來源 IP，就用程式指定的；沒指定時，核心才會照路由表選這個網段對應的 src 當預設值。
  • 為什麼需要指定：常見於一張網卡有多個 IP、或多網卡多路由的情況，核心需要知道「走這條路由時該用哪個 IP 自報家門」。

驗證方式一樣是 ip route get，輸出裡的 src 就是核心實際會用的來源 IP：

ip route get 8.8.8.8

判斷邏輯

  1. 最長前綴匹配（longest prefix match）：核心拿目的 IP 比對所有路由的網段（CIDR，Classless Inter-Domain Routing，無類別網域間路由，即 /24 這種網段表示法），選前綴最精確的一條。
  2. metric 決勝負：若有多條前綴長度相同的路由，比較 metric，數字小的優先。

實用技巧

不用自己比對整張表，直接問核心「這個目的地會走哪條路由」：

ip route get 8.8.8.8

會直接回傳實際會用到的介面、下一跳、來源 IP，最適合用來驗證設定是否如預期生效。

總結

  • Linux 上的「forwarding table」= ip route show 看到的路由表。
  • 想知道特定目的地實際走哪條路，用 ip route get 而不是自己肉眼比對。
  • ip_forward 是「這台機器要不要幫忙轉發」的開關，跟路由表本身是兩回事，別搞混。
