## 一、40 歲太慢嗎

**就這個領域來說不慢**，有三個理由：

- **系統程式靠累積，不靠年輕的反應速度。** 記憶體、行程、連結、ELF（Executable and Linkable Format，可執行與可連結格式）、
  系統呼叫（syscall）這些東西幾十年來變動很小，現在學的 `argv`、`errno`、短讀短寫、GOT（Global Offset Table，全域偏移表）／PLT（Procedure Linkage Table，程序連結表），
  10 年後照樣用得到。前端框架三年換一輪，這一行沒有這種折舊問題。
- **kernel 社群裡 40、50 歲的人很多。** 維護者普遍不年輕，社群反而擔心維護者老化、接班的人不夠。沒有人看年齡，只看 patch 與審查（review）的品質。
- **不是從零開始。** 已經有 Go、Docker、K8s、網路排查（nftables、TPROXY）的實務經驗；很多年輕人懂 C 但沒碰過真實的線上系統，兩邊都有的人不多。

但要老實講：**臺灣的求職市場確實有年齡偏見**，尤其是「資淺職位找 40 歲的人」這種組合很難。
所以策略不能是「學完課程，再以新人身分應徵 kernel 工程師」。

**精進有沒有用，取決於能不能把它變成別人看得到的成果**（第七節）。不用等成為維護者才有價值：
學到第 ② 站、第 ③ 站時，能用 `strace`、`perf` 查出別人查不出來的問題，這就是 40 歲在職場上最有說服力的東西——**資深加上有深度**，
而不是跟年輕人比便宜、比加班。

## 二、三個方向：A、B、C

把「長期目標」和「中途就能換到錢的目標」分開：

| | 長期目標 | 中途就能換到錢的目標 |
|---|---|---|
| 內容 | kernel 維護者 | 懂底層的工程師（下表 A、B、C） |
| 現實 | 好幾年持續貢獻；多數維護者是**先貢獻、累積名聲，才被** Red Hat、SUSE、Google、Intel、Arm 這類公司雇用，很少是直接應徵進去的 | 市場一直缺人 |

中途的目標依「這一年學得到」加上「原本就有的經驗」排出三個方向，越上面越容易達成：

| 方向 | 職位例子 | 為什麼適合 | 要拿出什麼 |
|---|---|---|---|
| **A. 懂底層的基礎設施工程師** | SRE（Site Reliability Engineering，網站可靠性工程）、平台工程、DevOps、雲端基礎設施 | 已有 Go、Docker、K8s、nftables 經驗，加上底層能力就有差異化 | 用 `strace`、`perf`、`/proc` 排查的實戰紀錄；懂命名空間（namespace）／cgroup（control group，控制群組） |
| **B. 系統程式／後端（C 或 Go）** | 儲存、網路設備、高效能服務 | 路線第 ②～⑥ 站的專案就是作品 | 迷你 shell、`malloc`、`epoll` 伺服器 |
| **C. 嵌入式 Linux／BSP／驅動** | BSP（Board Support Package，板級支援套件）工程師、Linux Driver 工程師、嵌入式軟體工程師、韌體工程師（Linux） | 最接近 kernel 的有薪職位：進去等於公司付錢讓你碰 kernel | 自己編 kernel、寫核心模組（kernel module）、跑在真實板子上的驅動、至少一個被合進主線的 patch |

## 三、目標是臺灣大公司：主攻 C、A 當備案

1. **臺灣的大型科技公司以硬體為主，Linux 底層的職缺集中在 C。** IC 設計、網通、伺服器、工業電腦的產品裡跑的都是 Linux，
   需要有人寫驅動、移植 kernel、處理開機、修跟硬體有關的 bug。
2. **A 類職缺在臺灣大多不在上市硬體公司。** SRE、平台工程多在網路服務公司和外商的雲端團隊；上市硬體公司也有，
   但多半是內部 IT 或雲端部門，數量少，看重的是 K8s／雲端經驗，底層知識只是加分。
3. **長期目標也是 C 最順。** 每天碰 kernel，往後要往 upstream（上游，也就是 Linus 那棵主線 kernel）貢獻、甚至成為維護者，這條路最直。
4. **背景在 C 也有差異化。** 很多 BSP 工程師只懂板子，不懂網路、容器、後端；懂 nftables、TPROXY、Docker 的人投網通或伺服器公司是加分。

A 仍然是備案：它最貼近既有經驗，C 方向一時投不上時，A 可以先接住收入。

## 四、可以去查的公司類型

> **未查證**：下表是 Claude 依印象整理的類型與例子，不代表這些公司現在有開缺。實際要求請上 104、LinkedIn 搜
> `BSP`、`Linux driver`、`kernel`、`嵌入式 Linux` 確認。

| 類型 | 例子 | Linux 底層做什麼 |
|---|---|---|
| IC 設計 | 聯發科、瑞昱、聯詠 | SoC（System on Chip，系統單晶片）的 BSP、驅動；有些團隊會往 upstream 送 patch |
| 網通 | 智易、明泰、啟碁、中磊 | 路由器、交換器的嵌入式 Linux、網路堆疊（netfilter 正好用得上） |
| 伺服器／ODM（Original Design Manufacturer，原廠委託設計） | 廣達、英業達、緯創／緯穎、鴻海 | 伺服器的 BMC（Baseboard Management Controller，基板管理控制器，常用 OpenBMC，是 Linux）、kernel 相容性 |
| 工業電腦 | 研華、凌華 | 工業板的 BSP、Yocto |
| 外商在臺 | Google（ChromeOS／硬體團隊）、NVIDIA、Intel、AMD、Qualcomm、Microsoft | 驅動、kernel、平台軟體，部分直接做 upstream |

**外商的面試**通常會考資料結構與演算法（LeetCode 類型的題目），臺灣上市公司比較少考。要投外商，就要從第 4 個月起每週排刷題時間。

## 五、要誠實面對的現實

- **職缺常寫「X 年以上 BSP／驅動經驗」**，目前沒有硬體專案經驗。所以作品要能**碰到硬體**：
  只在 x86 上寫使用者空間程式不夠，要有在 ARM 板子上跑起來的東西（驅動＋device tree 節點）。
- **一開始可以接受中階或稍低的職級**，這比較實際。進去一兩年有了實績，之後跳槽就不受年齡影響。
- **大公司的年齡偏見其實比較小**：制度化的面試看技術。比較麻煩的是**空窗期**——這是第六節「第 5 個月就開始投」的主要理由。

## 六、求職時間表

從 2026-11 起算一年。下表只列求職這一側；學習側要怎麼配合（各站的順序、什麼時候做哪個作品）另外討論。

| 期間 | 求職要做的事 |
|---|---|
| **第 1～2 月**（2026-11～12） | GitHub 公開作品（`wc`／`cat`，之後是迷你 shell），每個 README 寫「學到什麼、踩過什麼坑」；**每週看 10 份 BSP／驅動職缺**，記下要求的技能，回頭校正學習重點 |
| **第 3～4 月**（2027-01～02） | 寫履歷：把空窗寫成「全職系統程式進修」，附這個 repo 與作品連結；每一站準備一則排查故事（第七節） |
| **第 4 月起**（要考外商才做） | 每週固定刷題時間 |
| **第 5～6 月**（2027-03～04） | **開始投履歷**，先投最有把握的。面試本身就是練習：被問倒的題目就排成下一堂課 |
| **第 7～9 月**（2027-05～07） | 繼續投，範圍擴大；有面試就優先準備面試 |
| **第 10～12 月** | 還沒找到工作就以面試需要的內容為主；找到了就把課程改成下班後的節奏，繼續往 kernel 走 |

**為什麼第 5 個月就要投，而不是學完再投：**

- **找工作本身就要 2～4 個月**，第 12 個月才開始，空窗會拉到一年半。
- **面試會告訴你市場要什麼**，比預先排的路線更準，可以拿來調整後面要學的東西。
- 錢和心理壓力是真實的限制。有了工作，學 kernel 反而走得更久、更穩。

## 七、把學到的變成拿得出手的成果

面試官看不到筆記讀了幾遍，只看得到這些：

1. **每站一個能跑的作品**，放上公開的 GitHub，README 寫清楚設計取捨與遇到的 bug。
2. **排查故事**：每站挑一個「用工具查出原因」的實驗，寫成 3～5 句話，例如「為什麼 `cat` 讀目錄會報 `EISDIR`」「GOT 是誰填的」。
   面試被問「你遇過最難的問題」時就有東西講。
3. **把底層接回原本的經驗**：「容器裡的行程在 kernel 看起來是什麼」「K8s 的 CPU limit 其實是 cgroup」——A 方向面試最愛問這類題目
   （跟 Go 後端的對照見 [學C與kernel對Go後端有沒有用](./學C與kernel對Go後端有沒有用-底層知識怎麼接到日常工作與系統設計.md#三每一站對應到後端的哪些真實問題)）。
4. **kernel patch**（C 方向）：就算只是 `drivers/staging/` 的清理或文件修正，一個被合進主線的 commit 都是很硬的證明；
   流程見 [系統化學習路線第七節〈第二段主線：K0～K4〉](./Linux與系統程式的系統化學習路線.md#七目標是-kernel-維護者第二段主線)。
5. **這個筆記庫本身**也是證明：持續、有方法地自學，而且寫得清楚。
