### 1. `call` 與 `ret`

`frame.c` 的 `main` 裡有 `call 1149 <add3>`（位址 `0x1194`），下一條指令在 `0x1199`；`add3` 最後一條是 `ret`。

```asm
# main
1194:	call   1149 <add3>
1199:	mov    %rax,-0x8(%rbp)
# add3 的最後
1177:	pop    %rbp
1178:	ret
```

#### 1-1. `call` 做了哪兩件事？

**第 1 次（2026-10-19）**
```
1. 把rsp-8byte, 讓rsp指向低8byte的位址,空出8byte, 在新的rsp位址寫上了返回位址也就是0x1199
2. 跳入到add3函式
```

> **批改**：**對**。兩件事都答到：`%rsp` 減 8、在新的頂端寫進返回位址 `0x1199`（`call` 的下一條指令），再跳進 `add3`。
>
> **參考答案**【[第三節](../../html/c/x86-64組合語言入門二-call與ret、堆疊框、參數與呼叫慣例.html#三call-與-ret用-gdb-一條一條走)】
>
> **核心關鍵**（答到這幾點就算對）：
>
> 1. 把**返回位址**（`call` 下一條指令的位址 `0x1199`）推進堆疊：`%rsp` 減 8，寫進新的頂端。
> 2. 跳到 `add3`（`%rip` 變成 `add3` 的位址）。
>
> **詳細說明**：`call add3` ＝ `push 返回位址` ＋ `jmp add3`。`frame.c` 實測：`call` 之後 `%rsp` 從 `d410` 變成 `d408`，`d408` 裡是 `0x555555555199`（PIE 載入後的 `0x1199`）。

#### 1-2. `ret` 做了什麼？

**第 1 次（2026-10-19）**
```
根據rsp的上存的返回位址 跳到那個位址,並且rsp要+回8byte(丟棄返回位址)
```

> **批改**：**對**。取出頂端的返回位址跳過去、`%rsp` 加回 8，兩點都對。
>
> **參考答案**【[第三節](../../html/c/x86-64組合語言入門二-call與ret、堆疊框、參數與呼叫慣例.html#三call-與-ret用-gdb-一條一條走)】
>
> **核心關鍵**（答到這幾點就算對）：
>
> 1. 把堆疊頂端那 8 byte 當成位址，放進 `%rip`（跳過去）。
> 2. `%rsp` 加 8（返回位址被拿走）。
>
> **詳細說明**：`ret` ＝ `pop` 到 `%rip`。沒有指令能直接 `mov` 到 `%rip`，`ret` 就是「從堆疊取一個值放進 `%rip`」。實測 `ret` 之後 `%rsp` 回到 `d410`，跟 `call` 之前一模一樣。

#### 1-3. `ret` 怎麼知道要回到 `0x1199`？

**第 1 次（2026-10-19）**
```
因爲rsp已經記錄了返回位址
```

> **批改**：**大致對**。方向對：返回位址就在堆疊頂端。兩點要修：
> - 用詞：`%rsp` 存的是**堆疊頂端的位址**（`0x…d408`），不是返回位址；返回位址 `0x1199` 存在 `%rsp` **指的那格記憶體**裡，是 `call` 推進去的。這個區別在 5-2 又出現一次。
> - 缺了題目的重點：`ret` 其實**不知道**是誰呼叫它，只是盲目地相信頂端那 8 byte。
>
> **參考答案**【[第三節](../../html/c/x86-64組合語言入門二-call與ret、堆疊框、參數與呼叫慣例.html#三call-與-ret用-gdb-一條一條走)】
>
> **核心關鍵**（答到這幾點就算對）：
>
> 1. `call` 把 `0x1199` 推進堆疊，存在 `%rsp` 指的那格記憶體裡。
> 2. `ret` 不知道呼叫者是誰，只是取堆疊頂端那 8 byte 當位址。
>
> **詳細說明**：所以 `add3` 在 `ret` 之前必須把 `%rsp` 還原到放返回位址的那一格：`pop %rbp` 把序言推的舊 `%rbp` 拿走，頂端就又是 `0x1199`（實測第 5 段：停在 `ret` 時 `%rsp` ＝ `d408`、裡面是 `0x555555555199`）。函式裡 `push` 和 `pop` 沒配好，`ret` 就會跳錯。

**自我練習**（不批改）

```
1. rsp的那格記憶體存了返回位址
2. ret 只管堆疊頂端的那8byte當返回位址
```

#### 1-4. 如果 `add3` 裡有個陣列越界寫入，剛好蓋掉了堆疊上的返回位址，`ret` 會發生什麼事？

**第 1 次（2026-10-19）**
```
讀到的返回位址會錯誤,程式不知道會跳到哪裏,可能會造成panic
```

> **批改**：**對**。兩點都答到：`ret` 照樣把被蓋掉的值當成位址，跳到不知道哪裡。用詞小修：panic 是 **kernel** 自己當掉的說法；一般程式跳到亂的位址，通常是收到 SIGSEGV（segfault）被 kernel 終止。
>
> **參考答案**【[第三節](../../html/c/x86-64組合語言入門二-call與ret、堆疊框、參數與呼叫慣例.html#三call-與-ret用-gdb-一條一條走)】
>
> **核心關鍵**（答到這幾點就算對）：
>
> 1. `ret` 不檢查，照樣把被蓋掉的值當成位址跳過去。
> 2. 跳到亂的地方，通常是 segfault 當掉（那個位址沒有對映，或不能執行）。
>
> **詳細說明**：第 3 課實際看過兩種下場：有堆疊保護時，函式返回**之前**檢查金絲雀，印 `stack smashing detected` 中止；關掉保護（`-fno-stack-protector`）就真的走到 `ret`，返回時 segfault（[第 3 課第五節](../../html/c/陣列、字串與指標運算-C不檢查邊界與用gdb找segfault.html#五c-不檢查邊界越界的三種下場)〈關掉保護，看看下面是什麼：返回時 segfault〉）。如果蓋上去的值是攻擊者刻意挑的位址，`ret` 就會跳去執行攻擊者要的程式碼——這是緩衝區溢位攻擊的原理，也是堆疊保護存在的理由。

### 2. 堆疊框

```asm
add3:                                 main:
  push   %rbp                           push   %rbp
  mov    %rsp,%rbp                      mov    %rsp,%rbp
  mov    %rdi,-0x18(%rbp)               sub    $0x10,%rsp
  ...（沒有 sub、沒有 call）              ...（有 call add3、call printf）
  pop    %rbp                           leave
  ret                                   ret
```

#### 2-1. 函式開頭的 `push %rbp` 和 `mov %rsp,%rbp` 各在做什麼？

**第 1 次（2026-10-19）**
```
push rbp是把 rbp存的記憶體位址 存到堆疊的頂端
mov rsp rbp則是讓rbp改指向堆疊的頂端
```

> **批改**：**大致對**。兩條指令的動作都描述對了，但只講了「做什麼」，沒講「為什麼」：
> - `push %rbp` 存的是**呼叫者**的 `%rbp`，為的是返回前要還原給它。
> - `mov %rsp,%rbp` 是把現在的頂端定成**自己這個函式的基準點**：之後 `%rsp` 還會動（`push`、`sub`），`%rbp` 不動，區域變數就能用 `-0x8(%rbp)` 這種固定偏移存取。
>
> **參考答案**【[第四節](../../html/c/x86-64組合語言入門二-call與ret、堆疊框、參數與呼叫慣例.html#四堆疊框pushq-rbp-movq-rsp-rbp-與-leave)】
>
> **核心關鍵**（答到這幾點就算對）：
>
> 1. `push %rbp`：把**呼叫者的** `%rbp` 存到堆疊上，返回前要還原。
> 2. `mov %rsp,%rbp`：把現在的頂端定成自己堆疊框的**基準點**，之後區域變數用 `%rbp` 加固定的負偏移存取。
>
> **詳細說明**：實測：`add3` 的 `push %rbp` 之後，`d400` 裡是 `main` 的 `%rbp`（`d420`）；`mov` 之後 `%rbp` ＝ `d400`。每個框的 `%rbp` 那格都存著上一層的 `%rbp`，串成一條鏈，`bt` 就是沿著它往回找。

**自我練習**（不批改）

```
push rbp 是把rbp的位址存在函式的堆棧頂端的那格,因爲函式結束後rbp還需要指回原本的位址,所以要把這個位址記錄起來

mov rsp rbp則是改寫rbp的位址爲堆棧頂端的位址,因爲rsp後面還有可能變化,例如push新的東西到堆棧上,所以rbp要記錄頂端的位址,方便後續區域變數的記憶體存取
```

#### 2-2. `main` 結尾的 `leave` 等於哪兩條指令？

**第 1 次（2026-10-19）**
```
mov rbp rsp 直接把rsp 剪掉的所有byte全部捨棄
pop rbp
```

> **批改**：**對**。對。AT&T 語法寫成 `mov %rbp,%rsp`（來源在前、目的在後）；你寫的「mov rbp rsp」沒有 `%`，照 AT&T 的順序讀是對的。
>
> **參考答案**【[第四節](../../html/c/x86-64組合語言入門二-call與ret、堆疊框、參數與呼叫慣例.html#四堆疊框pushq-rbp-movq-rsp-rbp-與-leave)〈`leave`：一條指令做兩件事〉】
>
> **核心關鍵**（答到這幾點就算對）：
>
> 1. `mov %rbp,%rsp`：把 `%rsp` 拉回基準點，`sub` 開的空間一次丟掉。
> 2. `pop %rbp`：還原呼叫者的 `%rbp`。
>
> **詳細說明**：`leave.gdb` 實測：`leave` 前 `%rsp` ＝ `d410`、`%rbp` ＝ `d420`；之後 `%rsp` ＝ `d428`（拉回 `d420` 再 `pop` 走 8 byte）、`%rbp` ＝ `d4c0`。只 `push` 沒 `sub` 的函式（`add3`）用 `pop %rbp` 就夠了。

#### 2-3. `add3` 把區域變數放在 `%rsp` 下面、沒有 `sub %rsp`，`main` 卻要 `sub $0x10,%rsp`，為什麼？

**第 1 次（2026-10-19）**
```
因爲add3沒有call任何函式,所以不需要
而main 有call函式,任何未知的函式根據ABI的協議應該要 函式的堆棧頂端應該是16的整數倍
```

> **批改**：**不完整**。「`add3` 沒有 `call` 所以不需要」方向對，但沒說出兩個關鍵：
> - 為什麼 `%rsp` **下面**能放變數：照第二節的規則，比 `%rsp` 低的地方還不屬於堆疊，隨時會被下一次 `push`／`call` 蓋掉。能放是因為 ABI 的**紅區**：`%rsp` 下方 128 byte 保證不會被**別人**（例如訊號處理函式）蓋掉；`add3` 是葉函式，自己也不會再 `push`／`call`，所以安全。
> - 為什麼 `main` 不行：`call` 會把返回位址推到 `%rsp - 8`，正好蓋掉 `%rsp` 下面那一區，所以 `main` 要先 `sub` 把變數的空間收進堆疊裡。
>
> 你寫的 16 byte 對齊是對的觀察，但它解釋的是「為什麼挪 `0x10` 而不是 8」（`r` 只要 8 byte），不是「為什麼要 `sub`」。
>
> **參考答案**【[第四節](../../html/c/x86-64組合語言入門二-call與ret、堆疊框、參數與呼叫慣例.html#四堆疊框pushq-rbp-movq-rsp-rbp-與-leave)〈上圖 `add3` 的變數在 `%rsp` 的「下面」：紅區〉】
>
> **核心關鍵**（答到這幾點就算對）：
>
> 1. **紅區**：ABI 保證 `%rsp` 下方 128 byte 不會被別人蓋掉；`add3` 是葉函式，自己也不會 `push`／`call`，所以直接用、省一條 `sub`。
> 2. `main` 要 `call`：`call` 推返回位址會寫在 `%rsp` 下面、蓋掉那一區，所以必須 `sub` 把變數空間放進堆疊（`%rsp` 上面）。
>
> **詳細說明**：`sub` 的大小是 `0x10` 不是 8，才是 16 byte 對齊的緣故（[第六節](../../html/c/x86-64組合語言入門二-call與ret、堆疊框、參數與呼叫慣例.html#六誰負責保存暫存器以及-16-byte-對齊)〈上面的 `sub $0x8,%rsp`：16 byte 對齊〉：進 `main` 時 `d428`，`push` 後 `d420`，`sub $0x10` 後 `d410` 是 16 的倍數）。kernel 不能用紅區（中斷會直接推資料到目前的堆疊上），所以編譯時加 `-mno-red-zone`。

**自我練習**（不批改）

```
根據ABI,rsp下方128byte都是紅區,除了funtion以外其他函式是不能寫得
add3 沒有call,或 push所以不用擔心紅區會被蓋掉
但是main 他call了add3 與 printf, rsp會 -8 byte並用返回位址複寫這8byte,如果這個時候這8byte有值,就會被蓋掉,
所以rsp 要先降低自己的位址,避免有區域變數被蓋掉,之所以要減0x10是爲了讓call 符合16byte對其
```

### 3. 8 個參數

`args8.c` 的 `sum8` 有 8 個 `long` 參數。

```c
long sum8(long a, long b, long c, long d, long e, long f, long g, long h)
{
    return a + b + c + d + e + f + g + h;
}

long call8(void)
{
    return sum8(1, 2, 3, 4, 5, 6, 7, 8);
}
```

### 4. callee-saved 與對齊

下面兩個函式用 `-O2` 編譯（`g` 只有宣告）。

```c
/* saved.c */                          /* noret.c */

long f(long x)                          long f(long x)
{                                       {
    long y = g(x);                          long y = g(x);
    return x + y;                           return y * 2;
}                                       }
```

```asm
# saved.c 的 f                          # noret.c 的 f
push   %rbx                             sub    $0x8,%rsp
mov    %rdi,%rbx                        call   g
call   g                                add    $0x8,%rsp
add    %rbx,%rax                        add    %rax,%rax
pop    %rbx                             ret
ret
```


> **批改**：**不完整**。為什麼**不能**留在 `%rdi` 答對了：`%rdi` 是 caller-saved，`g` 可以改掉它。但題目問的是「為什麼要 `push %rbx`」，這部分沒答：
> - `x` 要放到 `g` **保證不改**的地方：callee-saved 的 `%rbx`（`mov %rdi,%rbx`）。
> - `f` 自己對呼叫 `f` 的人也有同樣的義務：要用 `%rbx`，就得先 `push` 存起來、返回前 `pop` 還原。這才是 `push %rbx` 的原因。
