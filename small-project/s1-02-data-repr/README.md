## 題目

程式碼都在這個資料夾裡**自己寫**，每支程式都用 `gcc -Wall -Wextra` 編譯。
筆記裡的範例可以參考寫法，但每一題的型別、數值、情境都跟範例不同，照抄範例答不出來。
每題「解釋原因」的地方都標了答案的來源：
- 【筆記第 X 節】：課堂教過，回筆記那一節找。
- 【新觀念，先猜】：還沒教過，寫下你的猜測就好，猜錯不算錯。

**「先預測」的題目，一定要先把預測寫進觀察紀錄，再執行程式。** 預測錯了沒關係，把錯在哪裡寫下來，這才是練習的重點。

1. **比 `int` 小的型別**：寫 `ranges.c`，印出 `short`、`unsigned short`、`signed char`、`unsigned char` 的 `sizeof`，
   以及它們的最小值、最大值（`<limits.h>` 裡的常數名稱，查 `/usr/include/limits.h`；無號型別只有最大值）。
   - 執行前先預測：`short` 是 2 byte、用二補數，範圍是多少到多少？把算的過程寫下來。【筆記第一、五節】
   - 為什麼 `unsigned short` 的最大值是 `short` 最大值的兩倍再加 1？【筆記第四、五節】

2. **8 byte 的位元組順序**：寫 `endian8.c`，宣告 `long v = 0x1122334455667788;`，用 `unsigned char *` 印出 `v` 的第一個 byte。
   - 執行前先預測第一個 byte 是什麼，說明理由。【筆記第三節】
   - 用 `gcc -g -O0` 編譯，在 `gdb` 裡用 `x/8xb &v` 看全部 8 個 byte，貼上輸出。【筆記第三節】
   - 再用 `x/2xw &v`（每單位 4 byte，印 2 個）看同一塊記憶體。**先預測**會印出哪兩個數字、順序為何，再執行驗證，
     解釋為什麼是這個順序。【筆記第三節】

3. **轉換預測**：寫 `predict.c`，印出下面五個運算式的值（有號的用 `%d`，無號的用 `%u`），其中 (3)(4) 另外用 `%x` 印出十六進位。
   **每一個都要先寫預測和推理過程，再執行。**
   1. `(signed char)200`
   2. `(unsigned short)-1`
   3. `(int)(short)0x8000`
   4. `(unsigned int)(signed char)-100`
   5. `(int)(unsigned char)-100`
   - 每一個都說明：發生了截斷、擴展（哪一種），還是只換了讀法？【筆記第五、六節】

4. **另外兩種比較陷阱**：寫 `compare.c`。
   - `unsigned int a = 3, b = 5;`，用 `if (a - b > 0)` 判斷「a 是否比 b 大」，印出判斷結果和 `a - b` 的值。解釋結果。【筆記第四節】
   - 用 `-Wall -Wextra` 編譯，gcc 會不會對這一行警告？【新觀念，先猜】（先寫猜測再編譯）
   - 把判斷改成正確的寫法。【筆記第四節】
   - `int i = -1;`，用 `if (i < sizeof(int))` 判斷，印出結果並解釋。`sizeof` 的結果是什麼型別？【筆記第一、七節】

5. **錯誤的溢位檢查**：寫 `overflow_check.c`，裡面有一個函式想檢查「`x + y` 會不會超過 `int` 的範圍」（只考慮 `y` 是正數）：
   ```c
   int will_overflow(int x, int y)
   {
       int sum = x + y;
       return sum < x;      /* 加了正數反而變小，就代表溢位了？ */
   }
   ```
   在 `main` 裡印出 `will_overflow(INT_MAX, 1)`。
   - 用 `-O0`、`-O2`、`-O2 -fwrapv` 各編一次，貼上三個結果，解釋為什麼不一樣。【筆記第八節】
   - 寫一個不會觸發有號溢位的版本 `safe_will_overflow(int x, int y)`：**在做加法之前**，用 `INT_MAX` 和 `y` 判斷
     `x` 會不會太大。三種編譯方式都要得到一樣的結果。【筆記第八節】
   - 兩個版本都用 `-O0 -fsanitize=undefined` 編譯執行，貼上輸出。哪一個有 runtime error？為什麼另一個沒有？【筆記第八節】
