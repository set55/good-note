### 1. `mov` 與 `lea`

> `movl (%rdi,%rsi,4), %eax` 和 `leaq (%rdi,%rsi,4), %rax` 括號裡寫的一模一樣。

#### 1-1. 兩個指令做的事差在哪？

**第 1 次（2026-10-08）**
```
movl 是把(%rdi,%rsi,4)這個記憶體位址的值 存入eax
leaq 則是把(%rdi,%rsi,4)這個值 直接塞入 rax
```

> **批改**：**對**。抓到重點：`movl` 去記憶體讀那個位址裡的值，`leaq` 把算出來的位址數字本身放進去。
>
> **參考答案**【[第四節](../../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#四mov-與-lea搬資料-vs-算位址)〈`lea`：只算位址，不碰記憶體〉】
>
> **核心關鍵**（答到這幾點就算對）：
>
> 1. `movl` 先算出位址 `a + i×4`，再**去記憶體讀**那個位址的 4 byte，放進 `%eax`。
> 2. `leaq` 只把算出來的**位址數字本身**放進 `%rax`，**不讀記憶體**。
>
> **詳細說明**：括號寫法一樣，代表兩個指令算出同一個數字 D ＋ B ＋ I × S；差別只在要不要拿這個數字去存取記憶體。因為 `lea` 根本不存取，位址不合法也不會 segfault。

#### 1-2. 各對應 C 的什麼寫法？

**第 1 次（2026-10-08）**
```
int f(int *a, long n) {return a[n];}
long f(long a, long b) {return a+4b;}
```

> **批改**：**大致對**。`movl` 對應 `a[n]`，對。`leaq` 寫成 `long` 的 `a + 4*b`：本機 `gcc -O2` 實測也編成同一行 `leaq (%rdi,%rsi,4), %rax`，算式沒錯；但這題要的是跟 `movl` 那一行**對照**——同一組括號，`mov` 是 `a[i]`，`lea` 是 `&a[i]`（指標），你沒接回指標的寫法。另外 C 不能寫 `4b`，要寫 `4*b`。
>
> **參考答案**【[第四節](../../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#四mov-與-lea搬資料-vs-算位址)〈`lea`：只算位址，不碰記憶體〉】
>
> **核心關鍵**（答到這幾點就算對）：
>
> 1. `movl (%rdi,%rsi,4), %eax` ↔ `a[i]`（就是 `*(a + i)`，`a` 是 `int *`）。
> 2. `leaq (%rdi,%rsi,4), %rax` ↔ `&a[i]`（就是 `a + i`，結果是指標）。
>
> **詳細說明**：第 3 課：`a[i]` ＝ `*(a + i)`、`&a[i]` ＝ `a + i`；括號裡的 `a + i×4` 是 `a + i` 換算成 byte 的算法。`mov` 比 `lea` 多做的就是那個 `*`。
>
> 純算數的寫法也會編出同一行（本機 `gcc -O2 -S` 實測），所以單看一行 `lea` 分不出是指標還是算數：
>
> ```c
> long  f(long a, long b) { return a + 4*b; }   /* → leaq (%rdi,%rsi,4), %rax */
> int  *h(int *a, long i) { return &a[i]; }     /* → leaq (%rdi,%rsi,4), %rax */
> ```
>
> 跟 `movl` 並排時，參數 `a` 被拿去讀記憶體，表示它是指標，這時 `lea` 讀成 `&a[i]` 才是對的對照。

#### 1-3. 為什麼 gcc 會拿 `lea` 來算 `x * 3` 這種跟位址無關的東西？

**第 1 次（2026-10-08）**
```
因爲位址說到底也是數字,數字計算適合用 lea
```

> **批改**：**大致對**。抓到「位址說到底也是數字」；缺了**怎麼算**：`x * 3` ＝ `x + x×2`，剛好是 `(%rdi,%rdi,2)` 的 B ＋ I × S，一個指令算完。
>
> **參考答案**【[第四節](../../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#四mov-與-lea搬資料-vs-算位址)〈`lea` 被拿來做算術〉】
>
> **核心關鍵**（答到這幾點就算對）：
>
> 1. `lea` 只算 D ＋ B ＋ I × S 這個數字、不碰記憶體，所以算的東西不必是位址。
> 2. `x * 3` ＝ `x + x×2`，正好寫成 `leaq (%rdi,%rdi,2), %rax`，一個指令做完。
>
> **詳細說明**：另外兩個好處：`lea` **不改旗標**（`add` 會），而且結果可以放到另一個暫存器（`add` 只能寫回其中一個運算元）。能一次做到的倍數是 x × S 或 x ＋ x × S：1、2、3、4、5、8、9 倍（作業第 1 題）。

### 2. 寫 32 位元暫存器與擴展

> `long widen_u(unsigned x) { return x; }` 只要一個 `movl %edi, %eax`，`long widen_s(int x) { return x; }` 卻要 `movslq %edi, %rax`。

#### 2-1. 為什麼 `movl` 就足以完成前者？

**第 1 次（2026-10-08）**
```
long widen_u(unsigned x) { return x; }
因爲unsigned 32位元, 轉64爲,剩32位直接補0就好

long widen_s(int x) { return x; }
來源是有號int, 根據最高爲補1/0 , 所以要用movslq (s:signed, l: int, q: long)
```

> **批改**：**不完整**。「`unsigned` 轉 `long` 補 0 就好」對，但沒答到題目問的**為什麼一個 `movl` 就做得到**：寫 `%eax` 時 CPU 會自動把 `%rax` 的高 32 位元清成 0。這正是作業還沒弄懂的「寫 32 位元暫存器會清掉高 32 位元」，**跟作業卡在同一處**。（`widen_s` 的說明是另一半，沒問，不扣分。）
>
> **參考答案**【[第二節](../../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#二暫存器cpu-裡的-16-個變數)〈寫低位的名字時，高位會怎樣？〉】
>
> **核心關鍵**（答到這幾點就算對）：
>
> 1. `unsigned` → `long` 是**零擴展**：高 32 位元補 0。
> 2. 寫 32 位元的名字（`%eax`）時，CPU 會**自動把 `%rax` 的高 32 位元清成 0**，所以一個 `movl %edi, %eax` 就完成了零擴展。
>
> **詳細說明**：這也是擴展指令裡**沒有 `movzlq`** 的原因：4 → 8 byte 的零擴展，`movl` 就做完了。`widen_s` 要補符號位元，CPU 不會自動補，才需要 `movslq`。

#### 2-2. 如果改寫 16 位元的 `%ax`，同樣的理由還成立嗎？

**第 1 次（2026-10-08）**
```
不成立,因爲無號的0xffffffff -> 有號ax = 0xffff 那會變成負的 改用movslw
```

> **批改**：**不完整**。「不成立」對，理由錯。跟有號無號無關（也沒有 `movslw` 這個指令：擴展指令是 `movs`／`movz` ＋ 來源大小 ＋ 目的大小，來源一定比目的小，例如 `movswl`）。真正的理由是：寫 16 位元的 `%ax` 時，**高位不動**，不會被清成 0。
>
> **參考答案**【[第二節](../../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#二暫存器cpu-裡的-16-個變數)〈寫低位的名字時，高位會怎樣？〉】
>
> **核心關鍵**（答到這幾點就算對）：
>
> 1. 不成立。
> 2. 寫 16 位元（`%ax`）或 8 位元（`%al`）的名字時，高位**保留原本的值、不會自動清 0**；只有寫 32 位元名字才會清。所以要零擴展得用 `movzwl`／`movzbl` 這類指令。
>
> **詳細說明**：這條規則不對稱：
>
> | 寫入的大小 | 高位會怎樣 |
> |---|---|
> | 32 位元（`%eax`） | 高 32 位元清成 0 |
> | 16 位元（`%ax`）、8 位元（`%al`） | 不動，保留舊值 |

### 3. 有號與無號在哪裡決定

> `lt_s` 和 `lt_u` 的 `cmpl %esi, %edi` 一模一樣，gdb 也看到兩者的旗標完全相同（`[ SF IF ]`）。

#### 3-1. 為什麼一個回傳 1、一個回傳 0？

**第 1 次（2026-10-08）**
```
#lt.c
int lt_s(int a, int b)           { return a < b; }
int lt_u(unsigned a, unsigned b) { return a < b; }

lt_s 兩個參數都是signed, 有號的就是要看 SF 是否等於 OF
SF = 1 OF = 0 故 a-b <0 爲真

lt_u 都是unsigned 看的是CF

CF = 0 a - b 正確答案裝得下 代表>0 故爲假
```

> **批改**：**對**。抓到重點：旗標一樣，有號看 SF ≠ OF、無號看 CF，並用這組旗標算出 1 和 0。
>
> **參考答案**【[第五節](../../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#五旗標與條件跳躍cmp-只負責比跳不跳由下一個指令決定)〈實驗：同一個 `cmp`、同一組旗標，`setl` 說是、`setb` 說否〉】
>
> **核心關鍵**（答到這幾點就算對）：
>
> 1. 旗標相同，差在**讀旗標的條件碼**：`lt_s` 用 `setl`（看 SF ≠ OF），`lt_u` 用 `setb`（看 CF）。
> 2. 這次 SF = 1、OF = 0 → `setl` 成立，回傳 1；CF = 0 → `setb` 不成立，回傳 0。
>
> **詳細說明**：實驗的 `a` 是 −1（位元 `0xffffffff`）、`b` 是 1。有號看是 −1 < 1；無號看是 4294967295 < 1，不成立。`cmpl` 算出的位元與旗標只有一份，兩種讀法是 gcc 挑條件碼時決定的。

#### 3-2. C 的「有號還是無號」在組合語言裡到底是在哪裡決定的？

**第 1 次（2026-10-08）**
```
c在轉成組合語言 根據自己的定義,決定要用哪個指令,例如movslb 就是因爲來源類型是有號
```

> **批改**：**大致對**。主線「gcc 依 C 的型別決定用哪個指令」對；但只舉了擴展的例子（而且 `movslb` 不存在，應為 `movsbl`），沒提這題本身就是的那一種：**比較之後挑哪個條件碼**。這跟作業 3-2 的「組合語言只有擴展與比較才看得出有號無號」是同一個觀念。
>
> **參考答案**【[第五節](../../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#五旗標與條件跳躍cmp-只負責比跳不跳由下一個指令決定)〈實驗：同一個 `cmp`、同一組旗標，`setl` 說是、`setb` 說否〉、[第三節](../../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#三指令的文法助憶符大小後綴運算元)〈`%dil` 是 `0xff`，為什麼 `%eax` 變成 `0xffffffff`〉】
>
> **核心關鍵**（答到這幾點就算對）：
>
> 1. 在**編譯時**由 gcc 依照 C 的型別選指令決定；CPU、暫存器、旗標裡都沒有「有號／無號」。
> 2. 只表現在兩種地方：比較之後挑的條件碼（有號 `l`／`g`，無號 `b`／`a`），以及變寬時挑 `movs` 還是 `movz`。
>
> **詳細說明**：`cmp` 把兩種解讀需要的旗標（OF 給有號、CF 給無號）一次都設好，`add`、`sub` 的位元也不分有號無號。所以從組合語言反推型別時，只能看這兩種地方。

### 4. 旗標與指令的排列

> `-O2` 的 `sum_to` 裡，`andl $1, %edi` 和 `je .L3` 中間夾了一個 `movl $1, %eax`。

#### 4-1. `je` 判斷的是哪個指令的結果？

**第 1 次（2026-10-08）**
```
