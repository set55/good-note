### 1. 指標的型別與指標運算

#### 1-1. `int *p` 和 `unsigned char *c` 存著同一個位址，為什麼 `p + 1` 和 `c + 1` 不一樣？

> 4 和 1 是它**指向的東西**（`int`、`unsigned char`）的大小。第 2 課也在這個用詞上錯過一次，要分清楚。
>

> 位址本身一樣，差在用什麼型別看它。

### 2. 陣列傳進函式之後

#### 2-1. `int a[10];` 在 `main` 裡 `sizeof a` 是 40，傳進 `void f(int a[])` 之後 `sizeof a` 變成 8。為什麼？

**第 1 次（2026-10-04）**
```
sizeof a是特例,他顯示的是a整個陣列的大小

```

> **批改（第 1 次，2026-10-04）**：**不完整**。「`sizeof a` 是不退化的特例」解釋了 `main` 裡為什麼是 40，這部分對。
> 但題目問的是**為什麼到了 `f` 裡變成 8**——同樣是寫 `sizeof a`，在 `f` 裡這個特例為什麼不成立了？「一般情況皆視為指標」太籠統，沒講到函式參數。
>
> **提示**【筆記[第三節](../../html/c/陣列、字串與指標運算-C不檢查邊界與用gdb找segfault.html#三陣列名稱什麼時候變成指標什麼時候不會)〈函式參數寫成 `int a[]`，其實就是 `int *a`〉】：
> 兩件事：(1) 呼叫 `f(a)` 時，真正傳過去的是什麼、幾個 byte？(2) 編譯器把參數宣告 `int a[]` 當成什麼型別？8 是什麼東西的大小？

**第 2 次（重答，2026-10-04）**
> 題目：`int a[10];` 在 `main` 裡 `sizeof a` 是 40，傳進 `void f(int a[])` 之後 `sizeof a` 變成 8。為什麼？
```
sizeof a是特例,他顯示的是a整個陣列的大小
函式參數int a[]之int的指標,而不管是什麼指標都是8byte
```

> **批改（第 2 次，重答，2026-10-04）**：**對**。關鍵「參數 `int a[]` 其實是 `int *`，指標在本機都是 8 byte」答出來了。
>
> **參考答案**【筆記[第三節](../../html/c/陣列、字串與指標運算-C不檢查邊界與用gdb找segfault.html#三陣列名稱什麼時候變成指標什麼時候不會)〈函式參數寫成 `int a[]`，其實就是 `int *a`〉】：在 `main` 裡 `sizeof a` 是不退化的例外，得到整個陣列 40 byte。
> 呼叫 `f(a)` 時 `a` 退化成指向 `a[0]` 的指標，傳過去的只是一個 8 byte 的位址；而函式參數宣告成 `int a[]`（甚至 `int a[10]`），編譯器一律當成 `int *a`，
> 所以 `f` 裡的 `sizeof a` 是指標的大小 8。gcc 的 `-Wsizeof-array-argument` 會警告這件事。

#### 2-2. 這件事對「怎麼設計接收陣列的函式」有什麼影響？

**第 1 次（2026-10-04）**
```
void f如果想知道陣列的大小,還需要多傳 sizeof a / sizeof a[0]
```

> **批改（第 1 次，2026-10-04）**：**對**。長度要另外傳，而且你傳的是**元素個數**，正確。要注意的是 `sizeof a / sizeof a[0]` 一定要在**呼叫端**（`a` 還是陣列的地方）算好再傳；
> 如果在 `f` 裡面算，會得到 8 / 4 = 2，就是 2-1 的陷阱。
>
> **參考答案**【筆記[第三節](../../html/c/陣列、字串與指標運算-C不檢查邊界與用gdb找segfault.html#三陣列名稱什麼時候變成指標什麼時候不會)】：
> 函式拿到的只有一個位址，不知道陣列多長，所以**長度一定要另外當參數傳**（例如 `long sum(int *p, int n)`），在呼叫端用 `sizeof a / sizeof a[0]` 算。
> 標準函式庫也是這樣設計：`memcpy(dst, src, n)`、`read(fd, buf, count)`。唯一的例外是字串，它靠結尾的 `\0` 知道在哪結束。

#### 2-3. `a` 和 `&a` 印出來的位址一樣，它們差在哪裡？

**第 1 次（2026-10-04）**
```

&a 是 把a看成陣列,dereference陣列的位址
```

> **批改（第 1 次，2026-10-04）**：**錯**。`&` 是**取位址**，不是 dereference（dereference 是 `*`，方向正好相反）。「`a` 是指標」只對一半：`a` 本身是陣列，是**在運算式裡退化**成指標。
> 兩者的差別也還沒講出來。
>
> **提示**【筆記[第三節](../../html/c/陣列、字串與指標運算-C不檢查邊界與用gdb找segfault.html#三陣列名稱什麼時候變成指標什麼時候不會)〈`a` 和 `&a`：位址一樣，型別不一樣〉】：
> 這題的答案是「型別」。`a` 退化成指向什麼的指標？`&a` 是指向什麼的指標？用 1-1 的規則想：`a + 1` 和 `&a + 1` 各會多幾個 byte（`int a[10]`）？

**第 2 次（重答，2026-10-04）**
> 題目：`a` 和 `&a` 印出來的位址一樣，它們差在哪裡？
```
a本身是陣列退化成指標 int*, a+1 是多4byte
&a是指向a整個陣列的指標 是 int *[40]  &a+1是多160byte
```

> **批改（第 2 次，重答，2026-10-04）**：**不完整**。觀念對了：`a` 退化成 `int *`、`+ 1` 多 4；`&a` 是「指向整個陣列」的指標。兩個細節錯：
> - 型別寫法：`int *[40]` 是「**40 個 `int *` 組成的陣列**」，不是指向陣列的指標。指向陣列的指標要加括號：**`int (*)[10]`**（括號讓 `*` 先跟名字結合，方括號裡是**元素個數** 10，不是 byte 數 40）。
> - `&a + 1` 多的是**整個陣列的大小 40 byte**（10 × 4），不是 160。你把 40 當成元素個數又乘了 4。
>
> **參考答案**【筆記[第三節](../../html/c/陣列、字串與指標運算-C不檢查邊界與用gdb找segfault.html#三陣列名稱什麼時候變成指標什麼時候不會)〈`a` 和 `&a`：位址一樣，型別不一樣〉】：兩者位址相同，**型別不同**。
> `a` 退化成 `int *`（指向一個 `int`），`a + 1` 走 4 byte；`&a` 的型別是 `int (*)[10]`（指向「10 個 `int` 的陣列」），`&a + 1` 走整個陣列 40 byte。
> 筆記用 `int a[5]` 實測：`a + 1` 多 4、`&a + 1` 多 20（`0x14`）。
