## gcc：[gcc最佳化等級-O0到O3差在哪](../html/c/gcc最佳化等級-O0到O3差在哪.html)

### gcc 1. `-O0` 的 `O` 和 `0` 各是什麼？為什麼說它是「預設值」——不加任何 `-O` 時會發生什麼？

> 盒子 4｜過去的作答：[s1-01 quiz.md 第 1 題](../small-project/s1-01-hello-compile/quiz.md#1--o0-的-o-和-0-各是什麼為什麼說它是預設值不加任何--o-時會發生什麼)、[10-10 複習](./2026-10-10-C資料-GNU-interp-hello-gcc.md)

```
O就是optimization的意思
0就是不最佳化

預設值就是說如果你在下編譯指令不帶任何與-O相關的option,那gcc默認是-O0 不最佳化
```

> **批改**：**對**。抓到：`O` 是 Optimize、`0` 是不最佳化；不加 `-O` 就是 `-O0`。
>
> **參考答案**【[第一節](../html/c/gcc最佳化等級-O0到O3差在哪.html#一文法-o等級)】
>
> **核心關鍵**：
>
> 1. `O` 是大寫字母 O，代表 Optimize（最佳化）；`0` 是等級 0，即不最佳化。
> 2. 不加任何 `-O` 時 gcc 就用 `-O0`，所以它是預設值。
>
> **詳細說明**：`man gcc` 在 `-O0` 底下寫著 *This is the default*。注意 `-O0` 是字母 O 加數字 0，不是兩個零。

### gcc 2. 為什麼 `-O0` 的組合語言每一圈都在讀寫記憶體（`-4(%rbp)`），而 `-O2` 不會？這個差別對 `gdb` 有什麼影響？

> 盒子 1｜過去的作答：[s1-01 quiz.md gcc 第 2 題](../small-project/s1-01-hello-compile/quiz.md#2-為什麼--o0-的組合語言每一圈都在讀寫記憶體-4rbp而--o2-不會這個差別對-gdb-有什麼影響)、[10-09 複習](./2026-10-09-陣列-gcc-GNU-C資料-interp-ELF.md)、[10-16 複習](./2026-10-16-interp-ELF-gcc-GNU-陣列-C資料.md)、[10-23 複習](./2026-10-23-大複習-hello-gcc-GNU-interp-ELF-objdump-C資料-字元-陣列-組語-組語二-多檔.md)

**題目用到的程式**：`sumto.c`（檔案：[`sumto.c`](../small-project/s1-01-hello-compile/sumto.c)），
用 `gcc -O0 -S sumto.c` 與 `gcc -O2 -S sumto.c` 產生組合語言（`-S`：只編譯到組合語言 `.s` 就停）。

```c
#include <stdio.h>

int sum_to(int n)
{
    int total = 0;
    for (int i = 1; i <= n; i++)
        total += i;
    return total;
}

int answer(void)
{
    return sum_to(100);
}

int main(void)
{
	printf("answer:%d\n", answer());
	return 0;
}
```

`-O0` 的 `sum_to`（本機 gcc 13.3 實際輸出，刪掉 `.cfi`、`.type` 這類組譯指示，右邊是逐行說明）：

```asm
sum_to:
	endbr64                    # 間接跳躍的保護標記（CET），跟這題無關
	pushq	%rbp               # 存起呼叫者的 %rbp
	movq	%rsp, %rbp         # %rbp = 這個函式的堆疊框底
	movl	%edi, -20(%rbp)    # 參數 n（放在 %edi 傳進來）寫到記憶體 -20(%rbp)
	movl	$0, -8(%rbp)       # total = 0，寫到記憶體 -8(%rbp)
	movl	$1, -4(%rbp)       # i = 1，寫到記憶體 -4(%rbp)
	jmp	.L2                # 先跳去檢查條件
.L3:                               # 迴圈本體
	movl	-4(%rbp), %eax     # 從記憶體讀 i 到 %eax
	addl	%eax, -8(%rbp)     # 記憶體裡的 total += %eax
	addl	$1, -4(%rbp)       # 記憶體裡的 i += 1
.L2:                               # 迴圈條件
	movl	-4(%rbp), %eax     # 從記憶體讀 i
	cmpl	-20(%rbp), %eax    # 比較 i 與記憶體裡的 n（算 i − n、設旗標）
	jle	.L3                # i <= n（有號）就回去跑本體
	movl	-8(%rbp), %eax     # 從記憶體讀 total 當回傳值
	popq	%rbp               # 還原 %rbp
	ret
```

> **批改**：**對**。抓到：`-O0` 不最佳化、變數放在堆疊的固定位置、每一圈都讀寫記憶體；`-O2` 把變數留在暫存器；gdb 上 `-O0` 每一行對得到指令、變數印得出來，`-O2` 行號亂跳、`<optimized out>` 是常態（10-09、10-16、10-23 缺的「每次都讀寫」這次有了）。小修（不扣分）：`-O2` 這裡是一圈加兩個數（展開兩倍），「一次進行多個計算」說得對，但重點是「暫存器」，不是展開。
>
> **參考答案**【[第二節](../html/c/gcc最佳化等級-O0到O3差在哪.html#二實驗同一段程式不同等級編出什麼)、[第三節](../html/c/gcc最佳化等級-O0到O3差在哪.html#三為什麼除錯要用--o0)】
>
> **核心關鍵**：
>
> 1. `-O0` 不最佳化、照字面翻譯：每個變數都有**固定的記憶體位置**（`i` 是 `-4(%rbp)`、`total` 是 `-8(%rbp)`），每條語句都從記憶體讀、再寫回記憶體。
> 2. `-O2` 把變數留在**暫存器**（`i` 在 `%eax`、`total` 在 `%edx`），迴圈裡完全不碰記憶體。
> 3. 對 gdb 的影響：`-O0` 原始碼的每一行都對得到一段指令，變數隨時印得出來；`-O2` 行號會跳、指令被重排，變數可能顯示 `<optimized out>`。
>
> **詳細說明**：`-O2` 版裡的 `andl $1, %edi` 不是計數，是在進迴圈前判斷 `n` 的奇偶，好讓迴圈一圈加兩個數。第三節的實測：`-O2` 停下來時跳過了第 3 行；只走兩行，`total` 就已經是 3；被內嵌進 `main` 的那一份變數全是 `<optimized out>`。所以學習、單步除錯用 `-O0 -g`，日常開發用 `-Og -g`。

`-O2` 的 `sum_to`（同上，實際輸出）：

```asm
sum_to:
	endbr64
	testl	%edi, %edi         # n & n，只為了設旗標
	jle	.L4                # n <= 0 就跳去回傳 0
	leal	1(%rdi), %ecx      # %ecx = n + 1（迴圈的終點）
	xorl	%edx, %edx         # %edx = 0（total）
	andl	$1, %edi           # %edi = n & 1（n 是奇數還是偶數）
	movl	$1, %eax           # %eax = 1（i）
	je	.L3                # n 是偶數就直接進迴圈
	movl	$2, %eax           # n 是奇數：先處理掉 i = 1，i 從 2 開始
	movl	$1, %edx           #           total = 1
	cmpl	%ecx, %eax         #           i 已經到 n + 1 了嗎（n = 1 時）
	je	.L1
.L3:                               # 迴圈本體：一圈加兩個數
	leal	1(%rdx,%rax,2), %edx  # total = total + 2×i + 1（＝ total + i + (i+1)）
	addl	$2, %eax           # i += 2
	cmpl	%ecx, %eax         # i 到 n + 1 了嗎
	jne	.L3
.L1:
	movl	%edx, %eax         # 回傳 total
	ret
.L4:
	xorl	%edx, %edx
	movl	%edx, %eax         # 回傳 0
	ret
```

> 題目：為什麼 `-O0` 的組合語言每一圈都在讀寫記憶體（`-4(%rbp)`），而 `-O2` 不會？這個差別對 `gdb` 有什麼影響？

```
-O0不執行任何最佳化,所以需要把變數之類的存在堆疊上,並且每次迴圈都需要讀寫
-O2進行了速度的最佳化,他把迴圈展開, 展開後,一次進行多個計算,並且使用寄存器去記相關的變數

-O0 可以找到每一行代碼 對應的一段組合語言, 而且變數用gdb 可以打印出來
-O2 因爲他把迴圈展開,還有其他優化,行數可能亂跳,而且變數打印出optimied out是常態
```

```
自己的程式可以改用-O0編譯
kernel的話 用-O0無法編譯,kernel的代碼都是一對內嵌與死碼,所以只能用像是printk trace等去把變數打印出來
```

> **批改**：**對**。抓到：自己的程式改用 `-O0` 重編；kernel **不能用 `-O0` 編**（依賴內嵌與刪除死碼），只能用 `printk`、tracing 觀察（10-23 缺的這點這次有了）。筆誤：「一對內嵌與死碼」應是「依賴內嵌與刪除死碼」。
>
> **參考答案**【[第三節](../html/c/gcc最佳化等級-O0到O3差在哪.html#三為什麼除錯要用--o0)、[第四節](../html/c/gcc最佳化等級-O0到O3差在哪.html#四跟-kernel-的關係)】
>
> **核心關鍵**：
>
> 1. 自己的程式：用 `-O0 -g`（或 `-Og -g`）重編，變數有固定位置，gdb 就印得出來；不能重編時，加 `printf` 把值印出來。
> 2. kernel：**不能用 `-O0` 編**（kernel 依賴編譯器一定會做的內嵌與刪除死碼才編得過），`<optimized out>` 是常態；只能改用 `printk`、tracing 這類方法觀察，並學會讀最佳化後的組合語言。
>
> **詳細說明**：kernel 不連結 libc，沒有 `printf`，也沒有 stdout；`printk` 的訊息寫進 kernel 的紀錄緩衝區，用 `dmesg` 看。一句話：自己的程式可以「改編譯方式」，kernel 只能「改觀察方式」。

## ELF：[ELF是什麼-可執行與可連結格式的兩種視角](../html/c/ELF是什麼-可執行與可連結格式的兩種視角.html)

### ELF 4. 區段（section）和載入段（segment）差在哪？為什麼核心載入時要把很多區段打包成少數幾個載入段？

> 盒子 1｜過去的作答：[s1-01 quiz.md 第 4 題](../small-project/s1-01-hello-compile/quiz.md#4-區段section和載入段segment差在哪為什麼核心載入時要把很多區段打包成少數幾個載入段)、[10-04 複習](./2026-10-04-字元-C資料-objdump-hello-ELF.md)、[10-08 複習](./2026-10-08-字元-C資料-objdump-hello-ELF-陣列.md#elf-4-區段section和載入段segment差在哪為什麼核心載入時要把很多區段打包成少數幾個載入段)、[10-19 複習](./2026-10-19-interp-GNU-C資料-ELF-objdump-組語.md)、[10-23 複習](./2026-10-23-大複習-hello-gcc-GNU-interp-ELF-objdump-C資料-字元-陣列-組語-組語二-多檔.md)

```
section是給連結器,readelf,objdump看的, 連結器會根據每個section的權限將他們組合成segment(load)
segment是給執行者看的,也就是kernel與interpreter,kernel會根據load在映射到實際的記憶體

核心處理記憶體的單位是分頁,一個分頁是4096,核心只在乎分頁的權限,一個分頁不能有兩種權限
如果不打包成load, 不同的section用的權限不同,最極端的例子可能每個section都用了一個分頁,造成記憶體的浪費,而且每次換section還要切換分頁,即使他們的權限是相同的
```

> **批改**：**對**。抓到：區段給連結器、`readelf`／`objdump` 看，載入段給核心與 interpreter 看；權限以分頁為單位、一頁只能一種權限，所以同權限的區段打包（10-23 缺的「給誰看」這次有了）。小修（不扣分）：「每次換 section 還要切換分頁」不是理由，CPU 執行時不會「切換分頁」；真正的代價是頁數變多、浪費記憶體，以及權限不同的區段擠在同一頁時沒辦法各自設權限。
>
> **參考答案**【[第四節](../html/c/ELF是什麼-可執行與可連結格式的兩種視角.html#四名字的關鍵兩種視角)】
>
> **核心關鍵**：
>
> 1. 區段（section）是**連結視角**的單位，切得很細（`hello` 有 31 個），給 `ld`、`nm`、`objdump` 用；載入段（segment）是**執行視角**的單位，數量很少（4 個 `LOAD`），給核心與動態載入器用，描述「哪一塊放進記憶體、權限是什麼」。
> 2. 記憶體權限**最小只能以分頁（本機 4096 byte）為單位**設定，同一頁不能一半可執行、一半可寫；所以 `ld` 把權限相同的區段排在一起、打包成一個載入段，核心每塊映射一次、設一種權限就能把程式放進記憶體。
>
> **詳細說明**：核心載入時只在乎權限（可讀／可寫／可執行），不在乎區段叫 `.text` 還是 `.rodata`。如果不打包，權限不同的小區段擠在同一頁就沒辦法各自設權限；每個區段各占一頁又會浪費記憶體。

```
沒有變

雖然記憶體內容一致,但是類別是C的,要根據C的型別 對記憶體的值做不同的解讀
兩個在記憶體的內容都是32位元, 每一位都是1, 但是在有號int 解讀出來時-1, 而無號就是2^32 - 1

> **批改**：**對**。抓到：記憶體沒變，32 個 bit 全是 1；有號讀是 −1、無號讀是 2³² − 1。小修（不扣分）：「型別」決定 C 運算時怎麼讀，印出來時是 `printf` 的 `%d`／`%u` 決定讀法。
>
> **參考答案**【[第五節](../html/c/C的資料在記憶體裡長怎樣-位元組、指標、位元組順序與有號無號.html#五有號整數二補數)、[第六節](../html/c/C的資料在記憶體裡長怎樣-位元組、指標、位元組順序與有號無號.html#六有號與無號之間的轉換位元不變換個讀法)】
>
> **核心關鍵**：
>
> 1. 沒有變：記憶體裡始終是 `ff ff ff ff`。同樣寬度的有號、無號轉換只換讀法、不動位元。
> 2. `%d` 用二補數讀（最高位權重是 −2³¹），得到 −1；`%u` 把每一位都當正的權重，得到 2³² − 1 = 4294967295。

### C資料 4. `int y = x + 1; return y > x;` 在 `x = INT_MAX` 時，`-O0` 回傳 0、`-O2` 回傳 1。為什麼會這樣？這算不算 gcc 的 bug？kernel 用哪個選項避免這種情況，代價是什麼？

> 盒子 1｜過去的作答：[s1-02 quiz.md 第 4 題](../small-project/s1-02-data-repr/quiz.md#4-int-y--x--1-return-y--x-在-x--int_max-時-o0-回傳-0-o2-回傳-1為什麼會這樣這算不算-gcc-的-bugkernel-用哪個選項避免這種情況代價是什麼)、[10-07 複習](./2026-10-07-GNU-C資料-hello-objdump-字元.md)、[10-11 複習](./2026-10-11-字元-C資料-objdump-GNU-陣列.md)、[10-22 複習](./2026-10-22-組語-C資料-objdump-字元-陣列.md)、[10-23 複習](./2026-10-23-大複習-hello-gcc-GNU-interp-ELF-objdump-C資料-字元-陣列-組語-組語二-多檔.md)

題目用到的程式是筆記[第八節](../html/c/C的資料在記憶體裡長怎樣-位元組、指標、位元組順序與有號無號.html#八溢位無號回繞有號是未定義行為)的 `ub.c`，完整原始碼：

```c
#include <stdio.h>
#include <limits.h>

int bigger(int x)
{
    int y = x + 1;
    return y > x;
}

int main(void)
{
    printf("bigger(INT_MAX) = %d\n", bigger(INT_MAX));
    return 0;
}
```

編譯與執行：`gcc -O0 ub.c -o ub && ./ub`、`gcc -O2 ub.c -o ub && ./ub`（結果如題目所述，分別印 0 與 1）。

> 題目：`int y = x + 1; return y > x;` 在 `x = INT_MAX` 時，`-O0` 回傳 0、`-O2` 回傳 1。為什麼會這樣？這算不算 gcc 的 bug？kernel 用哪個選項避免這種情況，代價是什麼？

```

> **批改**：**對**。抓到：有號溢位是 UB、`-O0` 回繞成 `INT_MIN` → 0、`-O2` 假設不溢位 → 1；不是 gcc 的 bug；`-fno-strict-overflow` 與代價（10-23 漏的「不是 bug」這次有了）。小修（不扣分）：「gcc 沒有定義溢位」應是「C 標準沒有定義」，gcc 只是照標準允許的方式最佳化。
>
> **參考答案**【[第八節](../html/c/C的資料在記憶體裡長怎樣-位元組、指標、位元組順序與有號無號.html#八溢位無號回繞有號是未定義行為)】
>
> **核心關鍵**：
>
> 1. 有號溢位是未定義行為（UB），C 標準允許編譯器**假設它不會發生**。
> 2. `-O0` 照字面算，`INT_MAX + 1` 回繞成 `INT_MIN`，`y > x` 為假 → 0；`-O2` 依這個假設推論 `x + 1` 一定大於 `x`，直接回傳 1。
> 3. 不是 gcc 的 bug：標準對發生 UB 的程式沒有任何要求，兩種結果都合法。
> 4. kernel 用 `-fno-strict-overflow`（等於 `-fwrapv -fwrapv-pointer`），讓溢位照二補數回繞、變成有定義的行為；代價是少了依賴「不會溢位」的最佳化，程式可能稍慢。
>
> **詳細說明**：連 `-O0` 也不保證照字面算：把同一件事寫成一行 `return x + 1 > x;`，`-O0` 也回傳 1，因為 gcc 在最佳化之前的化簡階段就把它改掉了。所以本題的 `bigger` 才故意拆成兩行。
-O0: 因爲當x = INT_MAX再加1算出來就會變成INT_MIN,所以返回0

>
> 1. 會得到 65536（`0x00010000`），不是協定要的 256。

> **批改**：**對**。抓到：參數只有 1 byte 在 `%dil`；高 7 byte 是垃圾（內容不保證），讀進來會出錯（缺了四次的「垃圾」這次有了）。

> 1. 參數是 1 byte 的 `signed char`，只放在 `%rdi` 最低的 1 byte（`%dil`）。

### 組語 9. 符號擴展補的是什麼

> 盒子 1｜過去的作答：[s1-04 quiz.md 第 9 題](../small-project/s1-04-asm-basics/quiz.md#9-符號擴展補的是什麼2026-10-06-課後提問新增)、[10-13 複習](./2026-10-13-組語-字元.md)、[10-23 複習](./2026-10-23-大複習-hello-gcc-GNU-interp-ELF-objdump-C資料-字元-陣列-組語-組語二-多檔.md)

#### 組語 9-1. `movsbl` 把 1 byte 擴展成 4 byte 時，新補的高 3 byte 是照哪一個位元補的？

```
最高的第8位元補的,看是0還是1
```

> **批改**：**對**。抓到：照最高位元補（你寫的「第 8 位元」是從 1 數起，筆記從 0 數叫第 7 位元，同一個位元）。
>
> **參考答案**【[第三節](../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#三指令的文法助憶符大小後綴運算元)〈`%dil` 是 `0xff`，為什麼 `%eax` 變成 `0xffffffff`：符號擴展補的是第 7 位元〉】
>
> **核心關鍵**：
>
> 1. 照來源的**最高位元**（1 byte 的第 7 位元，也就是符號位）補：新多出來的每個 bit 都複製它。

#### 組語 9-2. 為什麼這樣補，`signed char` 的 −1 變成 `int` 之後才會還是 −1（用二補數的權重解釋）？

```
char的二補數權重: -2^8 + (2^8 - 1)
擴展成int後,的二補數: -2^32 + (2^32 - 1)
權重從2^8 -> 2^32
可以看出來當你擴展時,你的上位也要跟着補1,最後的結果才能維持-1
```

> **批改**：**大致對**。方向對了：這次用「最高位權重是負的」來解釋（10-23 用無號權重的錯改正了），也看出要補 1 才維持 −1。但**指數錯一位**：8 位元的最高位權重是 **−2⁷**，其他 7 位合起來是 2⁷ − 1，所以 `0xff` ＝ −2⁷ ＋ (2⁷ − 1) ＝ −1；32 位元是 −2³¹ ＋ (2³¹ − 1)。你寫的 −2⁸ ＋ (2⁸ − 1) 算出來也是 −1，但那是 9 位元的權重。另外沒講對照：補 0 的話 `0x000000ff` ＝ 255，值就變了。
>
> **參考答案**【[第三節](../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#三指令的文法助憶符大小後綴運算元)〈`%dil` 是 `0xff`，為什麼 `%eax` 變成 `0xffffffff`：符號擴展補的是第 7 位元〉】
>
> **核心關鍵**：
>
> 1. 二補數的**最高位權重是負的**：8 位元 `0xff` ＝ −2⁷ ＋ (2⁷ − 1) ＝ −1；32 位元 `0xffffffff` ＝ −2³¹ ＋ (2³¹ − 1) ＝ −1。
> 2. 所以高位全補 1，值還是 −1；補 0 的話 `0x000000ff` ＝ 255，值就變了。
>
> **詳細說明**：一般化：前面多補一個 1，新的最高位權重是 −2⁸，原本那一位從 −2⁷ 變成 +2⁷，合起來 −2⁸ ＋ 2⁷ ＝ −2⁷，跟原來一樣，**值不變**；補幾個都同理。

### 組語 11. gdb 的 `break *位址`

> `break deref+4` 會得到 `Function "deref+4" not defined.`，`break *deref+4` 卻可以。
>
> 盒子 1｜過去的作答：[s1-04 quiz.md 第 11 題](../small-project/s1-04-asm-basics/quiz.md#11-gdb-的-break-位址2026-10-06-課後提問新增)、[10-13 複習](./2026-10-13-組語-字元.md)、[10-22 複習](./2026-10-22-組語-C資料-objdump-字元-陣列.md)、[10-23 複習](./2026-10-23-大複習-hello-gcc-GNU-interp-ELF-objdump-C資料-字元-陣列-組語-組語二-多檔.md)

用到的程式（檔案：[`paren.c`](../small-project/s1-04-asm-basics/paren.c)）：

```c
#include <stdio.h>

__attribute__((noinline)) long copy_val(long x)  { return x; }    /* 回傳 x 本身 */
__attribute__((noinline)) long deref(long *p)    { return *p; }   /* 回傳 p 指向的值 */

int main(void)
{
    long v = 1234;
    printf("%ld %ld\n", copy_val(v), deref(&v));
    return 0;
}
```

```sh
gcc -O2 -g paren.c -o paren
objdump -d --no-show-raw-insn paren
```

`-O2` 編出的 `deref`：

```asm
deref:
	endbr64                 # 控制流程保護標記（佔 4 byte，所以下一條是 deref+4）
	mov	(%rdi),%rax         # 把 %rdi 當位址，讀 8 byte 放進 %rax
	ret                     # 回傳 %rax
```

#### 組語 11-1. `*` 讓 gdb 怎麼理解後面的東西？

```
沒有*的時候: gdb 是把 break deref+4, deref+4 當成函式名稱或行數 而沒有這個deref+4的名稱,更不是行數了
有*的時候: break *deref+4, *後面當成算式,把後面的記憶體位址算出來
```

> **批改**：**對**。抓到：沒 `*` 時 `deref+4` 被當成函式名或行號，找不到；有 `*` 時後面是算出位址的式子（10-23 缺的前半這次有了）。
>
> **參考答案**【[第三節](../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#三指令的文法助憶符大小後綴運算元)〈上面 `break *widen_char+4` 的 `*`：為什麼要加？〉】

> **核心關鍵**：
>
> 1. `*` 表示後面是**一個算出位址的式子**：gdb 計算 `deref + 4`（函式開頭往後 4 byte），停在那個位址的機器指令。
> 2. 沒有 `*` 時，後面被當成函式名或行號（linespec），`deref+4` 整串被當成函式名，所以 `not defined`。

#### 組語 11-2. 這個 `*` 跟 C 的 `*p` 是同一個意思嗎？

不同
C的*p 是讀這個位址那格的數值

> **核心關鍵**：
>
> 1. 不是：`break` 的 `*` 是 gdb 的語法記號，意思是「後面是位址」；C 的 `*p` 是取出指標指向的值。

#### 組語 11-3. 在 `-O0` 的程式上，`break deref` 和 `break *deref` 為什麼會停在不同的位址？

同一個 `paren.c` 改用 `-O0` 編，`deref` 的組合語言：

000000000000117b <deref>:
    117b:	endbr64                 # 控制流程保護標記
    117f:	push   %rbp             # 把呼叫者的 %rbp 存到堆疊（第 5 課的序言）
    1180:	mov    %rsp,%rbp        # %rbp = 目前堆疊頂，建立這個函式的堆疊框

>
> **核心關鍵**：
>
> 1. `break deref`（函式名）會把中斷點**下在函式開頭的準備工作之後**（`-O0` 的 `push %rbp`、`mov %rsp,%rbp` 等；這些指令照常執行，停下時已經跑完）。有 `-g` 照行號表，連「把參數存進堆疊」也算進去，停在 `0x1187`；沒有 `-g` 停在 `0x1183`。
> 2. `break *deref` 不跳過任何東西，停在函式的**第一條指令** `endbr64`（實測 `0x117b`）。

> 題目：在 `-O0` 的程式上，`break deref` 和 `break *deref` 為什麼會停在不同的位址？

```

break deref 是會停在前置工作做完的地方,也就是push %rbp, mov %rsp,%rbp結束後
```

#### 組語 15-2. 留下的位元當無號讀是多少，它跟數學上的正確答案差了多少、為什麼剛好差這麼多？

>
> 1. 留下 `0xfb`，無號讀是 **251**。
> 2. 數學答案是 −5，**差 256**：往第 8 位元之外借的 1 價值 2⁸ ＝ 256，結果多了 256（251 ＝ 4 − 9 ＋ 256）。
>

#### 組語 15-3. 如果 CPU 是用加法器算（D + S 反轉 + 1），加法器有沒有往外進位，跟 CF 是什麼關係？

> 題目：（8 位元算 4 − 9）如果 CPU 是用加法器算（D + S 反轉 + 1），加法器有沒有往外進位，跟 CF 是什麼關係？

```
9 = 00001001 => 11110110 (反轉) => 0xf6

4 + 0xf6 + 1 = 0xfb
所以關係是 沒進位 = 有借位 = CF 1
           有進位 = 沒借位 = CF 0
```

> **批改**：**對**。抓到：反轉 `0xf6`、相加 `0xfb` 沒進位；沒進位 ＝ 有借位 ＝ CF 1、有進位 ＝ 沒借位 ＝ CF 0（10-22、10-23 缺的「關係」這次有了）。
>
> **參考答案**【[第五節](../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#五旗標與條件跳躍cmp-只負責比跳不跳由下一個指令決定)〈上面③：3 − 5 在 CPU 裡實際上是怎麼算的？〉的「電路上其實是用加法做的」】
>
> **核心關鍵**：
>
> 1. 4 ＋ (9 反轉 ＝ 246) ＋ 1 ＝ 251，沒超過 255 → 加法器**沒有**往外進位。
> 2. 減法時進位跟借位**相反**：x86 把加法器的進位反過來存進 CF，所以「沒進位」→ CF ＝ 1（借位了）。
>
> **詳細說明**：對照 5 − 3：5 ＋ 252 ＋ 1 ＝ 258，有進位 → CF ＝ 0（不用借）。ARM 等架構減法時直接存加法器的進位，CF 的意思剛好相反。

### 組語二 1. `call` 與 `ret`

> 盒子 1｜過去的作答：[s1-05 quiz.md 第 1 題](../small-project/s1-05-asm-calls/quiz.md#1-call-與-ret)、[10-23 複習](./2026-10-23-大複習-hello-gcc-GNU-interp-ELF-objdump-C資料-字元-陣列-組語-組語二-多檔.md)

`frame.c` 的 `main` 裡有 `call 1149 <add3>`（位址 `0x1194`），下一條指令在 `0x1199`；`add3` 最後一條是 `ret`。

完整原始碼（檔案：[`frame.c`](../small-project/s1-05-asm-calls/frame.c)）與編譯指令：

```c
#include <stdio.h>

long add3(long a, long b, long c)
{
    long s = a + b;
    return s + c;
}

int main(void)
{
    long r = add3(1, 2, 3);
    printf("%ld\n", r);
    return 0;
}
```

```sh
gcc -O0 -g -fno-asynchronous-unwind-tables frame.c -o frame
objdump -d --no-show-raw-insn frame
```

```asm
# main
1194:	call   1149 <add3>
1199:	mov    %rax,-0x8(%rbp)
# add3 的最後
1177:	pop    %rbp
1178:	ret
```

#### 組語二 1-1. `call` 做了哪兩件事？

```
%rsp 減掉 8byte, 並在空出來的那格塞入返回的位址(0x1199)
jump 到 add3
```

> **批改**：**對**。抓到：`%rsp` 減 8 寫進返回位址 `0x1199`，再跳到 `add3`（10-23 漏的「跳」這次有了）。
>
> **參考答案**【[第三節](../html/c/x86-64組合語言入門二-call與ret、堆疊框、參數與呼叫慣例.html#三call-與-ret用-gdb-一條一條走)】
>
> **核心關鍵**：
>
> 1. 把**返回位址**（`call` 下一條指令的位址 `0x1199`）推進堆疊：`%rsp` 減 8，寫進新的頂端。
> 2. 跳到 `add3`（`%rip` 變成 `add3` 的位址）。
>
> **詳細說明**：`frame.c` 實測：`call` 之後 `%rsp` 從 `d410` 變成 `d408`，`d408` 裡是 `0x555555555199`（PIE 載入後的 `0x1199`）。

#### 組語二 1-2. `ret` 做了什麼？

```
看當時堆疊頂端 就是%rsp指的那格, 拿到那格的返回位址, %rsp再+8byte, 清除返回位址,並跳到返回位址
```

> **批改**：**對**。抓到：取 `%rsp` 指的那格當位址跳過去，`%rsp` 加 8。小修（不扣分）：返回位址沒有被「清除」，那格記憶體的內容還在，只是 `%rsp` 移過去、之後會被覆蓋。
>
> **參考答案**【[第三節](../html/c/x86-64組合語言入門二-call與ret、堆疊框、參數與呼叫慣例.html#三call-與-ret用-gdb-一條一條走)】
>
> **核心關鍵**：
>
> 1. 把堆疊頂端那 8 byte 當成位址，放進 `%rip`（跳過去）。
> 2. `%rsp` 加 8（返回位址被拿走）。
>
> **詳細說明**：`ret` ＝ `pop` 到 `%rip`。實測 `ret` 之後 `%rsp` 回到 `d410`，跟 `call` 之前一模一樣。

#### 組語二 1-3. `ret` 怎麼知道要回到 `0x1199`？

```
ret不知道,他只管從%rsp指的那格 拿值,並當作返回位址跳過去
```

> **批改**：**對**。抓到：`ret` 不知道，只拿 `%rsp` 指的那格（那格是 1-1 的 `call` 寫進去的）。
>
> **參考答案**【[第三節](../html/c/x86-64組合語言入門二-call與ret、堆疊框、參數與呼叫慣例.html#三call-與-ret用-gdb-一條一條走)】
>
> **核心關鍵**：
>
> 1. `call` 把 `0x1199` 推進堆疊，存在 `%rsp` 指的那格記憶體裡。
> 2. `ret` 不知道呼叫者是誰，只是取堆疊頂端那 8 byte 當位址。
>
> **詳細說明**：所以 `add3` 在 `ret` 之前必須把 `%rsp` 還原到放返回位址的那一格：`pop %rbp` 把序言推的舊 `%rbp` 拿走，頂端就又是 `0x1199`。函式裡 `push` 和 `pop` 沒配好，`ret` 就會跳錯。

#### 組語二 1-4. 如果 `add3` 裡有個陣列越界寫入，剛好蓋掉了堆疊上的返回位址，`ret` 會發生什麼事？

```
ret不管,拿到值後,照樣跳過去.不管會不會出問題
```

> **批改**：**對**（改判）。抓到：`ret` 不檢查，照樣把被蓋掉的值當位址跳過去。原判因沒寫「通常 segfault」給大致對；2026-10-25 使用者指出題目問的是「`ret` 會發生什麼事」，沒要求說明跳過去之後的下場，`ret` 的行為就是「照跳」，改判為對，「通常 segfault」移到詳細說明。
>
> **參考答案**【[第三節](../html/c/x86-64組合語言入門二-call與ret、堆疊框、參數與呼叫慣例.html#三call-與-ret用-gdb-一條一條走)】
>
> **核心關鍵**：
>
> 1. `ret` 不檢查，照樣把被蓋掉的值當成位址跳過去。
>
> **詳細說明**：跳到亂的地方，通常是 segfault 當掉（那個位址沒有對映，或不能執行）。有堆疊保護時，函式返回**之前**檢查金絲雀，印 `stack smashing detected` 中止；關掉保護就真的走到 `ret`，返回時 segfault。如果蓋上去的值是攻擊者刻意挑的位址，`ret` 就會跳去執行攻擊者要的程式碼——這是緩衝區溢位攻擊的原理。

### 組語二 2. 堆疊框

> 盒子 1｜過去的作答：[s1-05 quiz.md 第 2 題](../small-project/s1-05-asm-calls/quiz.md#2-堆疊框)、[10-23 複習](./2026-10-23-大複習-hello-gcc-GNU-interp-ELF-objdump-C資料-字元-陣列-組語-組語二-多檔.md)

完整原始碼（檔案：[`frame.c`](../small-project/s1-05-asm-calls/frame.c)）與編譯指令（同組語二 1）：

```c
#include <stdio.h>

long add3(long a, long b, long c)
{
    long s = a + b;
    return s + c;
}

int main(void)
{
    long r = add3(1, 2, 3);
    printf("%ld\n", r);
    return 0;
}
```

```sh
gcc -O0 -g -fno-asynchronous-unwind-tables frame.c -o frame
objdump -d --no-show-raw-insn frame
```

```asm
add3:                                 main:
  push   %rbp                           push   %rbp
  mov    %rsp,%rbp                      mov    %rsp,%rbp
  mov    %rdi,-0x18(%rbp)               sub    $0x10,%rsp
  ...（沒有 sub、沒有 call）              ...（有 call add3、call printf）
  pop    %rbp                           leave
  ret                                   ret
```

#### 組語二 2-1. 函式開頭的 `push %rbp` 和 `mov %rsp,%rbp` 各在做什麼？

```
%rsp 減下8byte,空出來的8byte那格用來存 %rbp的值, 這是爲了結束函式後,%rbp要恢復原來的值,也就是先幫%rbp備份
而 mov %rsp, %rbp 是這個時候幫rsp的值覆蓋到rbp, 這樣%rbp就是指向當前函式堆疊的頂端,以此作爲整個函式的基準,區域變數都以此爲基準放置
```

> **批改**：**對**。抓到：`push %rbp` 備份呼叫者的 `%rbp`、返回前還原；`mov %rsp,%rbp` 把 `%rbp` 定成本函式的基準點，區域變數以它為準（10-19、10-23 缺的兩個目的這次都有了）。
>
> **參考答案**【[第四節](../html/c/x86-64組合語言入門二-call與ret、堆疊框、參數與呼叫慣例.html#四堆疊框pushq-rbp-movq-rsp-rbp-與-leave)】
>
> **核心關鍵**：
>
> 1. `push %rbp`：把**呼叫者的** `%rbp` 存到堆疊上，返回前要還原。
> 2. `mov %rsp,%rbp`：把現在的頂端定成自己堆疊框的**基準點**，之後區域變數用 `%rbp` 加固定的負偏移存取。
>
> **詳細說明**：每個框的 `%rbp` 那格都存著上一層的 `%rbp`，串成一條鏈，`bt` 就是沿著它往回找。

#### 組語二 2-2. `main` 結尾的 `leave` 等於哪兩條指令？

```
mov %rbp, %rsp , 這是爲了把rsp一開始sub的0x10 清除掉,直接跳回堆疊頂端
pop %rbp, 然後在把%rbp恢復,在加上8byte, 這樣%rsp存的那格就變成了main的返回位址了
```

> **批改**：**對**。抓到：`mov %rbp,%rsp` 把 `sub` 開的空間丟掉、`pop %rbp` 還原，頂端就是返回位址（10-23 寫成「加 16」的錯改正了）。小修：`%rsp` 是拉回「基準點」（存舊 `%rbp` 的那格），不是「堆疊頂端」。
>
> **參考答案**【[第四節](../html/c/x86-64組合語言入門二-call與ret、堆疊框、參數與呼叫慣例.html#四堆疊框pushq-rbp-movq-rsp-rbp-與-leave)〈`leave`：一條指令做兩件事〉】
>
> **核心關鍵**：
>
> 1. `mov %rbp,%rsp`：把 `%rsp` 拉回基準點，`sub` 開的空間一次丟掉。
> 2. `pop %rbp`：還原呼叫者的 `%rbp`。
>
> **詳細說明**：`leave.gdb` 實測：`leave` 前 `%rsp` ＝ `d410`、`%rbp` ＝ `d420`；之後 `%rsp` ＝ `d428`（拉回 `d420` 再 `pop` 走 8 byte）、`%rbp` ＝ `d4c0`。

#### 組語二 2-3. `add3` 把區域變數放在 `%rsp` 下面、沒有 `sub %rsp`，`main` 卻要 `sub $0x10,%rsp`，為什麼？

```
因爲main有執行call, call的時候爲了要記住call之後的返回位址 rsp下面要寫上返回位址, 如果這個時候rsp還是在堆疊頂端
有可能會覆蓋到區域變數,導致安靜的出錯,所以最好是先把rsp的位址往下移,在進行call,這樣比較能夠避免返回地址誤寫到 區域變數之類的
```

> **批改**：**大致對**。主線對了（10-19、10-23 說成對齊的錯改正）：`main` 會 `call`，`call` 推返回位址會寫在 `%rsp` 下面、蓋掉放在那裡的變數，所以先 `sub` 把變數空間挪到 `%rsp` 上面。缺另一半：`add3` 為什麼**可以**放在 `%rsp` 下面——**紅區**，ABI 保證 `%rsp` 下方 128 byte 不會被別人蓋掉，`add3` 是不呼叫別人的葉函式，自己也不會寫那一區。另外這不是「最好」「比較能夠避免」，是**一定**會被蓋掉。
>
> **參考答案**【[第四節](../html/c/x86-64組合語言入門二-call與ret、堆疊框、參數與呼叫慣例.html#四堆疊框pushq-rbp-movq-rsp-rbp-與-leave)〈上圖 `add3` 的變數在 `%rsp` 的「下面」：紅區〉】
>
> **核心關鍵**：
>
> 1. **紅區**：ABI 保證 `%rsp` 下方 128 byte 不會被別人蓋掉；`add3` 是葉函式，自己也不會 `push`／`call`，所以直接用、省一條 `sub`。
> 2. `main` 要 `call`：`call` 推返回位址會寫在 `%rsp` 下面、蓋掉那一區，`call` 之後還要用的變數就壞了，所以 gcc 對會 `call` 的函式一律 `sub`，把變數空間放進堆疊（`%rsp` 上面）。
>
> **詳細說明**：兩個核心關鍵各管一半：`main` 要 `sub` 跟紅區無關（只因為它會 `call`），紅區解釋的是 `add3` 為什麼可以不 `sub`；用 `-mno-red-zone` 編，`main` 不變、`add3` 多出 `sub $0x28,%rsp`（2026-10-25 使用者提問後補上）。`sub` 的大小是 `0x10` 不是 8，才是 16 byte 對齊的緣故（進 `main` 時 `d428`，`push` 後 `d420`，`sub $0x10` 後 `d410` 是 16 的倍數）。kernel 不能用紅區（中斷會直接推資料到目前的堆疊上），所以編譯時加 `-mno-red-zone`。

**自我練習**（不批改）

```
根據ABI的規定 rsp下127byte是紅區,別人不能直接覆蓋,而且add3是葉函數,沒有call 也沒有push,紅區可以隨便他用

而main需要是因爲他自己有做call 需要避免返回位址蓋到區域變數,所以rsp要下降
```

### 組語二 3. 8 個參數

> 盒子 1｜過去的作答：[s1-05 quiz.md 第 3 題](../small-project/s1-05-asm-calls/quiz.md#3-8-個參數)、[10-23 複習](./2026-10-23-大複習-hello-gcc-GNU-interp-ELF-objdump-C資料-字元-陣列-組語-組語二-多檔.md)

`args8.c` 的 `sum8` 有 8 個 `long` 參數。

完整原始碼（檔案：[`args8.c`](../small-project/s1-05-asm-calls/args8.c)，只有兩個函式、沒有 `main`，只編成 `.o` 看組合語言）與編譯指令：

```c
long sum8(long a, long b, long c, long d, long e, long f, long g, long h)
{
    return a + b + c + d + e + f + g + h;
}

long call8(void)
{
    return sum8(1, 2, 3, 4, 5, 6, 7, 8);
}
```

```sh
gcc -O0 -c -fno-asynchronous-unwind-tables args8.c -o args8.o
objdump -d --no-show-raw-insn args8.o
```

```asm
call8:                                sum8 裡讀第 7、8 個參數：
  push   %rbp                           mov    0x10(%rbp),%rax
  mov    %rsp,%rbp                      ...
  push   $0x8                           mov    0x18(%rbp),%rax
  push   $0x7
  mov    $0x6,%r9d
  ...（5～1 分別放進 %r8d、%ecx、%edx、%esi、%edi）
  call   sum8
  add    $0x10,%rsp
  leave
  ret
```

#### 組語二 3-1. 前 6 個參數放在哪裡？

```
rdi, rsi, rdx, rcx, r8, r9
```

> **批改**：**對**。
>
> **參考答案**【[第五節](../html/c/x86-64組合語言入門二-call與ret、堆疊框、參數與呼叫慣例.html#五參數與回傳值放哪裡)】
>
> **核心關鍵**：
>
> 1. 照順序放 `%rdi`、`%rsi`、`%rdx`、`%rcx`、`%r8`、`%r9`。
>
> **詳細說明**：`call8` 寫的是 `%r9d`、`%ecx` 這些 32 位元的名字：常數小，寫 32 位元會清掉高 32 位元，整個 64 位元就是那個值，指令還比較短。

#### 組語二 3-2. 第 7、8 個放在哪裡、`call8` 用什麼順序放？

```
放在函數的堆疊上
順序是先放8,再放7
```

> **批改**：**對**。抓到：堆疊、先推 8 再推 7。小修：是推在**呼叫者 `call8`** 的堆疊上。
>
> **參考答案**【[第五節](../html/c/x86-64組合語言入門二-call與ret、堆疊框、參數與呼叫慣例.html#五參數與回傳值放哪裡)〈實驗：8 個參數，第 7、8 個去哪了〉】
>
> **核心關鍵**：
>
> 1. 放在堆疊上（呼叫者用 `push` 推進去，每個 8 byte）。
> 2. 從最後一個開始推：先 `push $0x8` 再 `push $0x7`，所以第 7 個在較低的位址。

#### 組語二 3-3. 在 `sum8` 裡第 7 個參數為什麼是 `0x10(%rbp)`，而不是 `0(%rbp)`？

```
在進入call sum8前, %rsp 指的就是第7個參數那一格,然後call會 -8 存返回地址, 然後-8byte 存rbp位址(push %rbp)
所以第7個參數就位在sum8的函式堆疊頂端往上16byte位址指的那格,故寫成0x10(%rbp)
```

> **批改**：**對**。抓到：`call` 推返回位址、`push %rbp` 推舊 `%rbp`，各 8 byte，所以第 7 個在 `0x10(%rbp)`。
>
> **參考答案**【[第五節](../html/c/x86-64組合語言入門二-call與ret、堆疊框、參數與呼叫慣例.html#五參數與回傳值放哪裡)〈實驗：8 個參數，第 7、8 個去哪了〉】
>
> **核心關鍵**：
>
> 1. `call8` 推完參數後，`call` 又推了返回位址、`sum8` 的序言又推了舊 `%rbp`。
> 2. 所以從 `sum8` 的 `%rbp` 往上：`0(%rbp)` 舊 `%rbp`、`0x8(%rbp)` 返回位址、`0x10(%rbp)` 才是第 7 個。
>
> **詳細說明**：記法：**參數用正的偏移（在呼叫者那邊），區域變數用負的偏移（在自己這邊）**。

#### 組語二 3-4. `call8` 在 `call` 之後為什麼要 `add $0x10,%rsp`？

```
跟push %rbp後 pop %rbp的道理有點像, 但是call8 是push 0x7, 0x8,都是純值,不像%rbp需要恢復%rbp的值,所以只需要把原本%rsp減的,再加回來就好,雖然後面的leave會顯得這個動作有點多餘
```

> **批改**：**大致對**。「把推的 16 byte 加回來」對。又缺**為什麼是 `call8` 清**：`sum8` 的 `ret` 只拿走返回位址、不清參數，所以誰推的誰清（跟 10-19、10-23 缺同一點，第三次）。
>
> **參考答案**【[第五節](../html/c/x86-64組合語言入門二-call與ret、堆疊框、參數與呼叫慣例.html#五參數與回傳值放哪裡)〈實驗：8 個參數，第 7、8 個去哪了〉】
>
> **核心關鍵**：
>
> 1. 第 7、8 個參數是 `call8` 自己 `push` 的（2 × 8 ＝ 16 byte）。
> 2. `sum8` 的 `ret` 只拿走返回位址、不清參數，所以由呼叫者 `call8` 在 `call` 回來後用 `add $0x10,%rsp` 丟掉。
>
> **詳細說明**：這裡 `add` 之後緊接著 `leave`，其實 `leave` 也會把 `%rsp` 拉回去；`-O0` 照規則先清掉參數，不管後面有沒有 `leave`。

**自我練習**（不批改）

```
因爲call8 推了0x7, 0x8, 而 sum8 的ret只拿走返回位址,所以誰推的誰清
```

### 組語二 4. callee-saved 與對齊

> 盒子 1｜過去的作答：[s1-05 quiz.md 第 4 題](../small-project/s1-05-asm-calls/quiz.md#4-callee-saved-與對齊)、[10-23 複習](./2026-10-23-大複習-hello-gcc-GNU-interp-ELF-objdump-C資料-字元-陣列-組語-組語二-多檔.md)

下面兩個函式用 `-O2` 編譯（`g` 只有宣告）。

```c
/* saved.c */                          /* noret.c */
long g(long x);                         long g(long x);

long f(long x)                          long f(long x)
{                                       {
    long y = g(x);                          long y = g(x);
    return x + y;                           return y * 2;
}                                       }
```

完整原始碼（檔案：[`saved.c`](../small-project/s1-05-asm-calls/saved.c)、[`noret.c`](../small-project/s1-05-asm-calls/noret.c)；`g` 只有宣告，只編成 `.o`）與編譯指令：

```sh
gcc -O2 -c -fno-asynchronous-unwind-tables saved.c -o saved.o
gcc -O2 -c -fno-asynchronous-unwind-tables noret.c -o noret.o
objdump -d --no-show-raw-insn saved.o noret.o
```

```asm
# saved.c 的 f                          # noret.c 的 f
push   %rbx                             sub    $0x8,%rsp
mov    %rdi,%rbx                        call   g
call   g                                add    $0x8,%rsp
add    %rbx,%rax                        add    %rax,%rax
pop    %rbx                             ret
ret
```

#### 組語二 4-1. 為什麼 `saved.c` 的 `f` 要 `push %rbx`，而不是讓 `x` 留在 `%rdi`？

```
因爲%rdi是caller-saved, 有可能會改,而f最後還是必須要用x加上g的計算結果,不能指望rdi經過g後不變,所以把他存到%rbx
但要存%rbx就會把%rbx的原值覆蓋掉,而%rbx是callee-saved,而f本身也是會被別人call的,所以他要負責把舊的%rbx存起來
因此他把舊的%rbx push起來,存到函式堆疊裏.
最後g把結果算出來後還要+x,那我們就可以把%rbx裏存的x直接拿出來計算完成.
```

> **批改**：**對**。抓到：`%rdi` 是 caller-saved 會被 `g` 改掉、`x` 搬到 callee-saved 的 `%rbx`、`f` 自己也要先備份 `%rbx`。
>
> **參考答案**【[第六節](../html/c/x86-64組合語言入門二-call與ret、堆疊框、參數與呼叫慣例.html#六誰負責保存暫存器以及-16-byte-對齊)〈實驗：要跨過 `call` 保存的值放哪裡〉】
>
> **核心關鍵**：
>
> 1. `x` 在 `g` 回來後還要用，但 `%rdi` 是 caller-saved，`g` 可能改掉它。
> 2. 所以把 `x` 搬到 callee-saved 的 `%rbx`：ABI 保證 `g` 回來時 `%rbx` 不變。
> 3. `f` 借用 `%rbx` 也要對自己的呼叫者負責：開頭 `push %rbx`、返回前 `pop %rbx` 還原。
>
> **詳細說明**：對照 `noret.c`：`call` 之後不再用 `x`，就不需要 `%rbx`。`saved.c` 的 `push %rbx` 還順便把 `%rsp` 挪了 8 byte，同時滿足 16 byte 對齊（4-2）。

#### 組語二 4-2. `noret.c` 的 `f` 不需要保存任何值，為什麼還要 `sub $0x8,%rsp`？

```
根據ABI的規則,當我們不確定g的定義的時候,需要確認%rsp在進入g之前是16的倍數,
首先f被call本身也要記得返回地址,所以-8byte, 然後在-8byte剛好是16的倍數
```

> **批改**：**對**。抓到：ABI 規定 `call` 時 `%rsp` 要是 16 的倍數；`call f` 推了 8 byte 返回位址，再補 8 才對齊（10-23 把 8 byte 歸給 `call g` 的錯改正了）。小修（不扣分）：這條規定跟「知不知道 `g` 的定義」無關，**每一次** `call` 都要對齊。
>
> **參考答案**【[第六節](../html/c/x86-64組合語言入門二-call與ret、堆疊框、參數與呼叫慣例.html#六誰負責保存暫存器以及-16-byte-對齊)〈上面的 `sub $0x8,%rsp`：16 byte 對齊〉】
>
> **核心關鍵**：
>
> 1. ABI 規定：執行 `call` 的那一刻，`%rsp` 必須是 16 的倍數。
> 2. 呼叫 `f` 的人照規定對齊，但 `call f` 推了 8 byte 返回位址，進到 `f` 時 `%rsp` 是「16 的倍數 − 8」。
> 3. `f` 要 `call g`，必須再挪 8 byte：沒東西要存，就用 `sub $0x8,%rsp` 單純挪。
>
> **詳細說明**：要 16 的原因：有些指令（例如 SSE 的 `movaps`）要求記憶體位址是 16 的倍數，否則會當掉。

#### 多檔 2-2. 如果 `mathx.c` 沒有 `#include "mathx.h"`，有人把 `mathx.c` 的定義改成 `int square(int x)` 卻忘了改 `mathx.h`，會發生什麼事、在哪個階段（編譯、連結、執行）才發現？

> 題目補充（2026-10-22 批改後補上，原題沒寫清楚）：呼叫端 `main.c` **有** `#include "mathx.h"`，內容是：
>
> ```c
> #include <stdio.h>
> #include "mathx.h"
>
> int main(void)
> {
>     long r = square(100000);
>     printf("%ld\n", r);
>     return 0;
> }
> ```

> 題目：如果 `mathx.c` 沒有 `#include "mathx.h"`，有人把 `mathx.c` 的定義改成 `int square(int x)` 卻忘了改 `mathx.h`，會發生什麼事、在哪個階段（編譯、連結、執行）才發現？

```

> **批改**：**對**。抓到：編譯不報錯（`mathx.c` 沒引入、`main.c` 照 `long` 編）、連結只比名字、**執行時**結果錯才發現（10-23 沒講明的「執行時、結果錯」這次有了）。
>
> **參考答案**【[第三節](../html/c/多檔案的C程式-標頭檔、static與extern、連結錯誤與make.html#定義的那個-c-為什麼也要-include-自己的標頭檔)〈定義的那個 `.c` 為什麼也要 `#include` 自己的標頭檔〉最後一段】

> **核心關鍵**：

### 多檔 3. `static` 的兩種意思

> 盒子 1｜過去的作答：[s1-06 quiz.md 第 3 題](../small-project/s1-06-multi-file/quiz.md#3-static-的兩種意思)、[10-23 複習](./2026-10-23-大複習-hello-gcc-GNU-interp-ELF-objdump-C資料-字元-陣列-組語-組語二-多檔.md)

`static` 寫在函式外面和寫在函式裡面，各改變了什麼？用下面兩個例子說明：(a) `a.c`、`b.c` 各有一個 `static int helper(void)`，為什麼能一起連結，拿掉 `static` 為什麼就 `multiple definition`？(b) `next_id()` 呼叫三次回傳 1、2、3，`plain_id()` 每次都是 1，兩個 `n` 各放在記憶體的哪裡？

```c
/* a.c（b.c 一樣，只是 helper 回傳 2、函式叫 b_value） */
static int helper(void)
{
    return 1;
}

int a_value(void)
{
    return helper();
}
```
```c
/* nextid.c 的兩個函式 */
int next_id(void)
{
    static int n = 0;
    n = n + 1;
    return n;
}

int plain_id(void)
{
    int n = 0;
    n = n + 1;
    return n;
}
```

#### 多檔 3-1. `static` 寫在函式外面和寫在函式裡面，各改變了什麼？

```
static在函式外面,這樣這個函式的符號就會變成local,只有local這個檔案可以用這個函式
static在函式裏面,這種靜態變數不會存到函式堆疊上,而是存在.bss/.data上,,只有這個函式能使用,不想區域變數一樣,函式ret後就沒了
```

> **批改**：**對**。抓到：外面 → `LOCAL`、只有這個檔案用；裡面 → 放 `.bss`／`.data`、只有這個函式能用、`ret` 後不會消失（10-23 說成「本檔可見」的錯改正了）。小修：檔案層級的 `static` 對全域變數也一樣，不只函式。
>
> **參考答案**【[第五節](../html/c/多檔案的C程式-標頭檔、static與extern、連結錯誤與make.html#五static兩種完全不同的意思)】
>
> **核心關鍵**：
>
> 1. 函式外面：改的是名字的**可見範圍**——只在這個 `.c` 有效，符號變成 `LOCAL`，連結器不拿它跟別的檔案配對。
> 2. 函式裡面：改的是**儲存期間**——不放堆疊，放在固定記憶體（`.bss`／`.data`），整個程式執行期間只有一份，值留到下一次呼叫；名字仍然只在那個函式裡看得到。

#### 多檔 3-2. (a) `a.c`、`b.c` 各有一個 `static int helper(void)`，為什麼能一起連結，拿掉 `static` 為什麼就 `multiple definition`？

```
因爲兩個helper都是local, ld不會去把他們兩個連結.
拿掉static,兩個都變global,ld在連結的時候就會發現這兩個符號都有定義,他不知道選哪個就會報這個錯誤
```

> **批改**：**對**。
>
> **參考答案**【[第五節](../html/c/多檔案的C程式-標頭檔、static與extern、連結錯誤與make.html#檔案層級的-static讓名字變成-local)〈檔案層級的 `static`〉】
>
> **核心關鍵**：
>
> 1. 有 `static`：兩個 `helper` 都是 `LOCAL`，連結器做符號解析時只用 `GLOBAL` 配對，所以同名也不衝突。
> 2. 拿掉 `static`：兩個 `.o` 各有一個 `GLOBAL` 的 `helper` 定義 → 同名的 `GLOBAL` 定義有兩個 → `multiple definition`。
>
> **詳細說明**：兩份內容不一樣（回傳 1 和 2）不是重點；就算一模一樣，有兩個同名的 `GLOBAL` 定義也是錯。

#### 多檔 3-3. (b) `next_id()` 呼叫三次回傳 1、2、3，`plain_id()` 每次都是 1，兩個 `n` 各放在記憶體的哪裡？

```
next_id: 放在.bss上
plain_id: 放在.stack
```

> **批改**：**對**。小修：`.stack` 不是區段名，寫「堆疊（堆疊框裡）」就好。
>
> **參考答案**【[第五節](../html/c/多檔案的C程式-標頭檔、static與extern、連結錯誤與make.html#函式裡的-static不放堆疊值留到下一次)〈函式裡的 `static`〉】
>
> **核心關鍵**：
>
> 1. `next_id` 的 `n`：固定記憶體 `.bss`（初值 0），只初始化一次、值留著，所以 1、2、3。
> 2. `plain_id` 的 `n`：堆疊框裡（`-0x4(%rbp)`），每次呼叫都重新設成 0，所以每次都是 1。

### 多檔 4. 標頭檔裡的 `long hits;`

> 盒子 1｜過去的作答：[s1-06 quiz.md 第 4 題](../small-project/s1-06-multi-file/quiz.md#4-標頭檔裡的-long-hits)、[10-23 複習](./2026-10-23-大複習-hello-gcc-GNU-interp-ELF-objdump-C資料-字元-陣列-組語-組語二-多檔.md)

下面的 `hits.h` 被 `hits.c` 和 `hits_main.c` 都 `#include`，兩個 `.c` 都沒有再寫 `hits` 的定義。本機 gcc 13 連結時出現 `multiple definition of 'hits'`。為什麼？已經有 include guard 了，為什麼沒擋住？該怎麼改（標頭檔寫什麼、哪裡寫什麼）？為什麼同樣的程式碼在舊版 gcc 上可以連結？

```c
/* hits.h */
#ifndef HITS_H
#define HITS_H

long hits;
void hit(void);

#endif
```
```c
/* hits.c */
#include "hits.h"

void hit(void)
{
    hits = hits + 1;
}
```
```c
/* hits_main.c */
#include <stdio.h>
#include "hits.h"

int main(void)
{
    hit();
    hit();
    hit();
    printf("hits = %ld\n", hits);
    return 0;
}
```
編譯與連結：`gcc -c hits.c hits_main.c && gcc -o hits hits_main.o hits.o`

#### 多檔 4-1. 為什麼？

```
因爲編譯時hits_main.c跟hits.c是各自編譯,而直接寫 long hits會被視爲定義
所以在連結的時候ld就會認爲同一個符號名稱定義了兩次
```

> **批改**：**對**。抓到：`long hits;` 本身就是定義，兩個 `.o` 各一份（10-23 缺的這點這次有了）。
>
> **參考答案**【[第六節](../html/c/多檔案的C程式-標頭檔、static與extern、連結錯誤與make.html#忘了-extern每個-c-都有一份定義)〈忘了 `extern`：每個 `.c` 都有一份定義〉】
>
> **核心關鍵**：
>
> 1. `long hits;`（沒有 `extern`、沒有初值）是暫定定義，實際上就是**定義**。
> 2. 標頭檔被貼進兩個 `.c`，兩個 `.o` 各有一個 `GLOBAL` 的 `hits` → 連結器看到兩個同名定義 → `multiple definition`。

#### 多檔 4-2. 已經有 include guard 了，為什麼沒擋住？

```
include gurad 沒辦法擋住多個檔案的編譯因爲各自引入,他只能一個檔案編譯的時候避免重複引入
```

> **批改**：**對**。
>
> **參考答案**【[第六節](../html/c/多檔案的C程式-標頭檔、static與extern、連結錯誤與make.html#忘了-extern每個-c-都有一份定義)〈忘了 `extern`：每個 `.c` 都有一份定義〉最後一段】
>
> **核心關鍵**：
>
> 1. include guard 只防止**同一個編譯單元**裡被貼兩次（`HITS_H` 這個巨集只在編譯這一個 `.c` 的期間有效）。
> 2. `hits.c` 和 `hits_main.c` 是分開編譯的兩個編譯單元，各貼一次是正常的；錯誤發生在連結時兩個 `.o` 之間，guard 管不到。

#### 多檔 4-3. 該怎麼改（標頭檔寫什麼、哪裡寫什麼）？

```
hits.h 寫 extern long hits; 這是全域的宣告 非定義
在hits.c 加入 long hits = 0;之類的定義
這樣編譯的時候 main只有宣告, 定義在hits.c ld就可以連結起來
```

> **批改**：**對**。
>
> **參考答案**【[第六節](../html/c/多檔案的C程式-標頭檔、static與extern、連結錯誤與make.html#六extern全域變數的宣告與定義)〈整理：全域變數放哪裡〉】
>
> **核心關鍵**：
>
> 1. 標頭檔寫 `extern long hits;`：宣告，不配置空間，幾個 `.c` 引入都沒關係。
> 2. **恰好一個 `.c`**（`hits.c`）寫定義 `long hits = 0;`，而且這個 `.c` 也引入 `hits.h`，讓編譯器檢查宣告與定義的型別一致。

#### 多檔 4-4. 為什麼同樣的程式碼在舊版 gcc 上可以連結？

```
舊版的gcc預設打開-fcommon,這樣hits會變成COM 會被統一起來 可以直接連接
```

> **批改**：**對**。
>
> **參考答案**【[第六節](../html/c/多檔案的C程式-標頭檔、static與extern、連結錯誤與make.html#忘了-extern每個-c-都有一份定義)〈`-fcommon`：舊程式為什麼這樣寫也能動〉】
>
> **核心關鍵**：
>
> 1. gcc 10 以前預設 `-fcommon`：沒有初值的全域變數被標成 **common 符號**（`Ndx` 是 `COM`，`nm` 印 `C`），不是一般的定義。
> 2. 連結器遇到好幾個同名的 common 符號會**合併成一份**，不報錯，兩個檔案共用同一個 `hits`。
>
> **詳細說明**：gcc 10 起預設改成 `-fno-common`。正確修法是補 `extern`（4-3），不是加 `-fcommon`。

### 多檔 5. 情境題：改了標頭檔，`make` 說不用重編

情境題：同事的專案用下面的 `Makefile`。他把 `config.h` 裡的 `#define BUF_SIZE 64` 改成 `128`，存檔後執行 `make`，`make` 只印了 `make: 'server' is up to date.`，跑起來的緩衝區還是 64。`make` 是怎麼判斷不用重編的？為什麼這個判斷錯了？你會怎麼改這個 `Makefile`，讓以後改任何標頭檔都會重編該重編的檔案？（不必寫出完整的 `Makefile`，說明要改哪些地方、各自的作用即可。）

```make
server: server.o net.o
	gcc -o server server.o net.o

server.o: server.c
	gcc -Wall -c server.c

net.o: net.c
	gcc -Wall -c net.c
```
（`server.c` 和 `net.c` 都 `#include "config.h"`；命令前面是 TAB。）

#### 多檔 5-1. `make` 是怎麼判斷不用重編的？

```
檢查目標的最後更新時間是否比 先決條件舊, 如果是就更新 否則就不重編
```

> **批改**：**對**。
>
> **參考答案**【[第七節](../html/c/多檔案的C程式-標頭檔、static與extern、連結錯誤與make.html#文法規則)〈文法：規則〉】
>
> **核心關鍵**：
>
> 1. 目標不存在，或任何一個**先決條件的修改時間比目標新**，就執行命令；否則跳過。
> 2. 本例 `server.o`、`net.o` 的先決條件只有各自的 `.c`，`.c` 都沒改 → 都不重編 → `server` 也不必重新連結。

#### 多檔 5-2. 為什麼這個判斷錯了？

```
他改的是config.h,而config.h沒有出現在任何先決條件裏
```

> **批改**：**對**。
>
> **參考答案**【[第七節](../html/c/多檔案的C程式-標頭檔、static與extern、連結錯誤與make.html#先決條件漏了標頭檔make-說不用重編結果是舊的)〈先決條件漏了標頭檔〉】
>
> **核心關鍵**：
>
> 1. `make` 只看 `Makefile` 寫的先決條件，不會自己去讀 `.c` 裡 `#include` 了哪些檔案；`config.h` 沒列進去，它改了 `make` 不知道。

#### 多檔 5-3. 你會怎麼改這個 `Makefile`，讓以後改任何標頭檔都會重編該重編的檔案？（不必寫出完整的 `Makefile`，說明要改哪些地方、各自的作用即可。）

```
gcc option 增加
-MMD: 如果有使用者的header檔案 產生.d(系統的header不要)
-MP: 把目前是.h的先決條件清空,避免觸發
-include $(OBJS:.o=.d): 用來引入.d到makefile,前面的-是說明第一次沒有.d的時候也不報錯
這樣header也加入先決條件了
```

> **批改**：**大致對**。`-MMD` 產生 `.d`、`-include` 讀進 `.d`、`-` 讓第一次沒有 `.d` 時不報錯，都對（10-23 缺的 `-` 這次有了）。`-MP` 又說錯：它不是「把 `.h` 的先決條件清空」，是替每個標頭檔**多加一條沒有先決條件、沒有命令的空規則**（`config.h:`），目的是標頭檔被刪掉或改名後，`make` 不會因為 `.d` 裡還列著它、又找不到規則而停下（`No rule to make target`）。另外 `-include` 是 `Makefile` 的指令，不是 gcc 的選項。
>
> **參考答案**【[第七節](../html/c/多檔案的C程式-標頭檔、static與extern、連結錯誤與make.html#實用的-makefile變數樣式規則自動產生相依)〈實用的 `Makefile`〉第 5、6 點】
>
> **核心關鍵**：
>
> 1. 編譯命令加 `-MMD -MP`：編譯時順便寫出 `.d` 檔，內容是「這個 `.o` 依賴哪些使用者標頭檔」的規則（例如 `server.o: server.c config.h`）；`-MP` 再替每個標頭檔加一條空規則，標頭檔刪掉或改名時 `make` 不會停下來。
> 2. `Makefile` 加 `-include $(OBJS:.o=.d)`：把 `.d` 讀進來、跟原本的規則合併，`config.h` 就成了 `.o` 的先決條件；`-` 表示第一次還沒有 `.d` 時不報錯。

> **核心關鍵**：
>
> 1. 符號表裡有：`total`、`add`、`main`、`limit`、`puts`（加上 ELF 記帳用的 `FILE`、`SECTION` 列）。
> 2. 這個檔案提供（有定義，`Ndx` 是區段編號）：`total`（`.bss`）、`add`、`main`（`.text`）。
> 3. 需要別人提供（`UND`）：`limit`（只有 `extern` 宣告）、`puts`（libc）。

#### 多檔 6-2. `n`、`sum`、`i` 為什麼不在符號表裡？

```
因爲 n, sum, i這些變數都可以直接存到各自函式的堆疊上,在函式內部就可以解決,
無需像靜態變數 或 全域變數,需要特定的記憶體位址(.bss/.data)
```

> **批改**：**對**。抓到：放在堆疊上、函式內部就解決，不像全域／靜態變數需要固定位址。
>
> **參考答案**【[第一節](../html/c/多檔案的C程式-標頭檔、static與extern、連結錯誤與make.html#一本課在做什麼編譯器一次只看一個-c)〈上面說的「符號」到底是什麼〉「區域變數不是符號」那段】
>
> **核心關鍵**：
>
> 1. `n`（參數）、`sum`、`i` 是函式裡的變數，放在堆疊框（或暫存器），位址是執行時 `%rbp` 的偏移。
> 2. 這個偏移編譯器自己就寫得出來，不需要連結器決定位址，所以不需要名字、不進符號表。

#### 多檔 6-3. 對連結器來說，符號表裡的一個符號代表什麼、拿來做什麼用？

```
對於連接器來說符號告訴他這個東西的類型,是obj,func還是notype,同時也告訴他這東西的大小,與偏移與名字
而相同符號名連接器要負責把他們接起來
```

> **批改**：**大致對**。符號的內容（名字、`FUNC`／`OBJECT`、大小、位置）與符號解析（同名接起來）對（10-23 把 `Type` 說成 C 型別的地方這次改正）。又漏**重定位**：連結器算出每個符號的最終位址，填進機器碼裡標著那個名字的洞（跟 10-22、10-23 缺同一點，第三次）。
>
> **參考答案**【[第一節](../html/c/多檔案的C程式-標頭檔、static與extern、連結錯誤與make.html#一本課在做什麼編譯器一次只看一個-c)〈上面說的「符號」到底是什麼〉】
>
> **核心關鍵**：
>
> 1. 一個符號 ＝ 名字＋它在哪裡（區段、偏移、大小）；有定義的代表「這個檔案提供」，`UND` 代表「這個檔案需要」。
> 2. 連結器用它做**符號解析**：把每個 `UND` 跟別的 `.o`／函式庫的 `GLOBAL` 定義配對（只比名字）。
> 3. 再做**重定位**：算出每個符號的最終位址，填進機器碼裡標著那個符號名字的洞。
