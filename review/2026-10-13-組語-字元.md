### 組語 7. 參數只佔暫存器的一部分

> `int widen_char(signed char c) { return c; }` 編出 `movsbl %dil, %eax`。
>
> 盒子 1｜過去的作答：[s1-04 quiz.md 第 7 題](../small-project/s1-04-asm-basics/quiz.md#7-參數只佔暫存器的一部分2026-10-06-課後提問新增)

用到的程式（檔案：[`dil.c`](../small-project/s1-04-asm-basics/dil.c)）：

```c
#include <stdio.h>

__attribute__((noinline)) int widen_char(signed char c) { return c; }   /* noinline：不准內嵌，才看得到真的呼叫 */

int main(void)
{
    printf("%d\n", widen_char(-1));
    return 0;
}
```

```sh
gcc -O2 -g dil.c -o dil
objdump -d --no-show-raw-insn dil
```

`widen_char` 編出來的組合語言（`objdump` 節錄）：

```asm
widen_char:
	endbr64                # 給 CPU 的控制流程保護標記，跟計算無關（佔 4 byte，所以下一條是 widen_char+4）
	movsbl	%dil, %eax     # 讀 %dil（1 byte），有號擴展成 4 byte 放進 %eax
	ret                    # 回傳 %eax
```

筆記的 gdb 實驗：停在 `movsbl` 之前，把 `%rdi` 整個改掉，再執行一條指令看結果。

```sh
gdb -batch -ex 'break *widen_char+4' -ex run -ex 'p/x $rdi' \
    -ex 'set $rdi = 0x11223344556677ff' -ex 'p/x $rdi' -ex 'p/x $dil' \
    -ex stepi -ex 'p $eax' -ex 'p/x $rax' -ex continue ./dil
```

（`break *widen_char+4`：停在 `widen_char` 開頭往後 4 byte 那條指令；`set $rdi = …`：改暫存器；`stepi`：只執行一條機器指令。）

#### 組語 7-1. 在 64 位元的機器上，為什麼它只讀 `%dil`，而不讀整個 `%rdi`？

```
因爲c的參數類型是signed char, 1byte, 因此讀低8位元dil
```

> **批改**：**大致對**。抓到「`c` 是 1 byte 的 `signed char`，所以讀 `%dil`」。缺第 2 點：**為什麼不能讀整個 `%rdi`**——高 7 byte 不屬於 `c`，呼叫的人沒有約定要放什麼，內容不保證（跟 10-08 缺同一點）。
>
> **參考答案**【[第三節](../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#三指令的文法助憶符大小後綴運算元)〈讀懂實驗一的範例：為什麼寫 `1(%rdi)`、為什麼用 `%dil`〉】
>
> **核心關鍵**：
>
> 1. 參數是 1 byte 的 `signed char`，只放在 `%rdi` 最低的 1 byte（`%dil`）。
> 2. 高 7 byte 呼叫的人沒有約定，**內容不保證**；讀整個 `%rdi` 會把垃圾一起讀進來。
>
> **詳細說明**：「64 位元系統」指暫存器和位址是 64 位元，不是每個資料都變成 8 byte。實例：`main` 寫 `%edi` 傳 −1，`%rdi` 是 `0x00000000ffffffff`，整個讀會得到 4294967295。

> 假設 `widen_char` 改成讀 4 byte 的 `movl %edi, %eax`，在上面的 `gdb` 實驗裡把 `%rdi` 改成 `0x11223344556677ff`。

#### 組語 7-4. 跟 C 期望的 −1 差在哪？

> 題目：（承 7-2）改成 `movl %edi, %eax` 之後得到的值，跟 C 期望的 −1 差在哪？

```
因爲rdi已經改成0x11223344556677ff, 因此eax就是0x556677ff
movl的話高位補0

c期望的-1是由movsbl	%dil, %eax來的, 0xff, 又是signed,高位補1 所以最後的eax是0xffffffff
```

> **批改**：**大致對**。兩個值都寫對了：`movl` 得到 `0x556677ff`，C 期望的 −1 是 `movsbl` 把 `0xff` 符號擴展成 `0xffffffff`。缺的是把差別講出來：**多讀的高 3 byte `0x556677` 是垃圾，不是 `c` 的一部分**，讀進來就變成一個正的大數（1432778751），不是 −1。
> 「`movl` 的話高位補 0」是在講 `%rax` 的高 32 位元被清掉，跟這題比的 `%eax` 無關。
> **組語 7 記為大致對**（盒子 1 → 1）。
>
> **參考答案**【[第三節](../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#三指令的文法助憶符大小後綴運算元)〈讀懂實驗一的範例：為什麼寫 `1(%rdi)`、為什麼用 `%dil`〉】
>
> **核心關鍵**：
>
> 1. C 的 `c` 只在最低 1 byte（`0xff`，符號擴展後是 −1）；讀 4 byte 會把高 3 byte 的垃圾 `0x556677` 一起讀進來，得到正的 1432778751，不是 −1。
>
> **詳細說明**：所以參數有多大，指令就讀多大的名字：`signed char` 讀 `%dil`、`short` 讀 `%di`、`int` 讀 `%edi`、`long` 和指標讀 `%rdi`。

### 組語 8. 暫存器的名字 vs 暫存器本身

> 盒子 1｜過去的作答：[s1-04 quiz.md 第 8 題](../small-project/s1-04-asm-basics/quiz.md#8-暫存器的名字-vs-暫存器本身2026-10-06-課後提問新增)

（程式同組語 7 的 `dil.c`。`main` 呼叫 `widen_char(-1)` 的那幾行，`objdump` 節錄：）

```asm
main:
	endbr64
	sub	$0x8,%rsp
	mov	$0xffffffff,%edi       # 呼叫的人：把 -1 放進 %edi（第 1 個參數）
	lea	0xf90(%rip),%rsi       # 準備 printf 的參數，跟本題無關
	call	widen_char         # 呼叫 widen_char
	...
widen_char:
	endbr64
	movsbl	%dil,%eax          # 被呼叫的人：只讀 %dil
	ret
```

#### 組語 8-1. `dil.c` 的組合語言裡只出現 `%edi`、`%dil`，沒有 `%rdi`，為什麼 gdb 能印出 `$rdi`？

```
edi,di,dil,rdi都是相同的暫存器,只是看的位元不同
```

> **批改**：**大致對**。第 1 點對：`%edi`、`%di`、`%dil` 都是 `%rdi` 這一個暫存器的一部分的名字。缺第 2 點：gdb 印得出來，是因為程式停下時 gdb 向核心把**整組暫存器**讀出來，跟程式有沒有用到那個名字無關。
>
> **參考答案**【[第三節](../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#三指令的文法助憶符大小後綴運算元)〈組合語言裡只有 `%edi`、`%dil`，為什麼 gdb 印得出 `$rdi`？〉】
>
> **核心關鍵**：
>
> 1. `%edi`、`%di`、`%dil` 不是另外的暫存器，都是 `%rdi` 這**一個**暫存器的一部分的名字。
> 2. 程式停下時，gdb 請核心把整組暫存器讀出來，所以任何暫存器都印得出來，跟程式有沒有用到無關。
>
> **詳細說明**：實驗裡 `widen_char` 沒用到 `%rcx`，`info registers rcx` 照樣印得出來，是之前留下來的值。

> **批改**：**錯**。**不會**清。gdb 的 `set $edi = …` 只改 `%rdi` 的低 4 byte，高 4 byte 保留原值（跟 10-08 錯在同一處）。

> **參考答案**【[第三節](../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#三指令的文法助憶符大小後綴運算元)〈組合語言裡只有 `%edi`、`%dil`，為什麼 gdb 印得出 `$rdi`？〉】
>
> **核心關鍵**：
>
> 1. **不會**：gdb 的 `set $edi = …` 只改 `%rdi` 的低 4 byte，高 4 byte 保留原值。
>
> **詳細說明**：實驗先把 `$rdi` 設成 `0x11223344556677ff`，`set $edi = 0xaabbccdd` 之後 `$rdi` 是 `0x11223344aabbccdd`。

#### 組語 8-3. 跟 CPU 執行 `movl $0xaabbccdd, %edi` 有什麼不同？

> 題目：（承 8-2）gdb 的 `set $edi = 0xaabbccdd` 跟 CPU 執行 `movl $0xaabbccdd, %edi` 有什麼不同？

```
用movl, 根據高32位自動補0的規則,到edi時,會自動補0,gdb的話是直接把設定的值寫進rdi
```

> **批改**：**不完整**。第 1 點對：CPU 執行 `movl` 會把高 32 位元清成 0。但 gdb 那半說成「直接把設定的值寫進 `rdi`」，配上 8-2 的「會」，等於認為 gdb 也清高位——兩邊其實相反：**清高位是 CPU 執行指令的規則，gdb 的 `set` 不是指令，不套用**，只改低 4 byte（跟 10-08 錯在同一處：把 gdb `set` 與 CPU `movl` 說反）。
> **組語 8 記為錯**（盒子 1 → 1）。
>
> **參考答案**【[第二節](../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#二暫存器cpu-裡的-16-個變數)〈寫低位的名字時，高位會怎樣？〉、[第三節](../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#三指令的文法助憶符大小後綴運算元)〈組合語言裡只有 `%edi`、`%dil`，為什麼 gdb 印得出 `$rdi`？〉】
>
> **核心關鍵**：
>
> 1. CPU 執行 `movl $0xaabbccdd, %edi` 會把 `%rdi` 的**高 32 位元清成 0**，結果是 `0x00000000aabbccdd`。
> 2. 「寫 32 位元清高位」是 CPU 執行指令的規則；gdb 的 `set` 不是指令，不套用這條規則。
>
> **詳細說明**：實例：`dil.c` 的 `main` 執行 `mov $0xffffffff,%edi`，`%rdi` 變成 `0x00000000ffffffff`（筆記 gdb 輸出 `$1 = 0xffffffff`）。用 gdb 改暫存器做實驗時要記得這個差別。
> 記法：**CPU 寫 32 位元 → 清；gdb 改 → 只改你說的那幾 byte**。

#### 組語 9-2. 為什麼這樣補，`signed char` 的 −1 變成 `int` 之後才會還是 −1（用二補數的權重解釋）？


>
> **核心關鍵**：
>

```asm
copy_val:
```

```
	mov	%rdi,%rax       # 直接拿rdi存的值,複製到rax
	ret                 # 回傳 %rax
deref:
	endbr64
	mov	(%rdi),%rax     # 把rdi的值當作地址,去讀這個地址存了什麼值,再複製到rax
	ret

```

> **批改**：**對**。沒括號複製數字本身；有括號把數字當位址去讀。

> **詳細說明**：暫存器裡永遠只是一個 64 位元的數字；括號的意思是「它是位址，請去記憶體的那裡」。

> **核心關鍵**：
>
> 1. `%rdi` ↔ 用變數的值 `x`（`return x;`）。
> 2. `(%rdi)` ↔ 用指標指向的值 `*p`（`return *p;`）。
>
> **詳細說明**：括號就是 C 的 `*`。筆記的 `paren.c`：`copy_val` 回傳 `x`，`deref` 回傳 `*p`。

#### 組語 10-3. 如果 `%rdi` 裡是 1234，哪一個會 segfault，為什麼？

### 組語 12. 檔案裡的位址 vs 執行時的位址

> 用 `objdump -d paren` 查到 `deref+4` 在 `0x11f4`，`break *0x11f4` 之後 `run` 卻得到 `Cannot access memory at address 0x11f4`，`break *deref+4` 就沒問題。

#### 組語 12-1. 為什麼？

> 2. `*deref+4` 裡有符號名稱，程式載入後 gdb 用新的位址重算成 `0x5555555551f4`；寫死的 `0x11f4` 只是數字，不會重算。

### 組語 14. 四個旗標各在回答什麼

```asm

	testl	%edi, %edi            # 算 n & n，只設旗標
	jle	.L4                   # 結果 ≤ 0 就跳到 .L4（回傳 0）
	leal	1(%rdi), %ecx         # %ecx = %rdi + 1

	movl	$2, %eax              # %eax = 2
	movl	$1, %edx              # %edx = 1
	cmpl	%ecx, %eax            # 比較 %eax 與 %ecx
	je	.L1                   # 相等就跳 .L1
.L3:

	addl	$2, %eax              # %eax += 2
	cmpl	%ecx, %eax            # 比較 %eax 與 %ecx
	jne	.L3                   # 不相等就再一圈
.L1:
	movl	%edx, %eax            # 回傳值 = %edx
	ret
.L4:
	xorl	%edx, %edx
	movl	%edx, %eax            # 回傳 0
	ret
```

```
testl 只是要驗證 edi是否<=0 所以只需要看旗標
andl只是要用edi去判斷他是不是奇數或偶數,而且後面edi已經沒有用了
```

> 2. 改成 `unsigned char c`（或比較時寫 `(unsigned char)c > 127`），byte 照 0～255 讀，`> 127` 的意思才正確。
>
> **詳細說明**：例如 `0xe5` 用 `char` 讀是 −27。`-Wextra` 的 `-Wtype-limits` 會警告「永遠為假」。不要改成 `unsigned int`：會先符號擴展成 `0xffffffe5`，判斷碰巧對、值卻是錯的；也不要寫 `c < 0`，它依賴 `char` 有號，換到 ARM 就失效。
