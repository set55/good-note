> **參考答案**【[第二節](../html/c/objdump能不能代替ldd找依賴庫-需求單與實際載入.html#二為什麼會差這麼多兩者看的是不同時間點)】
>
> **核心關鍵**：
>
> 1. 多出來的三類：**間接依賴**（最大宗，例如 `libssl.so.3` 是 `libcurl.so.4` 要的，不是 `curl` 自己要的）、`linux-vdso.so.1`（核心提供的虛擬函式庫）、動態載入器本身。
> 2. `objdump -p` 只讀連結時寫進 `curl` 的需求單（`NEEDED`），裡面**只有直接依賴**；`ldd` 是請載入器實際跑一次，一路照每個函式庫的 `NEEDED` 找下去，才拿到完整清單。
>
> **詳細說明**：`NEEDED` 放在 dynamic section，不在檔頭。另外兩類也不會出現在 `curl` 的需求單裡：vdso 是核心在執行時直接放進行程的，沒有對應的檔案；載入器的路徑寫在 `INTERP`，不在 `NEEDED`。

### 組語二 2. 堆疊框

> 盒子 2｜過去的作答：[s1-05 quiz.md 第 2 題](../small-project/s1-05-asm-calls/quiz.md#2-堆疊框)、[10-23 複習](./2026-10-23-大複習-hello-gcc-GNU-interp-ELF-objdump-C資料-字元-陣列-組語-組語二-多檔.md)、[10-24 複習](./2026-10-24-gcc-GNU-ELF-objdump-C資料-字元-陣列-組語-組語二-多檔.md)、[10-25 複習](./2026-10-25-C資料-陣列-組語-組語二-多檔.md)、[10-28 複習](./2026-10-28-ELF-C資料-陣列-組語-組語二-多檔.md#組語二-2-堆疊框)

完整原始碼（檔案：[`frame.c`](../small-project/s1-05-asm-calls/frame.c)）與編譯指令：

```c
#include <stdio.h>

long add3(long a, long b, long c)
{
    long s = a + b;
    return s + c;
}

int main(void)
{
    long r = add3(1, 2, 3);
    printf("%ld\n", r);
    return 0;
}
```

```sh
gcc -O0 -g -fno-asynchronous-unwind-tables frame.c -o frame
objdump -d --no-show-raw-insn frame
```

```asm
add3:                                 main:
  push   %rbp                           push   %rbp
  mov    %rsp,%rbp                      mov    %rsp,%rbp
  mov    %rdi,-0x18(%rbp)               sub    $0x10,%rsp
  ...（沒有 sub、沒有 call）              ...（有 call add3、call printf）
  pop    %rbp                           leave
  ret                                   ret
```

#### 組語二 2-1. 函式開頭的 `push %rbp` 和 `mov %rsp,%rbp` 各在做什麼？

```
目的: 儲存%rbp的原值, 並且把%rbp指向函式堆疊的頂端作爲基準

push %rbp: rsp減掉8byte,並且補上%rbp的原值
mov %rsp %rbp: 將%rsp的值複製到%rbp裏
```

> **批改**：**對**。`push %rbp` 存呼叫者的 `%rbp`、`mov %rsp,%rbp` 把現在的頂端定成這個函式的基準點，兩點都有，每條指令的動作（`%rsp` 減 8、把值寫進去；複製 `%rsp` 到 `%rbp`）也寫對了。小修（不扣分）：「原值」可以寫明是**呼叫者的** `%rbp`；AT&T 語法兩個運算元之間要逗號：`mov %rsp,%rbp`。
>
> **參考答案**【[第四節](../html/c/x86-64組合語言入門二-call與ret、堆疊框、參數與呼叫慣例.html#四堆疊框pushq-rbp-movq-rsp-rbp-與-leave)】
>
> **核心關鍵**：
>
> 1. `push %rbp`：把**呼叫者的** `%rbp` 存到堆疊上，返回前要還原。
> 2. `mov %rsp,%rbp`：把現在的頂端定成自己堆疊框的**基準點**，之後區域變數用 `%rbp` 加固定的負偏移存取（例如 `-0x18(%rbp)`）。
>
> **詳細說明**：每個框的 `%rbp` 那格都存著上一層的 `%rbp`，串成一條鏈，`bt` 就是沿著它往回找。

#### 組語二 2-2. `main` 結尾的 `leave` 等於哪兩條指令？

```
mov %rbp, %rsp : rsp移到堆疊頂端順便清除sub的值
pop %rbp : %rbp復原,%rsp移到返回位址那格
```

> **批改**：**對**。`mov %rbp,%rsp` 把 `sub` 開的空間丟掉、`pop %rbp` 還原，之後 `%rsp` 指著返回位址給 `ret` 用，都對。小修（不扣分）：「`%rsp` 移到堆疊頂端」不精確——是移回**基準點**（`%rbp` 指的那格，存著舊 `%rbp`），移完它就是新的頂端。
>
> **參考答案**【[第四節](../html/c/x86-64組合語言入門二-call與ret、堆疊框、參數與呼叫慣例.html#四堆疊框pushq-rbp-movq-rsp-rbp-與-leave)〈`leave`：一條指令做兩件事〉】
>
> **核心關鍵**：
>
> 1. `mov %rbp,%rsp`：把 `%rsp` 拉回基準點，`sub` 開的空間一次丟掉。
> 2. `pop %rbp`：還原呼叫者的 `%rbp`。
>
> **詳細說明**：`pop` 之後 `%rsp` 剛好指著 `call` 推進來的返回位址，下一條 `ret` 就從那格取。

#### 組語二 2-3. `add3` 把區域變數放在 `%rsp` 下面、沒有 `sub %rsp`，`main` 卻要 `sub $0x10,%rsp`，為什麼？

```
根據ABI,%rsp下方128byte是紅區,其他人不能修改裏面的堆疊,而且add3本身是葉函式,沒有push也沒有call,所以不需要擔心返回位址
會改動到區域變數

main有call,他爲了避免返回位址改動到區域變數,所以-16byte
```

> **批改**：**對**（組語二 2 整題對，盒子 2 → 3，11-07 再考）。紅區（ABI 保證 `%rsp` 下方 128 byte 別人不會蓋）＋葉函式（自己沒有 `push`／`call`）兩半都有了——10-24、10-28 都缺紅區，這次補齊；`main` 那一半也對：`call` 推返回位址會寫在 `%rsp` 下面、蓋掉那一區，所以先 `sub`。小修（不扣分）：紅區保證的「別人」指訊號處理函式這類**非同步**進來的程式碼，不包含函式自己的 `call`，這正是 `main` 雖然也有紅區、還是要 `sub` 的原因。
>
> **參考答案**【[第四節](../html/c/x86-64組合語言入門二-call與ret、堆疊框、參數與呼叫慣例.html#四堆疊框pushq-rbp-movq-rsp-rbp-與-leave)〈上圖 `add3` 的變數在 `%rsp` 的「下面」：紅區〉】
>
> **核心關鍵**：
>
> 1. **紅區**：ABI 保證 `%rsp` 下方 128 byte 不會被別人蓋掉；`add3` 是葉函式，自己也不會 `push`／`call`，所以直接用、省一條 `sub`。
> 2. `main` 要 `call`：`call` 推返回位址會寫在 `%rsp` 下面、蓋掉那一區，所以 gcc 對會 `call` 的函式一律 `sub`，把變數空間放進堆疊（`%rsp` 上面）。
>
> **詳細說明**：`sub` 的大小是 `0x10` 不是 8，是 16 byte 對齊的緣故。kernel 不能用紅區（中斷會直接推資料到目前的堆疊上），所以編譯時加 `-mno-red-zone`。
