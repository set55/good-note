## ELF：[ELF是什麼-可執行與可連結格式的兩種視角](../html/c/ELF是什麼-可執行與可連結格式的兩種視角.html)

### ELF 1. ELF 三個字母各代表什麼？為什麼說「Executable」和「Linkable」對應兩種不同的讀者？

> 盒子 3｜過去的作答：[s1-01 quiz.md 第 1 題](../small-project/s1-01-hello-compile/quiz.md#1-elf-三個字母各代表什麼為什麼說executable和linkable對應兩種不同的讀者)、[10-06 複習](./2026-10-06-字元-interp-ELF-gcc-GNU.md)、[10-21 複習](./2026-10-21-字元-objdump-陣列-組語-interp-ELF-GNU.md)

```
executable and linkable format
executable 對應的是像kernel / interpreter, 執行看的是program header,有動態載入器的路徑,dynamic section的需求單, 載入段
符號重定位,這些都是執行階段看與做的事情

linkable 對應的是連結器ld 看的是section header 與 symbol table, 連結符號,重定位 補洞等,補不了的寫需求單,執行階段由interpreter載入
```

> **批改**：**對**。抓到：Executable and Linkable Format；執行視角是**程式標頭表**（載入段），給核心與動態載入器看；連結視角是**區段標頭表**（加上符號表），給連結器 `ld` 看（10-21 缺的「區段標頭表」這次有了）。小修（不扣分）：「符號重定位」寫在 executable 那一半要分清楚——執行時動態載入器做的是**動態重定位**（照 `.dynamic` 的需求單把位址填進 GOT），它找到 `.dynamic` 也是靠程式標頭表裡 `DYNAMIC` 那一項；把 `.o` 裡的洞補起來的重定位是 `ld` 連結時讀區段做的。
> **ELF 1 記為對**（盒子 3 → 4）。
>
> **參考答案**【[第一節](../html/c/ELF是什麼-可執行與可連結格式的兩種視角.html#一名字的意思)、[第四節](../html/c/ELF是什麼-可執行與可連結格式的兩種視角.html#四名字的關鍵兩種視角)】
>
> **核心關鍵**：
>
> 1. Executable and Linkable Format（可執行與可連結格式）。
> 2. ELF 有兩張目錄：**程式標頭表**（執行視角，單位是載入段 segment）給核心與動態載入器看——載入時把哪幾塊放進記憶體、權限是什麼。
> 3. **區段標頭表**（連結視角，單位是區段 section）給連結器 `ld` 看——每個區段叫什麼、在哪、多大。
>
> **詳細說明**：`nm`、`objdump` 也讀區段標頭表。`.o` 只有區段標頭表、沒有程式標頭表（`readelf -l hello.o` 說 `There are no program headers in this file`），所以只能給連結器用、不能執行；連結器把區段合併、打包成載入段，寫出程式標頭表，「可連結的」才變成「可執行的」。

### C資料 5. 情境題：你從網路封包裡讀到 4 個 byte，依序是 `00 00 01 00`。協定規定數字用大端序，所以它代表 256。如果直接用 `int *` 把這 4 個 byte 讀進本機（x86-64），會得到多少？為什麼？

> 盒子 2｜過去的作答：[s1-02 quiz.md 第 5 題](../small-project/s1-02-data-repr/quiz.md#5-情境題你從網路封包裡讀到-4-個-byte依序是-00-00-01-00協定規定數字用大端序所以它代表-256如果直接用-int--把這-4-個-byte-讀進本機x86-64會得到多少為什麼)、[10-10 複習](./2026-10-10-C資料-GNU-interp-hello-gcc.md)、[10-24 複習](./2026-10-24-gcc-GNU-ELF-objdump-C資料-字元-陣列-組語-組語二-多檔.md)、[10-25 複習](./2026-10-25-C資料-陣列-組語-組語二-多檔.md)

```
00 01 00 00 
65536
因爲本機電腦是小端序,所以要反過來讀
```

> **批改**：**對**。抓到：65536；x86-64 是小端序，位址最低的 byte 當最低位。小修（不扣分，跟 10-25 同一點）：「`00 01 00 00`」是把 byte 順序倒過來、照人習慣的大端寫法寫出來的數字 `0x00010000`；記憶體裡的 4 個 byte 沒有被搬動，「反過來讀」指的是 CPU **解讀**它們的方式。
> **C資料 5 記為對**（盒子 2 → 3）。
>
> **參考答案**【[第三節](../html/c/C的資料在記憶體裡長怎樣-位元組、指標、位元組順序與有號無號.html#三位元組順序endianness)】
>
> **核心關鍵**：
>
> 1. 會得到 65536（`0x00010000`），不是協定要的 256。
> 2. x86-64 是小端序：位址最低的 byte 當最低位，記憶體從低到高的 `00 00 01 00` 拼回來是 `0x00010000`。
>
> **詳細說明**：反過來排的單位是**整個 byte**（兩個十六進位數字一組），byte 裡面的 `01` 不會變成 `10`。網路上的位元組順序（network byte order）是大端序，所以讀網路資料要用 `ntohl`（network to host long）之類的函式轉換。在大端序的機器上這個函式什麼都不做，在 x86-64 上會把 4 個 byte 反過來。

### 組語 9. 符號擴展補的是什麼

> 盒子 2｜過去的作答：[s1-04 quiz.md 第 9 題](../small-project/s1-04-asm-basics/quiz.md#9-符號擴展補的是什麼2026-10-06-課後提問新增)、[10-13 複習](./2026-10-13-組語-字元.md)、[10-23 複習](./2026-10-23-大複習-hello-gcc-GNU-interp-ELF-objdump-C資料-字元-陣列-組語-組語二-多檔.md)、[10-24 複習](./2026-10-24-gcc-GNU-ELF-objdump-C資料-字元-陣列-組語-組語二-多檔.md)、[10-25 複習](./2026-10-25-C資料-陣列-組語-組語二-多檔.md)

#### 組語 9-1. `movsbl` 把 1 byte 擴展成 4 byte 時，新補的高 3 byte 是照哪一個位元補的？

```
看最高符號位(第7位元) 有1補1,有0補0
```

> **批改**：**對**。抓到：照第 7 位元（符號位）補，0 補 0、1 補 1。
>
> **參考答案**【[第三節](../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#三指令的文法助憶符大小後綴運算元)〈`%dil` 是 `0xff`，為什麼 `%eax` 變成 `0xffffffff`：符號擴展補的是第 7 位元〉】
>
> **核心關鍵**：
>
> 1. 照來源的**最高位元**（1 byte 的第 7 位元，也就是符號位）補：新多出來的每個 bit 都複製它。

#### 組語 9-2. 為什麼這樣補，`signed char` 的 −1 變成 `int` 之後才會還是 −1（用二補數的權重解釋）？

```
有號1byte的2補數權重是 -2^7
-1 = -2^7 + (2^6 + 2^5 + ....+1)

有號的4byte的2補數權重是 -2^31
-1 = -2^31 + (2^30 + 2^29 +..... + 1) => 從這裏可以看出 要-1 第31位, 第30位....都要是1
```

> **批改**：**對**。抓到：最高位的權重是負的，1 byte 是 −2⁷、4 byte 是 −2³¹；−1 ＝ −2³¹ ＋ (2³⁰ ＋ … ＋ 1)，所以 32 位元的 −1 第 31 位到第 0 位全是 1（10-25 少算第 31 位的地方這次寫對了）。小修（不扣分）：最後可以補一句把 9-1 接起來——低 8 位本來就全是 1，所以新補的第 8～31 位都要補 1，正好就是「照符號位補」。
> **組語 9 記為對**（盒子 2 → 3）。
>
> **參考答案**【[第三節](../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#三指令的文法助憶符大小後綴運算元)〈`%dil` 是 `0xff`，為什麼 `%eax` 變成 `0xffffffff`：符號擴展補的是第 7 位元〉】
>
> **核心關鍵**：
>
> 1. 二補數的**最高位權重是負的**：8 位元 `0xff` ＝ −2⁷ ＋ (2⁷ − 1) ＝ −1；32 位元 `0xffffffff` ＝ −2³¹ ＋ (2³¹ − 1) ＝ −1。
> 2. 所以高位全補 1，值還是 −1。
>
> **詳細說明**：對照：補 0 的話 `0x000000ff` ＝ 255，值就變了。一般化：前面多補一個 1，新的最高位權重是 −2⁸，原本那一位從 −2⁷ 變成 +2⁷，合起來 −2⁸ ＋ 2⁷ ＝ −2⁷，跟原來一樣，**值不變**；補幾個都同理。

### 組語二 2. 堆疊框

> 盒子 2｜過去的作答：[s1-05 quiz.md 第 2 題](../small-project/s1-05-asm-calls/quiz.md#2-堆疊框)、[10-23 複習](./2026-10-23-大複習-hello-gcc-GNU-interp-ELF-objdump-C資料-字元-陣列-組語-組語二-多檔.md)、[10-24 複習](./2026-10-24-gcc-GNU-ELF-objdump-C資料-字元-陣列-組語-組語二-多檔.md)、[10-25 複習](./2026-10-25-C資料-陣列-組語-組語二-多檔.md)

完整原始碼（檔案：[`frame.c`](../small-project/s1-05-asm-calls/frame.c)）與編譯指令：

```c
#include <stdio.h>

{
    long s = a + b;

}

int main(void)
{
    long r = add3(1, 2, 3);

```


```asm
add3:                                 main:
  push   %rbp                           push   %rbp
  mov    %rsp,%rbp                      mov    %rsp,%rbp
  mov    %rdi,-0x18(%rbp)               sub    $0x10,%rsp
  ...（沒有 sub、沒有 call）              ...（有 call add3、call printf）
  pop    %rbp                           leave
  ret                                   ret
```

#### 組語二 2-1. 函式開頭的 `push %rbp` 和 `mov %rsp,%rbp` 各在做什麼？

```
push %rbp ,是rsp下移,並挪出8byte 用來儲存%rbp的原值
mov %rsp, %rbp 則是把rbp指向當前堆疊的頂點,作爲函式堆疊的基準點
```

> **批改**：**對**。抓到：`push %rbp` 把舊的（呼叫者的）`%rbp` 存到堆疊；`mov %rsp,%rbp` 把現在的頂端定成自己的基準點。小修（不扣分）：基準點的用途是之後區域變數用 `%rbp` 加固定的負偏移存取（例如 `-0x18(%rbp)`），返回前再把存起來的舊值 `pop` 回去。
>
> **參考答案**【[第四節](../html/c/x86-64組合語言入門二-call與ret、堆疊框、參數與呼叫慣例.html#四堆疊框pushq-rbp-movq-rsp-rbp-與-leave)】
>
> **核心關鍵**：
>
> 1. `push %rbp`：把**呼叫者的** `%rbp` 存到堆疊上，返回前要還原。
> 2. `mov %rsp,%rbp`：把現在的頂端定成自己堆疊框的**基準點**，之後區域變數用 `%rbp` 加固定的負偏移存取。
>
> **詳細說明**：每個框的 `%rbp` 那格都存著上一層的 `%rbp`，串成一條鏈，`bt` 就是沿著它往回找。

#### 組語二 2-2. `main` 結尾的 `leave` 等於哪兩條指令？

```
leave 等於
mov %rbp %rsp => 可以清除掉之前push或sub的值
pop %rbp => 恢復rbp,並且清除rbp原值,rsp上移,指的那格是返回地址
```

> **批改**：**對**。抓到：`mov %rbp,%rsp`（丟掉 `push`／`sub` 開的空間）＋`pop %rbp`（還原舊 `%rbp`），之後 `%rsp` 指著返回位址給 `ret` 用。小修（不扣分）：AT&T 語法兩個運算元之間要逗號：`mov %rbp,%rsp`。
>
> **參考答案**【[第四節](../html/c/x86-64組合語言入門二-call與ret、堆疊框、參數與呼叫慣例.html#四堆疊框pushq-rbp-movq-rsp-rbp-與-leave)〈`leave`：一條指令做兩件事〉】
>
> **核心關鍵**：
>
> 1. `mov %rbp,%rsp`：把 `%rsp` 拉回基準點，`sub` 開的空間一次丟掉。
> 2. `pop %rbp`：還原呼叫者的 `%rbp`。

#### 組語二 2-3. `add3` 把區域變數放在 `%rsp` 下面、沒有 `sub %rsp`，`main` 卻要 `sub $0x10,%rsp`，為什麼？

```
add3 沒有 call 也沒有push,他是一個葉函式,所以不需要擔心區域函數,被call or push 改到區域函數
main 有call add3, 根據ABI的規則,爲了避免存儲返回位址的時候蓋到區域變數,規定%rsp需要下移預留空間
```

> **批改**：**大致對**。`main` 那一半對：`call` 推返回位址會寫在 `%rsp` 下面、蓋掉那一區，所以先 `sub` 把變數空間放進堆疊。`add3` 那一半缺「**紅區**」：你寫的「葉函式、自己不會 `call`／`push`」只說明 `add3` **自己**不會蓋，沒說明**別人**（例如訊號處理函式）為什麼也不會蓋——這是 ABI 的紅區保證：`%rsp` 下方 128 byte 留給目前這個函式，別人不會蓋。另外「根據 ABI 規定 `%rsp` 需要下移」放錯邊了：ABI 規定的是紅區；`main` 要 `sub` 是因為紅區保證的「別人」本來就不包含自己的 `call`（筆記第四節〈紅區保證的是「誰」不會蓋〉，10-25 你追問的那段）。跟 10-24 缺在同一處（紅區）。
> **組語二 2 記為大致對**（盒子 2 → 2，10-31 再考）。
>
> **參考答案**【[第四節](../html/c/x86-64組合語言入門二-call與ret、堆疊框、參數與呼叫慣例.html#四堆疊框pushq-rbp-movq-rsp-rbp-與-leave)〈上圖 `add3` 的變數在 `%rsp` 的「下面」：紅區〉】
>
> **核心關鍵**：
>
> 1. **紅區**：ABI 保證 `%rsp` 下方 128 byte 不會被別人蓋掉；`add3` 是葉函式，自己也不會 `push`／`call`，所以直接用、省一條 `sub`。
> 2. `main` 要 `call`：`call` 推返回位址會寫在 `%rsp` 下面、蓋掉那一區，所以 gcc 對會 `call` 的函式一律 `sub`，把變數空間放進堆疊（`%rsp` 上面）。
>
> **詳細說明**：`sub` 的大小是 `0x10` 不是 8，才是 16 byte 對齊的緣故。kernel 不能用紅區（中斷會直接推資料到目前的堆疊上），所以編譯時加 `-mno-red-zone`。

**自我練習**（不批改）

```

main雖然也有紅區,但他自己有call,所以有可能改到區域變數的堆疊上,所以%rsp下移預留空間
```

> 2. 所以從 `sum8` 的 `%rbp` 往上：`0(%rbp)` 舊 `%rbp`、`0x8(%rbp)` 返回位址、`0x10(%rbp)` 才是第 7 個。

> **詳細說明**：記法：**參數用正的偏移（在呼叫者那邊），區域變數用負的偏移（在自己這邊）**。

> **批改**：**對**。抓到：`sum8` 的 `ret` 不清參數；`call8` 自己推的兩個 8 byte 由它自己 `add $0x10,%rsp` 丟掉（誰推誰清）。

> **參考答案**【[第五節](../html/c/x86-64組合語言入門二-call與ret、堆疊框、參數與呼叫慣例.html#五參數與回傳值放哪裡)〈實驗：8 個參數，第 7、8 個去哪了〉】
>
> **核心關鍵**：

> 1. 第 7、8 個參數是 `call8` 自己 `push` 的（2 × 8 ＝ 16 byte）。
> 2. `sum8` 的 `ret` 只拿走返回位址、不清參數，所以由呼叫者 `call8` 在 `call` 回來後用 `add $0x10,%rsp` 丟掉。

### 多檔 5. 情境題：改了標頭檔，`make` 說不用重編

情境題：同事的專案用下面的 `Makefile`。他把 `config.h` 裡的 `#define BUF_SIZE 64` 改成 `128`，存檔後執行 `make`，`make` 只印了 `make: 'server' is up to date.`，跑起來的緩衝區還是 64。`make` 是怎麼判斷不用重編的？為什麼這個判斷錯了？你會怎麼改這個 `Makefile`，讓以後改任何標頭檔都會重編該重編的檔案？（不必寫出完整的 `Makefile`，說明要改哪些地方、各自的作用即可。）

#### 多檔 5-1. `make` 是怎麼判斷不用重編的？


> **批改**：**對**。抓到：目標比先決條件舊才重編。小修（不扣分）：完整的規則還有「目標不存在」也要重編；套到本例——`server.o`、`net.o` 的先決條件只有 `.c`，`.c` 沒改，所以全部跳過，`server` 也不重新連結。

> **核心關鍵**：
>
> 1. 目標不存在，或任何一個**先決條件的修改時間比目標新**，就執行命令；否則跳過。
> 2. 本例 `server.o`、`net.o` 的先決條件只有各自的 `.c`，`.c` 都沒改 → 都不重編 → `server` 也不必重新連結。

```

```

> **批改**：**對**。抓到：`config.h` 不在先決條件裡，`make` 不會自己去讀 `#include`，所以不知道它改了。

> **參考答案**【[第七節](../html/c/多檔案的C程式-標頭檔、static與extern、連結錯誤與make.html#先決條件漏了標頭檔make-說不用重編結果是舊的)〈先決條件漏了標頭檔〉】

> **核心關鍵**：

> 1. `make` 只看 `Makefile` 寫的先決條件，不會自己去讀 `.c` 裡 `#include` 了哪些檔案；`config.h` 沒列進去，它改了 `make` 不知道。

#### 多檔 5-3. 你會怎麼改這個 `Makefile`，讓以後改任何標頭檔都會重編該重編的檔案？（不必寫出完整的 `Makefile`，說明要改哪些地方、各自的作用即可。）


> **批改**：**對**。抓到：`-MMD`（寫 `.d`，不含系統標頭檔）、`-MP`（每個標頭檔一條沒有先決條件、沒有命令的空規則，刪掉或改名時 `make` 不會停）、`-include $(OBJS:.o=.d)`（把 `.d` 讀進來，`-` 是第一次沒有 `.d` 不報錯）。小修（不扣分）：講明 `-MMD -MP` 加在**編 `.o` 的那兩條命令**（或 `CFLAGS`）；`.d` 的內容就是 `server.o: server.c config.h` 這種規則，讀進來後 `config.h` 才成了先決條件。
> **多檔 5 記為對**（盒子 2 → 3）。
>
> **參考答案**【[第七節](../html/c/多檔案的C程式-標頭檔、static與extern、連結錯誤與make.html#實用的-makefile變數樣式規則自動產生相依)〈實用的 `Makefile`〉第 5、6 點】
>
> **核心關鍵**：
>
> 1. 編譯命令加 `-MMD -MP`：編譯時順便寫出 `.d` 檔，內容是「這個 `.o` 依賴哪些使用者標頭檔」的規則（例如 `server.o: server.c config.h`）；`-MP` 再替每個標頭檔加一條空規則，標頭檔刪掉或改名時 `make` 不會停下來。

#### 多檔 6-1. 哪些名字會出現在 `t.o` 的符號表裡？其中哪些是「這個檔案提供」、哪些是「需要別人提供」？

> **核心關鍵**：

> 1. 符號表裡有：`total`、`add`、`main`、`limit`、`puts`（加上 ELF 記帳用的 `FILE`、`SECTION` 列）。
> 2. 這個檔案提供（有定義，`Ndx` 是區段編號）：`total`（`.bss`）、`add`、`main`（`.text`）。

#### 多檔 6-2. `n`、`sum`、`i` 為什麼不在符號表裡？

```
因爲它們是區域變數,用函式堆疊就可以算完了,存在函式堆疊裏,並在函式結束時清除
```

> **批改**：**對**（改判，原判大致對）。抓到：區域變數放在堆疊框裡，「用函式堆疊就可以算完」就是「在函式自己裡面就定位得到，不需要外面（連結器）決定位址」。改判理由：10-25 幾乎一樣的寫法（「用各自函式的堆疊就可以算完」）判對，那次多寫的全域變數對照不是核心關鍵，這次不能拿它來扣分。小修（不扣分）：講明一點會更完整——堆疊上的位置是 `%rbp` 的偏移（例如 `-0x8(%rbp)`），編譯器自己就寫得出來，不需要連結器決定位址、也沒有別的檔案要找它，所以不需要名字。「在函式結束時清除」是它的生命週期，不是不進符號表的理由。
>
> **參考答案**【[第一節](../html/c/多檔案的C程式-標頭檔、static與extern、連結錯誤與make.html#一本課在做什麼編譯器一次只看一個-c)〈上面說的「符號」到底是什麼〉「區域變數不是符號」那段】
>
> **核心關鍵**：
>
> 1. `n`（參數）、`sum`、`i` 是函式裡的變數，放在堆疊框（或暫存器），位址是執行時 `%rbp` 的偏移。
> 2. 這個偏移編譯器自己就寫得出來，不需要連結器決定位址，所以不需要名字、不進符號表。

#### 多檔 6-3. 對連結器來說，符號表裡的一個符號代表什麼、拿來做什麼用？

```
符號告訴連接器他的大小,偏移,符號名
符號名 可以直接 拿來讓連接器做多檔案的連結,同時連接器還會對符號做重定位,給予記憶體位址
如果無法填洞,那就開需求單寫在dynamic section 等執行交給interpreter處理
```

> **批改**：**對**。抓到：符號是名字＋位置（區段、偏移、大小）；連結器用名字配對各檔案（符號解析），再重定位給位址、把洞補起來。小修（不扣分）：「補不了的洞寫需求單交給 interpreter」只在那個符號**由共享函式庫 `.so` 提供**時成立（例如 `puts` 在 `libc.so.6`）；如果所有 `.o` 和函式庫都沒有定義（例如這題的 `limit`），連結器直接報 `undefined reference to 'limit'`、連結失敗，不會寫需求單。
> **多檔 6 記為對**（盒子 2 → 3；6-2 改判為對）。
>
> **參考答案**【[第一節](../html/c/多檔案的C程式-標頭檔、static與extern、連結錯誤與make.html#一本課在做什麼編譯器一次只看一個-c)〈上面說的「符號」到底是什麼〉】
>
> **核心關鍵**：
>
> 1. 一個符號 ＝ 名字＋它在哪裡（區段、偏移、大小）；有定義的代表「這個檔案提供」，`UND` 代表「這個檔案需要」。
> 2. 連結器用它做**符號解析**：把每個 `UND` 跟別的 `.o`／函式庫的 `GLOBAL` 定義配對（只比名字）。
> 3. 再做**重定位**：算出每個符號的最終位址，填進機器碼裡標著那個符號名字的洞。
