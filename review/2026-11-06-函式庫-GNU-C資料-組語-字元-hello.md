
>
> **參考答案**【[第九節第 2 章](../html/c/靜態與動態函式庫-ar與.a、-fPIC與.so、執行時怎麼找到.so.html#2-兩份-counter接-so-為什麼不算重複定義)〈兩份 `counter`：接 `.so` 為什麼不算重複定義〉】
>
> **核心關鍵**（答到這幾點就算對）：
>
> 1. 不會。
> 2. `ld` 不把 `.so` 的內容複製進輸出檔，只讀它的動態符號表（解決未定義符號）並記進 `NEEDED`；輸出檔裡只有 `app.c` 那份 `verbose`，`multiple definition` 只檢查放進同一個輸出檔的定義。
>
> **詳細說明**：連結成功後兩份 `verbose` 都還在，各在各的檔案裡，要到執行時才由 `ld.so` 挑一份。

#### 函式庫 7-4. 把 `conf.c` 第一行改成 `static int verbose = 0;`，重做 `libconf.so`，不重新連結就執行 `./app`，印出多少？為什麼跟 7-3 不同？

```
0
因爲.so的verbose已經是靜態變數了,不需要在用got了,組語會直接寫,找%rip到 static verbose的距離,因此是0

```

> **批改**：**大致對**。0、`.so` 不經 GOT、用 `%rip` 加固定距離讀自己那份都對；但**你寫的「為什麼」是錯的**：「編 `.so` 的時候還沒有 `app.c` 的 `verbose`，所以一定是找跟 static verbose 的距離」——不加 `static` 的時候，編 `.so` 時也一樣看不到 `app.c`，編譯器卻用 GOT，可見原因不在「看不看得到」。真正的原因是 **`static` 讓 `verbose` 變成 `LOCAL` 符號，不會出現在動態符號表、別人不可能插入**，所以編譯器確定最後用的一定是 `.so` 自己這份，才敢用固定距離；沒有 `static` 時它可能被執行檔那份蓋掉（7-3），只好經過 GOT 等 `ld.so` 決定。（11-03 這題可補的也是這一點。）
>
> **參考答案**【[第四節](../html/c/靜態與動態函式庫-ar與.a、-fPIC與.so、執行時怎麼找到.so.html#為什麼不能直接用固定距離counter-最後不一定是這一份)〈為什麼不能直接用固定距離：`counter` 最後不一定是這一份〉】
>
> **核心關鍵**（答到這幾點就算對）：
>
> 1. 印 `get_verbose() = 0`。
> 2. `static` 讓 `verbose` 變成 `LOCAL`，別人不可能插入：編譯器直接用 `%rip` 加固定距離讀 `.so` 自己那份，不經過 GOT，`ld.so` 也不會把它接到執行檔的 `verbose`。
>
> **詳細說明**：執行檔不用重新連結也會變：`get_verbose` 的程式碼在 `.so` 裡，換掉 `.so` 就換了讀法。

### C資料 2. `int x = 0x12345678; unsigned char *b = (unsigned char *)&x;` 在本機 `*b` 是多少？換到大端序的機器上是多少？各是為什麼？另外，為什麼 `int *p = &x;` 的 `*p` 在兩種機器上都是 `0x12345678`？

> 盒子 4｜過去的作答：[s1-02 quiz.md 第 2 題](../small-project/s1-02-data-repr/quiz.md#2-int-x--0x12345678-unsigned-char-b--unsigned-char-x-在本機-b-是多少換到大端序的機器上是多少為什麼-int-p--x-的-p-在兩種機器上都是-0x12345678)、[10-07 複習](./2026-10-07-GNU-C資料-hello-objdump-字元.md)、[10-16 複習](./2026-10-16-interp-ELF-gcc-GNU-陣列-C資料.md)、[10-23 複習](./2026-10-23-大複習-hello-gcc-GNU-interp-ELF-objdump-C資料-字元-陣列-組語-組語二-多檔.md#c資料-2-int-x--0x12345678-unsigned-char-b--unsigned-char-x-在本機-b-是多少換到大端序的機器上是多少各是為什麼另外為什麼-int-p--x-的-p-在兩種機器上都是-0x12345678)

```c
#include <stdio.h>

int main(void)
{
    int x = 0x12345678;
    int *p = &x;                              /* p 存著 x 的位址 */
    unsigned char *b = (unsigned char *)&x;   /* 同一個位址，但宣告成指向 1 個 byte */

    printf("x        = 0x%x (%d)\n", x, x);
    printf("&x       = %p\n", (void *)&x);
    printf("p        = %p\n", (void *)p);
    printf("*p       = 0x%x\n", *p);              /* 從那個位址讀 4 個 byte，當成 int */
    printf("b        = %p\n", (void *)b);
    printf("*b       = 0x%02x\n", *b);            /* 從同一個位址只讀 1 個 byte */
    *p = 0x11223344;                              /* 第 15 行：透過指標寫回去 */
    printf("after *p = 0x11223344, x = 0x%x\n", x);
    return 0;
}
```

```sh
$ gcc -Wall -g -O0 -o addr addr.c
$ ./addr
```

> 題目：`int x = 0x12345678; unsigned char *b = (unsigned char *)&x;` 在本機 `*b` 是多少？換到大端序的機器上是多少？各是為什麼？另外，為什麼 `int *p = &x;` 的 `*p` 在兩種機器上都是 `0x12345678`？

```
因爲使用unsigned char 1byte的指標 所以只看1byte
小端序 0x78 因爲要從低位開始讀
大端序 0x12 從高位開始讀

因爲不管從低位還是高位開始讀p都需要經過4個byte,結果都一樣
```

> **批改**：**不完整**。兩個數值（本機 `0x78`、大端序 `0x12`）都對，「`unsigned char *` 只讀 1 byte」也對；但**兩個「為什麼」都講錯了方向**：
>
> 1. **`*b` 不是「從低位開始讀／從高位開始讀」**：`b` 在兩台機器上都一樣，指向 `x` 的**最低位址**、只讀那 1 個 byte，讀法沒有不同。不同的是**寫進記憶體時怎麼放**：小端序把最低位的 byte `0x78` 放在最低位址（記憶體裡是 `78 56 34 12`），大端序把最高位的 `0x12` 放在最低位址（`12 34 56 78`）。所以差別在「最低位址那格放了誰」，不在「從哪邊開始讀」。
> 2. **`*p` 一樣不是因為「都經過 4 個 byte」**：讀滿 4 個 byte 不保證結果一樣——把小端機器寫出的 `78 56 34 12` 拿到大端機器上照大端讀，同樣讀 4 個 byte，得到的是 `0x78563412`（網路封包、檔案就會遇到）。一樣的真正原因是：**同一台機器用自己那一套順序寫、再用同一套順序讀**，一來一回抵消。
>
> （2026-11-06 使用者質疑「同一套順序讀，小端序不就是 `0x78563412`？」後補充，判定不變）「同一套順序」指的是**同一條「哪個位址放第幾位」的規則**，不是「照位址由低到高把 byte 一個個接起來」。小端的規則是「低位址那格＝最低位」：寫的時候 `0x78` 放最低位址；讀的時候最低位址那格的 `0x78` 當最低位、`0x12` 當最高位，拼回 `0x12345678`。照位址由低到高、把第一格當最高位接成 `0x78563412`，用的是**大端的規則**——正是「寫讀規則不一致」的情況。實測（`b` 指向 `x`，`le`、`be` 分別照兩種規則用 `b[0]`～`b[3]` 拼）：`記憶體: 78 56 34 12`、`照小端規則拼: 0x12345678`、`照大端規則拼: 0x78563412`、`*p: 0x12345678`。
>
> **參考答案**【[第三節](../html/c/C的資料在記憶體裡長怎樣-位元組、指標、位元組順序與有號無號.html#三位元組順序endianness)〈什麼時候要在意位元組順序？〉】
>
> **核心關鍵**（答到這幾點就算對）：
> 1. 本機（小端序）`*b` 是 `0x78`，大端序機器是 `0x12`。原因（2026-11-05 補問「為什麼」後加入）：`b` 指向 `x` 的**最低位址**、只讀那 1 個 byte；小端序把**最低位**的 byte（`0x78`）放在最低位址，大端序把**最高位**的 byte（`0x12`）放在最低位址。
> 2. `*p` 兩邊都一樣，是因為每台機器都用**自己那一套順序寫、再用同一套順序讀**（小端把第一個 byte 當最低位，也就是從後往前拼；大端把第一個 byte 當最高位，從前往後拼），一來一回抵消。
>
> **詳細說明**：小端機器寫成 `78 56 34 12`，大端機器寫成 `12 34 56 78`。`*p` 讀 4 byte 是因為 `p` 指向 `int`；`p` 本身在 x86-64 上是 8 byte。看得出順序的只有兩種情況：用 `unsigned char *` 一個 byte 一個 byte 看，或者一台機器寫、另一種順序的機器讀（網路封包、檔案，第 5 題）。
