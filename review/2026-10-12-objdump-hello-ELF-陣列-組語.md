## hello：[hello.c怎麼變成能跑的程式-編譯的四個階段](../html/c/hello.c怎麼變成能跑的程式-編譯的四個階段.html)

### hello 5. 情境題：你把一支動態連結的程式複製到另一台機器，執行時出現找不到 `libc.so.6` 某個版本符號的錯誤。從本課的哪個階段可以解釋這件事？如果改用 `-static` 編譯，這個問題還會發生嗎？

> 盒子 1｜過去的作答：[s1-01 quiz.md 第 5 題](../small-project/s1-01-hello-compile/quiz.md#5-情境題你把一支動態連結的程式複製到另一台機器執行時出現找不到-libcso6-某個版本符號的錯誤從本課的哪個階段可以解釋這件事如果改用--static-編譯這個問題還會發生嗎)、[10-04 複習](./2026-10-04-字元-C資料-objdump-hello-ELF.md)、[10-08 複習](./2026-10-08-字元-C資料-objdump-hello-ELF-陣列.md#hello-5-情境題你把一支動態連結的程式複製到另一台機器執行時出現找不到-libcso6-某個版本符號的錯誤從本課的哪個階段可以解釋這件事如果改用--static-編譯這個問題還會發生嗎)

```
在動態鏈接的階段ld回去找出函式庫與函式庫的版本,並寫到dynamic section 與 version symbol的地方,然後我們在執行的時候interpreter會去看有沒有這個版本的庫支不支持,沒有的話就會出現這個錯誤

不會 -static會直接把程式碼寫入,也不會有interpreter所以不會發生
```

> **批改**：**對**（盒子 1 → 2）。三個核心關鍵都答到了：**連結時** `ld` 把版本需求寫進執行檔、**執行時**載入器檢查本機的 `libc.so.6` 有沒有那個版本、`-static` 不會發生。10-04、10-08 都漏掉的「連結時寫下版本需求」這次補上了。
>
> **參考答案**【[第九節](../html/c/hello.c怎麼變成能跑的程式-編譯的四個階段.html#九作業解說四題背後的原因)〈自我測驗第 5 題延伸：「找不到版本符號」是怎麼回事〉】
>
> **核心關鍵**（答到這幾點就算對）：
>
> 1. **連結時**：`ld` 把需要的符號版本（例如 `GLIBC_2.34`）寫進執行檔。
> 2. **執行時**：動態載入器檢查目標機器的 `libc.so.6` 有沒有提供這個版本，沒有就報 `` version `GLIBC_2.34' not found ``。
> 3. `-static` 不會發生：libc 的程式碼已經整份複製進執行檔，不再找外部的 `libc.so.6`。
>
> **詳細說明**：一句話：「連結時記下要求、執行時才被檢查」。`readelf -V hello` 看得到版本需求；本機的真正門檻是 2.34（`__libc_start_main`），不是 `puts` 的 2.2.5。`-static` 的代價是檔案大，而且 libc 的安全修補要重新編譯才會帶進去。

## ELF：[ELF是什麼-可執行與可連結格式的兩種視角](../html/c/ELF是什麼-可執行與可連結格式的兩種視角.html)

### ELF 3. 本機一般 `gcc` 編出的執行檔，`Type` 為什麼是 DYN，跟 `libc.so.6` 同一類，而靜態版是 EXEC？

> 盒子 1｜過去的作答：[s1-01 quiz.md 第 3 題](../small-project/s1-01-hello-compile/quiz.md#3-本機一般-gcc-編出的執行檔type-為什麼是-dyn跟-libcso6-同一類而靜態版是-exec)、[10-04 複習](./2026-10-04-字元-C資料-objdump-hello-ELF.md)、[10-08 複習](./2026-10-08-字元-C資料-objdump-hello-ELF-陣列.md#elf-3-本機一般-gcc-編出的執行檔type-為什麼是-dyn跟-libcso6-同一類而靜態版是-exec)

```
要看是不是PIE, 遵守ASLR, 如果是的話那就是DYN, 如果編譯時下-no-pie 那就會是EXEC
```

> **批改**：**對**（改判，盒子 1 → 2）。**進步**：這次抓到「`Type` 看的是是不是 PIE」，沒有再說「因為動態編譯」（10-04、10-08 錯的地方），還知道 `-no-pie` 會變 EXEC。
> 原判大致對（認為缺「PIE 跟函式庫一樣可放任意位址」與「靜態版是固定位址」）。使用者指出題目沒要求解釋 PIE 的意思；而「是 PIE → DYN，否則 → EXEC」的規則已經涵蓋靜態版（靜態版不是 PIE），核心判斷完整，改判對。「為什麼跟 `libc.so.6` 同類」的細節移到詳細說明。
>
> **參考答案**【[第三節](../html/c/ELF是什麼-可執行與可連結格式的兩種視角.html#三一種格式四種檔案)〈DYN／EXEC 跟「有沒有動態連結」無關：兩個反例〉】
>
> **核心關鍵**（答到這幾點就算對）：
>
> 1. `Type` 看的是**是不是 PIE**（位置無關執行檔，每次執行由 ASLR 放在隨機位址）：本機 gcc 預設產生 PIE → DYN。
> 2. 不是 PIE（`-static` 版，固定位址）→ EXEC。
>
> **詳細說明**：PIE 跟共享函式庫一樣「可以放在任意位址」，所以跟 `libc.so.6` 同屬 DYN。`Type` **跟有沒有動態連結無關**，兩個反例：`-no-pie` 照樣動態連結，`Type` 卻是 EXEC；`-static-pie` 是靜態連結，`Type` 卻是 DYN。


> **批改**：**對**。`*(p + 3)`，10-08 漏掉的 `*` 這次寫對了。

#### 陣列 1-3. 為什麼 `3[p]` 也能編譯，而且值跟 `p[3]` 一樣？

```
p[3] = *(p+3) = *(3+p) = 3[p]
[在c的意思是位移某個數然後取值
```

> **批改**：**對**。`*(p+3)` ＝ `*(3+p)` ＝ `3[p]`，也講出 `[]` 是「位移再取值」。
> **陣列 1 記為對**（盒子 1 → 2）。
>
> **參考答案**【[第二節](../html/c/陣列、字串與指標運算-C不檢查邊界與用gdb找segfault.html#二指標運算p--1-走一個元素不是一個-byte)〈`p[i]` 就是 `*(p + i)`〉】
>
> **核心關鍵**（答到這幾點就算對）：
>
> 1. 1-1：`T *p` 的 `p + n` 走 `n × sizeof(T)` byte：`int *` 走 4，`unsigned char *` 走 1。
> 2. 1-2：`p[3]` 的定義是 **`*(p + 3)`**（往後走 3 個元素，再取值）。
> 3. 1-3：`3[p]` ＝ `*(3 + p)`，加法可以交換，所以等於 `*(p + 3)` ＝ `p[3]`。
>
> **詳細說明**：位址本身一樣，差在用什麼型別看它。C 標準把下標定義成 `E1[E2]` ≡ `*((E1) + (E2))`；`3[p]` 能編譯，證明 `[]` 只是「指標加法再取值」的縮寫。

```
安靜出錯, 存取還是在自己的stack內存取,但是存取到stack內其他的數值,而且不滿足stack smashing detected

stack smashing detected: 金絲雀位址,在我們分配內存的時候會給一個金絲雀位址,如果接下來存取修改了這個,那最後函式就會跳到不知道哪裏去了

segfault: 這是越界存取至沒有權限的區段,kernel會直接報錯
```

> **批改**：**大致對**。三種的分界都對：還在可存取的記憶體 → 安靜出錯；改到金絲雀 → `stack smashing detected`；沒有權限 → segfault（kernel）。兩處要修：
> - **金絲雀被改掉之後，函式不會「跳到不知道哪裡」**：返回前檢查碼發現金絲雀不對，就呼叫 `__stack_chk_fail` 印出 `stack smashing detected` 並**中止程式**，根本不會執行 `ret`。「跳到不知道哪裡」是**沒有金絲雀**時，返回位址被蓋掉的下場——金絲雀正是為了擋這個。
> - segfault 的條件是分頁**沒有對映**或**權限不允許**，不只是「沒有權限」；「安靜出錯」也不限於自己的堆疊，只要位址落在還能存取的記憶體都算。

#### 陣列 4-2. 為什麼「程式沒當掉」不能證明沒有越界？

```
因爲在安靜出錯的情況,我可能已經讀了某個已經超出stack,或金絲雀的位址,但我沒有改金絲雀位址,也還沒有讀到segfault 權限不允許的位址
程式就停了,但他可能還是越過了他的stack或其他,但不會有任何錯誤噴出kernel沒察覺 c也沒察覺
```

> **批改**：**對**。抓到：落在還能存取的記憶體時，kernel 和金絲雀都察覺不到、不會報錯。小修：「程式就停了」應該是「程式**照常跑完**」——讀到垃圾、寫壞別的資料，結束狀態仍是 0。
> **陣列 4 記為大致對**（盒子 1 → 1）。
>
> **參考答案**【[第五節](../html/c/陣列、字串與指標運算-C不檢查邊界與用gdb找segfault.html#五c-不檢查邊界越界的三種下場)開頭的表格、〈下場一：安靜地出錯〉、〈下場二：被堆疊保護抓到〉】
>
> **核心關鍵**（答到這幾點就算對）：
>
> 1. 4-1：位址還在可存取的記憶體 → **安靜出錯**；越界**寫入**改掉金絲雀、函式返回前檢查 → **`stack smashing detected`**；分頁**沒有對映或權限不允許** → **segfault**。
> 2. 4-2：C 不檢查邊界（越界是未定義行為），落在還能存取的記憶體時沒有任何機制會報錯。
>
> **詳細說明**：金絲雀是 gcc 放在區域陣列後面的檢查值，返回前才檢查，所以發現得比犯錯晚；只讀不寫不會改到它。檢查失敗時程式由 `__stack_chk_fail` 中止，不會執行 `ret`，所以被蓋掉的返回位址不會被用到。segfault 則是核心送出的 `SIGSEGV`。「沒當掉」的時候，程式可能讀到垃圾、寫壞別人的資料，照常結束（`oob.c` 結束狀態 0），錯誤很久以後才在別處出現。

### 組語 1. `mov` 與 `lea`

> `movl (%rdi,%rsi,4), %eax` 和 `leaq (%rdi,%rsi,4), %rax` 括號裡寫的一模一樣。
>
> 盒子 1｜過去的作答：[s1-04 quiz.md 第 1 題](../small-project/s1-04-asm-basics/quiz.md#1-mov-與-lea)

（`%rdi` 是第 1 個參數、`%rsi` 是第 2 個參數。）

#### 組語 1-1. 兩個指令做的事差在哪？

```
movl這個是把 (%rdi,%rsi,4) 這個位址上面的值 複寫到 eax裏

leaq 這個是把(%rdi,%rsi,4)的記憶體位址 複寫到rax
```

> **批改**：**對**。`movl` 讀那個位址上的值，`leaq` 放的是位址本身。
>
> **參考答案**【[第四節](../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#四mov-與-lea搬資料-vs-算位址)〈`lea`：只算位址，不碰記憶體〉】
>
> **核心關鍵**：
>
> 1. `movl` 先算出位址 `a + i×4`，再**去記憶體讀**那個位址的 4 byte，放進 `%eax`。
> 2. `leaq` 只把算出來的**位址數字本身**放進 `%rax`，**不讀記憶體**。

#### 組語 1-2. 各對應 C 的什麼寫法？

> 題目：`movl (%rdi,%rsi,4), %eax` 和 `leaq (%rdi,%rsi,4), %rax` 各對應 C 的什麼寫法？

```
int f(int *a, long b){return a[b];}
int* f(int *a, long b){return &a[b];}
```

> **批改**：**對**。`a[b]` 與 `&a[b]`——10-08 沒接回的指標寫法這次寫對了（`lea` 對應 `&a[i]`）。
>
> **參考答案**【[第四節](../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#四mov-與-lea搬資料-vs-算位址)〈`lea`：只算位址，不碰記憶體〉】
>
> **核心關鍵**：
>
> 1. `movl (%rdi,%rsi,4), %eax` ↔ `a[i]`（就是 `*(a + i)`，`a` 是 `int *`）。
> 2. `leaq (%rdi,%rsi,4), %rax` ↔ `&a[i]`（就是 `a + i`，結果是指標）。

#### 組語 1-3. 為什麼 gcc 會拿 `lea` 來算 `x * 3` 這種跟位址無關的東西？

`long times3(long x) { return x * 3; }` 用 `gcc -S -O2` 編出來是：

```asm
times3:
	endbr64                       # 給 CPU 的控制流程保護標記，跟計算無關
	leaq	(%rdi,%rdi,2), %rax       # 這一行就是本題要解釋的
	ret                           # 回傳 %rax
```

```
因爲位址的計算就是8byte的位址直接計算,純數字計算自然也可以用到這裏
而且如果不用這個算 就需要分配內存去計算, 用leaq只用到寄存器
```

> **批改**：**大致對**。第一句抓到「`lea` 算的就是數字，不一定要是位址」。缺的跟 10-08 一樣：**怎麼用它算 `x * 3`**——`x * 3` ＝ `x + x×2`，剛好是 `(%rdi,%rdi,2)` 的 B ＋ I × S。
> 第二句不對：不用 `lea` 也**不需要記憶體**，例如 `imulq $3, %rdi, %rax` 一樣全在暫存器裡算；`lea` 的好處是一個便宜的指令就做完、**不改旗標**、結果可以放到另一個暫存器。
> **組語 1 記為大致對**（盒子 1 → 1）。
>
> **使用者爭論後維持**（2026-10-12）：使用者認為題目沒要求舉例。但 `x + x×2` 不是「例子」，而是題目問的「為什麼」本身：gcc 選 `lea` 是因為 `x * 3` 剛好能寫成 B ＋ I × S，一個指令算完；「`lea` 能算數字」只說明它**可以**這樣用，沒說明為什麼**選**它。作答裡唯一給出的選用理由（不用 `lea` 就要用記憶體）是錯的，所以維持大致對。
>
> **參考答案**【[第四節](../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#四mov-與-lea搬資料-vs-算位址)〈`lea` 被拿來做算術〉】
>
> **核心關鍵**：
>
> 1. `lea` 只算 D ＋ B ＋ I × S 這個數字、不碰記憶體，所以算的東西不必是位址。
> 2. `x * 3` ＝ `x + x×2`，正好寫成 `leaq (%rdi,%rdi,2), %rax`，一個指令做完。
>
> **詳細說明**：另外兩個好處：`lea` **不改旗標**（`add` 會），而且結果可以放到另一個暫存器（`add` 只能寫回其中一個運算元）。能一次做到的倍數是 x × S 或 x ＋ x × S：1、2、3、4、5、8、9 倍。

### 組語 2. 寫 32 位元暫存器與擴展

> `long widen_u(unsigned x) { return x; }` 只要一個 `movl %edi, %eax`，`long widen_s(int x) { return x; }` 卻要 `movslq %edi, %rax`。
>
> 盒子 1｜過去的作答：[s1-04 quiz.md 第 2 題](../small-project/s1-04-asm-basics/quiz.md#2-寫-32-位元暫存器與擴展)

程式（筆記檔案：[`ops.c`](../small-project/s1-04-asm-basics/ops.c) 的其中兩個函式，不需要 `main`）與編譯指令：

```c
long widen_s(int x)       { return x; }
long widen_u(unsigned x)  { return x; }
```

```sh
gcc -S -O2 -fno-asynchronous-unwind-tables ops.c -o ops.s
```

```asm
widen_s:
	endbr64                 # 控制流程保護標記，跟計算無關
	movslq	%edi, %rax      # 把 4 byte 的 %edi 有號擴展成 8 byte 放進 %rax
	ret                     # 回傳 %rax
widen_u:
	endbr64
	movl	%edi, %eax      # 把 %edi 的 4 byte 複製到 %eax
	ret
```

#### 組語 2-1. 為什麼 `movl` 就足以完成前者？

```
因爲 x是無號的,無號寫32位元eax,高32位元可以自動補0

另外widen_s x是有號的,有號的要用 movslq s:signed, l: 4byte, q:8byte
```

> **批改**：**對**。抓到「寫 32 位元的 `%eax`，高 32 位元自動變 0」——10-08 測驗與作業都卡在這裡，這次答出來了。小修：清高位是 CPU 對**所有**寫 32 位元暫存器的規則，跟「無號」無關；是因為無號剛好需要補 0，gcc 才能只用一個 `movl`。
>
> **參考答案**【[第二節](../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#二暫存器cpu-裡的-16-個變數)〈寫低位的名字時，高位會怎樣？〉】
>
> **核心關鍵**：
>
> 1. `unsigned` → `long` 是**零擴展**：高 32 位元補 0。
> 2. 寫 32 位元的名字（`%eax`）時，CPU 會**自動把 `%rax` 的高 32 位元清成 0**，所以一個 `movl %edi, %eax` 就完成了零擴展。

#### 組語 2-2. 如果改寫 16 位元的 `%ax`，同樣的理由還成立嗎？

```
不成立,非32位元不會自動補0
```

> **批改**：**對**。寫 16 位元不會清高位，所以理由不成立。
> **組語 2 記為對**（盒子 1 → 2）。
>
> **參考答案**【[第二節](../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#二暫存器cpu-裡的-16-個變數)〈寫低位的名字時，高位會怎樣？〉】
>
> **核心關鍵**：
>
> 1. 不成立。
> 2. 寫 16 位元（`%ax`）或 8 位元（`%al`）的名字時，高位**保留原本的值、不會自動清 0**；只有寫 32 位元名字才會清。所以要零擴展得用 `movzwl`／`movzbl` 這類指令。

### 組語 3. 有號與無號在哪裡決定

> `lt_s` 和 `lt_u` 的 `cmpl %esi, %edi` 一模一樣，gdb 也看到兩者的旗標完全相同（`[ SF IF ]`）。
>
> 盒子 1｜過去的作答：[s1-04 quiz.md 第 3 題](../small-project/s1-04-asm-basics/quiz.md#3-有號與無號在哪裡決定)

實驗（筆記[第五節〈實驗：同一個 `cmp`、同一組旗標，`setl` 說是、`setb` 說否〉](../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#五旗標與條件跳躍cmp-只負責比跳不跳由下一個指令決定)）：用 `-1` 和 `1` 呼叫兩個函式，在 `cmp` 剛做完時用 gdb 看旗標。

檔案 [`lt.c`](../small-project/s1-04-asm-basics/lt.c)：

```c
/* lt.c：用 -O2 編 */
int lt_s(int a, int b)           { return a < b; }
int lt_u(unsigned a, unsigned b) { return a < b; }
```

檔案 [`ltmain.c`](../small-project/s1-04-asm-basics/ltmain.c)：

```c
/* ltmain.c：另外一個檔，這樣 -O2 的 lt.c 不會被內嵌進 main */
#include <stdio.h>

int lt_s(int a, int b);
int lt_u(unsigned a, unsigned b);

int main(void)
{
    printf("lt_s(-1, 1) = %d\n", lt_s(-1, 1));
    printf("lt_u(-1, 1) = %d\n", lt_u(-1, 1));
    return 0;
}
```

```sh
gcc -O2 -g -c lt.c
gcc -O0 -g ltmain.c lt.o -o lt
./lt
gdb -q -batch -ex 'break *lt_s+8' -ex 'break *lt_u+8' -ex run \
    -ex 'x/i $pc' -ex 'info registers eflags' -ex continue \
    -ex 'x/i $pc' -ex 'info registers eflags' ./lt
```

`lt.c` 編出的組合語言：

```asm
lt_s:
	endbr64                 # 控制流程保護標記
	xorl	%eax, %eax      # %eax = 0
	cmpl	%esi, %edi      # 算 a − b，只設旗標、不存結果
	setl	%al             # 依旗標把 %al 設成 1 或 0（看哪些旗標是本題要答的）
	ret                     # 回傳 %eax
lt_u:
	endbr64
	xorl	%eax, %eax
	cmpl	%esi, %edi      # 完全一樣的比較
	setb	%al             # 依旗標把 %al 設成 1 或 0（看哪些旗標是本題要答的）
	ret
```

#### 組語 3-1. 為什麼一個回傳 1、一個回傳 0？

```
因爲lt_s a,b都是有號的, 有號看sf != of , setl, l看sf != of 設成1

lt_u是無號所以要看CF,CF=0  setb 看cf = 1, 故 設成0
```

> **批改**：**對**。`setl` 看 SF ≠ OF（1 ≠ 0 → 1），`setb` 看 CF（0 → 0）。
>
> **參考答案**【[第五節](../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#五旗標與條件跳躍cmp-只負責比跳不跳由下一個指令決定)〈實驗：同一個 `cmp`、同一組旗標，`setl` 說是、`setb` 說否〉】
>
> **核心關鍵**：
>
> 1. 旗標相同，差在**讀旗標的條件碼**：`lt_s` 用 `setl`（看 SF ≠ OF），`lt_u` 用 `setb`（看 CF）。
> 2. 這次 SF = 1、OF = 0 → `setl` 成立，回傳 1；CF = 0 → `setb` 不成立，回傳 0。

#### 組語 3-2. C 的「有號還是無號」在組合語言裡到底是在哪裡決定的？

```
c 會根據 他的型別是有號/無號, 而決定要用 setl or setb, 所以是在set這裏決定的,在根據set的決定再去看要看cmp的哪個旗標
```

> **批改**：**對**（改判）。抓到：gcc 依 C 的型別在編譯時挑條件碼（`setl` 或 `setb`），旗標本身不分有號無號。原判大致對（缺變寬時挑 `movs`／`movz`）；使用者指出題目是在比較的情境下問，變寬不是必要點，改判對，變寬移到詳細說明。
> **組語 3 記為對**（改判，盒子 1 → 2）。
>
> **參考答案**【[第五節](../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#五旗標與條件跳躍cmp-只負責比跳不跳由下一個指令決定)〈實驗：同一個 `cmp`、同一組旗標，`setl` 說是、`setb` 說否〉、[第三節](../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#三指令的文法助憶符大小後綴運算元)〈`%dil` 是 `0xff`，為什麼 `%eax` 變成 `0xffffffff`〉】
>
> **核心關鍵**：
>
> 1. 在**編譯時**由 gcc 依照 C 的型別選指令決定；CPU、暫存器、旗標裡都沒有「有號／無號」。
> 2. 這題的情境：比較之後挑哪個條件碼（有號 `l`／`g`，無號 `b`／`a`）。
>
> **詳細說明**：另一個看得出有號無號的地方是變寬時挑 `movs` 還是 `movz`（組語 2 的 `movslq` vs `movl`）。`cmp` 把兩種解讀需要的旗標（OF 給有號、CF 給無號）一次都設好，所以從組合語言反推型別時，只能看這兩種地方。

> **核心關鍵**：
>
> 1. 位址 ＝ `a + i×8 + 24` ＝ `a + (i + 3)×8`，就是 `a[i + 3]`（`i` 是第 2 個參數）。

#### 組語 5-3. 如果同一個位置看到的是 `leaq` 而不是 `movq`，C 又會是什麼？

> 題目：如果看到的是 `leaq 24(%rdi,%rsi,8), %rax` 而不是 `movq`，C 又會是什麼？

```
long *(long *a, long i) {return &a[i+3];}
```

> **批改**：**對**。`&a[i+3]`——10-08 沒接回的指標寫法這次對了。（函式少了名字，例如 `long *k(long *a, long i)`，不扣分。）
> **組語 5 記為對**（盒子 1 → 2）。
>
> **參考答案**【[第四節](../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#四mov-與-lea搬資料-vs-算位址)〈`lea`：只算位址，不碰記憶體〉】
>
> **核心關鍵**：
>
> 1. `lea` 不讀記憶體，只算出位址 `a + i×8 + 24`。
> 2. 對應 `&a[i + 3]`（就是 `a + i + 3`），結果是指標。

### 組語 6. 組合語言的大小名稱 vs C 的型別

> 盒子 1｜過去的作答：[s1-04 quiz.md 第 6 題](../small-project/s1-04-asm-basics/quiz.md#6-組合語言的大小名稱-vs-c-的型別2026-10-06-課後提問新增)

#### 組語 6-1. `movsbl` 的 `l` 叫 long，為什麼是 4 byte，而本機 C 的 `long` 是 8 byte？

```
組合語言的long標準與c的不是相同的
c的標準對於long的定義是32位元以上,看平臺而定
本機是x86_64 long是64位元

但組合語言與平臺無關,他的long就是32位元,不管在哪裏都是固定的
```

> **批改**：**大致對**。C 那一半對：`long` 由平台決定（至少 32 位元），本機是 64 位元。組合語言那一半缺了**為什麼是 4 byte**：這是 **x86 的歷史命名**——8086 是 16 位元，word ＝ 2 byte，long（兩個 word）＝ 4 byte，為了相容一直沒改。另外「跟平台無關」不精確：`b`／`w`／`l`／`q` 是 x86（AT&T 語法）自己的命名，換到 ARM 等別的架構就是另一套名字。
>
> **參考答案**【[第三節](../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#三指令的文法助憶符大小後綴運算元)〈為什麼 `l` 叫 long 卻是 4 byte〉】
>
> **核心關鍵**：
>
> 1. 組合語言的 `b`／`w`／`l`／`q` 是 **x86 的歷史命名**：8086 是 16 位元，word ＝ 2 byte；32 位元叫 long（兩個 word）＝ 4 byte；為了相容，名字一直沒改。
> 2. C 的 `long` 大小**由平台決定**（標準只要求至少 32 位元），本機 x86-64 Linux 是 LP64，`long` ＝ 8 byte。兩者只是剛好同名。

#### 組語 6-2. 本機 C 的 `long` 在組合語言裡對到哪個字尾？

```
q:8byte
```

> **批改**：**對**。`q`。
>
> **參考答案**【[第三節](../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#三指令的文法助憶符大小後綴運算元)〈為什麼 `l` 叫 long 卻是 4 byte〉】核心關鍵：1. `q`（quad word，8 byte）。
