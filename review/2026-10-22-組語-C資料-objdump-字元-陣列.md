### 組語 8. 暫存器的名字 vs 暫存器本身

> 盒子 1｜過去的作答：[s1-04 quiz.md 第 8 題](../small-project/s1-04-asm-basics/quiz.md#8-暫存器的名字-vs-暫存器本身2026-10-06-課後提問新增)、[10-13 複習](./2026-10-13-組語-字元.md)

用到的程式（檔案：[`dil.c`](../small-project/s1-04-asm-basics/dil.c)）：

```c
#include <stdio.h>

__attribute__((noinline)) int widen_char(signed char c) { return c; }   /* noinline：不准內嵌，才看得到真的呼叫 */

int main(void)
{
    printf("%d\n", widen_char(-1));
    return 0;
}
```

```sh
gcc -O2 -g dil.c -o dil
objdump -d --no-show-raw-insn dil
```

`main` 呼叫 `widen_char(-1)` 的那幾行，`objdump` 節錄：

```asm
main:
	endbr64
	sub	$0x8,%rsp
	mov	$0xffffffff,%edi       # 呼叫的人：把 -1 放進 %edi（第 1 個參數）
	lea	0xf90(%rip),%rsi       # 準備 printf 的參數，跟本題無關
	call	widen_char         # 呼叫 widen_char
	...
widen_char:
	endbr64                    # 給 CPU 的控制流程保護標記，跟計算無關
	movsbl	%dil,%eax          # 被呼叫的人：只讀 %dil（1 byte），有號擴展成 4 byte 放進 %eax
	ret                        # 回傳 %eax
```

#### 組語 8-1. `dil.c` 的組合語言裡只出現 `%edi`、`%dil`，沒有 `%rdi`，為什麼 gdb 能印出 `$rdi`？

```
edi, dil, rdi都是相同的寄存器,只是讀與寫位元數大小不同
edi是32位元
dil是8
rdi是64
```

> **批改**：**對**（改判）。抓到：`%edi`、`%dil` 都是 `%rdi` 這一個暫存器的一部分，組合語言沒寫出 `%rdi`，只代表指令只碰它的一部分。原本判「大致對」、說缺「gdb 讀出整組暫存器」；使用者指出題目問的就是「只出現 `%edi`、`%dil`，為什麼印得出 `$rdi`」，「同一個暫存器」就是答案。重看筆記，該節的主答案也是這一句，「整組暫存器」是延伸到 `%rcx` 這類完全沒用到的暫存器時的補充，不該列成核心關鍵，已移到詳細說明。小修（不扣分）：要講的是「同**一個**暫存器的不同部分」，不只是「讀寫位元數不同」。
>
> **參考答案**【[第三節](../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#三指令的文法助憶符大小後綴運算元)〈組合語言裡只有 `%edi`、`%dil`，為什麼 gdb 印得出 `$rdi`？〉】
>
> **核心關鍵**：
>
> 1. `%edi`、`%di`、`%dil` 不是另外的暫存器，都是 `%rdi` 這**一個**暫存器的一部分的名字；組合語言沒寫出 `%rdi`，只代表那個指令只碰它的一部分。
>
> **詳細說明**：延伸：gdb 不只印得出 `$rdi`，**任何**暫存器都印得出來——程式停下時，gdb 請核心把整組暫存器讀出來，跟程式有沒有用到無關。實驗裡 `widen_char` 沒用到 `%rcx`，`info registers rcx` 照樣印得出來，是之前留下來的值。

#### 組語 8-2. 在 gdb 裡 `set $edi = 0xaabbccdd`，`$rdi` 的高 4 byte 會不會被清成 0？

```
不會,edi只有32位元,gdb只會去設定你要他寫的地方
```

> **批改**：**對**。抓到：**不會**清，gdb 的 `set $edi = …` 只改低 4 byte。10-08、10-13 兩次答「會」，這次對了。
>
> **參考答案**【[第三節](../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#三指令的文法助憶符大小後綴運算元)〈組合語言裡只有 `%edi`、`%dil`，為什麼 gdb 印得出 `$rdi`？〉】
>
> **核心關鍵**：
>
> 1. **不會**：gdb 的 `set $edi = …` 只改 `%rdi` 的低 4 byte，高 4 byte 保留原值。
>
> **詳細說明**：實驗先把 `$rdi` 設成 `0x11223344556677ff`，`set $edi = 0xaabbccdd` 之後 `$rdi` 是 `0x11223344aabbccdd`。

#### 組語 8-3. 跟 CPU 執行 `movl $0xaabbccdd, %edi` 有什麼不同？

> 題目：（承 8-2）gdb 的 `set $edi = 0xaabbccdd` 跟 CPU 執行 `movl $0xaabbccdd, %edi` 有什麼不同？

```
cpu這樣執行是把 $0xaabbccdd 設到下32位的地方,而高32位會自動補0
```

> **批改**：**對**。抓到：CPU 執行 `movl` 寫 32 位元會把高 32 位元清成 0。gdb 那半（不清）在 8-2 已經答到，兩題合起來就是正確的對比。10-13 把兩邊說反的地方這次對了。
> **組語 8 記為對**（盒子 1 → 2；8-1 改判後三個小題全對）。
>
> **參考答案**【[第二節](../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#二暫存器cpu-裡的-16-個變數)〈寫低位的名字時，高位會怎樣？〉、[第三節](../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#三指令的文法助憶符大小後綴運算元)〈組合語言裡只有 `%edi`、`%dil`，為什麼 gdb 印得出 `$rdi`？〉】
>
> **核心關鍵**：
>
> 1. CPU 執行 `movl $0xaabbccdd, %edi` 會把 `%rdi` 的**高 32 位元清成 0**，結果是 `0x00000000aabbccdd`。
> 2. 「寫 32 位元清高位」是 CPU 執行指令的規則；gdb 的 `set` 不是指令，不套用這條規則。
>
> **詳細說明**：實例：`dil.c` 的 `main` 執行 `mov $0xffffffff,%edi`，`%rdi` 變成 `0x00000000ffffffff`（筆記 gdb 輸出 `$1 = 0xffffffff`）。用 gdb 改暫存器做實驗時要記得這個差別。

### 組語 11. gdb 的 `break *位址`

> `break deref+4` 會得到 `Function "deref+4" not defined.`，`break *deref+4` 卻可以。
>
> 盒子 1｜過去的作答：[s1-04 quiz.md 第 11 題](../small-project/s1-04-asm-basics/quiz.md#11-gdb-的-break-位址2026-10-06-課後提問新增)、[10-13 複習](./2026-10-13-組語-字元.md)

用到的程式（檔案：[`paren.c`](../small-project/s1-04-asm-basics/paren.c)）：

```c
#include <stdio.h>

__attribute__((noinline)) long copy_val(long x)  { return x; }    /* 回傳 x 本身 */
__attribute__((noinline)) long deref(long *p)    { return *p; }   /* 回傳 p 指向的值 */

int main(void)
{
    long v = 1234;
    printf("%ld %ld\n", copy_val(v), deref(&v));
    return 0;
}
```

```sh
gcc -O2 -g paren.c -o paren
objdump -d --no-show-raw-insn paren
```

`-O2` 編出的 `deref`：

```asm
deref:
	endbr64                 # 控制流程保護標記（佔 4 byte，所以下一條是 deref+4）
	mov	(%rdi),%rax         # 把 %rdi 當位址，讀 8 byte 放進 %rax
	ret                     # 回傳 %rax
```

#### 組語 11-1. `*` 讓 gdb 怎麼理解後面的東西？

```
*會讓gdb去找deref這個符號的記憶體位址
```

> **批改**：**不完整**。「找 `deref` 的位址」說得不精確：不加 `*` 的 `break deref` 一樣會去找 `deref` 的位址，所以這不是 `*` 的作用。兩個核心都沒答到：(1) `*` 表示後面是**一個算出位址的式子**，gdb 把 `deref + 4` 算成一個數字、停在那個位址；(2) 沒有 `*` 時，後面被當成函式名或行號（linespec），`deref+4` 整串被當成一個函式名，所以 `not defined`（跟 10-13 缺同一點）。
>
> **參考答案**【[第三節](../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#三指令的文法助憶符大小後綴運算元)〈上面 `break *widen_char+4` 的 `*`：為什麼要加？〉】
>
> **核心關鍵**：
>
> 1. `*` 表示後面是**一個算出位址的式子**：gdb 計算 `deref + 4`（函式開頭往後 4 byte），停在那個位址的機器指令。
> 2. 沒有 `*` 時，後面被當成函式名或行號（linespec），`deref+4` 整串被當成函式名，所以 `not defined`。
>
> **詳細說明**：實測：`break *deref+4` 得到 `Breakpoint 3 at 0x11f4`；`break deref+4` 得到 `Function "deref+4" not defined.`。

**自我練習**（不批改）

```
*表示會算出後面式子的位址
不加*就代表是函數名或行號
```

#### 組語 11-2. 這個 `*` 跟 C 的 `*p` 是同一個意思嗎？

```
不是,gdb的*可以讓他找到這個符號的位址
C的*是顯示這個位址那格存的值
```

> **批改**：**對**。抓到：不是同一個意思；gdb 的 `*` 表示「後面是位址」，C 的 `*p` 是取出那個位址存的值。
>
> **參考答案**【[第三節](../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#三指令的文法助憶符大小後綴運算元)〈上面 `break *widen_char+4` 的 `*`：為什麼要加？〉】
>
> **核心關鍵**：
>
> 1. 不是：`break` 的 `*` 是 gdb 的語法記號，意思是「後面是位址」；C 的 `*p` 是取出指標指向的值。
>
> **詳細說明**：`break *deref` 停在 `deref` 這個位址，不會去讀那裡的值。

#### 組語 11-3. 在 `-O0` 的程式上，`break deref` 和 `break *deref` 為什麼會停在不同的位址？

同一個 `paren.c` 改用 `-O0` 編，`deref` 的組合語言：

```sh
gcc -O0 -g paren.c -o paren0
objdump -d --no-show-raw-insn paren0
gdb -batch -ex 'break deref' -ex 'break *deref' ./paren0     # 看兩個中斷點各下在哪個位址
```

```asm
000000000000117b <deref>:
    117b:	endbr64                 # 控制流程保護標記
    117f:	push   %rbp             # 把呼叫者的 %rbp 存到堆疊（第 5 課的序言）
    1180:	mov    %rsp,%rbp        # %rbp = 目前堆疊頂，建立這個函式的堆疊框
    1183:	mov    %rdi,-0x8(%rbp)  # 把參數 p（在 %rdi）存進堆疊上的區域變數
    1187:	mov    -0x8(%rbp),%rax  # 從堆疊讀回 p 放進 %rax
    118b:	mov    (%rax),%rax      # *p：把 p 當位址讀 8 byte
    118e:	pop    %rbp             # 還原呼叫者的 %rbp
    118f:	ret                     # 回傳 %rax
```

> 題目：在 `-O0` 的程式上，`break deref` 和 `break *deref` 為什麼會停在不同的位址？

```
因爲*deref是找到這個符號的位址,那就會停在endbr64的地方

	je	.L1                   # 相等就跳 .L1

	jne	.L3                   # 不相等就再一圈
.L1:
	movl	%edx, %eax            # 回傳值 = %edx
	ret
.L4:
	xorl	%edx, %edx
	movl	%edx, %eax            # 回傳 0
	ret
```

#### 陣列 7-1. 這個陣列佔幾個 byte？

```
12個byte
```

> **批改**：**錯**。應是 **22 byte**。1 個影子 byte 代表**應用程式的 8 個 byte**：`00` ＝ 這 8 個全部可以碰，`06` ＝ 這 8 個裡前 6 個可以碰，所以 8 ＋ 8 ＋ 6 ＝ 22。（10-20 的陣列 6 用「24 byte → 3 個 `00`」答對過，這次反過來算就忘了。）
>
> **參考答案**【[第七節](../html/c/陣列、字串與指標運算-C不檢查邊界與用gdb找segfault.html#七addresssanitizer在第一次越界的當下抓到它)〈上圖的 `01`：影子 byte 的值是「個數」，不是資料〉】
>
> **核心關鍵**：
>
> 1. `00 00 06` ＝ 8 ＋ 8 ＋ 6 ＝ **22 byte**（1 個影子 byte 代表 8 個 byte）。

**自我練習**（不批改）

```

#### 陣列 7-2. `06` 的 6 是什麼意思？

> 題目：（影子 byte 是 `00 00 06`，前後都是 `f2`）`06` 的 6 是什麼意思？

```
代表0110 倒數第二位,第三爲有值
```

> **批改**：**錯**。`06` 不是位元圖（bitmap），不能拆成 `0110` 一個 bit 對一個 byte 來讀。影子 byte 的值是**個數**：最後那一組 8 個 byte 裡，**前 6 個**可以碰、後 2 個是禁區。這正是筆記那一小段標題要防的誤會〈影子 byte 的值是「個數」，不是資料〉。
>
> **參考答案**【[第七節](../html/c/陣列、字串與指標運算-C不檢查邊界與用gdb找segfault.html#七addresssanitizer在第一次越界的當下抓到它)〈上圖的 `01`：影子 byte 的值是「個數」，不是資料〉】
>
> **核心關鍵**：
>
> 1. 最後那一組 8 個 byte 裡，**只有前 6 個**可以碰，後 2 個是禁區。

**自我練習**（不批改）

```
8個byte中前6個可以動
```

#### 陣列 7-3. 如果它是 `char s[] = "…";` 這樣用字串初始化的，字串本身（不含 `'\0'`）有幾個字元？

> 題目：（影子 byte 是 `00 00 06`）如果它是 `char s[] = "…";` 這樣用字串初始化的，字串本身（不含 `'\0'`）有幾個字元？

```
11個字元
```

> **批改**：**不完整**。方法對：`char s[] = "…"` 的大小是字串長度 ＋ 1（`'\0'`），所以減 1。但數字承 7-1 錯：陣列是 22 byte，字串有 **21** 個字元。
>
> **參考答案**【[第七節](../html/c/陣列、字串與指標運算-C不檢查邊界與用gdb找segfault.html#七addresssanitizer在第一次越界的當下抓到它)〈上圖的 `01`：影子 byte 的值是「個數」，不是資料〉】

```

#### 陣列 7-4. 為什麼影子 byte 裡不會出現 `08`？

```
因爲全滿就是1111
```

> **批改**：**錯**。「全滿就是 1111」是把影子 byte 當位元圖讀（而且 `1111` 是 `0x0f`，也不是 `08`）。理由是：8 個 byte 全部可以碰**已經寫成 `00`**；`01`～`07` 只用來表示「不滿 8 個、前幾個可以碰」，所以不需要 `08`。
> **陣列 7 記為錯**（盒子 2 → 1）。
>
> **參考答案**【[第七節](../html/c/陣列、字串與指標運算-C不檢查邊界與用gdb找segfault.html#七addresssanitizer在第一次越界的當下抓到它)〈上圖的 `01`：影子 byte 的值是「個數」，不是資料〉】
>
> **核心關鍵**：
>
> 1. 7-1：`00 00 06` ＝ 8 ＋ 8 ＋ 6 ＝ **22 byte**。
> 2. 7-2：最後那一組 8 個 byte 裡，**只有前 6 個**可以碰，後 2 個是禁區。
> 3. 7-3：`char s[] = "…"` 的大小是字串長度 ＋ 1（`'\0'`），所以字串有 **21 個字元**。
> 4. 7-4：8 個 byte 全部可以碰已經寫成 `00`；`01`～`07` 只用來表示「不滿 8 個」，所以不需要 `08`。
>
> **詳細說明**：影子 byte 存的是計數，不是記憶體內容。前後的 `f2` 是變數之間的中間禁區。反過來，宣告 `char s[22]` 就能預測影子 byte 是 `00 00 06`。可以碰的部分一定從一組的開頭算起，因為 ASan 把每個變數的起點對齊到 8 的倍數。
