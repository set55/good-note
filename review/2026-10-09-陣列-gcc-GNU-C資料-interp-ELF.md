#### 陣列 5-1. 同事的程式偶爾 segfault，gdb 的 `bt` 顯示當在 `parse()` 裡 `x = buf[k];` 這一行，`k` 的值是 523871，而 `buf` 只有 256 個元素。你接下來要怎麼查出真正的錯誤在哪裡？

```
使用frame 一層一層看 k是在什麼時候變得超過256, 需要了解k超過256的原因
```

> **批改**：**對**。抓到重點：當掉的這一行不是 `k` 變錯的地方，要用 `frame` 一層一層往上找 `k` 是在哪裡變成 523871 的。
>
> **參考答案**【[第 3 課第六節](../html/c/陣列、字串與指標運算-C不檢查邊界與用gdb找segfault.html#六用-gdb-找-segfault實際走一次)〈當掉的那一行 ≠ 犯錯的那一行〉】

> 1. 當掉的那一行只是錯的 `k` **第一次碰到不能碰的分頁**的地方，不是 `k` 變錯的地方。

>
> 詳細說明：順便檢查 `parse` 有沒有拿到 `buf` 的長度、有沒有檢查 `k` 的範圍。`k` 可能在更早之前就已經越界過好幾次，只是那幾次落在還能存取的記憶體裡，沒有當掉。

### 陣列 2. 陣列傳進函式之後

#### 陣列 2-1. `int a[10];` 在 `main` 裡 `sizeof a` 是 40，傳進 `void f(int a[])` 之後 `sizeof a` 變成 8。為什麼？

> 盒子 1｜過去的作答：[s1-03 quiz.md 2-1](../small-project/s1-03-arrays-pointers/quiz.md#2-1-int-a10-在-main-裡-sizeof-a-是-40傳進-void-fint-a-之後-sizeof-a-變成-8為什麼)、[10-05 複習](./2026-10-05-gcc-陣列-GNU-C資料-字元.md)

```
在main , sizeof a 指的是指向 a的整個數組 所以是40byte

在f a之指向a陣列頭的指標,指標大小就是8byte
```

> **批改**：**對**。抓到重點：`main` 裡量的是整個陣列，`f` 裡的 `a` 其實是指標。
>
> **參考答案**【[第 3 課第三節](../html/c/陣列、字串與指標運算-C不檢查邊界與用gdb找segfault.html#三陣列名稱什麼時候變成指標什麼時候不會)〈函式參數寫成 `int a[]`，其實就是 `int *a`〉】
>
> 核心關鍵：
> 1. 在 `main` 裡，`sizeof a` 是「陣列名稱不退化成指標」的例外，量的是整個陣列：10 × 4 = 40 byte。
> 2. 參數寫成 `int a[]` 其實就是 `int *a`，呼叫 `f(a)` 時傳過去的只是 `a[0]` 的位址，所以 `f` 裡的 `sizeof a` 是指標的大小 8。
>
> 詳細說明：gcc 對這種寫法有 `-Wsizeof-array-argument` 警告。

#### 陣列 2-2. 這件事對「怎麼設計接收陣列的函式」有什麼影響？

> 過去的作答：[s1-03 quiz.md 2-2](../small-project/s1-03-arrays-pointers/quiz.md#2-2-這件事對怎麼設計接收陣列的函式有什麼影響)、[10-05 複習](./2026-10-05-gcc-陣列-GNU-C資料-字元.md)

```
a只代表陣列頭的指標,不知道陣列長度,所以需要給長度參數
```

> **批改**：**對**。
>
> **參考答案**【[第 3 課第三節](../html/c/陣列、字串與指標運算-C不檢查邊界與用gdb找segfault.html#三陣列名稱什麼時候變成指標什麼時候不會)〈函式參數寫成 `int a[]`，其實就是 `int *a`〉】
>
> 核心關鍵：
> 1. 函式拿到的只是位址，不知道陣列有多長，所以**長度要另外當參數傳進去**（例如 `long sum(int *p, int n)`）。
>
> 詳細說明：呼叫端用 `sizeof a / sizeof a[0]` 算長度（這時 `a` 還是陣列）。標準函式庫的 `memcpy`、`read` 也是這樣設計的。字串是例外：靠結尾的 `\0` 判斷在哪裡結束。

#### 陣列 2-3. `a` 和 `&a` 印出來的位址一樣，它們差在哪裡？

> 過去的作答：[s1-03 quiz.md 2-3](../small-project/s1-03-arrays-pointers/quiz.md#2-3-a-和-a-印出來的位址一樣它們差在哪裡)、[10-05 複習](./2026-10-05-gcc-陣列-GNU-C資料-字元.md)

```
a 是陣列退化成指標,a就是一個指向整列頭的指標, a+1 就是位移到第二個元素(4byte)

&a 是代表整個陣列的代表位址, 如果&a + 1, 你的位移是位移整個陣列的大小(40byte)


```

> **批改**：**大致對**。步長都對：`a + 1` 走 4 byte、`&a + 1` 走 40 byte。但這題問「差在哪裡」，答案是**型別**，而你這次沒有寫出 `&a` 的型別。
> 上兩次卡住的正是這裡（10-05 寫成 `int *[10]`），這次沒寫，看不出是不是已經改正。正確寫法是 **`int (*)[10]`**：括號讓 `*` 先跟名字結合，意思是「指標，指向 10 個 `int` 組成的陣列」；
> `int *[10]` 沒有括號，意思是「10 個 `int *` 組成的陣列」。
>
> **參考答案**【[第 3 課第三節](../html/c/陣列、字串與指標運算-C不檢查邊界與用gdb找segfault.html#三陣列名稱什麼時候變成指標什麼時候不會)〈`a` 和 `&a`：位址一樣，型別不一樣〉】
>
> 核心關鍵：
> 1. 位址相同、**型別不同**。
> 2. `a` 退化成 `int *`，`+ 1` 走 4 byte；`&a` 的型別是 `int (*)[10]`（指向整個陣列的指標），`+ 1` 走 40 byte。
>
> 詳細說明：宣告這種指標的變數要寫成 `int (*p)[10] = &a;`。

### 陣列 3. `char s1[]` 與 `char *s2`

#### 陣列 3-1. `char s1[] = "hi";` 和 `char *s2 = "hi";` 的 `"hi"` 分別在記憶體的哪裡？

> 盒子 1｜過去的作答：[s1-03 quiz.md 3-1](../small-project/s1-03-arrays-pointers/quiz.md#3-1-char-s1--hi-和-char-s2--hi-的-hi-分別在記憶體的哪裡)、[10-05 複習](./2026-10-05-gcc-陣列-GNU-C資料-字元.md)

```
s1是區域變數, 存在的是stack裏面, 也就是data裏(記憶體權限分區是rw_p)

而s2 指的 hi是常數,是在rodata裏,也就是r__p權限的分區
```

> **批改**：**大致對**。`s1` 在堆疊、`s2` 指的 `"hi"` 在 `.rodata`（`r--p`），這兩點對。兩個問題：
> - 「stack 也就是 data 裡」**錯**：堆疊和 `.data` 是兩個不同的地方。`.data` 是執行檔裡的一個區段，放**有初始值的全域變數與 `static` 變數**；堆疊是程式執行時才有的那一段（`info proc mappings` 裡的 `[stack]`），放區域變數。兩者權限剛好都是 `rw-p`，所以容易混在一起。
> - 漏了 `s1` 的關鍵：`s1` 裡的 `"hi"` 是**複製**過來的副本，是 `s1` 自己的一份；`s2` 本身只是一個 8 byte 的指標。
>
> **參考答案**【[第 3 課第四節](../html/c/陣列、字串與指標運算-C不檢查邊界與用gdb找segfault.html#四字串以-0-結尾的-char-陣列)】
>
> 核心關鍵：
> 1. `char s1[] = "hi";`：在**堆疊**上開一個 3 byte 的陣列，把 `h`、`i`、`\0` **複製**進去。
> 2. `char *s2 = "hi";`：`"hi"` 本體是字串常數，放在 **`.rodata`**；`s2` 只是指向它的 8 byte 指標（`s2` 自己在堆疊上）。

#### 陣列 3-2. 為什麼改 `s1[0]` 沒事，改 `s2[0]` 卻 segfault？

> 過去的作答：[s1-03 quiz.md 3-2](../small-project/s1-03-arrays-pointers/quiz.md#3-2-為什麼改-s10-沒事改-s20-卻-segfault)、[10-05 複習](./2026-10-05-gcc-陣列-GNU-C資料-字元.md)

```
因爲s2指向的位址,是不能做寫入的,那邊是rodata,權限r_p
```

> **批改**：**對**。抓到重點：`.rodata` 載入後的分頁是 `r--p`，不准寫。（`s1` 那一邊可以寫，你在 3-1 已經寫了它在 `rw-p`。）
>
> **參考答案**【[第 3 課第四節](../html/c/陣列、字串與指標運算-C不檢查邊界與用gdb找segfault.html#四字串以-0-結尾的-char-陣列)、[第五節](../html/c/陣列、字串與指標運算-C不檢查邊界與用gdb找segfault.html#五c-不檢查邊界越界的三種下場)開頭的表格】
>
> 核心關鍵：
> 1. `s1` 的副本在堆疊上，那一頁是 `rw-p`，可以寫。
> 2. `s2` 指向 `.rodata`，分頁權限是 `r--p`：**有對映**但**不允許寫**，CPU 拒絕，核心送出 `SIGSEGV`。
>
> 詳細說明：C 標準只說「修改字串常數是未定義行為」；在本機會 segfault，是因為 gcc 把字串常數放進唯讀分頁。

### gcc 2. 為什麼 `-O0` 的組合語言每一圈都在讀寫記憶體（`-4(%rbp)`），而 `-O2` 不會？這個差別對 `gdb` 有什麼影響？

> 盒子 1｜過去的作答：[s1-01 quiz.md gcc 第 2 題](../small-project/s1-01-hello-compile/quiz.md#2-為什麼--o0-的組合語言每一圈都在讀寫記憶體-4rbp而--o2-不會這個差別對-gdb-有什麼影響)（2026-09-22 之後暫停到第 4 課教完組合語言，這是放回後第一次考）

**題目用到的程式**：`sumto.c`（檔案：[`sumto.c`](../small-project/s1-01-hello-compile/sumto.c)），
用 `gcc -O0 -S sumto.c` 與 `gcc -O2 -S sumto.c` 產生組合語言（`-S`：只編譯到組合語言 `.s` 就停）。

```c
#include <stdio.h>

int sum_to(int n)
{
    int total = 0;
    for (int i = 1; i <= n; i++)
        total += i;
    return total;
}

int answer(void)
{
    return sum_to(100);
}

int main(void)
{
	printf("answer:%d\n", answer());
	return 0;
}
```

`-O0` 的 `sum_to`（本機 gcc 13.3 實際輸出，刪掉 `.cfi`、`.type` 這類組譯指示，右邊是逐行說明）：

```asm
sum_to:
	endbr64                    # 間接跳躍的保護標記（CET），跟這題無關
	pushq	%rbp               # 存起呼叫者的 %rbp
	movq	%rsp, %rbp         # %rbp = 這個函式的堆疊框底
	movl	%edi, -20(%rbp)    # 參數 n（放在 %edi 傳進來）寫到記憶體 -20(%rbp)
	movl	$0, -8(%rbp)       # total = 0，寫到記憶體 -8(%rbp)
	movl	$1, -4(%rbp)       # i = 1，寫到記憶體 -4(%rbp)
	jmp	.L2                # 先跳去檢查條件
.L3:                               # 迴圈本體
	movl	-4(%rbp), %eax     # 從記憶體讀 i 到 %eax
	addl	%eax, -8(%rbp)     # 記憶體裡的 total += %eax
	addl	$1, -4(%rbp)       # 記憶體裡的 i += 1
.L2:                               # 迴圈條件
	movl	-4(%rbp), %eax     # 從記憶體讀 i
	cmpl	-20(%rbp), %eax    # 比較 i 與記憶體裡的 n（算 i − n、設旗標）
	jle	.L3                # i <= n（有號）就回去跑本體
	movl	-8(%rbp), %eax     # 從記憶體讀 total 當回傳值
	popq	%rbp               # 還原 %rbp
	ret
```

`-O2` 的 `sum_to`（同上，實際輸出）：

```asm
sum_to:
	endbr64
	testl	%edi, %edi         # n & n，只為了設旗標
	jle	.L4                # n <= 0 就跳去回傳 0
	leal	1(%rdi), %ecx      # %ecx = n + 1（迴圈的終點）
	xorl	%edx, %edx         # %edx = 0（total）
	andl	$1, %edi           # %edi = n & 1（n 是奇數還是偶數）
	movl	$1, %eax           # %eax = 1（i）
	je	.L3                # n 是偶數就直接進迴圈
	movl	$2, %eax           # n 是奇數：先處理掉 i = 1，i 從 2 開始
	movl	$1, %edx           #           total = 1
	cmpl	%ecx, %eax         #           i 已經到 n + 1 了嗎（n = 1 時）
	je	.L1
.L3:                               # 迴圈本體：一圈加兩個數
	leal	1(%rdx,%rax,2), %edx  # total = total + 2×i + 1（＝ total + i + (i+1)）
	addl	$2, %eax           # i += 2
	cmpl	%ecx, %eax         # i 到 n + 1 了嗎
	jne	.L3
.L1:
	movl	%edx, %eax         # 回傳 total
	ret
.L4:
	xorl	%edx, %edx
	movl	%edx, %eax         # 回傳 0
	ret
```

```
-O0 把迴圈計數存在-4(%rbp) 所以沒做完一個迴圈就要寫入這個rbp計數
-O2 計數的判斷交由andl $1,%edi來做
兩者實現不同

一個計數用記憶體記, O2用的是指令 搭配寄存器

O2無法打印i,有可能產生optimization out, 如果值是存在寄存器
```

> **批改**：**大致對**（這是第一次正式作答：09-22 那次是因為組合語言還沒教，不算分）。抓到：`-O0` 把 `i` 放在記憶體 `-4(%rbp)`，`-O2` 放在暫存器；`-O2` 下 gdb 可能印不出 `i`（`<optimized out>`）。兩個問題：
> - **沒講「為什麼」**：`-O0` 是**不做最佳化、照字面翻譯**。每個變數都分到一個固定的堆疊位置，每一條語句都「從記憶體讀出來 → 算 → 寫回記憶體」，下一條語句也不假設暫存器裡還留著上一次的值。所以每一圈都在讀寫 `-4(%rbp)`。`-O2` 會做**暫存器配置**，整個迴圈都把 `i`、`total` 留在暫存器裡。
> - 「`-O2` 計數的判斷交由 `andl $1,%edi` 來做」**錯**：`andl $1, %edi` 算的是 `n & 1`，用來判斷 `n` 是奇數還是偶數（奇數就先把 `i = 1` 加掉，迴圈才能一圈加兩個數），而且只在**進迴圈前**做一次。
>   計數器 `i` 在 `%eax`（每圈 `addl $2, %eax`），終點 `n + 1` 在 `%ecx`，每圈用 `cmpl %ecx, %eax` 判斷要不要繼續。見[第 4 課第七節](../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#七逐行讀-sum_to-的--o2-版)〈先找出「誰是誰」〉。
>
> **參考答案**【[gcc 最佳化第二節](../html/c/gcc最佳化等級-O0到O3差在哪.html#二實驗同一段程式不同等級編出什麼)、[第三節](../html/c/gcc最佳化等級-O0到O3差在哪.html#三為什麼除錯要用--o0)；組合語言見[第 4 課第六節](../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#六逐行讀-sum_to-的--o0-版)、[第七節](../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#七逐行讀-sum_to-的--o2-版)】
>
> 核心關鍵：
> 1. `-O0` 不最佳化、照字面翻譯：每個變數都有**固定的記憶體位置**（`i` 是 `-4(%rbp)`、`total` 是 `-8(%rbp)`），每條語句都從記憶體讀、再寫回記憶體。
> 2. `-O2` 把變數留在**暫存器**（`i` 在 `%eax`、`total` 在 `%edx`），迴圈裡完全不碰記憶體。
> 3. 對 gdb 的影響：`-O0` 原始碼的每一行都對得到一段指令，變數隨時印得出來；`-O2` 行號會跳、指令被重排，變數可能顯示 `<optimized out>`。
>
> 詳細說明：筆記第三節的實測中，`-O2` 版停下來時跳過了第 3 行；只走兩行，`total` 就已經是 3；被內嵌進 `main` 的那一份，變數全是 `<optimized out>`；中斷點顯示 `(2 locations)`（獨立的 `sum_to` 一份、內嵌進 `main` 一份）。所以學習、單步除錯用 `-O0 -g`，日常開發用 `-Og -g`。

`-O0` 與 `-O2` 的 `answer`（本機 gcc 13.3 實際輸出，刪掉組譯指示）：

```asm

answer:

	pushq	%rbp
	movq	%rsp, %rbp
	movl	$100, %edi         # 第一個參數 = 100
	call	sum_to             # 呼叫 sum_to
	popq	%rbp
	ret                        # 回傳值就是 sum_to 留在 %eax 的結果

# -O2
answer:

```

```
2. 將100直接帶入內嵌的程式sum_to計算
```

> **參考答案**【[gcc 最佳化第二節](../html/c/gcc最佳化等級-O0到O3差在哪.html#二實驗同一段程式不同等級編出什麼)〈「內嵌」是什麼〉】

### GNU 6. 情境題：同事說「我在這台機器上打 `uname -o` 看到 `GNU/Linux`，所以它一定用 glibc」。這個推論錯在哪？`uname` 的哪些欄位可以信、哪一欄不行，為什麼？你會改看什麼來判斷？

```
uname -o 我們用strace查,發現他不是uname去問kernel得到的,是直接打印出來的,所以在那臺機械都會是GNU/Linux,這個推論就是錯在這裏

-o 的原因如同上面
另外還有-i 與 -p,因爲這兩個在不同架構上的定義不同,沒有統一的定義

編譯完後 用readelf -V  直接看函式庫的版本
```

> **批改**：**大致對**。
> - 第一問**對**：`-o` 不是問 kernel 來的，是 `uname` 自己印的字串（用 `strace` 驗證是好方法）。
> - 第二問**不完整**：只列了不能信的 `-o`、`-p`、`-i`，沒說**可以信的是 `-s -n -r -v -m`**，也沒說為什麼：它們來自 `uname()` 系統呼叫回傳的 `struct utsname`，是 kernel 給的；`-o` 是程式編譯時寫死的。
> - 第三問**可行**，而且是前兩次都沒答出來的一問，這次答出來了。本機實測 `readelf -V /bin/ls` 的版本需求列出 `File: libc.so.6`、`Name: GLIBC_2.38` 等項目，只有 glibc 有 `GLIBC_` 版本符號，musl 不用符號版本。也不必「編譯完後」才看，直接看機器上現成的程式就行。
>   更直接的是看 interpreter：同一支 `/bin/ls`，`readelf -l` 印出 `[Requesting program interpreter: /lib64/ld-linux-x86-64.so.2]`，這是 glibc 的載入器；musl 是 `/lib/ld-musl-*`。
>
> **參考答案**【[GNU 是什麼第四節](../html/linux/GNU是什麼-Linux核心與GNU工具的分工.html#四不是-gnu-的-linux你已經遇過了)〈`uname -o` 印出 `GNU/Linux`，不代表它是 GNU〉】
>
> 核心關鍵：
> 1. 錯在把 `-o` 當證據：它是 `uname` 程式寫死的字串，不是問 kernel 來的（BusyBox 版也印 `GNU/Linux`，實測用 musl 的 OpenWrt 一樣印）。
> 2. `-s`、`-n`、`-r`、`-v`、`-m` 來自 `uname()` 系統呼叫（kernel 回傳），可以信；`-o` 不行，`-p`、`-i` 也是程式自己判斷的（說明裡標 non-portable）。
> 3. 判斷 libc 要看**程式本身**：`readelf -l /bin/ls | grep interpreter`（`ld-linux-*` 是 glibc、`ld-musl-*` 是 musl），或用 `readelf -V` 看有沒有 `GLIBC_` 版本需求。
>
> 詳細說明：也可以 `ls /lib/ld-musl-*`，或直接執行載入器，看它怎麼自我介紹。

> 2. `c < d` 為**假**：無號那邊（`unsigned long`）的等級 ≥ 有號那邊（`int`）→ 兩邊轉成 `unsigned long`，−1 變成 18446744073709551615。

> **參考答案**【[interpreter 第三節](../html/c/ELF的interpreter是什麼-動態載入器與井字號驚嘆號.html#三它自己也是一支程式可以直接執行)】

### ELF 5. 情境題：你把 Ubuntu（x86-64）上編好的程式複製到路由器（ARM），`file` 顯示它是 ELF，執行卻失敗。這跟 [interpreter 那篇](../html/c/ELF的interpreter是什麼-動態載入器與井字號驚嘆號.html) 第五節「interpreter 不存在」是不是同一種問題？從檔頭的哪一欄可以看出來？

> 盒子 3｜過去的作答：[s1-01 quiz.md ELF 第 5 題](../small-project/s1-01-hello-compile/quiz.md#5-情境題你把-ubuntux86-64上編好的程式複製到路由器armfile-顯示它是-elf執行卻失敗這跟-interpreter-那篇-第五節interpreter-不存在是不是同一種問題從檔頭的哪一欄可以看出來)

```
如果是動態編譯的程式

```

> **批改**：**錯**（盒子 3 → 1；09-29 那次答對過）。**不是同一種問題**。
> - 架構不符時，kernel 在 `execve` 讀**檔頭（ELF header）**時，就發現 `Machine` 欄位跟 CPU 不符，根本還沒走到「找 interpreter」那一步，回報 `ENOEXEC`（`Exec format error`）。interpreter 不存在則是 `ENOENT`（`not found`）。兩種錯誤的訊息不同。
> - 你看的 `INTERP` 在**程式標頭（program header）**，不是檔頭。反例：就算路由器上剛好有同路徑的檔案，或程式是靜態編譯的（根本沒有 `INTERP`），x86-64 的機器碼一樣不能在 ARM 上跑。
>
> **參考答案**【[ELF 是什麼第五節](../html/c/ELF是什麼-可執行與可連結格式的兩種視角.html#五檔頭裡的其他欄位)】
>
> 核心關鍵：
> 1. 不是同一種問題：ELF 格式在哪台機器都讀得懂，但裡面的**機器碼是給特定 CPU 的**。
> 2. 看檔頭的 **`Machine`** 欄位（`readelf -h`），它寫著 `Advanced Micro Devices X86-64`。kernel 在 `execve` 發現跟 CPU 不符，回 `ENOEXEC`（`Exec format error`）；interpreter 不存在則是 `ENOENT`（`not found`）。
