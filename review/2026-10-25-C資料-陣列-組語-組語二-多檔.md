### C資料 5. 情境題：你從網路封包裡讀到 4 個 byte，依序是 `00 00 01 00`。協定規定數字用大端序，所以它代表 256。如果直接用 `int *` 把這 4 個 byte 讀進本機（x86-64），會得到多少？為什麼？

> 盒子 1｜過去的作答：[s1-02 quiz.md 第 5 題](../small-project/s1-02-data-repr/quiz.md#5-情境題你從網路封包裡讀到-4-個-byte依序是-00-00-01-00協定規定數字用大端序所以它代表-256如果直接用-int--把這-4-個-byte-讀進本機x86-64會得到多少為什麼)、[10-10 複習](./2026-10-10-C資料-GNU-interp-hello-gcc.md)、[10-24 複習](./2026-10-24-gcc-GNU-ELF-objdump-C資料-字元-陣列-組語-組語二-多檔.md)

```
65536
小端序排法的順序要反過來
00 01 00 00
換成10進制=> 65536
```

> **批改**：**對**。抓到：65536；小端序是整個 byte 的順序反過來，拼回來是 `0x00010000`（10-24 把 byte 裡的 `01` 也翻成 `10` 的錯改正了）。小修（不扣分）：你寫的「`00 01 00 00`」是反過來之後**照大端序的寫法**讀出的數字，記憶體裡的 byte 本身沒動。
>
> **參考答案**【[第三節](../html/c/C的資料在記憶體裡長怎樣-位元組、指標、位元組順序與有號無號.html#三位元組順序endianness)】
>
> **核心關鍵**：
>
> 1. 會得到 65536（`0x00010000`），不是協定要的 256。
> 2. x86-64 是小端序：位址最低的 byte 當最低位，記憶體從低到高的 `00 00 01 00` 拼回來是 `0x00010000`。
>
> **詳細說明**：反過來排的單位是**整個 byte**（兩個十六進位數字一組），byte 裡面的 `01` 不會變成 `10`。網路上的位元組順序（network byte order）是大端序，所以讀網路資料要用 `ntohl`（network to host long）之類的函式轉換。在大端序的機器上這個函式什麼都不做，在 x86-64 上會把 4 個 byte 反過來。

### 組語 8. 暫存器的名字 vs 暫存器本身

> 盒子 2｜過去的作答：[s1-04 quiz.md 第 8 題](../small-project/s1-04-asm-basics/quiz.md#8-暫存器的名字-vs-暫存器本身2026-10-06-課後提問新增)、[10-13 複習](./2026-10-13-組語-字元.md)、[10-22 複習](./2026-10-22-組語-C資料-objdump-字元-陣列.md)

用到的程式（檔案：[`dil.c`](../small-project/s1-04-asm-basics/dil.c)）：

```c
#include <stdio.h>

__attribute__((noinline)) int widen_char(signed char c) { return c; }   /* noinline：不准內嵌，才看得到真的呼叫 */

int main(void)
{
    printf("%d\n", widen_char(-1));
    return 0;
}
```

```sh
gcc -O2 -g dil.c -o dil
objdump -d --no-show-raw-insn dil
```

`main` 呼叫 `widen_char(-1)` 的那幾行，`objdump` 節錄：

```asm
main:
	endbr64
	sub	$0x8,%rsp
	mov	$0xffffffff,%edi       # 呼叫的人：把 -1 放進 %edi（第 1 個參數）
	lea	0xf90(%rip),%rsi       # 準備 printf 的參數，跟本題無關
	call	widen_char         # 呼叫 widen_char
	...
widen_char:
	endbr64                    # 給 CPU 的控制流程保護標記，跟計算無關
	movsbl	%dil,%eax          # 被呼叫的人：只讀 %dil（1 byte），有號擴展成 4 byte 放進 %eax
	ret                        # 回傳 %eax
```

#### 組語 8-1. `dil.c` 的組合語言裡只出現 `%edi`、`%dil`，沒有 `%rdi`，為什麼 gdb 能印出 `$rdi`？

```
rdi, edi, dil 都是同一個寄存器,他們的差別只是在讀的時候要讀這個寄存器的多少位元數
所以雖然組合語言只寫了edi,dil,但是rdi還是能印出來,他就是要看這個寄存器64位元的長度存的值
edi是32位元
dil是8位元
```

> **批改**：**對**。抓到：`%rdi`、`%edi`、`%dil` 是**同一個**暫存器，差別只在指令碰它的幾個位元。
>
> **參考答案**【[第三節](../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#三指令的文法助憶符大小後綴運算元)〈組合語言裡只有 `%edi`、`%dil`，為什麼 gdb 印得出 `$rdi`？〉】
>
> **核心關鍵**：
>
> 1. `%edi`、`%di`、`%dil` 不是另外的暫存器，都是 `%rdi` 這**一個**暫存器的一部分的名字；組合語言沒寫出 `%rdi`，只代表那個指令只碰它的一部分。
>
> **詳細說明**：延伸：gdb 不只印得出 `$rdi`，**任何**暫存器都印得出來——程式停下時，gdb 請核心把整組暫存器讀出來，跟程式有沒有用到無關。

#### 組語 8-2. 在 gdb 裡 `set $edi = 0xaabbccdd`，`$rdi` 的高 4 byte 會不會被清成 0？

```
不會,清高4byte爲0那是cpu的機制,
gdb是把低位的32位元用0xaabbccdd覆蓋
```

> **批改**：**對**。抓到：不會清，gdb 只覆蓋低 32 位元；清高位是 CPU 執行指令的規則。
>
> **參考答案**【[第三節](../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#三指令的文法助憶符大小後綴運算元)〈組合語言裡只有 `%edi`、`%dil`，為什麼 gdb 印得出 `$rdi`？〉】
>
> **核心關鍵**：
>
> 1. **不會**：gdb 的 `set $edi = …` 只改 `%rdi` 的低 4 byte，高 4 byte 保留原值。
>
> **詳細說明**：實驗先把 `$rdi` 設成 `0x11223344556677ff`，`set $edi = 0xaabbccdd` 之後 `$rdi` 是 `0x11223344aabbccdd`。

#### 組語 8-3. 跟 CPU 執行 `movl $0xaabbccdd, %edi` 有什麼不同？

> 題目：（承 8-2）gdb 的 `set $edi = 0xaabbccdd` 跟 CPU 執行 `movl $0xaabbccdd, %edi` 有什麼不同？

```
按cpu的機制,寫低32位元(edi),會自動把高32位元清除爲0
```

> **批改**：**對**。抓到：CPU 寫 32 位元的 `%edi` 會把高 32 位元清成 0；跟 8-2 的「gdb 不清」合起來就是兩者的差別。
> **組語 8 記為對**（盒子 2 → 3）。
>
> **參考答案**【[第二節](../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#二暫存器cpu-裡的-16-個變數)〈寫低位的名字時，高位會怎樣？〉】
>
> **核心關鍵**：
>
> 1. CPU 執行 `movl $0xaabbccdd, %edi` 會把 `%rdi` 的**高 32 位元清成 0**，結果是 `0x00000000aabbccdd`。
> 2. 「寫 32 位元清高位」是 CPU 執行指令的規則；gdb 的 `set` 不是指令，不套用這條規則。
>

#### 組語 9-2. 為什麼這樣補，`signed char` 的 −1 變成 `int` 之後才會還是 −1（用二補數的權重解釋）？

```
因爲二補數的最高位權重是負的
sigend char的最高位權重是 -2^7(第7位元), 所以 -1 = -2^7 + (2^7 - 1)
int的最高位權重是 -2^31(第31位元), 爲了達成 -1 = -2^31 + (2^31 - 1)

```

> **批改**：**對**。抓到：最高位權重是負的，8 位元 −2⁷ ＋ (2⁷ − 1) ＝ −1、32 位元 −2³¹ ＋ (2³¹ − 1) ＝ −1，所以高位要補 1 才維持 −1（10-24 指數錯一位的地方改正了）。小修（不扣分）：要補 1 的是第 8～31 位元（第 31 位就是那個 −2³¹），你寫「第 8 位元到第 30 位元」少算了最高位，但算式裡已經用到它。
> 判定說明：10-24 的核心關鍵第 2 點寫了「補 0 會變 255」；題目問的是「為什麼這樣補才會還是 −1」，用權重算出全 1 是 −1 就答到了，跟 10-13 已經寫在筆記的判定一致。這一點只是對照，移到詳細說明，不當成核心關鍵。
> **組語 9 記為對**（盒子 1 → 2）。
>
> **參考答案**【[第三節](../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#三指令的文法助憶符大小後綴運算元)〈`%dil` 是 `0xff`，為什麼 `%eax` 變成 `0xffffffff`：符號擴展補的是第 7 位元〉】
>
> **核心關鍵**：
>
> 1. 二補數的**最高位權重是負的**：8 位元 `0xff` ＝ −2⁷ ＋ (2⁷ − 1) ＝ −1；32 位元 `0xffffffff` ＝ −2³¹ ＋ (2³¹ − 1) ＝ −1。

```c
#include <stdio.h>

int sum_to(int n)
{
    int total = 0;
    for (int i = 1; i <= n; i++)
        total += i;
    return total;
}

int answer(void)
{
    return sum_to(100);
}

{
	printf("answer:%d\n", answer());

}
```

```sh
gcc -S -O2 -fno-asynchronous-unwind-tables sumto.c -o sumto2.s
```

`sum_to` 的 `-O2` 組合語言（`%edi` 是參數 `n`）：

```asm
sum_to:
	endbr64
	testl	%edi, %edi            # 算 n & n，只設旗標
	jle	.L4                   # 結果 ≤ 0 就跳到 .L4（回傳 0）
	leal	1(%rdi), %ecx         # %ecx = %rdi + 1
	xorl	%edx, %edx            # %edx = 0（total）
	andl	$1, %edi              # %edi = %edi & 1，設旗標
	movl	$1, %eax              # %eax = 1（i），不改旗標
	je	.L3                   # 上一個設旗標的指令結果是 0 就跳 .L3
	movl	$2, %eax              # %eax = 2
	movl	$1, %edx              # %edx = 1
	cmpl	%ecx, %eax            # 比較 %eax 與 %ecx
	je	.L1                   # 相等就跳 .L1
.L3:
	leal	1(%rdx,%rax,2), %edx  # %edx = %edx + %rax×2 + 1（一圈加兩個數）
	addl	$2, %eax              # %eax += 2
	cmpl	%ecx, %eax            # 比較 %eax 與 %ecx
	jne	.L3                   # 不相等就再一圈
.L1:
	movl	%edx, %eax            # 回傳值 = %edx
	ret
.L4:
	xorl	%edx, %edx
	movl	%edx, %eax            # 回傳 0
	ret
```

> 題目：`sum_to` 的 `-O2` 開頭為什麼一定要用 `testl %edi, %edi` 而不能用 `andl $1, %edi` 之類會改掉 `%edi` 的指令，中間的 `andl $1, %edi` 卻可以改掉 `%edi`？

```

而中間可以用andl是因爲edi已經沒有用到了,改了也沒關係
```

> **批改**：**對**。抓到：開頭之後 `leal 1(%rdi), %ecx` 還要用 `n`，不能改；中間 `andl` 之後 `%edi` 沒再被用到，改掉沒關係。
> **組語 16 記為對**（盒子 2 → 3）。
>
> **參考答案**【[第七節](../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#七逐行讀-sum_to-的--o2-版)〈上表的 `andl` 和 `testl`：看起來一樣，差在哪？〉的「回到 `sum_to`：為什麼開頭用 `test`、中間用 `and`？」】

#### 組語二 2-1. 函式開頭的 `push %rbp` 和 `mov %rsp,%rbp` 各在做什麼？

```
push %rbp:

mov %rsp,%rbp
把%rsp當前存的位址 存到 %rbp,這樣%rbp就變成這個函式堆疊的頂端了,可以作爲建立區域變數的基準點
```

> **批改**：**對**。抓到：`push` 把舊 `%rbp`（呼叫者的）存到堆疊；`mov` 把現在的頂端定成自己的基準點，區域變數用它定位。
>
> **參考答案**【[第四節](../html/c/x86-64組合語言入門二-call與ret、堆疊框、參數與呼叫慣例.html#四堆疊框pushq-rbp-movq-rsp-rbp-與-leave)】
>
> **核心關鍵**：
>
> 1. `push %rbp`：把**呼叫者的** `%rbp` 存到堆疊上，返回前要還原。
> 2. `mov %rsp,%rbp`：把現在的頂端定成自己堆疊框的**基準點**，之後區域變數用 `%rbp` 加固定的負偏移存取。
>
> **詳細說明**：每個框的 `%rbp` 那格都存著上一層的 `%rbp`，串成一條鏈，`bt` 就是沿著它往回找。

#### 組語二 2-2. `main` 結尾的 `leave` 等於哪兩條指令？

```
mov %rbp, %rsp 相當於讓rsp回到基準點(頂端),清除掉原本push或sub的值
pop %rbp 還原%rbp,並且%rsp+8byte指回 函式返回位址的那格位址
```

> **批改**：**對**。抓到：`mov %rbp,%rsp`＋`pop %rbp`，`pop` 之後 `%rsp` 指著返回位址，正好給 `ret` 用。
>
> **參考答案**【[第四節](../html/c/x86-64組合語言入門二-call與ret、堆疊框、參數與呼叫慣例.html#四堆疊框pushq-rbp-movq-rsp-rbp-與-leave)〈`leave`：一條指令做兩件事〉】
>
> **核心關鍵**：
>
> 1. `mov %rbp,%rsp`：把 `%rsp` 拉回基準點，`sub` 開的空間一次丟掉。
> 2. `pop %rbp`：還原呼叫者的 `%rbp`。

#### 組語二 2-3. `add3` 把區域變數放在 `%rsp` 下面、沒有 `sub %rsp`，`main` 卻要 `sub $0x10,%rsp`，為什麼？

```
根據ABI的規則,%rsp下面128byte是紅區,故不用擔心別人寫入堆疊空間,而且add3沒有call或push 是葉函式,所以add3把區域變數直接放在rsp下面沒有問題

但main有call add3,%rsp會減8byte存add3的返回位址,如果直接把區域變數放到%rsp下面,會弄壞區域變數,所以main需要把rsp的位址往下挪
```

> **批改**：**對**。抓到：紅區（`%rsp` 下方 128 byte ABI 保證不被別人蓋）＋`add3` 是葉函式；`main` 會 `call`，返回位址會蓋到 `%rsp` 下面，所以要 `sub`（10-24 缺的「紅區」這次有了）。
> **組語二 2 記為對**（盒子 1 → 2）。
>
> **參考答案**【[第四節](../html/c/x86-64組合語言入門二-call與ret、堆疊框、參數與呼叫慣例.html#四堆疊框pushq-rbp-movq-rsp-rbp-與-leave)〈上圖 `add3` 的變數在 `%rsp` 的「下面」：紅區〉】
>
> **核心關鍵**：
>
> 1. **紅區**：ABI 保證 `%rsp` 下方 128 byte 不會被別人蓋掉；`add3` 是葉函式，自己也不會 `push`／`call`，所以直接用、省一條 `sub`。
> 2. `main` 要 `call`：`call` 推返回位址會寫在 `%rsp` 下面、蓋掉那一區，所以 gcc 對會 `call` 的函式一律 `sub`，把變數空間放進堆疊（`%rsp` 上面）。
>
> **詳細說明**：`sub` 的大小是 `0x10` 不是 8，才是 16 byte 對齊的緣故。kernel 不能用紅區（中斷會直接推資料到目前的堆疊上），所以編譯時加 `-mno-red-zone`。

> 1. 放在堆疊上（呼叫者用 `push` 推進去，每個 8 byte）。
> 2. 從最後一個開始推：先 `push $0x8` 再 `push $0x7`，所以第 7 個在較低的位址。

#### 組語二 3-3. 在 `sum8` 裡第 7 個參數為什麼是 `0x10(%rbp)`，而不是 `0(%rbp)`？

```
在call8 call sum8之前,%rsp指向的是存第7個參數那格的位址,call sum8後
%rsp要-8byte存返回位址,還要在減8byte 存%rbp的舊值,而後面知道讀取第七個參數,然後rbp就會在存住這個時候的%rsp,也就是堆疊頂端

所以第7個參數就在rbp上面16byte 故 取0x10(%rbp)
```

> **批改**：**對**。抓到：`call` 推返回位址（8）、序言推舊 `%rbp`（8），`%rbp` 定在那之後，所以第 7 個在 `%rbp` 上面 16 byte。
>
> **參考答案**【[第五節](../html/c/x86-64組合語言入門二-call與ret、堆疊框、參數與呼叫慣例.html#五參數與回傳值放哪裡)〈實驗：8 個參數，第 7、8 個去哪了〉】
>
> **核心關鍵**：
>
> 1. `call8` 推完參數後，`call` 又推了返回位址、`sum8` 的序言又推了舊 `%rbp`。
> 2. 所以從 `sum8` 的 `%rbp` 往上：`0(%rbp)` 舊 `%rbp`、`0x8(%rbp)` 返回位址、`0x10(%rbp)` 才是第 7 個。
>
> **詳細說明**：記法：**參數用正的偏移（在呼叫者那邊），區域變數用負的偏移（在自己這邊）**。

#### 組語二 3-4. `call8` 在 `call` 之後為什麼要 `add $0x10,%rsp`？

```
因爲sum8只有ret,本着誰推誰清的原則call8 要把原本push的空間清除掉也就是7,8參數佔用的16byte
```

> **批改**：**對**。抓到：`sum8` 的 `ret` 不清參數、誰推誰清，`call8` 把推的 16 byte 丟掉（10-19、10-23、10-24 三次缺的「`ret` 不清」這次有了）。
> **組語二 3 記為對**（盒子 1 → 2）。
>
> **參考答案**【[第五節](../html/c/x86-64組合語言入門二-call與ret、堆疊框、參數與呼叫慣例.html#五參數與回傳值放哪裡)〈實驗：8 個參數，第 7、8 個去哪了〉】
>
> **核心關鍵**：
>
> 1. 第 7、8 個參數是 `call8` 自己 `push` 的（2 × 8 ＝ 16 byte）。
> 2. `sum8` 的 `ret` 只拿走返回位址、不清參數，所以由呼叫者 `call8` 在 `call` 回來後用 `add $0x10,%rsp` 丟掉。
>
> **詳細說明**：這裡 `add` 之後緊接著 `leave`，其實 `leave` 也會把 `%rsp` 拉回去；`-O0` 照規則先清掉參數，不管後面有沒有 `leave`。

#### 多檔 5-1. `make` 是怎麼判斷不用重編的？

```
重編的條件是,目標更新時間 小於 先決條件的更新時間
```

> 2. 本例 `server.o`、`net.o` 的先決條件只有各自的 `.c`，`.c` 都沒改 → 都不重編 → `server` 也不必重新連結。

>
> **核心關鍵**：
>
> 1. `make` 只看 `Makefile` 寫的先決條件，不會自己去讀 `.c` 裡 `#include` 了哪些檔案；`config.h` 沒列進去，它改了 `make` 不知道。

#### 多檔 5-3. 你會怎麼改這個 `Makefile`，讓以後改任何標頭檔都會重編該重編的檔案？（不必寫出完整的 `Makefile`，說明要改哪些地方、各自的作用即可。）

```

MMD: 建立.d檔,但只引入使用者的.h,不用系統的.h
MP: .d檔加一條 沒有先決條件,也沒有指令的 .h目標, 這樣可以避免在刪除或者修改.h檔名的時候,因爲找不到.h而終止make執行

在Makefile加一句
-include $(OBJS:.o=.d)
把所有.d檔都引入到makefile,就是爲了把.h考慮進來,- 的意思是就算第一次因爲還沒有產生.d,也不要因爲這樣報錯繼續執行 
```

> **批改**：**對**。抓到：`-MMD` 產生只含使用者標頭檔的 `.d`；`-MP` 替標頭檔加沒有先決條件、沒有命令的空規則，標頭檔刪掉或改名時 `make` 不會停；`-include $(OBJS:.o=.d)` 讀進 `.d`，`-` 讓第一次沒有 `.d` 時不報錯（三次說錯的 `-MP` 這次對了）。
> **多檔 5 記為對**（盒子 1 → 2）。
>
> **參考答案**【[第七節](../html/c/多檔案的C程式-標頭檔、static與extern、連結錯誤與make.html#實用的-makefile變數樣式規則自動產生相依)〈實用的 `Makefile`〉第 5、6 點】
>
> **核心關鍵**：
>
> 1. 編譯命令加 `-MMD -MP`：編譯時順便寫出 `.d` 檔，內容是「這個 `.o` 依賴哪些使用者標頭檔」的規則（例如 `server.o: server.c config.h`）；`-MP` 再替每個標頭檔加一條空規則，標頭檔刪掉或改名時 `make` 不會停下來。
> 2. `Makefile` 加 `-include $(OBJS:.o=.d)`：把 `.d` 讀進來、跟原本的規則合併，`config.h` 就成了 `.o` 的先決條件；`-` 表示第一次還沒有 `.d` 時不報錯。

#### 多檔 6-1. 哪些名字會出現在 `t.o` 的符號表裡？其中哪些是「這個檔案提供」、哪些是「需要別人提供」？

```
total: 自己提供
limit: 別人提供
add: 自己提供
main: 自己提供
puts: 別人提供
```

> **批改**：**對**。抓到：五個符號，`total`、`add`、`main` 自己提供，`limit`、`puts` 要別人提供。
>
> **參考答案**【[第一節](../html/c/多檔案的C程式-標頭檔、static與extern、連結錯誤與make.html#一本課在做什麼編譯器一次只看一個-c)〈上面說的「符號」到底是什麼〉】
>
> **核心關鍵**：
>
> 1. 符號表裡有：`total`、`add`、`main`、`limit`、`puts`（加上 ELF 記帳用的 `FILE`、`SECTION` 列）。
> 2. 這個檔案提供（有定義，`Ndx` 是區段編號）：`total`（`.bss`）、`add`、`main`（`.text`）。
> 3. 需要別人提供（`UND`）：`limit`（只有 `extern` 宣告）、`puts`（libc）。

#### 多檔 6-2. `n`、`sum`、`i` 為什麼不在符號表裡？

```
因爲n,sum,i這些區域變數,用各自函式的堆疊就可以算完
不像是static 或 全域變數這些有特殊需求的變數,需要另外找記憶體空間儲存(.bss/.data)
```

> **批改**：**對**。抓到：區域變數放在堆疊框裡，不像全域／`static` 要在 `.bss`／`.data` 有固定位置。小修（不扣分）：再講一句「堆疊上的位置是 `%rbp` 的偏移，編譯器自己寫得出來，不需要連結器決定位址，所以不需要名字」會更完整。
>
> **參考答案**【[第一節](../html/c/多檔案的C程式-標頭檔、static與extern、連結錯誤與make.html#一本課在做什麼編譯器一次只看一個-c)〈上面說的「符號」到底是什麼〉「區域變數不是符號」那段】
>
> **核心關鍵**：
>
> 1. `n`（參數）、`sum`、`i` 是函式裡的變數，放在堆疊框（或暫存器），位址是執行時 `%rbp` 的偏移。
> 2. 這個偏移編譯器自己就寫得出來，不需要連結器決定位址，所以不需要名字、不進符號表。

#### 多檔 6-3. 對連結器來說，符號表裡的一個符號代表什麼、拿來做什麼用？

```
對連接器來說,他可以看到每個符號的名字,大小,偏移,名字可以用來做連接
而連接器還要把每個符號重定位,在機械碼填入每個符號的真實位址
```

> **批改**：**對**。抓到：符號有名字、大小、位置；連結器用名字接起來（符號解析），再把真實位址填進機器碼（重定位）（三次漏的重定位這次有了）。
> **多檔 6 記為對**（盒子 1 → 2）。
>
> **參考答案**【[第一節](../html/c/多檔案的C程式-標頭檔、static與extern、連結錯誤與make.html#一本課在做什麼編譯器一次只看一個-c)〈上面說的「符號」到底是什麼〉】
>
> **核心關鍵**：
>
> 1. 一個符號 ＝ 名字＋它在哪裡（區段、偏移、大小）；有定義的代表「這個檔案提供」，`UND` 代表「這個檔案需要」。
> 2. 連結器用它做**符號解析**：把每個 `UND` 跟別的 `.o`／函式庫的 `GLOBAL` 定義配對（只比名字）。
> 3. 再做**重定位**：算出每個符號的最終位址，填進機器碼裡標著那個符號名字的洞。
