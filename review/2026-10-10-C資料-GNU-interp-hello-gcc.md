## C資料：[C的資料在記憶體裡長怎樣](../html/c/C的資料在記憶體裡長怎樣-位元組、指標、位元組順序與有號無號.html)

### C資料 11. `unsigned x`、`unsigned int x`、`signed x` 各是什麼型別？為什麼 `char` 和 `signed char` 在本機的範圍完全一樣，gcc 卻說它們是不同型別、宣告衝突？情境題：同事在錯誤訊息裡看到 `long unsigned int`，說「我明明寫的是 `unsigned long`，gcc 是不是把型別搞錯了？」你怎麼回答？

> 盒子 1｜過去的作答：2026-10-06 在對話裡作答（第一問對；二、三問重答後仍不完整），參考答案見[筆記〈自我測驗〉第 11 題](../html/c/C的資料在記憶體裡長怎樣-位元組、指標、位元組順序與有號無號.html#自我測驗)

```
unsigned x 是 unsigned int
unsigned int x 是 unsigned int
signed x 是 signed int

因爲有號轉無號,比較的時候有可能出現 -1 -> 255 造成比較的時候的錯誤

沒有錯誤,因爲 long = long int
short = short int
long只是縮寫, long, short都是整數 只是大小不同
```

> **批改**：**不完整**。第一問對：`unsigned x`、`unsigned int x` 是 `unsigned int`，`signed x` 寫成 `signed int` 就是 `int`，正確。第二問錯：你答的是「有號轉無號、比較時 −1 變 255 會出錯」，那是轉換的陷阱，跟題目無關。題目問的是：範圍一樣，為什麼還是不同型別。答案在 C 標準怎麼定義 `char`：`char` 有號還是無號交給平台決定，所以 `char` 不能等於 `signed char` 或 `unsigned char` 其中之一，只能是第三個型別。跟 10-06 錯在同一處（那次也沒推到「所以是第三個型別」）。第三問大致對：答出是同一個型別、`int` 可以省略；缺了「指定字的順序不重要」與「gcc 印型別時用它自己的固定寫法」。
>
> **參考答案**【[第一節](../html/c/C的資料在記憶體裡長怎樣-位元組、指標、位元組順序與有號無號.html#一位元組與型別大小)〈`unsigned` 單獨寫就是 `unsigned int`：整數型別的所有寫法〉】
>
> 核心關鍵：
> 1. `unsigned x`、`unsigned int x` 都是 `unsigned int`；`signed x` 是 `int`（＝ `signed int`）。
> 2. `char` 有號還是無號，C 標準交給平台決定（x86-64 有號、ARM 通常無號），標準沒辦法把它定成 `signed char` 或 `unsigned char` 其中之一，所以 `char` 是**第三個獨立的型別**。型別相不相同看標準的規定，不看範圍。
> 3. gcc 沒搞錯：`unsigned long` 和 `long unsigned int` 是同一個型別。指定字的順序不重要、有其他指定字時 `int` 可以省略，gcc 印型別時用它自己的固定寫法（大小在前、有號無號居中、`int` 放最後）。
>
> 詳細說明：如果把 `char` 定義成 `signed char`，換到 ARM 這種 `char` 無號的平台就錯了，定成 `unsigned char` 則在 x86-64 錯，所以標準只好讓它自成一個型別。同一個函式先宣告成吃 `char`、再定義成吃 `signed char`，gcc 會報 `conflicting types`。`same.c` 實驗裡 `unsigned f(unsigned x)` 也被 gcc 印成 `unsigned int(unsigned int)`。

### C資料 1. 一個 `int` 變數存著 `-1`，用 `%d` 印出 `-1`，轉成 `unsigned` 再用 `%u` 印出 `4294967295`。記憶體裡的內容有沒有變？為什麼同一個東西會印出兩個不同的數？

> 盒子 3｜過去的作答：[s1-02 quiz.md 第 1 題](../small-project/s1-02-data-repr/quiz.md#1-一個-int-變數存著--1用-d-印出--1轉成-unsigned-再用-u-印出-4294967295記憶體裡的內容有沒有變為什麼同一個東西會印出兩個不同的數)

```
沒有變化

雖然記憶體內容沒變,但C的型別不一樣,不同的型別轉出來的可能不同
signed 類型有二補數的規則
unsigned 並沒有
```

> **批改**：**對**。抓到：記憶體內容沒變，差在用哪一種型別去解讀，有號用二補數讀。小補：「`unsigned` 並沒有」講完整是「無號把每一位都當正的權重」，所以全 1 的 32 bit 讀成 2³² − 1。
>
> **參考答案**【[第五節](../html/c/C的資料在記憶體裡長怎樣-位元組、指標、位元組順序與有號無號.html#五有號整數二補數)、[第六節](../html/c/C的資料在記憶體裡長怎樣-位元組、指標、位元組順序與有號無號.html#六有號與無號之間的轉換位元不變換個讀法)】
>
> 核心關鍵：
> 1. 沒有變：記憶體裡始終是 `ff ff ff ff`。同樣寬度的有號、無號轉換只換讀法、不動位元。
> 2. `%d` 用二補數讀（最高位權重是 −2³¹），得到 −1；`%u` 把每一位都當正的權重，得到 2³² − 1 = 4294967295。
>
> 詳細說明：是 `printf` 的 `%d`／`%u` 決定用哪一種讀法解讀那 32 個 bit；變數的型別決定 C 在運算、比較時用哪一種讀法。

### C資料 5. 情境題：你從網路封包裡讀到 4 個 byte，依序是 `00 00 01 00`。協定規定數字用大端序，所以它代表 256。如果直接用 `int *` 把這 4 個 byte 讀進本機（x86-64），會得到多少？為什麼？

> 盒子 3｜過去的作答：[s1-02 quiz.md 第 5 題](../small-project/s1-02-data-repr/quiz.md#5-情境題你從網路封包裡讀到-4-個-byte依序是-00-00-01-00協定規定數字用大端序所以它代表-256如果直接用-int--把這-4-個-byte-讀進本機x86-64會得到多少為什麼)

```
00 01 00 00

int取值的話會得到 16^4

x86-64 是小端序,所以讀得方向是反過來的
然後因爲是int的指標,取值的時候會用成十進位整數
```

> **批改**：**對**。抓到：小端序反過來讀，得到 `0x00010000` ＝ 16⁴ ＝ 65536。「取值的時候會用成十進位整數」這句不需要：`int` 就是 32 個 bit 的整數，十進位只是 `printf` 印出來的方式，跟讀出來的值無關。補一句實務做法：讀網路資料要用 `ntohl` 之類的函式轉換位元組順序。
>
> **參考答案**【[第三節](../html/c/C的資料在記憶體裡長怎樣-位元組、指標、位元組順序與有號無號.html#三位元組順序endianness)】
>
> 核心關鍵：
> 1. 會得到 65536（`0x00010000`），不是協定要的 256。
> 2. x86-64 是小端序：位址最低的 byte 當最低位，記憶體從低到高的 `00 00 01 00` 拼回來是 `0x00010000`。
>
> 詳細說明：網路上的位元組順序（network byte order）是大端序，所以讀網路資料要用 `ntohl`（network to host long）之類的函式轉換。在大端序的機器上這個函式什麼都不做，在 x86-64 上會把 4 個 byte 反過來。

### C資料 7. `2147483648` 和 `0x80000000` 是同一個數，為什麼一個的型別是 `long`、一個是 `unsigned int`？`-1 < 0x80000000` 和 `-1 < 2147483648` 的結果各是什麼？為什麼？

> 盒子 3｜過去的作答：[s1-02 quiz.md 第 7 題](../small-project/s1-02-data-repr/quiz.md#7-2147483648-和-0x80000000-是同一個數為什麼一個的型別是-long一個是-unsigned-int-1--0x80000000-和--1--2147483648-的結果各是什麼為什麼)

```
因爲0x80000000 轉成long需要高位補1, 兩者就不是同一個數了

-1 < 0x80000000 false -1轉unsigned int會遠大於

-1 < 2147483648 true -1 沒有超過long的範圍

```

> **批改**：**不完整**。第二、三問對：`-1 < 0x80000000` 假（`-1` 轉成 `unsigned int` 變很大），`-1 < 2147483648` 真（`-1` 轉成 `long` 還是 −1），理由也對。第一問錯：原因不是「`0x80000000` 轉成 `long` 需要高位補 1」。`0x80000000` 當成 `long` 是正的 2147483648，補的是 0，`long` 也裝得下，仍是同一個數。型別不同的原因是：十進位和十六進位常數的**候選型別清單不同**，十六進位會先試 `unsigned int`，十進位永遠不會變成無號。09-30 這題答對過，這次第一問忘了。
>
> **參考答案**【[第四節](../html/c/C的資料在記憶體裡長怎樣-位元組、指標、位元組順序與有號無號.html#四無號整數二進位與回繞)〈常數也有型別：`0u` 的 `u` 是什麼〉、〈怎麼確定一個常數的型別？比較時以誰為準？〉】
>
> 核心關鍵：
> 1. 沒有後綴的常數，依序嘗試、選第一個裝得下的型別。十進位的清單是 `int` → `long` → `long long`（永遠不變成無號），`2147483648` 超過 `INT_MAX`，所以是 `long`。
> 2. 十六進位的清單是 `int` → `unsigned int` → `long` → …，`0x80000000` 裝得進 `unsigned int`，所以是 `unsigned int`。
> 3. `-1 < 0x80000000` 為**假**：`int` 與 `unsigned int` 比，`-1` 轉成 4294967295。
> 4. `-1 < 2147483648` 為**真**：`int` 與 `long` 比，`-1` 轉成 `long` 還是 −1。
>
> 詳細說明：十六進位清單多放無號型別，是因為寫十六進位的人通常在寫位元樣式（例如遮罩 `0x80000000`），要的是那個 bit 樣式，不是負數。

### GNU 4. GPL 的 copyleft 要求什麼？glibc 用 LGPL 而不是 GPL，對「商業軟體能不能連結 libc」有什麼差別？

> 盒子 1｜過去的作答：[s1-01 quiz.md 第 4 題](../small-project/s1-01-hello-compile/quiz.md#4-gpl-的-copyleft-要求什麼glibc-用-lgpl-而不是-gpl對商業軟體能不能連結-libc有什麼差別)、[10-06 複習](./2026-10-06-字元-interp-ELF-gcc-GNU.md#gnu-4-gpl-的-copyleft-要求什麼glibc-用-lgpl-而不是-gpl對商業軟體能不能連結-libc有什麼差別)

```
要求使用GPL軟體的人,必須要把代碼開源出來

LGPL不要求使用他的人把程式開源
```

> **批改**：**不完整**。「使用 GPL 軟體的人必須把程式碼開源」錯：義務是在**散布**（把軟體給別人）時才發生，只是使用、或改了自己用，都沒有義務；而且漏了「必須用**同樣的授權（GPL）**」。跟 10-06 錯在同一處：那次寫「必須對外發布」，這次寫成「使用就要開源」，兩次都把義務什麼時候發生說錯了。LGPL 那一問大致對：方向對，要點出的是「**連結**它的程式不必開放原始碼」，所以商業軟體可以連結 `libc.so.6`。
>
> **參考答案**【[第五節](../html/linux/GNU是什麼-Linux核心與GNU工具的分工.html#五gplgnu-最深遠的影響)】
>
> 核心關鍵：
> 1. copyleft：可以自由使用、修改、散布，但**散布**修改後（或以它為基礎）的版本時，必須用**同樣的授權（GPL）**並提供原始碼。
> 2. 只是使用、或改了自己用、不給別人，沒有義務。
> 3. glibc 用 LGPL：允許非自由的程式**連結**它而不必開放自己的原始碼，所以商業軟體都能連結 `libc.so.6`；如果 glibc 是 GPL，連結它的程式在散布時就得整個用 GPL 開放。
>
> 詳細說明：copyleft 的目的是讓「自由不能在傳遞途中被拿走」：拿到 GPL 軟體的人，也要拿得到原始碼、有同樣的權利。例子：公司內部改了 GPL 的工具自己用，不必公開；把改過的版本賣給客戶，就要給客戶原始碼，並讓客戶同樣能以 GPL 再散布。

### GNU 2. 目標三元組 `x86_64-linux-gnu` 的三段各代表什麼？為什麼說它剛好說明了「核心」和「C 函式庫」是兩件事？

> 盒子 3｜過去的作答：[s1-01 quiz.md 第 2 題](../small-project/s1-01-hello-compile/quiz.md#2-目標三元組-x86_64-linux-gnu-的三段各代表什麼為什麼說它剛好說明了核心和c-函式庫是兩件事)

```
cpu架構,kernel, c函式庫

因爲這三元祖是可以自由排列組合的,核心跟c函式庫不用是固定搭配,兩者獨立
```

> **批改**：**對**。抓到：三段是 CPU 架構、核心、C 函式庫，核心和 C 函式庫可以各自替換。小補：能舉出例子更好，例如同一個 Linux 核心搭 musl 就寫成 `x86_64-linux-musl`。
>
> **參考答案**【[第二節](../html/linux/GNU是什麼-Linux核心與GNU工具的分工.html#二gnu-做了什麼你這台機器上到處都是)〈那個到處出現的 `x86_64-linux-gnu` 是什麼〉】
>
> 核心關鍵：
> 1. `x86_64` 是 CPU 架構，`linux` 是核心，`gnu` 是 ABI／C 函式庫（glibc）。
> 2. 核心和 C 函式庫可以各自替換（同一個 Linux 核心搭 musl 就是 `x86_64-linux-musl`），所以三元組要分成兩欄寫，正好說明它們是兩件事。
>
> 詳細說明：OpenWrt 用的是 `aarch64-linux-musl` 這類三元組：核心一樣是 Linux，C 函式庫換成 musl。

### interp 2. `ld` 和 `ld.so`（`ld-linux-x86-64.so.2`）各在什麼時間點、做什麼事？

> 盒子 1｜過去的作答：[s1-01 quiz.md 第 2 題](../small-project/s1-01-hello-compile/quiz.md#2-ld-和-ldsold-linux-x86-64so2各在什麼時間點做什麼事)、[10-06 複習](./2026-10-06-字元-interp-ELF-gcc-GNU.md#interp-2-ld-和-ldsold-linux-x86-64so2各在什麼時間點做什麼事)

```
ld 在連接時, 負責組合section header的element, 把同權限的合併在一起,並且找出使用的函式庫版本,與載入器連接路徑 都寫在header

ld.so是執行時被kernel載入,負責載入直接或簡介的函式庫,填入程式碼,之後cpu再去執行機械碼
```

> **批改**：**不完整**。時間點對：`ld` 在連結時、`ld.so` 在執行時被核心載入。`ld` 的部分：答到合併同權限的區段、把 interpreter 路徑與函式庫版本寫進檔頭（接近「需求單」）；但沒講 `ld` 的主要工作「決定每個符號的位址、把 `call` 的洞填上」，也沒講填不了的（`puts`）才只寫 `NEEDED`。`ld.so` 的部分：載入直接與間接依賴的函式庫，對；「填入程式碼」錯，`ld.so` 填的是**位址**（把 `puts` 的真實位址填進 `.got`，這叫接線），程式碼是函式庫檔案映射進記憶體時就在了。最後也漏了「跳到程式的進入點 `_start`」。跟 10-06 錯在同一處（接線）。
>
> **參考答案**【[第二節](../html/c/ELF的interpreter是什麼-動態載入器與井字號驚嘆號.html#二執行時發生什麼事)〈「跳進程式」是什麼意思：進入點（entry point）〉、[第 1 課第五節](../html/c/hello.c怎麼變成能跑的程式-編譯的四個階段.html#五連結把洞接上但-puts-還是沒接完)】
>
> 核心關鍵：
> 1. `ld`：**連結時**（`gcc` 的最後一步，只做一次）合併各 `.o` 的區段、決定每個符號的位址、把 `call` 的洞填上。
> 2. 位址在共享函式庫裡的符號（例如 `puts`），`ld` 填不了真實位址，只寫需求單：`NEEDED libc.so.6`、`INTERP` 路徑。連結完 `ld` 就結束，執行時不會出現。
> 3. `ld.so`：**執行時**（每次執行都做）由核心先啟動，依 `NEEDED` 找到函式庫（含間接依賴）映射進記憶體。
> 4. `ld.so` 把 `puts` 等符號的真實位址填進 `.got`（接線），最後跳到程式的進入點 `_start`（不是 `main`）。
>
> 詳細說明：`ld` 也會產生程式標頭表，把同權限的區段打包成載入段；`ld.so` 載入時會檢查函式庫版本（`GLIBC_2.34` 這種需求）。「填入程式碼」的誤會：`ld.so` 不搬程式碼，函式庫的程式碼映射進記憶體就在那裡了；它填的是「去哪裡找那段程式碼」的位址。

### interp 3. 腳本的 `#!/bin/sh` 和 ELF 的 interpreter，哪裡相同、哪裡不同？用 `#!/bin/cat` 的實驗說明「核心把什麼交給直譯器」。

> 盒子 1｜過去的作答：[s1-01 quiz.md 第 3 題](../small-project/s1-01-hello-compile/quiz.md#3-腳本的-binsh-和-elf-的-interpreter哪裡相同哪裡不同用-bincat-的實驗說明核心把什麼交給直譯器)、[10-06 複習](./2026-10-06-字元-interp-ELF-gcc-GNU.md#interp-3-腳本的-binsh-和-elf-的-interpreter哪裡相同哪裡不同用-bincat-的實驗說明核心把什麼交給直譯器)

題目說的 `#!/bin/cat` 實驗（筆記[第四節](../html/c/ELF的interpreter是什麼-動態載入器與井字號驚嘆號.html#四跟腳本的--是同一個機制)開頭）：寫一支第一行是 `#!/bin/cat` 的腳本，給它執行權限，再用 `./` 直接執行它。

腳本 `catscript` 的完整內容（兩行）：

```
#!/bin/cat
這一行會被 cat 印出來
```

建檔與執行的指令：

```
printf '#!/bin/cat\n這一行會被 cat 印出來\n' > catscript
chmod +x catscript
./catscript
```

（執行結果不附，因為會洩漏答案。）

```
都是被核心第一個載入
不同的是interpreter是負責載入函式庫, 而sh是負責執行檔案

會把腳本內容整個印出來
也就是  cat catscript.sh
也就是核心把整個腳本交給直譯器cat了
```

> **批改**：**不完整**。相同的地方對：核心先啟動直譯器，不是檔案本身。不同的地方答到直譯器做的事（`ld.so` 載入函式庫、`sh` 執行腳本），缺寫的地方（第一行的 `#!` vs 程式標頭的 `INTERP`）。第三問錯：「核心把整個腳本交給直譯器 cat」，又說成**內容**，跟 10-06 和更早幾次錯在同一處。其實你自己寫的「也就是 `cat catscript.sh`」就是答案：這個命令列交給 `cat` 的只有 `./catscript` 這個**名字**（參數），是 `cat` 自己拿這個名字去打開檔案、讀出內容、印出來。要分清兩件事：核心交給直譯器的東西，是直譯器的**命令列參數**；印出來的內容，是 `cat` 自己讀檔的結果。
>
> **參考答案**【[第四節](../html/c/ELF的interpreter是什麼-動態載入器與井字號驚嘆號.html#四跟腳本的--是同一個機制)、〈交給直譯器的是「路徑」，不是內容：三個實驗〉】
>
> 核心關鍵：
> 1. 相同：核心在 `execve` 時讀到「請先執行這支程式」，先啟動直譯器，而不是檔案本身。
> 2. 不同：寫的地方（文字檔第一行的 `#!` vs 程式標頭的 `INTERP`）；直譯器拿到檔案後做的事（`sh` 逐行讀文字、執行命令 vs `ld.so` 載入函式庫、接線後跳進程式本身，之後由 CPU 執行程式的指令）。
> 3. 核心交給直譯器的是**腳本的路徑（當作命令列參數）**：實際執行的是 `/bin/cat ./catscript`，`cat` 用這個路徑自己打開檔案，才把整個檔案（含第一行）印出來。
>
> 詳細說明：兩個實驗可以證明交的是路徑、不是內容：`#!/usr/bin/echo` 的腳本印出的是 `./echoscript.sh` 這個路徑（`echo` 只印參數，不讀檔）；把腳本改成 `chmod 111`（只能執行、不能讀），錯誤訊息是 `/usr/bin/cat: ./catscript.sh: Permission denied`——`cat` 自己開檔被擋。如果核心交的是內容，`cat` 根本不必開檔，這個錯誤就不會發生。

## hello：[hello.c怎麼變成能跑的程式](../html/c/hello.c怎麼變成能跑的程式-編譯的四個階段.html)

### hello 3. `hello.o` 裡「呼叫 `puts`」的地方，要跳去的位址為什麼暫時是 0（空著）？什麼資訊讓連結器知道之後要把它填成什麼？

> 盒子 2｜過去的作答：[s1-01 quiz.md 第 3 題](../small-project/s1-01-hello-compile/quiz.md#3-helloo-裡-call-指令後面的四個-byte-為什麼是-00-00-00-00什麼資訊讓連結器知道要把它填成什麼)（舊題目文字）、[10-04 複習](./2026-10-04-字元-C資料-objdump-hello-ELF.md#hello-3-helloo-裡-call-指令後面的四個-byte-為什麼是-00-00-00-00什麼資訊讓連結器知道要把它填成什麼)

題目用到的程式 `hello.c`（檔案：[`hello.c`](../small-project/s1-01-hello-compile/hello.c)）完整原始碼：

```c
#include <stdio.h>

#define GREETING "hello, world"

int main(void)
{
    printf("%s\n", GREETING);
    return 0;
}
```

產生 `hello.o` 的指令（只編譯＋組譯、不連結）：

```
gcc -c hello.c -o hello.o
```

（原始碼寫的是 `printf`，gcc 把「`printf("%s\n", 字串)`」換成了 `puts(字串)`，所以 `hello.o` 裡呼叫的是 `puts`——見筆記第三節。）

```
因爲這個時候連接器還沒有把需要連接的函式庫連接起來,所以用00 準備讓連接器補

用objdump -dr 可以看到組合語言裏面已經提示了他該去找什麼方法


0000000000000000 <main>:
   0:   f3 0f 1e fa             endbr64
   4:   55                      push   %rbp
   5:   48 89 e5                mov    %rsp,%rbp
   8:   48 8d 05 00 00 00 00    lea    0x0(%rip),%rax        # f <main+0xf>
                        b: R_X86_64_PC32        .rodata-0x4
   f:   48 89 c7                mov    %rax,%rdi
  12:   e8 00 00 00 00          call   17 <main+0x17>
                        13: R_X86_64_PLT32      puts-0x4
  17:   b8 00 00 00 00          mov    $0x0,%eax
  1c:   5d                      pop    %rbp
  1d:   c3                      ret
```

> **批改**：**對**。抓到：連結之前還不知道 `puts` 的位址，先填 0 留給連結器補；並用 `objdump -dr` 找到 `13: R_X86_64_PLT32 puts-0x4` 這一筆，就是它告訴連結器要填誰。小補兩點：這一筆叫**重定位項目**（relocation），是**組譯器**留下來的；`13` 是要填的位置（`call` 的 `e8` 後面那 4 byte 從位移 0x13 開始）。
>
> **參考答案**【[第四節](../html/c/hello.c怎麼變成能跑的程式-編譯的四個階段.html#四組譯機器碼裡的洞)】
>
> 核心關鍵：
> 1. 組譯器一次只處理 `hello.s` 這一個檔案，`puts` 的程式碼在別的檔案（`libc.so.6`），組譯時不知道它的位址，只能先填 0 占位。
> 2. 組譯器同時記下一筆重定位項目 `13: R_X86_64_PLT32 puts-0x4`（「位移 0x13 的地方，將來填上 `puts` 的位址」）；連結器照這筆項目去找名叫 `puts` 的符號，把位址填進那 4 個 byte。
>
> 詳細說明：`objdump -dr` 的 `-r` 會把重定位項目印在對應指令的下面。同一段裡的 `lea 0x0(%rip),%rax` 也是同樣情況：字串 `"hello, world"` 放在 `.rodata`，位址到連結時才決定，所以也有一筆 `R_X86_64_PC32 .rodata-0x4`。

### gcc 1. `-O0` 的 `O` 和 `0` 各是什麼？為什麼說它是「預設值」——不加任何 `-O` 時會發生什麼？

> 盒子 3｜過去的作答：[s1-01 quiz.md 第 1 題](../small-project/s1-01-hello-compile/quiz.md#1--o0-的-o-和-0-各是什麼為什麼說它是預設值不加任何--o-時會發生什麼)

```
O是最佳化的意思
0 就是沒有
所以O0就是不要最佳化

-O0之所以是預設值,就是因爲gcc默認不最佳化編譯
不加任何-O 就是 -O0
```

> **批改**：**對**。抓到：`O` 是最佳化、`0` 是等級 0（不最佳化），不加任何 `-O` 就等於 `-O0`。
>
> **參考答案**【[第一節](../html/c/gcc最佳化等級-O0到O3差在哪.html#一文法-o等級)】
>
> 核心關鍵：
> 1. `O` 是大寫字母 O，代表 Optimize（最佳化）；`0` 是等級 0，即不最佳化。
> 2. 不加任何 `-O` 時 gcc 就用 `-O0`，所以它是預設值。
>
> 詳細說明：`man gcc` 在 `-O0` 底下寫著 *This is the default*。注意 `-O0` 是字母 O 加數字 0，不是兩個零。
