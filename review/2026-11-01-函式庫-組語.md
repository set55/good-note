## 函式庫：[靜態與動態函式庫-ar與.a、-fPIC與.so、執行時怎麼找到.so](../html/c/靜態與動態函式庫-ar與.a、-fPIC與.so、執行時怎麼找到.so.html)

### 函式庫 2. 順序：`-ltxt` 寫在 `main.c` 前面

> 盒子 1｜過去的作答：[s1-07 quiz.md 第 2 題](../small-project/s1-07-libraries/quiz.md#2-順序-ltxt-寫在-mainc-前面)（10-29 第一次作答）

一個靜態函式庫 `libtxt.a` 由下面的 `case.c`、`space.c`、`trim.c` 三個成員組成，`main.c` 只呼叫 `trim`（檔案同第 1 題）。`gcc -Wall -L. -ltxt main.c -o app` 會失敗，錯誤訊息是 `undefined reference to 'trim'`。用 `ld` 處理輸入檔的方式解釋為什麼。這個錯誤跟 `cannot find -ltxt` 差在哪（各是什麼東西找不到）？在 Ubuntu 上把 `libtxt.a` 換成 `libtxt.so`、命令一樣寫成 `-L. -ltxt main.c`，也會失敗，原因是什麼？

```c
/* case.c */
void to_upper_str(char *s) { for (; *s; s++) if (*s >= 'a' && *s <= 'z') *s -= 32; }
void to_lower_str(char *s) { for (; *s; s++) if (*s >= 'A' && *s <= 'Z') *s += 32; }
```
```c
/* space.c */
int is_space(char c) { return c == ' ' || c == '\t' || c == '\n'; }
```
```c
/* trim.c */
int is_space(char c);

char *trim(char *s)
{
    while (is_space(*s))
        s++;
    return s;
}
```
```c
/* main.c */
#include <stdio.h>

char *trim(char *s);

int main(void)
{
    char buf[] = "   hello";
    printf("[%s]\n", trim(buf));
    return 0;
}
```
建立與連結：`gcc -Wall -c case.c space.c trim.c && ar rcs libtxt.a case.o space.o trim.o && gcc -Wall main.c -L. -ltxt -o app`

#### 函式庫 2-1. `gcc -Wall -L. -ltxt main.c -o app` 會失敗，錯誤訊息是 `undefined reference to 'trim'`。用 `ld` 處理輸入檔的方式解釋為什麼。

```
因爲ld是先讀到-ltxt,發現清單上面並沒有跟txt相關的符號,直接把-ltxt丟棄,接着才獨到main.o,這個時候才知道有trim,但已經來不及了
```

> **批改**：**對**。抓到重點：`ld` 由左往右，讀到 `-ltxt` 時清單上沒有 `trim`，一個成員都不拉就略過；讀到 `main.o` 才多了 `trim`，`ld` 不會回頭重掃 → `undefined reference`。小修：清單比對的是「`libtxt.a` 的成員能不能提供清單上的符號」，不是「跟 txt 相關」；「丟棄」精確說是「一個成員都不拉」。
>
> **參考答案**【[第二節](../html/c/靜態與動態函式庫-ar與.a、-fPIC與.so、執行時怎麼找到.so.html#順序ld-由左往右只掃一次)〈順序：`ld` 由左往右只掃一次〉】
>
> **核心關鍵**（答到這幾點就算對）：
>
> 1. `ld` 照命令列順序處理輸入檔，手上維持一張「還沒找到定義的符號」清單。
> 2. 遇到 `libtxt.a` 時 `main` 的 `.o` 還沒讀，清單裡沒有 `trim`（只有啟動檔帶進來的 `main` 等），一個成員都不拉就略過。
> 3. 讀到 `main` 才多了 `trim`，命令列結束時還在清單上，`ld` 不會回頭重掃 `libtxt.a` → `undefined reference`。
>
> **詳細說明**：規則：函式庫寫在用到它的檔案後面（`main.c -L. -ltxt`）。函式庫之間互相需要時，寫兩次或用 `-Wl,--start-group … -Wl,--end-group`。

#### 函式庫 2-2. 這個錯誤跟 `cannot find -ltxt` 差在哪（各是什麼東西找不到）？

```
cannot find -ltxt 是找不到庫,有可能是預設搜尋的庫路徑沒有,有可能是在執行的時候ld.so會報

> **參考答案**【[第五節](../html/c/靜態與動態函式庫-ar與.a、-fPIC與.so、執行時怎麼找到.so.html#rpath-和-runpath-差在哪跟-ld_library_path-誰優先)〈`RPATH` 和 `RUNPATH` 差在哪：跟 `LD_LIBRARY_PATH` 誰優先〉、[第五節](../html/c/靜態與動態函式庫-ar與.a、-fPIC與.so、執行時怎麼找到.so.html#ldso-去了哪些地方找)〈`ld.so` 去了哪些地方找〉】
>
> **核心關鍵**（答到這幾點就算對）：
>
> 1. `RUNPATH` 換得掉：`ld.so` 的搜尋順序裡 `LD_LIBRARY_PATH`（第 2 步）排在 `RUNPATH`（第 3 步）前面，先找到同事自己的版本。

> **批改**：**對**。抓到重點：`log_msg@plt` 是一段程式碼（跳板），不是存位址的表；`log_msg` 的位址存在 `.got.plt` 的 `0x4008` 那格；`0x107a ＋ 0x2f8e ＝ 0x4008`。用詞小修：跳板不是「跳到 `.got.plt` 的位址」，而是**讀出 `0x4008` 那格裡存的位址、跳過去**（`jmp` 前面的 `*`）。

> 3. `jmp *0x2f8e(%rip)` 的下一條是 `0x107a`：`0x107a ＋ 0x2f8e ＝ 0x4008`。

第二次: 跳到log_msg@plt的程式碼 -> 跳到.got.plt的位址(0x4008) -> 從0x4008獲得了log_msg的位址,直接跳過去

ld.so的介入的時間點與行爲都在第一次的流程裏面了
```

> 盒子 3｜過去的作答：[s1-04 quiz.md 第 8 題](../small-project/s1-04-asm-basics/quiz.md#8-暫存器的名字-vs-暫存器本身2026-10-06-課後提問新增)、[10-13 複習](./2026-10-13-組語-字元.md)、[10-22 複習](./2026-10-22-組語-C資料-objdump-字元-陣列.md)、[10-25 複習](./2026-10-25-C資料-陣列-組語-組語二-多檔.md#組語-8-暫存器的名字-vs-暫存器本身)

用到的程式（檔案：[`dil.c`](../small-project/s1-04-asm-basics/dil.c)）：

```c
#include <stdio.h>

__attribute__((noinline)) int widen_char(signed char c) { return c; }   /* noinline：不准內嵌，才看得到真的呼叫 */

int main(void)
{
    printf("%d\n", widen_char(-1));
    return 0;
}
```

```sh
gcc -O2 -g dil.c -o dil
objdump -d --no-show-raw-insn dil
```

`main` 呼叫 `widen_char(-1)` 的那幾行，`objdump` 節錄：

```asm
main:
	endbr64
	sub	$0x8,%rsp
	mov	$0xffffffff,%edi       # 呼叫的人：把 -1 放進 %edi（第 1 個參數）
	lea	0xf90(%rip),%rsi       # 準備 printf 的參數，跟本題無關
	call	widen_char         # 呼叫 widen_char
	...
widen_char:
	endbr64                    # 給 CPU 的控制流程保護標記，跟計算無關
	movsbl	%dil,%eax          # 被呼叫的人：只讀 %dil（1 byte），有號擴展成 4 byte 放進 %eax
	ret                        # 回傳 %eax
```

#### 組語 8-1. `dil.c` 的組合語言裡只出現 `%edi`、`%dil`，沒有 `%rdi`，為什麼 gdb 能印出 `$rdi`？

```
三個只是同一個寄存器,讀的位元數不一樣而已,所以gdb還是能印出$rdi
```

> **批改**：**對**。抓到重點：`%rdi`、`%edi`、`%dil` 是同一個暫存器，名字不同只是指令碰的位元數不同；組合語言沒寫 `%rdi` 不代表它不存在。
>
> **參考答案**【[第三節](../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#三指令的文法助憶符大小後綴運算元)〈組合語言裡只有 `%edi`、`%dil`，為什麼 gdb 印得出 `$rdi`？〉】
>
> **核心關鍵**（答到這幾點就算對）：
>
> 1. `%edi`、`%di`、`%dil` 不是另外的暫存器，都是 `%rdi` 這**一個**暫存器的一部分的名字；組合語言沒寫出 `%rdi`，只代表那個指令只碰它的一部分。
>
> **詳細說明**：gdb 不只印得出 `$rdi`，**任何**暫存器都印得出來——程式停下時，gdb 請核心把整組暫存器讀出來，跟程式有沒有用到無關。

#### 組語 8-2. 在 gdb 裡 `set $edi = 0xaabbccdd`，`$rdi` 的高 4 byte 會不會被清成 0？

```
不會,那是cpu的機制,
```

> **批改**：**對**。抓到重點：不會清；「寫 32 位元清高位」是 CPU 執行指令的機制，gdb 的 `set` 不是 CPU 在執行指令。可以寫得更具體：gdb 只改 `%rdi` 的低 4 byte，高 4 byte 保留原值。
>
> **參考答案**【[第三節](../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#三指令的文法助憶符大小後綴運算元)〈組合語言裡只有 `%edi`、`%dil`，為什麼 gdb 印得出 `$rdi`？〉】
>
> **核心關鍵**（答到這幾點就算對）：
>
> 1. **不會**：gdb 的 `set $edi = …` 只改 `%rdi` 的低 4 byte，高 4 byte 保留原值。
>
> **詳細說明**：實驗先把 `$rdi` 設成 `0x11223344556677ff`，`set $edi = 0xaabbccdd` 之後 `$rdi` 是 `0x11223344aabbccdd`。

#### 組語 8-3. 跟 CPU 執行 `movl $0xaabbccdd, %edi` 有什麼不同？

> 題目：（承 8-2）gdb 的 `set $edi = 0xaabbccdd` 跟 CPU 執行 `movl $0xaabbccdd, %edi` 有什麼不同？

```
cpu會把高32位元的默認清除爲0
```

> **批改**：**對**。抓到重點：CPU 執行寫 32 位元暫存器的指令，會把 `%rdi` 的高 32 位元清成 0（結果 `0x00000000aabbccdd`）；跟 8-2「gdb 不清」合起來就是兩者的差別。
>
> **參考答案**【[第二節](../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#二暫存器cpu-裡的-16-個變數)〈寫低位的名字時，高位會怎樣？〉】
>
> **核心關鍵**（答到這幾點就算對）：
>
> 1. CPU 執行 `movl $0xaabbccdd, %edi` 會把 `%rdi` 的**高 32 位元清成 0**，結果是 `0x00000000aabbccdd`。
> 2. 「寫 32 位元清高位」是 CPU 執行指令的規則；gdb 的 `set` 不是指令，不套用這條規則。
>
> **詳細說明**：實例：`dil.c` 的 `main` 執行 `mov $0xffffffff,%edi`，`%rdi` 變成 `0x00000000ffffffff`。用 gdb 改暫存器做實驗時要記得這個差別。

#### 組語 14-1. 寫出做完後 ZF、SF、CF、OF 各是 0 還是 1，並說明 CF、OF 各是用哪一種解讀（無號／有號）算出來的。

```
0x7f - 0xff = 0x80

zf = 0
sf = 1
cf = 1 用無號可算出: 127 - 255 = - 128 => 超出無號8位元範圍
of = 1 用有號: 127 - (-1) = 128 => 超出有號範圍
```

> **批改**：**對**。抓到重點：留下的位元是 `0x80`，ZF ＝ 0、SF ＝ 1；CF ＝ 1 是當**無號**算（127 − 255 小減大、結果是負的，無號裝不下，要借位）；OF ＝ 1 是當**有號**算（127 − (−1) ＝ 128，超出 −128～127）。
>
> **參考答案**【[第五節](../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#五旗標與條件跳躍cmp-只負責比跳不跳由下一個指令決定)〈上表的四個旗標在講什麼：用 10 組數字實際跑一次〉】
>
> **核心關鍵**（答到這幾點就算對）：
>
> 1. ZF ＝ 0、SF ＝ 1：留下的位元是 `0x80`。
> 2. CF ＝ 1：當**無號**算，127 − 255 小減大，要借位。
> 3. OF ＝ 1：當**有號**算，127 − (−1) ＝ 128，超出 −128～127。
>
> **詳細說明**：本機用筆記的 `flags_cmp(0x7f, 0xff)` 實測：`res=0x80 ZF=0 SF=1 CF=1 OF=1`。

#### 組語 14-2. 接著 `setl` 和 `setb` 各會得到 1 還是 0？

setl(有號): 0 因爲sf == of 不爲小於

> **核心關鍵**（答到這幾點就算對）：
>
> 1. `setl`：SF ≠ OF？1 ＝ 1，不成立 → **0**（有號 127 < −1 為假）。

#### 組語 14-3. 為什麼有號的「小於」要看 SF ≠ OF，不能只看 SF？

```
sf只說明運算後結果是否爲負,
假如沒有溢位,OF = 0, 這個結果是小於沒錯

如果sf = 0是正的,沒有溢位,說明結果是大於,
但如果有產生溢位OF = 1 結果是要變號的,

sf =1 溢位 of = 1 ,結果是大於
sf = 0 溢位 of =1 ,結果變小於
```

> **批改**：**對**。抓到重點：SF 只是「留下的位元」的正負；沒溢位時它就是答案，溢位時正負號被翻過來。四種組合列對了：沒溢位 SF ＝ 1 → 小於、SF ＝ 0 → 不小於；溢位 SF ＝ 1 → 不小於、SF ＝ 0 → 小於——合起來正好是 SF ≠ OF。
>
> **參考答案**【[第五節](../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#五旗標與條件跳躍cmp-只負責比跳不跳由下一個指令決定)〈上表的四個旗標在講什麼：用 10 組數字實際跑一次〉的「回頭看條件碼表」】
>
> **核心關鍵**（答到這幾點就算對）：
>
> 1. 溢位時留下的位元正負號跟真正的答案**相反**，只看 SF 會答錯。
> 2. OF ＝ 1 表示 SF 是反的；SF ≠ OF ＝「沒溢位看 SF，溢位看 SF 的相反」。
>
> **詳細說明**：筆記的⑥：−128 − 1 ＝ −129，是負的，但溢位後留下 `0x7f`，SF ＝ 0、OF ＝ 1；只看 SF 會說「不小於」，SF ≠ OF 才答對。

#### 組語 14-4. 情境題：同學說「OF = 1 就代表這次加法的結果錯了」。這句話什麼時候對、什麼時候不對？用 8 位元的 `0x7f + 0x01` 說明。

```
有號的時候, 0x7f + 0x01, 產生溢位, 127 + 1 = -128 加法結果是錯的
但無號的時候, 127 + 1 = 128 是沒問題的

不管是哪個類型情況of都是1

所以要看類型是有號還是無號
```

> **批改**：**對**。抓到重點：當有號數，127 ＋ 1 裝不下、`0x80` 讀成 −128，結果錯了；當無號數，128 完全正確。「不管是哪個類型 OF 都是 1」這句講得好：CPU 不知道型別，兩個旗標都設，看 OF 還是 CF 由資料型別決定。可以再補一句：無號時要看的是 CF，這裡 CF ＝ 0，代表無號沒出錯。
>
> **參考答案**【[第五節](../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#五旗標與條件跳躍cmp-只負責比跳不跳由下一個指令決定)〈上表的四個旗標在講什麼：用 10 組數字實際跑一次〉（⑦）】
>
> **核心關鍵**（答到這幾點就算對）：
>
> 1. 當**有號數**時對：127 ＋ 1 ＝ +128 裝不下，留下的 `0x80` 讀成 −128，結果確實錯了。
> 2. 當**無號數**時不對：127 ＋ 1 ＝ 128 完全正確（CF ＝ 0），OF 是在回答一個跟無號資料無關的問題。
>
> **詳細說明**：筆記⑦：`add D=0x7f S=0x01 -> 0x80 | ... | ZF=0 SF=1 CF=0 OF=1`。

### 組語 16. `and` 與 `test`

> 盒子 3｜過去的作答：[s1-04 quiz.md 第 16 題](../small-project/s1-04-asm-basics/quiz.md#16-and-與-test2026-10-07-課後提問新增)、[10-13 複習](./2026-10-13-組語-字元.md)、[10-22 複習](./2026-10-22-組語-C資料-objdump-字元-陣列.md)、[10-25 複習](./2026-10-25-C資料-陣列-組語-組語二-多檔.md#組語-16-and-與-test)

#### 組語 16-1. `andl $1, %edi` 和 `testl $1, %edi` 做完後，旗標有什麼不同？`%edi` 有什麼不同？

```
旗標相同,
但是edi不同,因爲andl還會把運算結果寫入edi
```

> **批改**：**對**。抓到重點：兩個都算 `%edi & 1`、旗標一樣；`andl` 把結果寫回 `%edi`，`testl` 算完就丟。
>
> **參考答案**【[第七節](../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#七逐行讀-sum_to-的--o2-版)〈上表的 `andl` 和 `testl`：看起來一樣，差在哪？〉】
>
> **核心關鍵**（答到這幾點就算對）：
>
> 1. **旗標一樣**：兩個都算 `%edi & 1`，照同樣的規則設旗標。
> 2. `andl` 把結果**寫回** `%edi`（變成 `n & 1`）；`testl` 把結果丟掉，`%edi` 不變。

#### 組語 16-2. `sum_to` 的 `-O2` 開頭為什麼一定要用 `testl %edi, %edi` 而不能用 `andl $1, %edi` 之類會改掉 `%edi` 的指令，中間的 `andl $1, %edi` 卻可以改掉 `%edi`？

用到的程式（第 1 課的檔案：[`sumto.c`](../small-project/s1-01-hello-compile/sumto.c)）：

```c
#include <stdio.h>

int sum_to(int n)
{
    int total = 0;
    for (int i = 1; i <= n; i++)
        total += i;
    return total;
}

int answer(void)
{
    return sum_to(100);
}

int main(void)
{
	printf("answer:%d\n", answer());
	return 0;
}
```

```sh
gcc -S -O2 -fno-asynchronous-unwind-tables sumto.c -o sumto2.s
```

`sum_to` 的 `-O2` 組合語言（`%edi` 是參數 `n`）：

```asm
sum_to:
	endbr64
	testl	%edi, %edi            # 算 n & n，只設旗標
	jle	.L4                   # 結果 ≤ 0 就跳到 .L4（回傳 0）
	leal	1(%rdi), %ecx         # %ecx = %rdi + 1
	xorl	%edx, %edx            # %edx = 0（total）
	andl	$1, %edi              # %edi = %edi & 1，設旗標
	movl	$1, %eax              # %eax = 1（i），不改旗標
	je	.L3                   # 上一個設旗標的指令結果是 0 就跳 .L3
	movl	$2, %eax              # %eax = 2
	movl	$1, %edx              # %edx = 1
	cmpl	%ecx, %eax            # 比較 %eax 與 %ecx
	je	.L1                   # 相等就跳 .L1
.L3:
	leal	1(%rdx,%rax,2), %edx  # %edx = %edx + %rax×2 + 1（一圈加兩個數）
	addl	$2, %eax              # %eax += 2
	cmpl	%ecx, %eax            # 比較 %eax 與 %ecx
	jne	.L3                   # 不相等就再一圈
.L1:
	movl	%edx, %eax            # 回傳值 = %edx
	ret
.L4:
	xorl	%edx, %edx
	movl	%edx, %eax            # 回傳 0
	ret
```

> 題目：`sum_to` 的 `-O2` 開頭為什麼一定要用 `testl %edi, %edi` 而不能用 `andl $1, %edi` 之類會改掉 `%edi` 的指令，中間的 `andl $1, %edi` 卻可以改掉 `%edi`？

```
因爲testl %edi, %edi目的只是想要確認edi是否爲0, 他不想改動edi

後面的andl $1, %edi要判斷edi的奇偶數,用了以後edi就不用了 
```

> **批改**：**大致對**。中間那半對：`andl $1, %edi` 判斷奇偶之後，`%edi` 再也沒被讀過，改掉沒關係。開頭那半只寫了「目的只是確認 `%edi` 是否為 0，不想改動 `%edi`」——這是在描述 `test` 的行為，沒回答**為什麼不能改**：`testl` 的下一段 `leal 1(%rdi), %ecx` 還要用 `n` 算出 `n + 1`（迴圈的終點），`%edi` 這時被改掉，`n + 1` 就算錯了。「能不能改掉一個暫存器」的判斷標準就是：**後面還有沒有指令要讀它**——開頭有、中間沒有。
>
> **參考答案**【[第七節](../html/c/x86-64組合語言入門-暫存器、mov與lea、cmp與條件跳躍.html#七逐行讀-sum_to-的--o2-版)〈上表的 `andl` 和 `testl`：看起來一樣，差在哪？〉的「回到 `sum_to`：為什麼開頭用 `test`、中間用 `and`？」】
>
> **核心關鍵**（答到這幾點就算對）：
>
> 1. 開頭 `testl` 之後，下一條 `leal 1(%rdi), %ecx` 還要用 `n` 算 `n + 1`，所以 `%edi` **不能被改掉**，只能看旗標。
> 2. 中間 `andl` 時，`n + 1` 已經存進 `%ecx`，之後 `%edi` **再也沒被讀過**，改成 `n & 1` 也沒關係。
>
> **詳細說明**：編譯器在中間選 `andl` 而不是 `testl`，是因為反正 `%edi` 不再用，兩者效果一樣；`test` 的價值在「還要保留原值」的地方。
