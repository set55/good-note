## 一、逐段拆解

```
./oob   ;   echo   "exit=$?"
└─┬─┘   │   └─┬┘   └───┬───┘
命令 1  串接  命令 2   命令 2 的參數（一個字串）
```

| 片段 | 是什麼 | 誰處理 | 詳見 |
|---|---|---|---|
| `./oob` | 執行**目前目錄**裡叫 `oob` 的檔案 | shell 找檔案，核心 `execve` 執行 | 第二節 |
| `;` | 命令分隔符號：前一個跑完，**不論成敗**都接著跑下一個 | shell | 第四節 |
| `echo` | shell 內建命令，把參數印出來、最後加換行 | shell 本身（不是外部程式） | 第七節 |
| `"..."` | 雙引號：裡面的 `$` 仍會展開，但整段算**一個**參數 | shell | 第六節 |
| `$?` | 特殊參數：**上一個**前景命令的結束狀態 | shell 在執行 `echo` **之前**就換成數字 | 第三、五節 |

shell 讀到這一行時的順序：
1. 看到 `;`，知道這是兩個命令，先執行 `./oob`，等它結束，記下它的結束狀態。
2. 準備執行 `echo` 時先做展開：`"exit=$?"` 裡的 `$?` 換成剛剛記下的數字，例如 `exit=0`。
3. 執行 `echo exit=0`，印出來。

所以 `echo` 看到的從來不是 `$?` 這兩個字元，而是已經換好的數字。

## 二、`./`：為什麼不能只打 `oob`

只打一個名字（不含 `/`）時，shell 會依序到 `PATH` 這個環境變數列出的目錄去找，**不會找目前目錄**。
本機的 `PATH`（節錄）：

```
$ echo "$PATH" | tr ':' '\n'
/home/set/.nvm/versions/node/v24.14.0/bin
...
/usr/local/bin
/usr/sbin
/usr/bin
/sbin
/bin
...
```

裡面沒有 `.`（目前目錄）。所以要執行剛編出來的程式，就得寫出路徑。`./oob` 的 `.` 是「目前目錄」，`/` 是路徑分隔，
名字裡只要有 `/`，shell 就不查 `PATH`，直接拿這個路徑去執行。

不把 `.` 放進 `PATH` 是刻意的安全設計：否則別人在某個目錄放一個叫 `ls` 的惡意程式，你一 `cd` 進去打 `ls` 就中招。

少打 `./` 的下場（實測，`ret` 是第三節的程式，在目前目錄裡）：

```
$ ret 1; echo "exit=$?"
bash: ret: command not found                   ← bash（互動）的訊息
zsh: command not found: ret                    ← zsh（互動）的訊息
exit=127                                       ← 兩個 shell 都是 127
```

127 是 shell 保留的值，代表「找不到命令」（第八節）。

## 三、結束狀態：0～255 這個數字從哪來

### 程式自己決定：`return` 或 `exit()` 的值

`main` 的 `return n`（或呼叫 `exit(n)`）就是把 `n` 交給核心，父行程（這裡是 shell）用 `waitpid` 系統呼叫拿回來。
慣例是 **0 代表成功，非 0 代表失敗**——跟 C 的「0 是假」剛好相反，因為成功只有一種、失敗可以有很多種原因要分辨。

用一個「把第一個參數當結束狀態」的小程式實測。`ret.c` 完整原始碼：

```c
#include <stdlib.h>

int main(int argc, char *argv[])
{
    if (argc < 2)
        return 0;
    return atoi(argv[1]);      /* 用第一個參數當結束狀態 */
}
```

```
$ gcc -Wall -Wextra -o ret ret.c
$ ./ret 3;   echo "exit=$?"
exit=3
$ ./ret 256; echo "exit=$?"
exit=0          ← 不是 256
$ ./ret 300; echo "exit=$?"
exit=44         ← 不是 300
$ ./ret -1;  echo "exit=$?"
exit=255        ← 不是 -1
```

（bash、zsh 結果完全相同。）

結束狀態只有 **8 bit**：`main` 回傳的 `int` 被**截斷**成最低的 1 個 byte，再當成**無號**數讀——
正是[第 2 課第六節](../c/C的資料在記憶體裡長怎樣-位元組、指標、位元組順序與有號無號.md#六有號與無號之間的轉換位元不變換個讀法)〈變窄（截斷，truncation）〉的規則：

| 回傳值 | 十六進位 | 留下最低 1 byte | 用無號讀 |
|---|---|---|---|
| 256 | `0x00000100` | `0x00` | 0 |
| 300 | `0x0000012c` | `0x2c` | 44 |
| −1 | `0xffffffff` | `0xff` | 255 |

所以 `return 256;` 會被當成「成功」——程式要回報錯誤，一律用 1～125 之間的值。

### 被訊號殺掉：shell 設成 128 + 訊號編號

程式如果被訊號（signal）終止，它根本沒有執行到 `return`，也就沒有自己的結束狀態。
這時 shell 用 **128 + 訊號編號** 代替（第 3 課〈[結束狀態 139 和 134 是什麼](../c/陣列、字串與指標運算-C不檢查邊界與用gdb找segfault.md#結束狀態-139-和-134-是什麼)〉）。
`crash.c` 完整原始碼：

```c
int main(void)
{
    int *p = 0;
    return *p;                 /* 讀位址 0：segfault */
}
```

```
$ gcc -o crash crash.c
$ ./crash; echo "exit=$?"
exit=139                       ← 128 + 11（SIGSEGV）
```

那行 `Segmentation fault (core dumped)` 是**誰印的**？不是程式（它已經死了），是 **shell** 發現子行程被訊號殺掉後自己印的，兩個 shell 的措辭不同：

```
bash（互動）：Segmentation fault (core dumped)
zsh （互動）：zsh: segmentation fault (core dumped)  ./crash
```

實測發現：zsh 以非互動方式執行（`zsh -c '...'`、腳本）時**不印**這一行，只剩 `exit=139`；bash 在 `bash -c` 下仍然會印。
所以看不到錯誤訊息不代表程式沒當掉——**`$?` 才是可靠的判斷依據**，這也是第 3 課每個實驗都要 `echo "exit=$?"` 的原因。

## 四、`;` 與其他串接命令的方式（完整清單）

`man bash` 的〈Lists〉一節：串接用的運算子**只有** `;`、`&`、`&&`、`||` 四個，外加換行（等同 `;`）。

| 寫法 | 名稱 | 意思 | 整串的結束狀態 |
|---|---|---|---|
| `A ; B` | 循序（sequential） | 等 A 結束，**不論成敗**都跑 B | 最後跑的那個（B） |
| `A`（換行）`B` | 同上 | 換行和 `;` 完全一樣 | 同上 |
| `A && B` | AND 串列 | A **成功**（狀態 0）才跑 B | 最後實際跑的那個 |
| `A \|\| B` | OR 串列 | A **失敗**（狀態非 0）才跑 B | 最後實際跑的那個 |
| `A & B` | 非同步（asynchronous） | A 丟到背景，**不等它**就跑 B | `A &` 本身永遠是 0 |

zsh 另外多兩個：`A &|` 和 `A &!`，都是「丟到背景，而且立刻跟 shell 脫鉤（disown）」（`man zshmisc` 的〈SIMPLE COMMANDS & PIPELINES〉）。

實測（`ret` 見第三節；bash、zsh 輸出相同）：

```
$ ./ret 1 ; echo "分號：上一個是 $?"
分號：上一個是 1
$ ./ret 1 && echo "&&：不會印"                   ← 沒有輸出
$ ./ret 0 && echo "&&：上一個成功才印"
&&：上一個成功才印
$ ./ret 1 || echo "||：上一個失敗才印"
||：上一個失敗才印
$ ./ret 0 || echo "||：不會印"                   ← 沒有輸出
```

**第 3 課為什麼用 `;`，不用 `&&`？** 實驗的目的就是看程式**失敗**時的結束狀態。
寫成 `./oob && echo "exit=$?"`，只要 `oob` 當掉（139），`echo` 根本不會執行，什麼都看不到。

**優先順序**：`&&` 和 `||` 同級、由左往右結合；`;` 和 `&` 同級、比它們低。所以 `A && B || C` 是 `(A && B) || C`——
B 失敗時 C 也會跑，不是「A 成功跑 B、否則跑 C」的三元式：

```
$ ./ret 0 && ./ret 1 || echo "C 被執行了"
C 被執行了                                         ← A 成功，但 B 失敗，所以 C 也跑了
```

這個陷阱在 [shell條件判斷測試](./shell條件判斷測試.md#三----三元式與它的陷阱)〈陷阱：`&&` 後面那段自己失敗時，`||` 也會跑〉有完整說明。

### 管線 `|` 不是串接，但 `$?` 會受它影響

`A | B` 把 A 的輸出接到 B 的輸入，兩個**同時**執行（見 [輸出重新導向與dev-null](./輸出重新導向與dev-null.md)）。
它不屬於上面的串列運算子，而是更小的單位「管線（pipeline）」：串列是由管線串成的。相關符號也全部列出：

| 寫法 | 意思 |
|---|---|
| `A \| B` | A 的 stdout 接到 B 的 stdin |
| `A \|& B` | 等於 `A 2>&1 \| B`，stdout 和 stderr 都接過去（bash、zsh 都有） |
| `! A` | 把管線的結束狀態反轉：0 變 1，非 0 變 0 |

管線的結束狀態是**最後一個命令**的，見第五節。

## 五、`$?`：只記得上一個命令

### 每跑一個命令就被覆蓋

```
$ ./ret 7; echo hi; echo "看到的是 $?"
hi
看到的是 0                     ← 是 echo hi 的狀態，不是 ret 的 7
$ ./ret 7; rc=$?; echo hi; echo "存起來的 rc=$rc"
hi
存起來的 rc=7                  ← 先存進變數，之後怎麼跑都不會變
```

`echo` 本身也是命令，它成功執行完，`$?` 就變成 0。要在好幾個命令之後還用得到，就要**立刻**存起來：`rc=$?`。

### 背景命令：`$?` 是 0，要用 `wait` 拿

```
$ ./ret 3 & echo "背景：\$? 立刻是 $?"; wait $!; echo "wait 之後 $?"
背景：$? 立刻是 0              ← 「成功把它丟到背景」的狀態
wait 之後 3                    ← wait 等它結束，把它的狀態當成自己的
```

（`$!` 是最近一個背景工作的行程 ID，見下表。）

> 課後討論：[第九節第 1 章〈`wait` 不加參數：等全部背景工作〉](#1-wait-不加參數等全部背景工作)

### 管線：只看最後一個命令

```
$ ./crash | tee log.txt; echo "exit=$?"
exit=0                         ← crash 明明 segfault 了，但 tee 成功
```

管線中間的程式當掉，`$?` 看不出來。三種補救（本機實測）：

| 方法 | bash | zsh | 輸出 |
|---|---|---|---|
| 看每一段的狀態 | `${PIPESTATUS[*]}` | `${pipestatus[*]}`（小寫） | `139 0` |
| 讓管線「有一段失敗就算失敗」 | `set -o pipefail` | `setopt pipefail` | `$?` 變成 3（用 `./ret 3 \| ./ret 0` 實測） |

`PIPESTATUS`／`pipestatus` 一樣會被下一個命令覆蓋，要馬上讀。

### zsh 的 `$status`

zsh 另有 `$status`，跟 `$?` 完全一樣（`./ret 9; echo $status` 印 9）；bash 沒有這個變數（印出空字串）。
可攜的寫法一律用 `$?`，因為所有 POSIX shell（含 dash、BusyBox ash）都有。

### `$?` 是 shell 的「特殊參數」之一：完整清單

`man bash` 的〈Special Parameters〉一共 **8 個**，只能讀、不能賦值：

| 參數 | 展開成 | 例子 |
|---|---|---|
| `$?` | 最近一個**前景管線**的結束狀態 | 本篇主角 |
| `$#` | 位置參數（腳本或函式收到的參數）個數 | 見 [shell條件判斷測試](./shell條件判斷測試.md#九實例拆解---eq-0-有沒有給參數) 第九節〈九、實例拆解：`[ $# -eq 0 ]`——「有沒有給參數」〉 |
| `$*` | 全部位置參數；在雙引號裡合成**一個**字串（用 `IFS` 第一個字元隔開） | `"$*"` → `"a b c"` |
| `$@` | 全部位置參數；在雙引號裡**每個參數各自一個**字串 | `"$@"` → `"a" "b" "c"`，傳遞參數時用這個 |
| `$-` | 目前開啟的 shell 選項旗標 | 互動 shell 會含 `i` |
| `$$` | 這個 shell 的行程 ID（在子 shell 裡仍是原本 shell 的） | 產生暫存檔名 |
| `$!` | 最近一個丟到背景的工作的行程 ID | 上面的 `wait $!` |
| `$0` | shell 或腳本的名字 | 腳本裡印出自己的檔名 |

（`$1`、`$2`… 是**位置參數**，不在這 8 個裡。bash 5.2 把 `$_` 歸在〈Shell Variables〉而不是特殊參數。
zsh 有同樣這 8 個，另外還有 `$status`、`$pipestatus` 等數十個 shell 自動設定的參數，完整清單見 `man zshparam` 的〈PARAMETERS SET BY THE SHELL〉。）

## 六、雙引號：為什麼寫成 `"exit=$?"`

三種寫法實測（前一個命令是 `./ret 5`；bash、zsh 輸出相同）：

```
$ ./ret 5; echo "exit=$?"
exit=5            ← 雙引號：$ 照樣展開
$ ./ret 5; echo 'exit=$?'
exit=$?           ← 單引號：什麼都不展開，原樣印出
$ ./ret 5; echo exit=$?
exit=5            ← 不加引號：這裡也對，因為展開結果沒有空白
```

- **單引號**裡的東西一律是字面，`$?` 不會被換掉，所以要用雙引號。
- 不加引號這裡也能跑，但**養成加雙引號的習慣**：展開結果如果含空白或 `*`，不加引號時會被拆成多個參數、或被當成檔名樣式展開。
  原因與實例見 [錢字號展開的四種形式](./錢字號展開的四種形式-bad-substitution的根因.md#六為什麼結果要加雙引號) 第六節；
  雙引號擋不住哪些展開見同篇[第四節](./錢字號展開的四種形式-bad-substitution的根因.md#四實測插曲雙引號擋不住-)。
- `exit=` 只是給人看的標籤，沒有任何特殊意義，寫成 `"狀態：$?"` 也一樣。

## 七、`echo`：完整選項，以及 bash 與 zsh 的差別

`echo` 有兩個：shell **內建**的，和 coreutils 的外部程式 `/usr/bin/echo`。打 `echo` 時用的是**內建**的：

```
$ type -a echo          （bash）
echo is a shell builtin
echo is /usr/bin/echo
echo is /bin/echo
```

文法：`echo [-neE] [參數 ...]`——把所有參數用**一個空白**隔開印出，最後加換行。

**選項（bash 的 `help echo`，全部 3 個）**：

| 選項 | 作用 |
|---|---|
| `-n` | 最後**不加**換行 |
| `-e` | **解讀**反斜線跳脫序列（`\t`、`\n`…） |
| `-E` | **不解讀**反斜線跳脫序列 |

zsh 內建 `echo` 的選項也是這 3 個（`man zshbuiltins`）；`/usr/bin/echo` 多了 `--help`、`--version`。

**bash 與 zsh 最大的差別：預設要不要解讀 `\t`**（實測）：

```
bash:  echo "a\tb"     →  a\tb        （預設 -E，不解讀；要 -e）
zsh:   echo "a\tb"     →  a<Tab>b     （預設就解讀；要 -E 才不解讀）
/usr/bin/echo "a\tb"   →  a\tb        （預設 -E）
```

同一行在兩個 shell 印出不同結果，這就是**寫腳本時建議改用 `printf`** 的原因（`/usr/bin/echo --help` 自己也寫 `printf(1) is a preferred alternative`）。
`printf` 的用法見 [在終端機怎麼計算](./在終端機怎麼計算-shell算術bc與printf.md)。只是印一行固定字串或 `"exit=$?"` 這種沒有反斜線的內容，`echo` 在哪裡都一樣，放心用。

**跳脫序列（bash `help echo` 全部列出，需 `-e`）**：

| 序列 | 意思 | 序列 | 意思 |
|---|---|---|---|
| `\a` | 響鈴 | `\r` | 歸位（carriage return） |
| `\b` | 退格 | `\t` | 水平定位（Tab） |
| `\c` | 之後的輸出全部不印（含換行） | `\v` | 垂直定位 |
| `\e`、`\E` | ESC 字元 | `\\` | 反斜線本身 |
| `\f` | 換頁（form feed） | `\0nnn` | 八進位 0～3 位數代表的字元 |
| `\n` | 換行 | `\xHH` | 十六進位 1～2 位數代表的字元 |
| `\uHHHH` | Unicode 字元（1～4 位十六進位） | `\UHHHHHHHH` | Unicode 字元（1～8 位十六進位） |

zsh 的清單相同，只是不必加 `-e`。`/usr/bin/echo` 沒有 `\E`、`\u`、`\U`。

## 八、錯誤與結束狀態對照

看到某個結束狀態時，可以這樣反推（bash 的值來自 `man bash`〈EXIT STATUS〉，本機實測 zsh 相同）：

| 結束狀態 | 意思 | 本篇的實例 | 典型訊息（bash／zsh） |
|---|---|---|---|
| 0 | 成功 | `./oob`（越界但沒當掉） | — |
| 1～125 | 程式自己回報的失敗 | `./ret 3` | 程式自己印的 |
| 2 | shell 內建命令用法錯誤（選項或參數不對） | — | — |
| 126 | 找到了但**不能執行**（例如沒有 x 權限） | `./noexec.c`（權限 `644`） | `bash: ./noexec.c: Permission denied`／`zsh: permission denied: ./noexec.c` |
| 127 | **找不到命令** | `ret`（忘了 `./`） | `bash: ret: command not found`／`zsh: command not found: ret` |
| 128 + N | 被訊號 N 終止 | `./crash` → 139（SIGSEGV 11）；第 3 課的 `smash` → 134（SIGABRT 6） | `Segmentation fault (core dumped)`／`zsh: segmentation fault` |

126 的更多成因（`noexec` 掛載、`#!` 直譯器不存在等）見 [root執行腳本也Permission denied](./root執行腳本也Permission-denied-缺執行位元.md#六長得像但原因不同的錯誤) 第六節。

### 1. `wait` 不加參數：等全部背景工作

> 2026-10-29 課後提問（做第 7 課自我測驗第 9 題時，題目的執行指令是 `./x & ./y & wait`）：「可以幫我註解wait是什麼用途嗎?」
>
> 正文出處：[第四節](#四-與其他串接命令的方式完整清單)的串接表 `A & B` 那一列（`&` 丟到背景、不等它）；[第五節〈背景命令：`$?` 是 0，要用 `wait` 拿〉](#背景命令-是-0要用-wait-拿)只教了 `wait $!`。

**一句話：`wait` 是 shell 的內建命令，讓 shell 停下來等背景工作結束。`wait $!` 只等最近丟到背景的那一個；`wait` 不加參數是等全部，而且結束狀態固定是 0，要拿各自的狀態得一個一個 `wait <行程 ID>`。**

#### `./x & ./y & wait` 逐段拆開

| 片段 | 意思 |
|---|---|
| `./x &` | 把 `x` 丟到背景，shell 不等它，馬上執行下一個 |
| `./y &` | `y` 也丟到背景。現在 `x`、`y` **同時**在跑——讓兩個行程同時活著的是 `&`，不是 `wait` |
| `wait` | shell 停在這裡，等**所有**背景工作都結束才往下走 |

第 7 課第 9 題加 `wait`，是讓這一整行等 `x`、`y` 都跑完才算結束：兩支程式的輸出一定在提示字元回來之前印完，放在腳本裡時，後面的命令也一定在它們跑完之後才執行。

#### 實驗：等全部、只等最後一個、結束狀態

`ret` 是[第三節〈程式自己決定〉](#程式自己決定return-或-exit-的值)的 `ret.c`（把第一個參數當結束狀態），完整原始碼：

```c
#include <stdlib.h>

int main(int argc, char *argv[])
{
    if (argc < 2)
        return 0;
    return atoi(argv[1]);      /* 用第一個參數當結束狀態 */
}
```

`demo.sh` 完整內容（`( … )` 是在子 shell 裡跑括號內的命令，整組可以一起丟到背景；A 睡 2 秒、B 睡 1 秒，所以 B 先結束）：

```sh
echo "--- 實驗 1：wait 等全部"
(sleep 2; echo "A 結束") & (sleep 1; echo "B 結束") &
echo "丟到背景後立刻印"
wait
echo "wait 回來"
echo "--- 實驗 2：wait \$! 只等最後丟出去的那個"
(sleep 2; echo "A 結束") & (sleep 1; echo "B 結束") &
wait $!
echo "wait \$! 回來"
wait
echo "--- 實驗 3：結束狀態"
./ret 3 & ./ret 5 & wait; echo "wait 之後 \$?=$?"
./ret 3 & p3=$!; ./ret 5 & p5=$!
wait $p3; echo "wait \$p3 之後 \$?=$?"
wait $p5; echo "wait \$p5 之後 \$?=$?"
```

```sh
gcc -Wall -Wextra -o ret ret.c
bash demo.sh
zsh demo.sh
```

bash 與 zsh 的輸出完全相同：

```
--- 實驗 1：wait 等全部
丟到背景後立刻印
B 結束
A 結束
wait 回來
--- 實驗 2：wait $! 只等最後丟出去的那個
B 結束
wait $! 回來
A 結束
--- 實驗 3：結束狀態
wait 之後 $?=0
wait $p3 之後 $?=3
wait $p5 之後 $?=5
```

- **實驗 1**：兩個都丟到背景後，shell 馬上印「丟到背景後立刻印」；`wait` 等到最慢的 A（2 秒）也結束才回來。
- **實驗 2**：`$!` 是最後丟出去的 B，`wait $!` 只等 B（1 秒）就回來，所以「wait $! 回來」印在「A 結束」**前面**。（後面那個 `wait` 是把 A 收完，免得它的輸出混進實驗 3。）
- **實驗 3**：不加參數的 `wait`，就算兩個都失敗（3、5），`$?` 還是 0——`man bash` 寫明「If ID is not given, waits for all currently active child processes, and the return status is zero」，zsh 實測相同。要知道每一個的狀態，就先用 `$!` 把行程 ID 存起來，再一個一個 `wait`。

**沒有 `wait` 會怎樣**：shell（或腳本）不等背景工作，自己先往下走或結束，背景工作的輸出之後才插進畫面。`nw.sh` 完整內容：

```sh
(sleep 1; echo "A 結束") &
echo "腳本結束"
```

```
$ bash nw.sh; echo "shell 已經回來"; sleep 2
腳本結束
shell 已經回來
A 結束                ← 腳本早就結束了，背景工作 1 秒後才印
```

（最後的 `sleep 2` 只是讓這次執行等到 `A 結束` 出現。）

#### `wait` 的完整用法

`wait` 是 shell 內建命令，沒有獨立的 man page，bash 用 `help wait` 查、zsh 看 `man zshbuiltins` 的 `wait` 一項。兩個 shell 不一樣：

**bash 5.2**：`wait [-fn] [-p var] [id ...]`，選項共 3 個，全部列出：

| 寫法 | 做什麼 |
|---|---|
| `wait` | 等**所有**還在跑的子行程，結束狀態固定是 0 |
| `wait id ...` | 等指定的工作；`id` 可以是行程 ID（例如 `$!`）或工作代號（job spec，例如 `%1`）。結束狀態是**最後一個 id** 的狀態；id 無效時失敗（127） |
| `-n` | 只等**一個**：給了 id 就等其中最先結束的那個，沒給就等下一個結束的背景工作，回傳它的狀態 |
| `-p var` | 把 `-n` 等到的那個工作的 ID 存進變數 `var`（只有搭配 `-n` 才有用） |
| `-f` | 開了工作控制（job control，互動式 shell 預設開）時，等指定的 id 真的**結束**，而不是只等它「狀態改變」（例如被 Ctrl+Z 暫停也算狀態改變） |

**zsh 5.9**：`wait [ job ... ]`，**沒有任何選項**。不給 job 就等全部；job 可以是工作代號或行程 ID；不認得的 id 會印警告、結束狀態 127。實測 `wait -n` 在 zsh 是錯的：印出 `job not found: -n`（把 `-n` 當成工作代號）。另外，給好幾個 id 時 zsh 的結束狀態跟 bash 不同（本機實測：A 狀態 3、1 秒結束，B 狀態 5、2 秒結束，`wait $a $b` bash 得 5、zsh 得 3），所以要拿狀態時一次只 `wait` 一個 id，兩個 shell 才一致。
