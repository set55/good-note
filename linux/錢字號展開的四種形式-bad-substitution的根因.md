# `${}`、`$()`、`$(())`、`$var` 差在哪？—— `bad substitution` 的根因

> 日期：2026-09-20
> 症狀：`readlink -f "${command -v iptables}"` → `zsh: bad substitution`
> 適用範圍：實測 zsh 5.9 與 bash 5.2（行為一致，另註明 zsh 的分詞特例）
> 相關：[用當前目錄名命名tmux-session.md](./用當前目錄名命名tmux-session.md)、
> [shell條件判斷測試.md](./shell條件判斷測試.md)、
> [bin與sbin的差別-以及怎麼正確找到執行檔.md](./bin與sbin的差別-以及怎麼正確找到執行檔.md)

**一句話結論：`${...}` 和 `$(...)` 是兩種完全不同的展開——`${}` 是「參數展開」，大括號裡只能放
**變數名**加上少數運算子；`$()` 是「命令替換」，括號裡放的才是**要執行的指令**。把指令寫進 `${}`，
shell 在解析階段就認定它不是合法的變數表達式，於是回報 `bad substitution`。**

---

## 一、直接診斷

```bash
$ readlink -f "${command -v iptables}"
zsh: bad substitution                    # bash 的訊息幾乎一樣

$ readlink -f "$(command -v iptables)"
/usr/sbin/xtables-nft-multi              # ✅ 正確
```

差別只有 `{}` 與 `()` 一個符號，但語意天差地遠。

---

## 二、`$` 開頭的四種展開

| 寫法 | 名稱 | 括號裡放什麼 | 結果 |
|---|---|---|---|
| `$var`、`${var}` | 參數展開（parameter expansion） | **變數名** | 該變數的值 |
| `$(cmd)`、`` `cmd` `` | 命令替換（command substitution） | **要執行的指令** | 指令的標準輸出 |
| `$((expr))` | 算術展開（arithmetic expansion） | **數學運算式** | 計算結果 |
| `<(cmd)`、`>(cmd)` | 行程替換（process substitution） | 指令 | 一個 `/dev/fd/N` 路徑 |

```bash
p=$(command -v iptables)      # 命令替換：跑指令，把輸出存進 p
echo "${p}"                   # 參數展開：把 p 的值拿出來
echo "$(( 3 + 4 ))"           # 算術展開 → 7
diff <(ls dirA) <(ls dirB)    # 行程替換：把兩個指令的輸出當成檔案
```

**`${}` 的大括號本身不是「執行」的意思，只是「變數名到這裡為止」的界線**：

```bash
echo "$pfile"      # shell 以為變數叫 pfile → 空的
echo "${p}file"    # 明確指出變數是 p，後面接字面的 file
```

## 三、`${}` 裡面能放什麼

只能是**變數名**，後面可以接少數運算子——這些是 shell 內建的字串處理，不是執行指令：

```bash
p=/usr/sbin/iptables

${p}              # /usr/sbin/iptables    值
${#p}             # 18                    長度
${p##*/}          # iptables              從頭切到最後一個 /（貪婪）
${p%/*}           # /usr/sbin             從尾切掉最後一個 / 之後
${nope:-預設值}    # 預設值                 未設定時給預設
${p/sbin/bin}     # /usr/bin/iptables     取代
```

（`#`／`##`／`%`／`%%` 的完整切除規則見
[用當前目錄名命名tmux-session.md](./用當前目錄名命名tmux-session.md)。）

**所以 `${command -v iptables}` 為什麼炸**：shell 從 `${` 開始，期待接下來是合法的變數名。
但變數名只能由英數字與底線組成，而 `command -v iptables` 裡有**空白**和 `-`——解析到那裡就
無法繼續，於是回報「這個替換是壞的」。

```bash
$ zsh -c 'echo ${a b}'    # 空白就不行
zsh:1: bad substitution
$ zsh -c 'echo ${-v}'     # 減號也不行
zsh:1: bad substitution
```

**這是語法（syntax）錯誤，不是執行錯誤**——shell 根本沒去跑 `command`，它在讀這行字的時候就掛了。

---

## 四、實測插曲：雙引號擋不住 `${}`

寫這篇筆記時，連想印一句說明都會炸：

```bash
echo "=== 為什麼 ${command -v iptables} 會炸 ==="
zsh: bad substitution          # ← 連 echo 都執行不到
```

**雙引號不會阻止 `${}` 與 `$()` 展開**，它只擋分詞（word splitting）與萬用字元展開。要讓 `$`
變成字面字元，必須用**單引號**或反斜線：

```bash
echo '${command -v iptables}'     # ✅ 單引號：完全不展開
echo "\${command -v iptables}"    # ✅ 反斜線跳脫
```

這條規則對所有 `$` 展開都成立——「加了雙引號就安全」是常見的誤解，雙引號防的是別的東西。

---

## 五、命令替換的兩種寫法

```bash
$(cmd)      # 建議
`cmd`       # 舊寫法，能用但不建議
```

反引號的三個缺點：

1. **巢狀難寫**：`$(a $(b))` 一眼看懂；反引號要寫成 `` `a \`b\`` ``，每層都要多跳脫一次。
2. **跳脫規則不同**：反引號裡的 `\` 行為和 `$()` 不一樣，容易踩雷。
3. **視覺上容易和單引號混淆**。

`$()` 是 POSIX 標準，所有現代 shell 都支援，沒有理由用反引號。

---

## 六、為什麼結果要加雙引號

命令替換的輸出若含空白，不加引號會被**分詞**成多個參數。實測（檔名是 `my file.txt`）：

| shell | 寫法 | 結果 |
|---|---|---|
| bash | `wc -c $v`（變數，無引號） | ❌ 拆成 `my` 和 `file.txt` 兩個參數 |
| bash | `wc -c "$(ls)"` | ✅ 當成一個參數 |
| **zsh** | `wc -c $v`（變數，無引號） | ✅ **不分詞**（zsh 的著名差異） |
| **zsh** | `wc -c $(ls)`（命令替換，無引號） | ❌ **仍然會分詞** |

**注意最後一行**：很多人記得「zsh 不會對變數分詞」，就以為命令替換也安全——**不對**。
zsh 只有對**參數展開**不做分詞，**命令替換照樣依 `IFS` 切開**。

**結論：不管哪個 shell、不管變數還是命令替換，一律加雙引號。** 這是唯一不用記例外的規則。

## 七、速查

```bash
# 四種展開
"${var}"          # 參數展開：變數的值
"$(cmd)"          # 命令替換：指令的輸出
"$(( 1 + 2 ))"    # 算術展開
<(cmd)            # 行程替換：把輸出當檔案用

# 常見組合
"$(command -v foo)"                      # 指令的完整路徑
"$(readlink -f "$(command -v foo)")"     # 解開符號連結後的真身（可以巢狀）
"${PWD##*/}"                             # 當前目錄名
"${var:-預設}"                            # 未設定時的預設值

# 想印出字面的 $
echo '${var}'         # 單引號：完全不展開
echo "\${var}"        # 反斜線跳脫
```

## 自我測驗

1. `${command -v iptables}` 的錯誤訊息是 `bad substitution`。為什麼是「替換」壞掉而不是「找不到
   command 這個變數」？這個錯誤發生在 shell 處理這行字的哪個階段？
2. `${}` 的大括號是「執行裡面的東西」的意思嗎？用 `${p}file` 這個例子說明它真正的作用。
3. 為什麼 `echo "=== ${cmd -v x} ==="` 連 echo 都執行不到？雙引號到底防的是什麼、不防什麼？
4. 有人說「zsh 不會做分詞，所以不用加引號」。這句話哪裡對、哪裡錯？用變數展開與命令替換的差別回答。
5. 情境題：你要把某個指令的輸出存進變數再拿來當檔名，檔名可能含空白。請寫出這段程式碼，並指出
   有哪兩個地方必須加引號、各自防的是什麼。
