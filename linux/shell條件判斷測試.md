## 一、`[` 是一個命令，不是語法

```bash
$ type [
[ is a shell builtin

$ ls -l /usr/bin/[
-rwxr-xr-x 1 root root 55744 Jan 23 21:30 /usr/bin/[
```

**`/usr/bin/[` 是一個真實存在的 55KB 執行檔。** 所以這行的結構是：

```bash
[ -d /sys/module/nvidia/parameters ]
│  │                                └─ 這是「參數」，不是語法收尾
│  └─ 傳給命令的第一個參數
└─ 命令名稱
```

### 這解釋了新手最常見的錯誤

```bash
[-d /foo]     # ✗ shell 會去找名叫「[-d」的命令 → command not found
[ -d /foo ]   # ✓ 空格是分隔「命令」與「參數」用的，不能省
```

### `[` 與 `test` 完全等價

```bash
test -d /foo        # 跟 [ -d /foo ] 一模一樣
```

`]` 純粹是為了視覺對稱而設計的**必填參數**，`test` 版本不需要它。

> **心法：** 一旦接受「`[` 是命令」，後面所有規則（空格必要、引號必要、參數個數會影響語意）就都是自然推論，不必死背。

## 二、回傳值：離開狀態碼

`[` 不印任何東西，只設定**離開狀態碼**（exit status）：

**0 = 真，非 0 = 假**——跟 C 語言相反，因為 0 代表「成功、無錯誤」。

```bash
$ [ -d /sys/module/nvidia_drm/parameters ]; echo $?
0                    # 存在 → 真

$ [ -d /sys/module/nvidia/parameters ]; echo $?
1                    # 不存在 → 假
```

`$?` 是「上一個命令的離開狀態碼」，是所有 shell 條件判斷的基礎。

## 三、`&& ... || ...` 三元式與它的陷阱

```bash
[ -d /sys/module/$m/parameters ] && echo "有" || echo "無"
```

- `A && B` —— A 成功（狀態碼 0）才執行 B
- `A || B` —— A 失敗（非 0）才執行 B

串起來近似其他語言的 `cond ? x : y`。

### 陷阱：`&&` 後面那段自己失敗時，`||` 也會跑

```bash
$ [ -d /tmp ] && false || echo "「假」的分支也跑了！"
「假」的分支也跑了！
```

**怎麼看：** `[ -d /tmp ]` 是真 → 執行 `false` → `false` 回傳 1 → `||` 判定「左邊失敗」→ 連 `else` 分支一起執行。**兩邊都跑了。**

正規 `if` 就不會：

```bash
$ if [ -d /tmp ]; then false; else echo "這行不會出現"; fi
                     # (無輸出，如預期)
```

### 判準

| 情況 | 寫法 |
|---|---|
| `&&` 後面是 `echo`（幾乎不會失敗） | `&& ||` 安全，適合一行式 |
| `&&` 後面是 `grep` / `cp` / `mkdir` / 任何可能失敗的命令 | **一律用 `if`** |

## 四、常用測試運算子

| 運算子 | 意思 | 記法 |
|---|---|---|
| `-e` | 存在（任何類型） | **e**xists |
| `-f` | 存在**且**是普通檔案 | **f**ile |
| `-d` | 存在**且**是目錄 | **d**irectory |
| `-L` | 是符號連結 | **L**ink |
| `-s` | 存在且**非空** | **s**ize > 0 |
| `-r` / `-w` / `-x` | 可讀／可寫／可執行 | |
| `-z` / `-n` | 字串為空／非空 | **z**ero / **n**on-zero |
| `=` / `!=` | **字串**相等／不等 | |
| `-eq` `-ne` `-lt` `-gt` `-le` `-ge` | **數值**比較 | equal / not-equal / less-than / greater-than / less-equal / greater-equal |
| `!` | 反相 | `[ ! -d /foo ]` |

### 最容易搞混：字串用 `=`，數字用 `-eq`

```bash
[ "10" = "10.0" ]    # 假（字串內容不同）
[ 10 -eq 10 ]        # 真
[ "007" -eq 7 ]      # 真（數值比較會轉型）
[ "007" = 7 ]        # 假（字串比較不轉型）
```

## 五、引號：`[ ]` 最大的坑

因為 `[` 是命令，參數會先經過 shell 展開。**變數為空或含空格時，參數個數會變，語意整個跑掉。**

### 危險案例：空變數會靜默回傳「真」

```bash
$ m=""
$ [ -d $m ] && echo "真" || echo "假"
真                          # ← 錯誤答案，而且不報錯
```

**怎麼看：** 展開後變成 `[ -d ]`，只剩一個參數。`test` 的**單參數形式**語意是「這個字串非空嗎」——字串 `-d` 當然非空，所以回傳真。

**它不再是在測目錄，而是在測字串 `-d`，但完全不會報錯。** 這是靜默的錯誤答案，最難抓。

加引號就正確：

```bash
$ [ -d "$m" ] && echo "真" || echo "假"
假                          # ← [ -d "" ]，兩個參數，正確判定
```

### 含空格的路徑

```bash
$ n="/tmp/a b"
$ [ -d $n ] && echo "真" || echo "假"
假                          # 展開成 [ -d /tmp/a b ]，三個參數，超出語法
```

> **鐵則：`[ ]` 裡的變數一律加引號 `"$var"`。** 沒有例外值得省這兩個字元。

## 六、`[ ]` vs `[[ ]]`

`[[ ]]` 是 bash / zsh / ksh 的**語法關鍵字**（不是命令），shell 不會對裡面做分詞與萬用字元展開，所以變數不加引號也安全。

```bash
$ m=""; [[ -d $m ]] && echo "真" || echo "假"
假                          # ← 不加引號也正確

$ n="/tmp/a b"; [[ -d $n ]] && echo "真" || echo "假"
假                          # ← 含空格也正確

$ [[ -d /tmp && -r /tmp ]] && echo "兩者皆是"
兩者皆是                     # ← 直接用 && ，不用 -a

$ [[ "nvidia_drm" == nvidia* ]] && echo "萬用字元比對成功"
萬用字元比對成功              # ← 支援 pattern matching
```

### 對照表

| | `[ ]` / `test` | `[[ ]]` |
|---|---|---|
| 本質 | **命令**（builtin + `/usr/bin/[`） | **語法關鍵字** |
| 可攜性 | POSIX（Portable Operating System Interface，可攜式作業系統介面標準），所有 shell 都有 | bash / zsh / ksh，**dash 沒有** |
| 變數要加引號 | **必須** | 不必 |
| 邏輯運算 | `-a` / `-o`（易出錯，已不建議） | `&&` / `\|\|` |
| 萬用字元比對 | 不支援 | `[[ $x == nvidia* ]]` |
| 正規表達式 | 不支援 | `[[ $x =~ ^nv ]]` |
| 數值比較 | `-eq` `-lt` | `-eq`，或改用 `(( ))` |

### 純數值用 `(( ))` 更自然

```bash
(( i < 10 ))          # 可直接用 < > <= >= == !=
(( i++ ))
(( sum = a + b ))
if (( count > 0 )); then ...; fi
```

注意 `(( ))` 的真假規則跟 C 一樣（**非 0 為真**），但它會把結果轉成 shell 慣例的離開狀態碼，所以在 `if` 裡用起來符合直覺。

## 七、可攜性陷阱：本機能跑不代表別台能跑

**本機實測（2026-07-25）：**

```bash
$ ls -l /bin/sh
lrwxrwxrwx 1 root root 4 May 24 2025 /bin/sh -> bash      # ← 本機指向 bash

$ dash -c '[[ -d /tmp ]] && echo 有'
dash: 1: [[: not found                                     # ← dash 確實沒有

$ dash -c '[ -d /tmp ] && echo 有'
有                                                          # ← [ 則正常
```

**這裡有個雙重陷阱：**

1. 標準 Debian/Ubuntu 的 `/bin/sh` 指向 **dash**（為了開機速度），但**本機被改成 bash**。
2. 因此本機 `#!/bin/sh` 的腳本用 `[[` **會正常跑**，搬到標準環境（或 Docker 官方 debian/ubuntu 映像）就會爆 `[[: not found`。

**檢查方法：** 寫 `#!/bin/sh` 的腳本時，用 `dash script.sh` 實測，不要只靠 `sh script.sh`。

順帶一提，`dash: [[: not found` 這個錯誤訊息本身就是證據——dash 把 `[[` 當成**命令名稱**去找，找不到。這反證了 `[[` 在支援的 shell 裡是**語法關鍵字**而非命令，跟 `[` 的本質不同。

## 八、實務建議

| 腳本開頭 | 用什麼 | 理由 |
|---|---|---|
| `#!/bin/bash` / `#!/bin/zsh` | **`[[ ]]`** | 更安全、功能多，不必煩惱引號 |
| `#!/bin/sh` | **只能 `[ ]`** | dash 沒有 `[[`；且變數務必加 `"$var"` |
| 純數值運算 | **`(( ))`** | 可直接寫 `<` `>` `++`，最自然 |
| 互動 shell 隨手敲 | 都可 | 確定變數無空格時 `[ ]` 不加引號也行 |

### 查文件

```bash
man test                 # [ ] 的完整運算子清單
man bash                 # [[ ]] 是 bash 語法，搜 CONDITIONAL EXPRESSIONS
                         # （man 內按 /CONDITIONAL 再 Enter）
help test                # bash builtin 的快速說明
```

## 九、實例拆解：`[ $# -eq 0 ]`——「有沒有給參數」

> 補充日期：2026-09-22，出自 [TPROXY設定腳本參數化與可重複執行.md](../openwrt/TPROXY設定腳本參數化與可重複執行.md)
> 的 `if [ $# -eq 0 ]; then 印用法; exit 1; fi`。以下輸出皆在 dash 與 bash 實測。

### 逐字拆開

shell 先做展開，再執行命令。腳本沒收到任何參數時，這一行在執行前會先變成：

```
原文：    [   $#   -eq   0   ]
展開後：  [   0    -eq   0   ]
          │   │     │    │   │
          │   │     │    │   └─ ⑤ 第 4 個參數：必填的結尾標記，只是讓 [ 知道「到這裡結束」
          │   │     │    └───── ④ 第 3 個參數：右運算元，字面的 0
          │   │     └────────── ③ 第 2 個參數：數值「等於」運算子（equal）
          │   └──────────────── ② 第 1 個參數：$# 展開後的值——「位置參數有幾個」
          └──────────────────── ① 命令名稱：[（跟 test 是同一個命令）
```

- `$#` 是 shell 的特殊參數，值是**位置參數的個數**，不含 `$0`（完整清單見
  [TPROXY 腳本那篇的特殊參數表](../openwrt/TPROXY設定腳本參數化與可重複執行.md#三shell-怎麼把參數交給腳本)）。
- `-eq` 是**整數**比較，不是字串比較（見第四節〈字串用 `=`，數字用 `-eq`〉）。
- `[` 什麼都不印，只回傳狀態碼：成立回 0（真），不成立回 1（假）。

```
$ dash -c '[ $# -eq 0 ]; echo $?' x          # 沒有參數
0
$ dash -c '[ $# -eq 0 ]; echo $?' x a b      # 兩個參數
1
```

（`dash -c '腳本' x a b` 裡，`x` 會成為 `$0`，`a b` 才是 `$1 $2`。）

### `if` 看的是命令的狀態碼

```sh
if [ $# -eq 0 ]; then
    echo "用法: ..." >&2
    exit 1
fi
```

`if` 後面接的是**任何命令**，不是只能接 `[ ]`。它執行那個命令，狀態碼是 0 就跑 `then` 那段。
所以 `if [ $# -eq 0 ]` 和 `if test $# -eq 0` 完全一樣，`if grep -q foo file` 也是同一個機制。
**`if` 和 `[` 是兩個獨立的東西**：`[` 只是剛好常被放在 `if` 後面。

### 為什麼 `$#` 可以不加引號

第五節說過「`[ ]` 裡的變數要加引號」，這裡卻沒加。原因是 `$#` **一定是一個不含空白的非負整數**
（0、1、2…），不會是空字串、也不會被切成兩個字，不會發生第五節那種「參數少一個」的狀況。
這是少數「不加也不會出事」的情況（`$?`、`$$` 同理，都是 shell 保證的整數）；
但第五節的鐵則仍然成立——寫成 `[ "$#" -eq 0 ]` 一樣正確，習慣一律加引號就不必每次判斷這是不是例外。

### 為什麼用 `$#`，不用 `[ -z "$1" ]`

兩者看起來都在問「有沒有給參數」，但實際上判斷的是不同的事：

| 寫法 | 問的是 | 呼叫時給了一個空字串 `''` | 開了 `set -u` 又沒給參數 |
|---|---|---|---|
| `[ $# -eq 0 ]` | 參數**個數**是不是 0 | `$#` 是 1 → 判定「有給」 | 正常運作（`$#` 永遠有值） |
| `[ -z "$1" ]` | 第一個參數的**內容**是不是空的 | 判定「沒給」 | **腳本直接中止**：`1: parameter not set` |

```
$ dash -c 'set -u; [ -z "$1" ] && echo 空' x
x: 1: 1: parameter not set
```

TPROXY 那支腳本開了 `set -eu`，如果用 `[ -z "$1" ]`，沒給參數時使用者看不到用法說明，
只會看到一行看不懂的 `parameter not set`。**要問「有幾個參數」就用 `$#`。**

### 寫錯時的錯誤訊息

| 寫法 | dash 的錯誤 | bash 的錯誤 | 錯在哪 |
|---|---|---|---|
| `[$# -eq 0 ]` | `[0: not found` | `[0: command not found` | `[` 後面少了空白，`[` 和展開後的 `0` 黏成一個字，被當成叫 `[0` 的命令 |
| `[ $# -eq 0]` | `[: missing ]` | ``[: missing `]'`` | `0]` 黏在一起，`[` 找不到獨立的結尾參數 `]` |
| `[ abc -eq 0 ]` | `[: Illegal number: abc` | `[: abc: integer expression expected` | `-eq` 兩邊都必須是整數 |

前兩種錯誤正好證明了第一節的結論：`[` 是命令，`]` 是它的**最後一個參數**，
所以兩邊都一定要用空白隔開。

### 其他等價寫法

| 寫法 | 可在 `#!/bin/sh` 用 | 備註 |
|---|---|---|
| `[ $# -eq 0 ]` | 是 | 最常見 |
| `[ $# = 0 ]` | 是 | 改成字串比較；因為 `$#` 不會出現 `00` 這種寫法，結果相同 |
| `test $# -eq 0` | 是 | 和 `[` 是同一個命令 |
| `[[ $# -eq 0 ]]` | **否** | bash／zsh 語法，dash 會報 `[[: not found`（第七節） |
| `(( $# == 0 ))` | **否** | bash／zsh 的算術測試，dash 不支援 |

## 速查

```bash
# 本質
[ 是命令（= test），] 是必填參數 → 空格不可省、變數要加引號
[[ 是語法關鍵字 → 不分詞、不展開、不必加引號

# 狀態碼
0 = 真，非 0 = 假        # 跟 C 相反
echo $?                  # 看上一個命令的狀態碼

# 常用測試
[ -e f ] [ -f f ] [ -d d ] [ -L l ] [ -s f ]     # 存在/檔案/目錄/連結/非空
[ -r f ] [ -w f ] [ -x f ]                        # 權限
[ -z "$s" ] [ -n "$s" ]                           # 字串空/非空
[ "$a" = "$b" ]                                   # 字串比較
[ "$a" -eq "$b" ]                                 # 數值比較

# 三元式（僅限 && 後面不會失敗時）
[ -d /foo ] && echo 有 || echo 無

# 進階（bash/zsh）
[[ $x == nvidia* ]]      # 萬用字元
[[ $x =~ ^nv ]]          # 正規表達式
[[ -d /a && -r /a ]]     # 直接用 &&
(( i < 10 ))             # 數值

# 可攜性驗證
dash script.sh           # #!/bin/sh 的腳本要用 dash 實測（本機 sh 是 bash，測不出問題）
```

## `test` / `[ ]` 的完整運算子（依 `help test`，bash 5.2）

**檔案運算子**

| 運算子 | 為真的條件 |
|---|---|
| `-e FILE` | 檔案存在 |
| `-a FILE` | 檔案存在（`-e` 的舊寫法，**和 AND 的 `-a` 撞名，別用**） |
| `-f FILE` | 存在且是**一般檔案** |
| `-d FILE` | 是目錄 |
| `-h` / `-L FILE` | 是符號連結 |
| `-b FILE` | 是區塊裝置 |
| `-c FILE` | 是字元裝置 |
| `-p FILE` | 是具名管線（FIFO） |
| `-S FILE` | 是 socket |
| `-s FILE` | 存在且**不是空的** |
| `-r` / `-w` / `-x FILE` | 你可讀／可寫／可執行 |
| `-u` / `-g` / `-k FILE` | 有 setuid／setgid／sticky bit |
| `-O` / `-G FILE` | 有效擁有者是你／你的群組 |
| `-N FILE` | 上次讀取之後被修改過 |
| `-t FD` | **該 fd 連著終端機**（判斷「有沒有在 pipe 裡」用這個） |
| `F1 -nt F2` / `-ot F2` | F1 比 F2 新／舊 |
| `F1 -ef F2` | 兩者是同一個 inode（硬連結或同檔） |

**字串運算子**

| 運算子 | 為真的條件 |
|---|---|
| `-z STR` | 長度為 0 |
| `-n STR` / `STR` | 長度不為 0 |
| `S1 = S2` / `S1 == S2` | 相等（`==` 是 bash 擴充） |
| `S1 != S2` | 不等 |
| `S1 < S2` / `S1 > S2` | 字典序比較（**在 `[ ]` 裡要跳脫成 `\<`，否則被當重新導向**） |

**數值運算子**（只能比整數）

`-eq`（等於）、`-ne`（不等）、`-lt`（小於）、`-le`、`-gt`、`-ge`。

**其他**

| 運算子 | 意思 |
|---|---|
| `-o OPTION` | shell 選項有開啟 |
| `-v VAR` | 變數有設定 |
| `-R VAR` | 變數是 nameref |
| `! EXPR` | 反向 |
| `EXPR1 -a EXPR2` | AND（**POSIX 已標示過時，建議改用 `[ A ] && [ B ]`**） |
| `EXPR1 -o EXPR2` | OR（同上） |
| `( EXPR )` | 分組（`[ ]` 裡要跳脫成 `\(` `\)`） |

> **`[[ ]]` 多出來的**：`=~`（正規式比對）、`&&`／`||`（不用跳脫）、
> 右側不會做分詞與路徑展開、`<`／`>` 不用跳脫。
> 完整差異見 `man bash` 的 CONDITIONAL EXPRESSIONS 段落。
