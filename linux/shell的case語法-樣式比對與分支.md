> 裡「把參數組成 nft 集合元素」那段 8 行迴圈看不懂：`case`、`''|*[!0-9./]*)`、`;;`、`esac`、

**一句話結論：`case` 是「拿一個字串去跟一串樣式（pattern）比，第一個配對成功的那組才執行」的分支
語法；樣式用的是跟檔名萬用字元同一套規則（`*`、`?`、`[...]`、`[!...]`），不是正規表示式
（regular expression）。在 `#!/bin/sh` 裡要做「字串長得像不像某種格式」的檢查，`case` 是唯一
不必呼叫外部程式、又在所有 shell 都能用的寫法。**

## 一、先看整段在做什麼

```sh
SRC=""                                  # ① 準備一個空字串來裝結果
for ip in "$@"; do                      # ② 參數一個一個取出來，每圈放進變數 ip
    case $ip in                         # ③ 拿 ip 的值去比對下面的樣式
        ''|*[!0-9./]*)                  # ④ 空字串，或含有數字、點、斜線以外的字元
            echo "不像 IPv4 位址或網段: '$ip'" >&2   # ⑤ 錯誤訊息寫到 stderr
            exit 1 ;;                   # ⑥ 整支腳本以失敗結束；;; 是這組分支的結尾
    esac                                # ⑦ case 的結尾（case 倒過來拼）
    SRC="${SRC:+$SRC, }$ip"             # ⑧ 通過檢查的才會走到這裡：接到 SRC 後面
done                                    # ⑨ 迴圈結尾
```

（原腳本把 ④⑤⑥ 寫在同一行，意思相同；這裡為了逐行標號而拆開。）

跑 `tproxy-up.sh 192.168.1.50 192.168.1.60` 時：

| 圈 | `ip` | `case` 結果 | 這圈結束後的 `SRC` |
|---|---|---|---|
| 1 | `192.168.1.50` | 沒配對到任何樣式 → 什麼都不做 | `192.168.1.50` |
| 2 | `192.168.1.60` | 同上 | `192.168.1.50, 192.168.1.60` |

只要有任何一個參數不合格，就在 ⑥ 直接結束，**後面的 `ip rule`、`nft` 一行都不會執行**——
先把所有輸入檢查完，才開始動系統。

② 的 `for ip in "$@"` 在 [shell的for迴圈語法.md](./shell的for迴圈語法.md) 有完整說明；
重點是 `"$@"` 一定要加引號，每個參數才會各自成為一圈。沒有參數時 `"$@"` 展開成零個字，
迴圈一圈都不跑（實測 dash：`set --; for ip in "$@"; do ...` 不會進入迴圈）。

## 二、`case` 的完整文法

`man dash` 的 Case Statements 一節給的骨架：

```
case <字> in
    [(]<樣式>[|<樣式>]...) <命令串> ;;
    [(]<樣式>[|<樣式>]...) <命令串> ;;
    ...
esac
```

逐個位置：

| 位置 | 是什麼 | 固定關鍵字還是自己寫的 |
|---|---|---|
| `case` | 開始 | 固定關鍵字 |
| `<字>` | 要被比對的字串，通常是 `$變數` | 自己寫 |
| `in` | 分隔「要比的字」和「樣式清單」 | 固定關鍵字，不能省 |
| `(` | 樣式前面**可以**加一個左括號，純粹是為了左右對稱 | 可省略，省略沒有任何差別 |
| `<樣式>` | 要比對的形狀，規則見第三節 | 自己寫 |
| `\|` | 在同一組裡放多個樣式：「這個**或**那個」 | 固定符號 |
| `)` | 樣式清單結束，後面開始是這組要執行的命令 | 固定符號，不能省 |
| `<命令串>` | 配對成功時要執行的一或多個命令，用 `;` 或換行分隔 | 自己寫，也可以是空的 |
| `;;` | 這一組結束 | 固定符號；**最後一組的 `;;` 可以省略**（實測 dash） |
| `esac` | 整個 `case` 結束 | 固定關鍵字（`case` 倒過來拼，跟 `if`／`fi` 同一個命名習慣） |

### 執行規則

1. **由上往下比，第一個配對成功的那組執行完就離開整個 `case`**，後面的組不會再比。
   ```
   $ case abc in a*) echo 第一個;; ab*) echo 第二個;; esac
   第一個                       ← ab* 也配得上，但輪不到它
   ```
   所以「萬用的」`*)` 一定要放在最後，當作「以上皆非」（相當於其他語言的 `default`）。
2. **都沒配對到就什麼都不做**，不會報錯，結束狀態是 0。本腳本正是利用這點：
   合格的 IP 不會配對到 ④，`case` 安靜地結束，往下走到 ⑧。
3. **`<字>` 不會被分詞、也不會做路徑展開**，所以 `case $ip in` 不加引號也安全
   （實測 `x="a b"; case $x in "a b")` 配對成功）。這跟 `[ ]` 裡變數一定要加引號不同——
   `case` 是語法，不是命令（對照 [shell條件判斷測試.md](./shell條件判斷測試.md) 第一節）。

### 分支結尾：`;;` 以外的兩種（bash 限定）

| 結尾 | 意思 | 哪裡能用 |
|---|---|---|
| `;;` | 結束整個 `case` | POSIX，所有 shell |
| `;&` | 不比對了，**直接執行下一組**的命令（fall-through，相當於 C 的 switch 沒寫 break） | bash、zsh；**dash 會報 `Syntax error: "&" unexpected`** |
| `;;&` | 繼續拿下一組的樣式來比，配對到就也執行 | bash |

`#!/bin/sh` 的腳本只用 `;;`。（BusyBox ash 是否支援 `;&` 沒有實測，不要依賴。）

## 三、樣式（pattern）的完整規則

`case` 的樣式跟 `ls *.md` 的萬用字元（glob）是**同一套**規則。依 `man dash` 的 Shell Patterns 一節，
特殊字元只有 `*`、`?`、`[`、`!` 四個：

| 寫法 | 配對什麼 | 例 |
|---|---|---|
| 一般字元 | 它自己 | `start` 只配 `start` |
| `*` | **任意長度**的任意字元，包含零個 | `a*` 配 `a`、`ab`、`abc` |
| `?` | **剛好一個**任意字元 | `a?` 配 `ab`，不配 `a`、`abc` |
| `[abc]` | 括號裡的**任一個**字元（只算一個字元的位置） | `[yY]` 配 `y` 或 `Y` |
| `[a-z]` | 範圍：`a` 到 `z` 之間任一個字元 | `[0-9]` 配一個數字 |
| `[!abc]` | **不是**括號裡任一個字元的一個字元（補集） | `[!0-9]` 配一個非數字字元 |
| `[[:digit:]]` 等 | 字元類別：`alpha`、`digit`、`alnum`、`space`、`upper`、`lower`、`punct` 等 | `[[:digit:]]` 等同 `[0-9]` |

括號裡的兩個特例（`man dash` 原文規定）：

- 要把 `]` 本身放進去，把它放在**第一個**（在 `!` 之後）：`[]]`、`[!]]`
- 要把 `-` 本身放進去，放在**第一個或最後一個**：`[a-]`、`[-a]`；放中間就會被當成範圍

### 容易踩的三個地方

1. **樣式要「整個字串」都配上，不是「包含」就算。** `1*` 配 `1.2.3.4`，但 `2*` 不配——
   開頭是 `1`。想表達「任何位置含有 X」要寫 `*X*`，兩邊都加 `*`。
2. **補集要用 `!`，不是 `^`。** 正規表示式的習慣是 `[^0-9]`，但 POSIX 樣式規定的是 `[!0-9]`。
   實測 bash 兩種都認；**dash 的 `[^a]` 不會當成補集**（`case x in [^a])` 在 dash 配對失敗）。
   OpenWrt 的 `/bin/sh` 不是 bash，一律寫 `!`。
3. **加引號就變成字面文字。**
   ```
   case 'a*' in 'a*') ...          ← 配對成功：引號裡的 * 只是星號這個字元
   case ab   in 'a*') ...          ← 配對失敗：它不再是萬用字元
   p='a*'; case abc in $p) ...     ← 配對成功：沒加引號的變數，值裡的 * 會變回萬用字元
   p='a*'; case abc in "$p") ...   ← 配對失敗：加了引號就是字面比較
   ```
   樣式裡要比對使用者給的字串時（例如「是不是等於某個檔名」），**樣式那邊要加引號**，
   否則對方給的 `*` 會把你的判斷變成永遠成立。

### 這不是正規表示式

| 想表達 | 正規表示式 | `case` 樣式 |
|---|---|---|
| 任意字串 | `.*` | `*` |
| 一個任意字元 | `.` | `?` |
| 不是數字 | `[^0-9]` | `[!0-9]` |
| 一個以上的數字 | `[0-9]+` | **做不到**（樣式沒有「重複」的概念） |
| 這個或那個 | `a\|b` | `a\|b`（只能用在整組樣式之間） |

「重複」做不到，所以 `case` 很難寫出「剛好四段、每段 0～255」的完整 IPv4 驗證。
本腳本只拿它擋掉危險字元（見下一節），完整的格式檢查交給 nft 自己報錯。

## 四、拆解 `''|*[!0-9./]*`

```
''   |   *   [!0-9./]   *
│    │   │      │       └─ 後面接任意字串（可以是空的）
│    │   │      └───────── 剛好一個字元，而且「不是」0～9、. 、/ 中的任一個
│    │   └──────────────── 前面接任意字串（可以是空的）
│    └──────────────────── 或
└───────────────────────── 空字串（兩個單引號之間什麼都沒有）
```

- 右半邊 `*[!0-9./]*` 讀成：**「字串裡某個位置，有一個不是數字、點、斜線的字元」**。
  兩邊的 `*` 就是第三節說的「要表達『含有』得兩邊都加 `*`」。
- 左半邊 `''` 要另外寫，是因為**空字串裡沒有任何字元**，右半邊找不到「不合格的字元」，
  會讓空字串通過。使用者執行 `tproxy-up.sh ''` 就會產生 `elements = { }` 這種壞規則。

實測 dash 與 bash 結果相同：

| 參數 | 結果 | 為什麼 |
|---|---|---|
| `192.168.1.50` | 通過 | 全是數字和點 |
| `192.168.1.0/24` | 通過 | 斜線也在允許清單裡，所以網段可以用 |
| `''` | 拒絕 | 配對到左半邊 |
| `'1.2.3.4 '`（尾巴有空白） | 拒絕 | 空白不在允許清單 |
| `abc` | 拒絕 | 字母 |
| `1.2.3.4;rm` | 拒絕 | `;` 不在允許清單——這正是要擋的東西 |
| `-1` | 拒絕 | `-` 不在允許清單 |
| `*` | 拒絕 | `*` 是被比對的字串，不是樣式，這裡就只是一個不合格字元 |
| `999.1.1.1` | **通過** | 字元都合格。這個檢查只管「字元」，不管「數值範圍」 |

為什麼只擋字元就夠：參數會被原封不動插進 nft 的規則文字裡，真正危險的是 `}`、`;`、空白、
換行這些會**改變 nft 語法結構**的字元。`999.1.1.1` 不會改變結構，nft 讀到時自己會報錯。

## 五、錯誤處理那一行：`echo ... >&2; exit 1`

```sh
echo "不像 IPv4 位址或網段: '$ip'" >&2; exit 1 ;;
```

| 片段 | 意思 |
|---|---|
| `"...'$ip'..."` | 外層是雙引號，所以裡面的 `$ip` **會展開**；裡面那對單引號在雙引號中**只是普通字元**，會照樣印出來，用來把值框起來。印出來是 `不像 IPv4 位址或網段: '1.2.3.4 '`，尾巴的空白一眼就看得到 |
| `>&2` | 把這個 `echo` 的標準輸出（fd 1）改接到標準錯誤（fd 2）。錯誤訊息應該寫到 stderr，這樣別人用 `tproxy-up.sh ... > log` 時錯誤還是會出現在螢幕上（fd 的觀念見 [輸出重新導向與dev-null.md](./輸出重新導向與dev-null.md)） |
| `;` | 分隔同一行裡的兩個命令 |
| `exit 1` | **結束整支腳本**（不是只結束迴圈或 `case`），結束狀態 1 表示失敗。呼叫它的人可以用 `$?` 或 `if` 判斷 |
| `;;` | 這組 `case` 分支結束 |

`exit` 和 `break` 要分清楚：`break` 只跳出迴圈、腳本繼續往下跑；`exit` 是整個行程結束。
這裡要的是「有任何一個參數不合格就什麼都不做」，所以用 `exit`。

## 六、累加字串：`${SRC:+$SRC, }$ip`

```sh
SRC="${SRC:+$SRC, }$ip"
```

右邊是兩段黏在一起：`${SRC:+$SRC, }` 和 `$ip`。

`${變數:+替代值}` 的規則：**變數有值（非空）時展開成「替代值」，否則展開成空字串**。
這裡的替代值是 `$SRC, `——原本的內容加上逗號和空白。

```
第 1 圈：SRC=""               → ${SRC:+...} 展開為 ""                 → SRC = "" + "192.168.1.50"
第 2 圈：SRC="192.168.1.50"   → ${SRC:+...} 展開為 "192.168.1.50, "   → SRC = "192.168.1.50, " + "192.168.1.60"
```

效果是「元素之間才有逗號，第一個前面沒有」。如果直接寫 `SRC="$SRC, $ip"`，
結果會是 `, 192.168.1.50, 192.168.1.60`，開頭多一個逗號，`{ , 192.168.1.50 }` 不是合法的集合元素寫法。

有冒號和沒冒號差在「空字串算不算有值」：

| 寫法 | 變數未設定 | 設為空字串 | 有值 |
|---|---|---|---|
| `${v:+X}` | 空 | **空** | `X` |
| `${v+X}` | 空 | **`X`** | `X` |

（實測：`e=""` 時 `${e:+X}` 是空、`${e+X}` 是 `X`。）這裡 `SRC` 一開始就被設成 `""`，
所以一定要用有冒號的 `:+`，否則第一圈就會多出逗號。

其他參數展開形式（`:-`、`:=`、`:?`、`#`、`%`）見
[錢字號展開的四種形式](./錢字號展開的四種形式-bad-substitution的根因.md) 與 `man dash` 的
Parameter Expansion 一節；這裡只講本段用到的 `:+`。

## 七、寫錯時的錯誤訊息

| 寫法 | dash | bash | 錯在哪 |
|---|---|---|---|
| `case a in a) echo 1`（沒有 `esac`） | `end of file unexpected (expecting ";;")` | `unexpected end of file` | 整個 `case` 沒有結尾 |
| `case a in a) echo 1; b) echo 2;; esac` | `")" unexpected (expecting ";;")` | ``near unexpected token `)'`` | 第一組只寫了 `;`，沒寫 `;;`，下一組的 `b)` 被當成命令的一部分 |
| `case a a) echo 1;; esac` | `word unexpected (expecting "in")` | ``near unexpected token `a'`` | 少了 `in` |
| `case a in a echo 1;; esac` | `word unexpected (expecting ")")` | ``near unexpected token `echo'`` | 樣式後面少了 `)` |
| `case a in a) echo 1;& b) ...`（在 dash） | `Syntax error: "&" unexpected` | （bash 正常） | `;&` 是 bash 擴充 |

dash 的訊息會直接說它**期待**什麼（`expecting ";;"`），比 bash 好反推。
寫 `#!/bin/sh` 的腳本，除錯時可以先 `dash -n script.sh` 只做語法檢查、不執行。
